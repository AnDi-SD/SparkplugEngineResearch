# Общее ядро инструментов

Приложения используют общую восстановленную логику из `Sparkplug/` и `Winx/`. Мост делает её доступной C# и Python, а каждый инструмент добавляет собственный пользовательский сценарий.

```text
GUI / CLI / Python-программа
        ↓
общие адаптеры чтения, сцены и редактирования
        ↓
SmoViewer.Sparkplug / sparkplug_native.py
        ↓ C ABI
SparkplugViewer.Native
        ↓
Sparkplug/ + Winx/
```

## Ответственность компонентов

| Компонент | Ответственность |
| --- | --- |
| `SparkplugViewer.Native` | C ABI, управление handles и операции над общими C++-объектами |
| `SmoViewer.Sparkplug` | P/Invoke, SafeHandle и managed-представления результатов |
| `SmoViewer.Core` | Форматный API и оставшиеся typed C#-декодеры/адаптеры; общие операции обращаются к C++ |
| `SmoViewer.Scene` | Подготовка отображаемой сцены, ссылок материалов и фактических размещений |
| `SmoViewer.Editing` | Общие операции редактирования, записи и установки результата |
| `SmoViewer.Rendering.Wpf` | Наш OpenGL backend, render input и математика viewport |
| `SmoViewer.Corpus` | Локальный SQLite-индекс ресурсов, объектов и полей |
| `SmoExporter.Core` | Перевод общей сцены в экспортное представление и целевые форматы |
| `SmoImporter.Core` | Подготовка донора и операции переноса в целевой ресурс |

Модули GUI владеют интерфейсом, выбором, камерой и командами пользователя. Viewer не подключает модуль записи только ради просмотра; редакторы используют общую `Editing`.

## Состояние реализации

C++-ядро уже обслуживает контейнер и поля, ряд serializers, mesh buffers, SAN, преобразования узлов и skin. Перенос всех операций ещё не завершён: в managed-слое остаются адаптеры, части typed graph writers и операции подготовки данных. Само наличие native DLL не означает, что каждый путь приложения полностью восстановлен из игры.

Преобразование координат целевого формата, UI, retargeting на MMD, создание весов и современный backend — наш код. Эти операции не выдаются за оригинальную игровую логику. Общие host-алгоритмы в `Sparkplug/Analysis/Host` обозначены тем же образом.

## Сборка и проверка

Инструкции [native-моста](SparkplugViewer.Native/README.md) и [общая сборка](../CONTRIBUTING.md) описывают C++ и .NET зависимости. DLL должна соответствовать текущей обвязке и находиться рядом с приложением. FBX дополнительно требует [FBX-мост](FbxBridge.Native/README.md).

Синтетические проверки можно запускать без игры; проверки оригинального loader требуют локальной копии файлов. Успешное чтение, запись и открытие файла — разные проверки, и результат одной не заменяет остальные.
