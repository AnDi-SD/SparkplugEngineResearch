# SAN → VMD — тестовый конвертер

Версия **0.1.0-test**. Один Python-скрипт с комментариями на русском.
Читает PC SAN персонажей со скелетом Bloom, сохраняет анимацию тела и пальцев
для стандартного PMD-скелета MMD. Blender и дополнительные Python-библиотеки
не нужны. Требуется Python **3.10 или новее**.

## Запуск

1. Положите нужные `.san` в эту папку, рядом с `san_to_vmd.py`.
2. Запустите **`run.bat`** двойным щелчком. Окно останется открытым с результатом.
3. Готовые `.vmd` появятся в подпапке **`vmd`**.

Можно запускать прямо из Python:

```powershell
python tools/SanToVmd/san_to_vmd.py
```

Скрипт ищет SAN рядом с **самим скриптом**, независимо от текущей папки терминала.
Регистр расширения не важен; вложенные папки не обходятся.
Одноимённые готовые VMD пропускаются. Для их замены:

```powershell
python tools/SanToVmd/san_to_vmd.py --overwrite
```

Для локального первого опыта сюда уже скопированы пять SAN. Они игнорируются
Git и не появятся при клонировании репозитория:

| Файл | Назначение примера |
|---|---|
| `blwa.san` | Ходьба |
| `blru.san` | Бег |
| `bljusm.san` | Вход в обычный прыжок; короткая часть, не весь прыжок |
| `blidlo.san` | Длинная анимация ожидания |
| `blabe.san` | Проверка кубических кривых перемещения |

## Откуда берутся скелеты

Из SAN нельзя узнать исходную позу и иерархию костей. Поэтому нужны два
референса: `bloom_jeans.smo` и целевая модель `Miku_Hatsune.pmd`.
Их меши/текстуры конвертер не экспортирует и не меняет.

В текущем workspace эти файлы находятся автоматически:

```text
local-data/bloom_jeans.smo
local-data/mmd/MikuMikuDanceE_v932/UserFile/Model/Miku_Hatsune.pmd
```

Чтобы использовать конвертер отдельно от репозитория, достаточно такой папки:

```text
SanToVmd/
  san_to_vmd.py
  run.bat
  bloom_jeans.smo
  Miku_Hatsune.pmd
  blwa.san
  blru.san
```

Сначала выбираются эталонные файлы рядом со скриптом, затем локальные файлы
workspace. Если рядом находится ровно один SMO/PMD с другим именем, используется
он. Путь, явно переданный параметром, имеет приоритет.

PMX и `.blend` как целевые модели в этой версии не читаются. Другой скелет PMD
должен содержать стандартные японские имена основных костей тела.
Одинаковые имена в другом SMO ещё не гарантируют совместимость его анимаций.

## Будет ли работать на других моделях

Да, VMD с обычными именами костей MMD можно пробовать на других моделях.
Имена связывают треки с костями; имя Miku в заголовке не делает движение
эксклюзивным для Miku. Такой поиск по именам виден и в
[импортёре VMD MMD Tools](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/vmd/importer.py).
Но одинаковые имена не гарантируют одинаковую позу: влияют пропорции,
иерархия, исходный наклон рук и управляющие кости.

Для поддержанного PMD лучше пересоздать VMD с `--model` этой модели:
конвертер пересчитает поправки направлений конечностей и масштаб перемещений.
Готовый VMD можно загрузить и на совместимый PMX; **читать PMX как референс
для `--model` этот скрипт пока не умеет**.

На комплекте `MikuMikuDanceE_v932` проверены все 20 SAN Icy для каждого
поддержанного профиля:

| Целевая PMD | Результат автоматической проверки |
|---|---|
| `Miku_Hatsune`, `Haku_Yowane`, `KAITO`, `Len_Kagamine` | По 20/20 VMD |
| `Meiko_Sakine`, `Neru_Akita`, `Rin_Kagamine`, `Rin_Kagamene_act2` | По 20/20 VMD |
| `Luka_Megurine`, `Miku_Hatsune_Ver2`, `Miku_Hatsune_metal` | Пока отклоняются: промежуточные кости скручивания рук, PMD type 8 |
| `MEIKO` | Пока отклоняется: две служебные кости `センター先` с одинаковым именем |
| `Dammy_Bone` | Не является человеческим скелетом, основных костей тела нет |

Проверены чтение VMD и направления сегментов рук/ног в трёх позах каждого
клипа. Это не визуальная проверка этих моделей в MMD и не проверка их физики.
Результаты относятся к конкретным комплектным файлам, а не к любой модели
с таким названием. Наличие костей волос/одежды само по себе не означает,
что автор настроил для них физику.

## Анимации Icy

Для Icy используйте её собственный `Icy.smo`: нужные имена и родители
совпадают с Bloom, но исходные позиции ряда суставов, в частности пальцев,
отличаются. Указание папки SAN само по себе не меняет референс SMO.
Команда из корня репозитория:

```powershell
python tools/SanToVmd/san_to_vmd.py --input-dir local-data/pc-pristine/Media/Characters/Icy --skeleton local-data/pc-pristine/Media/Characters/Icy/Icy.smo --output-dir tools/SanToVmd/vmd/icy/Miku_Hatsune
```

Готовые локальные результаты уже лежат в `vmd/icy/<имя PMD>/` — по 20 файлов
для восьми моделей из таблицы. Например, `Miku_Hatsune/xiwa.vmd` — ходьба,
`Miku_Hatsune/xiru.vmd` — бег, `Miku_Hatsune/xiid.vmd` — ожидание.
Для пробы в MMD диапазоны соответственно **0–30**, **0–20**, **0–50**.
Для другой модели добавьте `--model <путь к PMD>` и выберите отдельную
папку через `--output-dir`; для замены готовых файлов добавьте `--overwrite`.

Из 86 узлов Icy в расчёте участвуют 58 нужных узлов и предков.
Во всех её SAN отбрасываются `Hair_01`–`Hair_04`, `Cape_01`–`Cape_02`,
а также служебные треки `Master` и `BLOOM`. В VMD остаются 47 целевых треков
тела и пальцев. Лишние ветви пропускаются по используемой иерархии,
а не по словам Hair/Cape: неизвестный предок кости тела всё равно нужен.

## Проверка в MMD

1. Откройте новую сцену в MikuMikuDance.
2. Загрузите `Miku_Hatsune.pmd` из `UserFile/Model` комплектного редактора.
3. Выберите эту модель и загрузите, например, `vmd/blwa.vmd` через
   `File → Load motion data`.
4. Установите диапазон проигрывания: для `blwa` кадры **0–30**, для `blru`
   **0–36**, для `blidlo` **0–283**. Проиграйте движение.

При выборе другой PMD для конвертации в MMD нужно загрузить именно её.
Включённая физика MMD использует настройки волос/одежды самой модели.

## Дополнительные параметры

```powershell
# Другая папка входов и результатов.
python tools/SanToVmd/san_to_vmd.py --input-dir "D:/motions" --output-dir "D:/converted"

# Другие эталонные файлы.
python tools/SanToVmd/san_to_vmd.py --skeleton "D:/bloom_jeans.smo" --model "D:/Rin_Kagamine.pmd"

# Только тело, без пальцев: 19 целевых треков на стандартной Miku.
python tools/SanToVmd/san_to_vmd.py --body-only

# Ручная поправка масштаба перемещений вместо автоматической оценки.
python tools/SanToVmd/san_to_vmd.py --motion-scale 0.133
```

`--motion-scale` меняет смещения тела, а не размеры модели и не углы вращений.
Без него масштаб оценивается по высоте таза над стопами в исходных скелетах.

Для каждого запуска создаётся `vmd/conversion_report.json`: статус файлов,
количество кадров/костей, игнорируемые треки и события, отсутствующие треки,
выбранные референсы и масштаб. Отсутствующий трек сохраняет исходную позу
соответствующего узла. Ошибка одного SAN не мешает обработке остальных.
При ошибках процесс возвращает код 1, при успехе/пропуске — 0.

## Что делает эта версия

- Вычисляет мировые transforms костей Bloom с учётом родителей.
- Убирает исходные ориентации костей и учитывает различия углов конечностей
  в исходных позах Bloom/Miku. Затем получает локальные вращения целевой иерархии.
- Сохраняет длины костей PMD. Исходная поза Bloom при переносе выравнивает
  направления конечностей; поэтому её результат не обязан иметь нулевые
  вращения всех костей Miku.
- Переносит 47 треков на обычной Miku: центр, 18 основных костей и 28 фаланг.
  Три сустава большого пальца Bloom объединяются в два целевых. Кости
  `上半身2` и `親指０` используются, если присутствуют в PMD.
- Поддерживает векторные линейные позиции, quaternion SLERP, скалярные
  линейные и кубические позиции с независимым временем осей.
- Запекает позы при 30 кадрах/с, включая начальную и конечную позы.
- Записывает VMD 0002 с именами CP932, непрерывными quaternion и линейными
  Bezier-параметрами; игровые события, камера, морфы и физика не экспортируются.
- Передаёт ноги через FK и записывает отключение четырёх IK ног/носков
  на кадре 0. IK других частей модели не выключается.
- Не записывает лишние кости. Неподдержанный используемый канал вызывает
  понятную ошибку; неподдержанные каналы отброшенных треков не мешают телу.

## Ограничения тестовой версии

**Это прототип переноса поз, а не окончательно отлаженный ретаргетер.**
Пользователь подтвердил работу исходных примеров на Miku в MMD 7 сентября
2026 года. Для нового набора Icy и остальных моделей пока выполнены
автоматические проверки структуры файлов и математики поз.

FK не фиксирует стопы на полу. Из-за разных пропорций, формы обуви и исходных
поз возможны скольжение и пересечение пола. Отдельное сгибание носков не
переносится: стандартные `つま先` Miku являются IK endpoints.
Выравнивание направления конечности не восстанавливает идеальный roll для
произвольного рига. Twist/grant и нестандартные управляющие кости не вычисляются.

Одна кость корпуса Miku приближает движение нескольких суставов позвоночника
Bloom. Для большого пальца тоже неизбежно приближение. Волосы и одежда
реагируют автоматически только при наличии настроенной физики в PMD.

Масштабирование костей, packed cubic representation 2 и скалярные вращения
SAN пока отклоняются для используемых треков. Набор из 168 SAN Bloom не
нуждается в этих формах. Края кривых удерживают крайний ключ; это выбранное
правило конвертера, а не побитное повторение всех особенностей runtime игры.
Движение персонажа по сцене, которое добавляет логика игры, из SAN не выдумывается.

## Проверки разработки

Проверены 168/168 SAN папки Bloom, включая семь с кубическими позициями.
Независимый VMD-reader из [MMD Tools](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/vmd/__init__.py)
прочитал все **386 434 ключа**. Проверены имена, номера кадров, границы всех
секций, нормы/знаки quaternion, интерполяция и четыре IK-off состояния.
На пяти контрольных SAN направления сегментов рук/ног после независимого
матричного FK по VMD совпали с исходными: максимальная разность единичных
векторов меньше `0.000002`. Это проверка выбранных поз, не контакта с полом.

```powershell
python -m unittest discover -s tools/SanToVmd/tests -v
```

13 синтетических проверок охватывают порядок вращений, исходный наклон рук,
родителей, cubic/time math, лишние треки и ветви SMO, плохие входы и сохранность
существующего VMD при неудачной замене.

Полная локальная проверка требует корпуса и отдельно сохранённого исходника
VMD-reader MMD Tools; конвертер сам ничего не скачивает:

```powershell
python tools/SanToVmd/tests/validate_local.py --reader local-data/mmd-research/mmd_tools_vmd_reader.py
```

По умолчанию она читает ранее созданные результаты из
`local-data/mmd-research/test-vmd-v01/`. JSON проверки сохраняется локально в
`local-data/mmd-research/validation-v01.json`.

Для Icy проверено **160 VMD / 562 872 ключа** на восьми PMD.
Максимальная разность единичных векторов сегментов рук/ног меньше `0.000001`.
В отдельном опыте для Miku во всех 20 SAN заменены 480 PRS-каналов восьми
игнорируемых треков на неподдерживаемую representation 99: все VMD остались
**побайтно одинаковыми**. При включении этих треков в требуемый граф чтение
закономерно завершается ошибкой. Удаление 28 лишних узлов из прочитанного
SMO также сохранило все 20 VMD побайтно.

Проверка Icy и намеренной порчи лишних SAN-каналов:

```powershell
python tools/SanToVmd/tests/validate_local.py --reader local-data/mmd-research/mmd_tools_vmd_reader.py --input-dir local-data/pc-pristine/Media/Characters/Icy --skeleton local-data/pc-pristine/Media/Characters/Icy/Icy.smo --vmd-dir tools/SanToVmd/vmd/icy/Miku_Hatsune --report local-data/mmd-research/icy/validation-Miku_Hatsune.json --check-ignored
```

Для проверки остальных профилей передайте валидатору `--model`, соответствующий
`--vmd-dir` и отдельный `--report`. Валидатор читает имеющиеся результаты,
поэтому перед ним нужно выполнить конвертацию. Сейчас позы проверяются для
каждого клипа, а не только для пяти контрольных примеров Bloom.
Расширенная проверка также прошла на всех 168 прежних VMD Bloom:
максимальная разность направлений `0.000002031`. Её локальный отчёт сохранён
отдельно в `local-data/mmd-research/validation-bloom-expanded-2026-09-07.json`.
Сводка с хэшами входов и границами проверки:
[Icy и совместимость PMD](../../research/san-to-vmd-icy-2026-09-07.json).

Основания формата и план дальнейших экспериментов:
[мини-исследование SAN → VMD](../../docs/research/san-to-vmd-feasibility.md).
Бинарный layout сверялся с MMD Tools; математика кубических SAN-кривых —
с [нативным исследованием Sparkplug](../../docs/research/native-pc-animation-keys.md).

Игровые SAN/SMO, PMD и сгенерированные VMD остаются локальными: правила этой
папки исключают их из Git.
