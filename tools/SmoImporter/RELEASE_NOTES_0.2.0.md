# SmoImporter 0.2.0 — release candidate

Версия подготовлена для ручной проверки перед публикацией. Новые пути skinned
GLB/FBX остаются экспериментальными и требуют резервной копии target SMO.

Importer использует обновлённое общее SMO-ядро и стандартную структуру
пользовательских пакетов. Расширение writer/repack для новых material и animation
данных будет выполняться только после отдельных безопасных round-trip проверок.

Добавлен экспериментальный импорт подготовленного skinned GLB. Importer читает
кости и веса, показывает дерево фактических соответствий, автоматически переводит
геометрию в bind pose скелета target и собирает существующие 16-костные palettes,
не удаляя служебные данные исходного SMO. Неизвестные активные кости блокируют
запись вместо неявного угадывания. Функция прошла структурные round-trip тесты,
но до игрового теста не считается подтверждённой.

После первого игрового crash усилена защита вложенных visual branches. Палитра
`bloom_eyes`, принадлежащая узлу `Head`, больше не может быть переписана костями
конечностей только из-за сходного числа triangles. Такие primitives объединяются
с body group, а интерфейс сообщает о потере их отдельных material/alpha flags.
Само это ограничение не устранило crash контрольного `uzhs`, поэтому функция
остаётся исследовательской; добавлены раздельные texture/geometry/skinning probes.
Пробы подтвердили: RGB, новая topology и полный skinning загружаются игрой, а
вариант с заменой Alpha вылетает. Production writer теперь переносит только RGB
embedded texture и сохраняет исходный Alpha target SMO.

Подготовленный skinned FBX теперь принимается напрямую. Importer автоматически
запускает Blender в фоне, отбирает skinned meshes и armatures, конвертирует их во
временный GLB и применяет уже проверенный GLB writer. Если Blender не найден,
интерфейс предлагает выбрать `blender.exe`.

Первой функцией цикла стал режим SMO → SMO. Он предназначен для моделей с общим
игровым скелетом: проверяет имена костей и иерархию, сохраняет полный object graph
target и записывает donor geometry/textures в существующие visual slots. Skin
indices перепривязываются по карте костей, а каталог, размеры и offsets проходят
strict parse, geometry/UV/texture и SHA-256 проверки.

Для частично различающихся skeletons добавлено дерево сопоставления. Общие кости
используются для target service references; дополнительные donor bones и weights
не удаляются. Target-анимации без соответствующих tracks просто не управляют ими.

Сложная Spirit-подмена разрешает разные промежуточные control nodes при
совпадающих ближайших weighted parents, сворачивает `L/R_strip_1…3` в
`L/R_UpperArm` и конвертирует compact vertex layout `0x093E` в Bloom `0x097E` с
вычислением normals. Все helper paths видны пользователю до сохранения.

Эксперимент Faragonda с упаковкой трёх textures в два target slots и следующая
попытка полной замены render graph прошли strict parser, но вызвали crash игры и
удалены. Такой donor теперь блокируется: parser не доказывает сохранение неизвестных
runtime bindings.
