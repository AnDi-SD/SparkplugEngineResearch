# SmoImporter 0.3.0

Крупное обновление импортера моделей для Windows x64. Версия 0.3.0 переносит
готовые SMO, rigid multi-material OBJ/GLB/FBX и подготовленные skinned GLB/FBX,
а после сохранения автоматически проверяет результат нативным загрузчиком игры.

## Главное

- SMO → SMO больше не пытается уложить модель-донора в старые mesh/texture slots.
  Полные visual branches донора добавляются к неизменённому service/skeleton graph
  target с новыми IDs; старые meshes остаются безопасными невидимыми anchors.
- Поддержаны несколько visual roots, отдельные rigid-детали, несколько texture
  groups и нативные последовательности кадров. Так перенесены Faragonda и обе
  стороны StellaX ↔ Bloom без прежнего atlas fallback.
- Rigid OBJ, GLB и FBX могут использовать папку PNG с `matN`-текстурами и кадрами.
  Уже POT-текстуры сохраняются пиксель-в-пиксель, остальные только увеличиваются
  до следующей степени двойки с пределом 2048.
- Подготовленные skinned GLB/FBX переносятся в игровой bind pose ровно один раз.
  В результат записываются только target skeleton, IDs и inverse-bind matrices;
  rest pose, nodes и animation logic внешней модели не попадают в SMO.
- Замена skinned texture ограничена сопоставленным body-atlas. Непарные глаза и
  эффекты сохраняются побайтно.
- Новый SMO автоматически проходит короткую нативную проверку в изолированном
  оконном режиме. В интерфейсе остаются только путь к `WinxClub.exe` и краткий
  итог «подходит / не подходит / не определено».
- Исправлен round-trip GLB старого SmoExporter: повторные padding-записи одной
  кости с идентичной inverse-bind matrix безопасно объединяются и `JOINTS_0`
  перенумеровывается. Реально неоднозначные одноимённые nodes не угадываются.

## Проверенные сценарии

- Faragonda → `bloom_jeans.smo`: семь meshes и три textures, strict parse, быстрый
  smoke test и контекстная загрузка в настоящем Bloom slot.
- StellaX ↔ `bloom_jeans.smo`: отдельная голова, rigid-крылья и анимированные
  texture references; оба направления прошли strict и быстрые native tests.
- OBJ и FBX Лейлы → `bloom_jeans.smo`: семь material meshes, одиннадцать textures
  и две texture sequences; strict, быстрый и контекстный native tests.
- Подготовленная Текна → `Tecna.smo`: 17 точно совпавших active joints,
  382 triangles и семь palettes; strict, быстрый и две контекстные загрузки на
  Cloud01_02 без serializer errors или crash.

Все игровые проверки во время разработки запускались только в оконном режиме.

## Важные ограничения

- Автоматическая проверка подтверждает, что игровой загрузчик принял ресурс и не
  завершился с ошибкой в окне наблюдения. Она не оценивает внешний вид, материалы,
  качество весов и анимации — их нужно проверить в игре вручную.
- Для FBX требуется установленный Blender. GLB и OBJ читаются напрямую.
- SMO → SMO с сильно отличающейся donor bind pose всё ещё требует особой
  осторожности: donor inverse-bind matrices работают вместе с target animation
  graph и могут дать неверную деформацию, даже если loader test зелёный.
- Skinned GLB/FBX по умолчанию использует `RetargetToGameBindPose`.
  `PreservePreparedGeometry` предназначен только для модели, уже подготовленной
  точно в игровой bind pose.
- Исходные target и donor никогда не перезаписываются. Храните оригинальные
  игровые ресурсы отдельно и записывайте результат в новый `.smo`.

Пакет не содержит игровые файлы, Blender, .NET installer или отдельную программу
SmoNativeValidator. Нативное ядро проверки встроено в SmoImporter; корневой
загрузчик при необходимости предлагает скачать официальный Microsoft .NET 8
Desktop Runtime только после подтверждения пользователя.
