# Sparkplug SMO Importer

Перенос модели, текстур и материалов в существующий **PC SMO** из Winx Club. Программа помогает совместить донора с игровой моделью, подготовить скелет и отдельные детали, посмотреть результат с анимацией и сохранить новый SMO.

**Версия 0.7.0.** [Изменения выпуска](docs/releases/RELEASE_NOTES_0.7.0.md) · [История версий](docs/releases/CHANGELOG.md).

Исходная модель и донор сохраняются. Результат записывается отдельно и устанавливается после проверочного чтения. Проверка загрузки в игре запускается отдельной кнопкой.

## Что умеет программа

- Прямой перенос совместимого SMO-донора с его геометрией и материалами.
- Импорт OBJ, GLB и FBX с текстурами; точная замена изображения у выбранного материала и автоподбор набора файлов по именам.
- Работа с готовыми весами, адаптация скелета донора и создание весов для человеческого игрового скелета.
- Статическая замена моделей без скелета.
- Подгонка размера, поворота, положения и позы в предпросмотре.
- Защита областей тела; назначение отдельных деталей голове или анимированным крыльям, настройка высоты и угла крыльев.
- Предпросмотр собранного SMO, тестовые SAN-анимации, экспорт и отдельная проверка загрузки оригинальным игровым загрузчиком.

## Запуск

Штатный комплект рассчитан на **Windows 10/11 x64**. Для сборки, использующей установленную среду выполнения, нужен **.NET 8 Desktop Runtime x64**. Обычного .NET Runtime без Desktop-компонентов для WPF недостаточно.

Если вы используете готовый комплект:

1. Полностью распакуйте архив в отдельную папку.
2. Сохраните его структуру, включая папки с зависимостями. Не переносите один EXE отдельно от комплекта.
3. Запустите `SmoImporter.Gui.exe`.
4. Подготовьте собственные файлы исходной игры и модель-донора. Игровые модели и анимации не входят в комплект инструмента.

FBX читает отдельный native-мост `SmoFbxBridge.exe` с `libfbxsdk.dll`. Для этого пути не нужны Blender и Python. Если импорт FBX сообщает об отсутствии моста, проверьте целостность комплекта; для сборки из исходников см. [инструкцию FBX-моста](../FbxBridge.Native/README.md).

Инструкции разработчику находятся в разделе [Сборка из исходников](#сборка-из-исходников).

## Какие файлы нужны

| Файл | Назначение |
| --- | --- |
| Исходный PC `.smo` | Игровая модель, которую нужно заменить. Она задаёт целевой скелет и структуру SMO. |
| Донор `.smo`, `.obj`, `.glb` или `.fbx` | Новая внешность или статическая геометрия. |
| Текстуры и `.mtl` для OBJ | Внешние изображения и их привязки к материалам. Храните их рядом с моделью или укажите вручную. |
| Подходящие `.san` | Проверка позы и движения на последнем шаге. |
| `WinxClub.exe` | Нужен для отдельной проверки загрузки результата в игре. |

Не подменяйте исходный игровой SMO во время настройки. Экспортируйте результат в отдельную рабочую папку.

## Быстрый первый результат

1. На **«Моделях»** выберите исходный SMO и донора. Файлы можно перетащить в соответствующие окна.
2. На **«Подготовке»** начните с «Автовыбора». Проверьте материалы и замечания о текстурах.
3. На **«Размере»** совместите модели. После ввода чисел нажмите «Применить».
4. На **«Скелете»**, если он есть у цели, подгоните позу. «Далее» принимает её.
5. На **«Защите»**, если этот шаг доступен, проверьте области тела и назначьте отдельные детали. Дождитесь расчёта.
6. На **«Результате»** осмотрите полную модель, проверьте подходящие анимации и нажмите «Экспортировать SMO…».
7. При необходимости выполните «Проверить загрузку в игре». После этого отдельно оцените внешний вид и поведение модели в самой игре.

Статическая модель переходит с размера сразу к результату. Модели с другими скелетами пропускают специализированную человеческую защиту.

## Шаги мастера

### 1. Модели

Слева выбирается исходный игровой SMO, справа — донор. Пока файл не выбран, его кнопка мягко пульсирует. Проверьте, что обе модели загрузились и соответствуют задаче.

Загрузку можно отменить кнопкой «Отменить загрузку». Отмена завершается на безопасной границе чтения; дождитесь освобождения интерфейса.

### 2. Подготовка

Выберите способ переноса. Программа оставляет доступными только варианты, подходящие выбранной паре.

| Способ | Когда использовать |
| --- | --- |
| **Автовыбор** | Начальная рекомендация по формату, скелету и весам донора. |
| **Готовая модель** | Донор уже подготовлен к игровому скелету и содержит пригодные веса. |
| **Адаптировать скелет** | У донора есть собственные кости и веса, которые нужно согласовать с игровыми. |
| **Создать веса** | Для внешней модели, которой нужны веса человеческого игрового скелета. |
| **Статическая модель** | Для цели без скелета и донора, у которого все меши без весов. |

SMO-донор использует отдельный прямой путь переноса и проходит собственную проверку совместимости.

**Текстуры:** выберите строку материала, чтобы увидеть связанную с ней геометрию. Изображение, назначенное конкретной строке, имеет приоритет над автоматическим поиском. Чтобы снова увидеть модель целиком, используйте «Вернуться к модели».

- Перетаскивание изображения на конкретную строку задаёт точную замену этой строки.
- Общий блок добавления изображений подбирает один или несколько файлов по именам. Неоднозначное совпадение не угадывается.
- Выбор **MTL** появляется только для OBJ. Он нужен, если автоматическая привязка материалов выбрала неверный файл или файл отсутствовал.
- Замечание об отсутствующей текстуре допускает продолжение без неё на затронутом меше. Остальные изображения сохраняются.

На этом шаге ещё не требуется готовый расчёт весов. Сначала настраиваются размер и поза.

### 3. Размер

Сравните исходную модель и донора. Масштаб задаётся в процентах; поворот и смещение — отдельными полями. «Автоподгонка» предлагает начальное совпадение по высоте и, если изменение положения доступно, по центру.

После ручного ввода корректных значений нажмите **«Применить»** или Enter в поле. Пока есть неприменённые изменения, переход может быть заблокирован. Маркеры в предпросмотре позволяют выполнять доступные преобразования мышью; Esc отменяет перетаскивание.

В адаптации скелета положение обычно вычисляется автоматически. Если нужна ручная правка, сначала включите соответствующую настройку. Набор доступных преобразований зависит от способа переноса.

### 4. Скелет

Подгоняйте игровой скелет к донору постепенно. Для человеческого скелета доступны общие настройки позы; режим отдельных костей позволяет уточнить локальные сгибы.

Выберите кость в списке или в предпросмотре. Осматривайте модель с разных сторон, особенно плечи, локти, кисти и ноги. «Сбросить позу» возвращает исходное положение. **«Далее» принимает текущую позу** — отдельную кнопку применения искать не нужно.

Автоматические веса остаются эвристическими. Хорошая неподвижная поза сама по себе не гарантирует правильное движение.

### 5. Защита и детали

В режиме создания весов для человеческого скелета доступны два раздела:

- **«Области»** — защита плеч, головы и кистей. Выберите область и настройте доступные границы, проверяя силуэт.
- **«Детали и крылья»** — выбор отдельных компонентов и их назначение голове либо крыльям. Для назначения крыльев выделяйте обе стороны.

ЛКМ выбирает деталь; перетаскивание ЛКМ выделяет прямоугольником. Ctrl добавляет детали к выбору или снимает выделение. Esc отменяет рамку. «Весь меш» расширяет выбор на части соответствующих мешей.

После назначения крыльев появляются две независимые настройки:

| Настройка | Диапазон и действие |
| --- | --- |
| **Высота крыльев** | От −25% до +25% высоты модели без выбранных крыльев. Сдвигает крылья вдоль их плоскостей. |
| **Поворот крыльев** | От −90° до +90° вокруг внутреннего края у спины, в плоскости каждого крыла. |

У обеих настроек ноль расположен по центру: минус опускает крылья, плюс поднимает. Каждый «Вернуть авто» сбрасывает только свою настройку. Подгонка использует крылья исходной модели, а если их нет — положение BloomX. Поправки геометрии сохраняют привязку к анимированным узлам крыльев.

Галочки **«Тело»**, **«Крылья»**, **«Голова»** скрывают части только в этом предпросмотре. Скрытые части не выбираются щелчком или рамкой. При возврате к шагу выбранная видимость сохраняется.

Общий прогресс появляется внизу предпросмотра, не сдвигая меню. В нём доступны отмена и повтор расчёта. Не закрывайте процесс принудительно, пока отмена завершает текущий блок работы.

### 6. Результат

Здесь показана полная собранная модель с текстурами, независимо от галочек на предыдущем шаге. «Далее» отключена. Для исправления размера, позы или деталей вернитесь назад.

**Анимации:** выберите SAN и используйте воспроизведение/паузу, стоп, перемотку, скорость и цикл. Сначала программа ищет анимации рядом с исходным SMO. Если их нет у человеческого персонажа, используется папка Bloom; при крыльях дополнительно подключается BloomX. Для других моделей без соседних SAN укажите папку вручную. Анимация предпросмотра не меняет экспортируемый SMO.

**«Экспортировать SMO…»** сохраняет показанную готовую модель. Новый файл устанавливается после проверочного чтения; существующий файл результата получает резервную копию с датой и расширением `.bak`, например `result.smo.20261110-180000-000.bak`. Исходные входные пути защищены от перезаписи.

**«Проверить загрузку в игре»** проверяет загрузку файла оригинальным игровым загрузчиком. Это не просмотр сцены и не проверка всего игрового поведения. Путь к установленной игре ищется в реестре; если его не удалось найти, укажите `WinxClub.exe` вручную.

## Управление и встроенная помощь

| Действие | Управление |
| --- | --- |
| Вращать вид на любом шаге | ПКМ и движение мыши |
| Приблизить или отдалить | Колесо мыши |
| Показать модель целиком | Home или «В кадр» |
| Править доступный маркер размера/положения | ЛКМ по маркеру; Esc отменяет перетаскивание |
| Выбрать кость | ЛКМ в режиме отдельных костей |
| Выбрать детали на «Защите» | ЛКМ, прямоугольная рамка; Ctrl меняет состав выбора |
| Вернуть или повторить изменение | Кнопки «Отменить» и «Повторить» внизу |

Под каждым предпросмотром постоянно видна короткая подсказка управления. На шагах 2–6 есть раскрываемая **«Инструкция»**: голубая ссылка прокручивает меню к нужному элементу и дважды плавно подсвечивает его. Она не нажимает кнопку и не меняет модель. Инструкция учитывает текущий способ импорта и назначенные детали.

## Замечания, ошибки и восстановление

Жёлтая панель сообщает о замечаниях, с которыми можно продолжить; красная — о проблеме, мешающей действию. Разверните **«Подробности»**, чтобы прочитать причину, и при необходимости откройте журнал.

| Ситуация | Что делать |
| --- | --- |
| Меш остался без текстуры | Проверьте MTL и пути, назначьте изображение нужной строке. Можно продолжить без текстуры на этом меше. |
| Изображение отсутствует или повреждено | Замените его исправным. Программа не подставляет случайную соседнюю картинку. |
| Размер введён, но «Далее» недоступна | Проверьте числа и нажмите «Применить». |
| Подгонка крыльев отклонена | Проверьте, что выбраны отдельные крылья с обеих сторон, а не тело вместе с ними. |
| Идёт длительный расчёт | Следите за прогрессом; при необходимости запросите отмену и дождитесь её завершения. |
| Неподходящие анимации или пустой список | Выберите SAN для целевого скелета либо другую папку. |
| Не найдена игра | Укажите исполняемый файл в блоке проверки загрузки. |
| Ошибка геометрии, весов или структуры SMO | Исправьте исходный файл либо выберите совместимую модель. Такие дефекты нельзя исправить отключением текстуры. |

Для сообщения о проблеме приложите текст ошибки, журнал, выбранный способ импорта и последовательность действий. Укажите форматы исходной модели и донора; игровые файлы не нужно включать в публичный отчёт.

## Ограничения

- Инструмент работает с подтверждёнными структурами **PC SMO**. Поддержка произвольных вариантов формата и PS2 SMO не заявляется.
- Создание весов и специализированные анатомические настройки рассчитаны на человеческий скелет. Деформации конкретного донора нужно проверять на анимациях.
- Неизвестные кости с весами, несовместимые преобразования, повреждённая геометрия и недопустимые диапазоны данных приводят к отказу с причиной.
- Внешняя промежуточная сцена не представляет несколько material passes/layers одного материала. Такой случай отклоняется с `MATERIAL_IMPORT_SHAPE`; прямой SMO-перенос использует отдельный путь.
- Успешная загрузка в игре не подтверждает внешний вид, столкновения и поведение модели во всех игровых ситуациях.

## Сборка из исходников

Работайте из корня полного репозитория. Нужны .NET SDK и инструменты C++/Windows SDK для native-зависимостей. Подробные требования и порядок сборки описаны в [CONTRIBUTING](../../CONTRIBUTING.md), [устройстве SmoImporter](docs/development.md) и [FBX-мосте](../FbxBridge.Native/README.md).

```powershell
dotnet run --project tools/SmoImporter/SmoImporter.Gui/SmoImporter.Gui.csproj
```

Проверки форматов и готовность комплекта к выпуску выполняются отдельно от запуска GUI. Сборка без ошибок сама по себе не доказывает качество импорта и работы результата в игре.
