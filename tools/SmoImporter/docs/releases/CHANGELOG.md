# Changelog

## 0.6.1 — кандидат, 2026-09-08

- Структурные PC BGRA-текстуры/NPOT и корректный порядок inline references.
- Исправлен выбор clean skinned templates и разрешение общей ссылки Fog.
- Запись быстрее на7–9%, подготовка весов примерно вдвое быстрее на выбранных
  случаях; выходные данные совпадают с прежним алгоритмом. Финальные проверки,
  сохранность входов и отмена остаются включены.
- Подробности и границы подтверждения — в RELEASE_NOTES_0.6.1.md.

## 0.6.0 — 2026-09-01

- возвращён импорт внешних статических моделей как standalone-профиль общего
  `SmoLevelModelGraphReplacer`, который уже обслуживает complete-model replacement
  Level Creator и batch pipeline, а не как отдельный writer или прежняя имитация
  rigid-модели через один bone palette slot. Для PC target без `spSkin` общее ядро
  сохраняет нативный `spRenderNode → spModel → material/mesh` граф. Одна безопасная
  нативная ветвь становится структурным шаблоном, остальные старые mesh-ветви
  удаляются, а шаблон расширяется до фактического числа частей донора. Прежнее
  количество mesh-ветвей и texture-layout target больше не ограничивают импорт.
  Общие donor-текстуры перенаправляются на один канонический PC BGRA-ресурс либо на
  независимые ресурсы для разных изображений. Профиль не создаёт `spSkin`, palettes или веса,
  поддерживает transform/автоподгонку GUI и использует общую строгую проверку с
  атомарной установкой и `.bak`;
- viewport gizmo размера, поворота и положения теперь доступен и в статическом
  режиме. Перетаскивание обновляет preview и сбрасывает только устаревший план,
  не переключая статическую модель в generated-skinning pipeline;
- автовыбор получил отдельный режим **Статическая модель (без костей)**. Он
  предлагается только когда target и все meshes донора действительно unskinned;
  для персонажа без весов по-прежнему выбирается генерация весов. Регрессия
  проверяет нормализацию targets с одной и несколькими model-ветвями, multipart
  mesh/material/texture-доноры, отсутствие `spSkin`, decode результата и повторную
  установку с backup;

- SMO принимается тем же каталогом моделей, что FBX/GLB/OBJ, но общий
  `ImportedScene` используется для него только в preview. Путь сохранения читает
  исходный контейнер донора и не декодирует/пересобирает его ресурсы;
- нативная SMO→SMO замена целиком удаляет старый render forest target и вставляет
  полный render forest донора. `spSkin`, `MeshData`, material-объекты, UV, palettes
  и `TextureData` сохраняются в исходной сериализации; только object IDs и ссылки
  переводятся в безопасный диапазон контейнера target;
- удалены прежние slot-подмены, packer и отдельный эвристический bone-mapping
  planner. Новый replacer переводит ссылки внутри `spSkin` palettes и сохраняемых
  service-объектов на новые IDs. Donor-only кости схлопываются в ближайшего общего
  логического предка и физически удаляются; palette slots и исходные индексы весов
  сохраняются, а forward inline definition общего предка переносится перед первым
  использованием. Отсутствующие у donor deform-кости target не блокируют перенос.
  Отсутствующие у донора target-only анимационные листья восстанавливаются на одноимённых
  родителях; неизвестное поддерево блокирует импорт. До атомарной установки
  проверяются все skins, отсутствие старых target mesh/texture IDs и висячих ссылок;
- каждый создаваемый renderable `spSkin`, включая palette/ushort-продолжения,
  теперь получает собственный `spMaterialData` с явной ссылкой на исходный
  `TextureData`. Неявное наследование штатного single-material run не переносится
  на пересобранный multi-texture граф: игра не обязана сохранять нужный material
  state между независимо созданными ветвями;
- skinned `ImportDonor` больше не подменяет слоты и не дописывает новую модель рядом
  со старой. Writer разбирает контейнер и пересобирает визуальный граф: все исходные
  `MeshData`, `spMaterialData` и `TextureData` target физически удаляются, а каждая
  texture group донора получает собственные заново созданные texture/material/skin
  ресурсы с исходными UV. Сохраняются только кости и обязательное служебное состояние;
  владеющий inline-костями `spSkin` становится material-less skeleton carrier и
  использует новый вырожденный служебный mesh;
- `TargetRigBodySelection` теперь служит только для размещения и подгонки позы.
  После fit все mesh/material/components образуют одно логическое deform-body;
  автоматически покинуть его может только цельный компонент со строгим большинством
  за `Back`, не защищённый `Head`. Поэтому отдельные руки, ноги и части одежды перед
  спинной плоскостью больше не попадают в список жёстких деталей из-за структуры OBJ;
- GUI больше не вырезает вручную закреплённый компонент из fitting-body при повторном
  расчёте, а **Скрыть основное тело** скрывает всё логическое deform-body и оставляет
  только реально извлечённые Back/manual детали;
- режим **Человек** зафиксирован как специализированный путь только для
  человекоподобных персонажей; его анатомические имена и эвристики не переносятся в
  общие SMO readers/writers;
- generated skinned multi-material import больше не объединяет исходные изображения
  в atlas: не поместившиеся target groups получают отдельные native
  `TextureData`/material/`spSkin`-ветви с исходными UV. Удалён мёртвый atlas API;
- каталог внешних текстур больше не угадывает соответствие по правилу «одна
  неразрешённая группа — один оставшийся файл»: автоматическое назначение требует
  явного совпадения имени, остальные ресурсы остаются для ручного выбора;
- skinned branch builder выбирает подходящий layout по всему render branch,
  поддерживает подтверждённые palettes размером 1..16 и добавляет явный material
  даже в continuation, построенный из штатного material-less `spSkin`-шаблона;
- прежний character-rigid путь, записывавший всю модель на один выбранный palette
  slot, удалён вместе с устаревшими packer-ами. Статический профиль общего
  model-graph writer-а не ищет `Head` и вообще не создаёт bone palette;
  rigid-ветви внутри режима генерации весов остаются частью отдельного skinned
  character pipeline;

- создание SMO больше не запускает WinxClub.exe автоматически. Последний успешно
  сохранённый output можно явно проверить кнопкой **Проверить в игре**; выбор executable,
  результат проверки и кнопка открытия лога собраны в одном диагностическом блоке;
- применение разделяющих плоскостей теперь всегда обновляет рассчитанные веса и
  список жёстких деталей. Ошибки совместимости материалов/writer продолжают
  блокировать создание SMO, но больше не откатывают предпросмотр к старым плоскостям;
- finite-preview плечевых стен больше не центрируется в суставе: точный shoulder
  anchor `L_Bicep`/`R_Bicep` является верхним краем, стена идёт только вниз и при
  изменении угла вращается вокруг соответствующего Bicep;
- приоритет плоскостей уточнён: плечевые стены и `Head` являются защитными, а `Back` —
  единственной плоскостью, отделяющей целую связную деталь для ручной обработки.
  Head-защита требует строгого большинства выше шеи и не менее 1% уникальных позиций
  перед Back. Если защита не сработала, строго больше 50% позиций за Back переводят
  деталь на rigid `Spine_03`; равенство и меньшинство ничего не отделяют;
- Head-защита больше не теряется между disconnected-островками одного hair-mesh:
  доказанный Head-компонент распространяет exact one-hot `Head` по пространственно
  соседней сборке островков того же исходного mesh до применения `Back`. Далёкие
  задние детали (включая крылья в том же техническом mesh), анатомический owner тела
  и ручные назначения не наследуют защиту; donor-имена и материалы не используются;
- provisional-роли `WholeBody`/`LowerBody`/`TorsoAndArms` больше не дают компоненту
  иммунитет от Back. После применения плоскостей все оставшиеся спереди и ниже Head
  компоненты образуют одну логическую deform-деталь; любой выбранный компонент,
  включая временный pose-якорь, уходит в rigid-путь при универсальном большинстве
  за Back;
- режим создания весов получил четыре target-anchored разделяющие плоскости.
  `Left/RightShoulder` начинаются от точных плечевых deform-ветвей, меняют только
  угол и после расчёта запрещают weights, пересёкшие стену. `Head` заменяет прежний
  эллипсоид и без перехода назначает всему выбранному body-полупространству строго
  one-hot `Head`; ниже плоскости Head-subtree запрещена. `Back` работает с точным
  `Spine_03`;
- detached-компоненты классифицируются только целиком. Уже отделённая головная деталь,
  прошедшая защиту Head+Back, получает rigid `Head`; задняя — rigid `Spine_03`.
  `SupplementalBody` переводит в список деталей только Back. Старый elongated-Head
  heuristic удалён из активного пути;
- панель **Разделяющие плоскости и кисти** показывает все стены цветными
  прямоугольниками, позволяет менять разрешённые offset/angle и мгновенно рисует
  точный черновик без перерасчёта. Легенда явно различает защитные стены и отделяющую Back;
  тяжёлая preparation и writer-анализ по-прежнему запускаются только кнопкой
  **Применить**. Override включает target/donor/alignment/pose identity и полный
  набор plane adjustments;
- все файловые writer-пути используют общий verified atomic install: результат
  сначала пишется во временный файл той же папки, flush’ится и проходит свой
  строгий verifier, затем атомарно устанавливается; существующий output получает
  timestamped `.bak`, а совпадение с target/donor input запрещено. Regression
  проверяет success/failure/cancellation/source-protection/cleanup 13 assertions, native
  writer-матрица прошла 5/5;
- production writers теперь принимают только подтверждённые PC/common platform
  masks; PS2 и смешанные профили блокируются до записи. Финальная сборка вынесена
  из UI-потока, получила безопасную отмену, пятиминутный предел и watchdog роста
  памяти; cancellation проверяется непосредственно перед атомарной установкой;
- SMO→SMO не угадывает соответствие костей и не выполняет retarget: имена костей
  проверяются точно, а donor bind data переносится без изменений;
- skinned writer сохраняет настоящий `TEXCOORD_1` во всех основных и alpha-ветвях;
  distinct UV1 блокируется, если целевой layout не может его представить. Legacy
  whole-model texture теперь сопоставляется по object ID и physical offset, а не
  по порядковому номеру среди частично распознанных `TextureData`;
- автоматическая native-проверка даёт зелёный результат только после scene-ready
  в известном штатном контексте персонажа/уровня. Generic loader acceptance теперь
  честно помечается как неопределённое: оно не доказывает скелет и анимацию;
- writable 16-bone palettes теперь исключают ссылки на node, который native
  one-pass `spSkinSerializer` ещё не создал; forward reference вроде раннего
  `skin[63] -> Pelvis`, впервые сериализуемого внутри `skin[69]`, блокируется до
  записи. Bloom и Flora с одной 248 223-triangle Miku прошли повторяемую запись,
  точную SAN-деформацию и native scene-ready;
- palette allocator получил компактный детерминированный поиск по 64-битным bone
  masks, удаление уже покрытых requirements и корректную симметрию с учётом
  load-safe bones. Доказанно невозможная раскладка теперь возвращается как обычный
  capacity result, а не как ложный `8 192 states` timeout;
- режим 3 после доказанной несовместимости 4/3/2 influences выполняет последний
  проход с одним ближайшим влиянием. Он не меняет геометрию или UV, сохраняет все
  вершины/треугольники и используется только если точный writer-plan подтверждает
  16-костные palettes; ручные semantic overrides при конфликте не отбрасываются;

- collision branch writer явно сериализует production-default Group 2 вместо
  случайного Group ближайшего template и проверяет exact triangle order после
  decode; SmoLVLcreator regression дополнительно сохраняет непустой
  `wxFaceData` существующей ветви byte-for-byte.
- rigid level import получил единый детерминированный preparation-путь для
  обычного и изолированного batch writer: большие части делятся до UInt16,
  сохраняя material, normals, UV0/UV1, vertex colors и triangle order;
- GLB reader сохраняет `TEXCOORD_1`, а двухканальные SMO layouts больше не
  получают безусловную копию UV0 во второй канал;
- отсутствующие/невалидные normals восстанавливаются перед записью rigid mesh;
  reflection оси Z сохраняет правильный winding;
- FBX material автоматически переводится в Blend, когда реально связанная
  декодируемая текстура содержит прозрачность. Неизвестный payload не угадывается.

## 0.5.0 — 2026-08-24

- для ручного эллипсоида головы длина и толщина теперь регулируются до `3×`:
  прежний общий с кистями предел `1,75×` мог оставлять максимальный контур внутри
  составной головы, когда автоматическая topology-калибровка начиналась с малого
  цельного лицевого острова. Кисти сохраняют предел `1,75×`; при применении Core
  по-прежнему проверяет точный membership, overlap и attribute seams;
- загрузка внешней модели получила конечные лимиты файла, meshes, vertices, indices,
  joints, materials, textures и декодированных texels. GUI заранее оценивает рабочую
  память и показывает конкретные MiB и долю от доступных игре `3,7 GiB`; крупная, но
  допустимая модель обрабатывается с явным предупреждением, а опасная блокируется до
  выделения памяти;
- тяжёлые расчёты выполняются вне UI-потока, показывают этап и процент, имеют общий
  timeout и cooperative cancellation. Закрытие окна отменяет активную работу и
  завершает процесс; при повторной загрузке предыдущие scene/texture/preview buffers
  отсоединяются и освобождаются до чтения следующего файла;
- каждый запуск ведёт новый постоянный `SmoImporter.log`: события загрузки, выбранные
  режимы, alignment/pose, защищённые области, прогресс, отмена, warnings, исключения и
  финальное состояние остаются после закрытия и позволяют воспроизвести действия
  тестировщика без самой модели;

- размещение donor в режиме 3 больше не запускает преждевременный расчёт weights и
  palette-plan: единственный первый расчёт начинается после применения позы игрового
  скелета; редактор суставов открывается сразу после принятия alignment без обходного
  переключения через режим «Человек»;
- ползунки защищённых областей теперь обновляют только локальный контур эллипсоида;
  тяжёлая preparation запускается исключительно кнопкой **Применить**. Для головы и
  кистей без доказанной donor-topology лопасти доступен явно включаемый ручной
  target-derived объём, включая приблизительные finger-motion веса для кистей;
- у головы появился наклон ручного эллипса к лицу в пределах ±45°. После изменения
  положения, размера или наклона именно показанный конечный объём задаёт one-hot
  `Head`, поэтому подбородок можно включить ценой ненужной части затылка; причина
  отклонения теперь берётся из конца Core-диагностики и полностью пишется в лог;
- ниже `Pelvis`/`Spine_01` действует target-rig сагиттальная стенка без прежней
  нейтральной полосы: вершины по одну сторону не могут получить веса костей другой
  стороны, даже когда ноги сведены близко. Итоговые packed weights проходят отдельную
  проверку стены перед writer-ом;
- допустимое число состояний точного 16-bone palette packing увеличено с 4 096 до
  8 192: новая Miku со всеми пятью finger-ветвями больше не блокируется на старой
  границе. Предел одного поиска увеличен с 5 до 10 секунд для GUI, где rendering и
  журнал замедляют тот же перебор; cooperative cancellation, общий 90-секундный
  предел расчёта и лимиты числа palette requirements сохранены;
- перед рекурсивным palette packing добавлен детерминированный best-overlap fast
  path. Он принимает только полностью готовую допустимую раскладку; при неудаче
  исходные bins остаются неизменными и запускается прежний точный поиск. Это убирает
  зависимость обычных раскладок Miku от случайно дорогой ветви перебора в GUI;
- переход кисти от запястья теперь ограничен проксимальной четвертью фактической
  геодезической длины donor-кисти. На Miku это увеличило приблизительно сгибаемую
  область каждой кисти со 107 примерно до 889 вершин. Поперечные дорожки
  нормализуются по устойчивой фактической ширине захваченной donor-кисти, а не по
  oversized защитному объёму: на проверенной Miku задействованы все пять цепочек
  каждой руки и все 52 deform-сустава target;
- FBX читается напрямую Autodesk FBX SDK без Blender, Python и временного GLB;
- native reader сохраняет material groups, external/embedded textures, skin weights, joint hierarchy и bind pose;
- bridge и `libfbxsdk.dll` входят в GUI/release package, добавлены textured/skinned smoke tests и GLB↔FBX round-trip regressions.
- обычный single-texture skinned path теперь автоматически обнаруживает настоящую прозрачность в donor base-color, переносит полный RGBA после resize и включает точную UV/component Alpha-классификацию;
- в меню режима материала добавлен явный вариант **Прозрачная поверхность** рядом с **Авто** и **Непрозрачная накладка**;
- импорт больше не уменьшает donor-текстуру до размера target-слота: представимые исходные размеры, включая проверенные в игре `3000x3000`, сохраняются точно; несовместимые размеры только увеличиваются до ближайшего представимого POT-варианта;
- resize теперь пересчитывает FFPS object catalog, смещения и размеры охватывающих объектов, после чего проходит strict parser;
- при росте встроенной текстуры также пересчитываются вложенные размеры `spSkin → material → TextureData` и inline object-prefix; writer проверяет, что все исходные skin-палитры по-прежнему декодируются и ссылаются на те же кости;
- этапы подгонки в GUI стали повторно редактируемыми: применение защищённых областей больше не блокирует их ползунки, gizmo размера/поворота/положения остаётся доступным, а черновые правки сохраняют последний подтверждённый PreparedScene и plan до успешного повторного применения;

- Viewer и Blender проверяют геометрию, UV, содержимое atlas и наличие Alpha, а
  native validator — корректную загрузку ресурса. Они не воспроизводят native blend,
  lighting и depth/sort: прежний единый alpha-run выглядел корректно в WPF, но в игре
  скрывал лицо и показывал украшения только под частью углов. Поворот камеры при
  фиксированном world-light Viewer также способен скрыть углозависимую ошибку.
  Визуальный паритет нового контракта не заявляется до пользовательского теста вновь
  созданного SMO в игре;
- workflow режима 3 сделан последовательным: сверху показывается одно главное
  действие или реальная причина блокировки, отдельная кнопка открывает точный
  канонический итог для подтверждения, а десятки технических предупреждений и
  rigid attachments находятся в свёрнутой ограниченной по высоте секции;
- перед автоматической нарезкой добавлен окончательный текстурированный preview. Он
  использует тот же preparation path, что writer, и показывает фактические atlas,
  переписанные UV и импортируемые изображения. В диагностическом режиме сохранения
  target-текстур остаётся явная одноцветная review-кнопка, доступная до зачёта
  текущей ревизии даже при уже видимом canonical scene. Для legacy rigid `matN`
  final preview отключён, поскольку сырой viewport не совпадает с packer/writer;
- skinned или частично skinned вход режима 3 целиком перечитывается geometry-only,
  без удаления отдельных meshes. Внешние texture overrides сохраняются. Папка
  `matN` остаётся rigid-only: bundle полностью игнорируется, его frames не
  показываются, а кнопка папки отключена в режиме 3. Вместо неё используется
  пакетное **Добавить файлы…** с однозначным material mapping;
- режим **Суставы** меняет только абсолютные local rotations временной позы;
  `FittingPreviewScene` показывает результат, а geometry для writer обратно
  запекается в canonical target bind как `PreparedScene`. Euler-представление имеет
  обычную неоднозначность и gimbal lock и не заменяет quaternion pose внутри Core;
- для режима 2 ручная подгонка опционально включает weights-only подготовку и
  uniform donor alignment. В режиме 3 разрешены только local rotations, а root
  transform отключён из-за canonical-space donor alignment;
- target service/skeleton graph во всех режимах остаётся исходным. **Человек**
  использует симметричный two-bone IK; выбор сустава кликом уже доступен, но viewport
  gizmos для прямого перетаскивания/вращения пока отсутствуют. Donor должен быть
  Y-up/same-facing, а анимации требуют ручной проверки в игре;
- режим создания weights с нуля остаётся экспериментальным: build, strict writer и
  native loader не доказывают качество weights, анимацию и итоговый blend/depth;

## 0.3.0 — 2026-08-14

- режим SMO → SMO переведён на append-only visual packing: service/skeleton graph,
  IDs и неизвестные связи target сохраняются, старые meshes остаются невидимыми
  structural anchors, а donor `spSkin`/material/texture/UV/mesh branches получают
  новые уникальные IDs;
- упаковщик переносит visual forest из нескольких render roots, отдельные rigid-
  детали, несколько texture groups и нативные texture sequences без atlas fallback;
  контрольные Faragonda → Bloom и StellaX ↔ Bloom прошли strict и native проверки;
- добавлен rigid multi-material импорт GLB, OBJ и FBX. Материалы связываются с
  PNG через metadata либо OBJ `mtllib`/`usemtl`/`map_Kd`; GUI принимает отдельную
  папку с `matN.png` и последовательностями `matN.1.png`, `matN.2.png`;
- non-POT текстуры увеличиваются до следующей степени двойки по каждой оси,
  никогда не уменьшаются и ограничены 2048 пикселями. Исходные opaque POT-пиксели
  сохраняются; привязанные frames с `A < 255` теперь fail-loud отклоняются до файла,
  поскольку alpha-контракт generated one-bone `spSkin` не подтверждён;
- исправлено зеркальное поле texture header `+0x38`: оно хранит `height << 8`.
  Формула подтверждена на 2 348 pristine textures и устранила нативный crash
  прямоугольных атласов 128×64;
- skinned GLB/FBX transfer разделён на режимы `RetargetToGameBindPose` и
  `PreservePreparedGeometry`. Production-режим выполняет ровно один bind-pose
  rebase, но записывает только target bone IDs, target graph и canonical target
  inverse-bind matrices — donor nodes и animation logic не переносятся;
- skinned texture replacement ограничен сопоставленным body-atlas. Материалы с
  одним source image объединяются, а глаза, эффекты и непарные texture objects
  остаются побайтно исходными;
- подготовленная Текна перенесена в чистый `Characters/Tecna/Tecna.smo`: 17 active
  joints совпали точно, 382 triangles распределены по семи игровым palettes,
  `tecna_e` сохранена. Результат прошёл strict parser, быстрый native smoke test и
  две контекстные загрузки на Cloud01_02 в оконном режиме;
- исправлен off-by-one texture parser/writer: для `0x32E3`/`0x43E3` marker `00`
  находится на `+0x3C`, а BGRA payload начинается с `+0x3D`;
- после сохранения GUI автоматически проверяет новый SMO нативным загрузчиком
  игры в быстром изолированном оконном режиме. Пользователю доступны только путь
  к `WinxClub.exe` и краткий результат «подходит / не подходит / не определено»;
- GUI не разрешает перезаписать target или donor. Skinned-режим также блокирует
  AutoFit и произвольный transform, которые могли бы повторно применить позу;
- FBX использует общий GLB pipeline через Blender, с расширенным автопоиском
  `blender.exe` и исключением helper meshes без Armature.
- GLB reader распознаёт безопасное palette padding старого SmoExporter: повтор
  одного glTF joint node с побайтно одинаковой inverse-bind matrix схлопывается с
  remap `JOINTS_0`; одинаковые имена разных nodes и разные matrices по-прежнему
  блокируются как неоднозначные.

## 0.1.0 — 2026-08-10

Первый экспериментальный релиз SmoImporter.

- импорт целой OBJ/GLB-сцены и новая triangle-list topology;
- single-slot rigid mesh replacement с ручным выбором подтверждённой bone palette;
- автоматическая подгонка размера, центра, вращения и смещения;
- сохранение остальных render slots через проверенные degenerate triangles;
- embedded GLB base-color и внешний PNG/JPEG;
- подтверждённая игрой fixed-size замена только RGB исходного ABGR atlas;
- исходные Alpha, headers, offsets, object graph и размер texture block сохраняются;
- запись всегда выполняется в новый SMO с повторной проверкой strict parser.

Изменение разрешения atlas, texture repack, скелетная деформация и импорт анимаций
в этой версии не поддерживались.
