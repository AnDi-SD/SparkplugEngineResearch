# Шаги массивов skinning в Remix renderer

Наш [патч skin-strides-v2.patch](skin-strides-v2.patch) для `rtx_remix_api.cpp` изменяет шаг чтения двух массивов:

- Веса: `sizeof(float) * bonesPerVertex`.
- Индексы: `sizeof(uint32_t) * ceil(bonesPerVertex / 4)`, поскольку в word упакованы четыре индекса.

Исходная версия и patch hash заданы в [manifest.json](manifest.json). Это изменение внешнего renderer, а не восстановленная игровая логика. Полный Release renderer с v2 собирается. Прямое выполнение исходного вычислительного shader на GPU подтверждает исправленные шаги; парное сравнение кадров через полный renderer ещё не завершено. Установленный прототип отдельный и автоматически не обновляется.

В v2 размер элемента приведён к `uint32_t` до умножения: именно этот тип
требуется полю шага `RasterBuffer`. Сохранённая [v1](skin-strides-v1.patch)
не собирается в x64 MSVC из-за сужения `size_t` в списке инициализации.
CPU-проверка теперь сохраняет это ограничение типов, а не скрывает его
приведением всего результата после вычисления.

## Ограничения

`skinning.h` читает B−1 весов и вычисляет последний как `1−sum`; при B1 эффективный вес равен 1. Произвольные ненормированные веса этим патчем не поддержаны. Вклады `weight <= 0` пропускаются, позиция затем не нормализуется; нормаль нормализуется отдельно.

Индексы упакованы в bytes. До вызова API необходимы корректные указатели, размеры массивов, `B > 0` и индексы `< actualPaletteCount <= 256`. Геометрические индексы — отдельный uint32 triangle-list массив.

[test_skin_strides.cpp](test_skin_strides.cpp) проверяет CPU-арифметику и упаковку с выбранными upstream-заголовками. Он не создаёт Vulkan backend и не доказывает результат GPU-отрисовки.

Тот же тест сопоставляет нормированные B1–B4 с общей реконструкцией
[Fixed.rfx](../../../docs/engine/animation/skin-deformation.md). Ненормированные
веса остаются различием семантики даже с правильными strides. Допуск только
на сумму весов недостаточен: для весов `0.5` и `0.5 + 2⁻²³` и переноса
последней кости на миллион единиц ошибка позиции достигает `0.125`.
Это проверка математической границы, не наблюдение масштаба игровой сцены.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-skinning-fix/Test-CPU.ps1 -Name fresh-contract-check
```

Стенд сохраняет собственную копию исходных зависимостей и общей реконструкции
в новом каталоге результатов. В `source.json` фиксируются их хеши.

Проверка отрисованной геометрии описана в
[руководстве стенда](../docs/skinning-fixture.md). Для сравнения нужны
два полных runtime из одной исходной версии: baseline и renderer с v2.

## Вычислительное ядро на GPU

[Test-GPU.ps1](Test-GPU.ps1) запускает собственный Vulkan-стенд с уже
собранным `gpu_skinning.spv`. Подготовка сверяет неизменность shader-исходников
с закреплённым upstream и точное совпадение SPIR-V с массивом в сгенерированном
заголовке renderer. Vulkan headers, import library, shader, наш стенд и
общие CPU-выражения сохраняются в новом каталоге с хешами.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-skinning-fix/Test-GPU.ps1 -Name fresh-gpu-check
```

Нужны собранные shader-артефакты отдельного checkout
`local-data/rtx-remix/renderer-skinning-build/source`, MSVC x64 и дискретный
GPU с Vulkan 1.3. Перехода на программное устройство нет. Validation layer
не включается; результат не является отчётом Vulkan validation.

Стенд выполняет B1, B2, B3, B4, B5, B8 на 3 и 325 вершинах. Для каждого
набора проверяются исходные strides, исправление только весов и полный v2.
Палитра содержит переносы, неравномерное масштабирование и shear; проверяются
позиции и нормали. Незаполненные области, выходные offsets, padding и лишние
потоки последней группы должны сохранить начальное значение. Нормированные
B1–B4 дополнительно сравниваются с общим эталоном Fixed.rfx.

Это прямые compute dispatch: CPU-порог renderer здесь не участвует.
Проверка устанавливает поведение GPU-ядра при заданных `SkinningArgs`.
Передачу этих аргументов через Remix API/bridge, выбор ветви полного renderer
и результат растеризации проверяет отдельный графический стенд.

`events.jsonl`, `result.json`, `stderr.log`, `memory.json` сохраняют завершение
всех dispatch, параметры устройства и ограничение ресурсов. Watchdog учитывает
рабочую и private-память собственного процесса вместе с оболочкой, останавливает
его при 900 МиБ или 120 секундах. Буферы освобождаются после завершения GPU;
при зависшем драйвере внешний watchdog ограничивает и ожидание очистки.
