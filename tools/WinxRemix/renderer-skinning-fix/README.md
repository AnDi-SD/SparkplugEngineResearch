# Шаги массивов skinning в Remix renderer

Наш [патч skin-strides-v2.patch](skin-strides-v2.patch) для `rtx_remix_api.cpp` изменяет шаг чтения двух массивов:

- Веса: `sizeof(float) * bonesPerVertex`.
- Индексы: `sizeof(uint32_t) * ceil(bonesPerVertex / 4)`, поскольку в word упакованы четыре индекса.

Исходная версия и patch hash заданы в [manifest.json](manifest.json). Это изменение внешнего renderer, а не восстановленная игровая логика. Полный Release renderer с v2 собирается. Исправленные шаги проверяются прямым выполнением вычислительного shader и парным сравнением кадров через полный renderer на собственной геометрии B1–B4. Установленный прототип отдельный и автоматически не обновляется.

В v2 размер элемента приведён к `uint32_t` до умножения: именно этот тип
требуется полю шага `RasterBuffer`. Сохранённая [v1](skin-strides-v1.patch)
не собирается в x64 MSVC из-за сужения `size_t` в списке инициализации.
CPU-проверка теперь сохраняет это ограничение типов, а не скрывает его
приведением всего результата после вычисления.

## Ограничения

`skinning.h` читает B−1 весов и вычисляет последний как `1−sum`; при B1 эффективный вес равен 1. Произвольные ненормированные веса этим патчем не поддержаны. Вклады `weight <= 0` пропускаются, позиция затем не нормализуется; нормаль нормализуется отдельно.

Индексы упакованы в bytes. До вызова API необходимы корректные указатели, размеры массивов, `B > 0` и индексы `< actualPaletteCount <= 256`. Геометрические индексы — отдельный uint32 triangle-list массив.

[test_skin_strides.cpp](test_skin_strides.cpp) проверяет CPU-арифметику и упаковку с выбранными upstream-заголовками. Он не создаёт Vulkan backend и не доказывает результат GPU-отрисовки.

Тот же тест сопоставляет нормированные B1–B4 с общей реконструкцией
[Fixed.rfx](../../../docs/engine/animation/skin-deformation.md). Ненормированные
веса остаются различием семантики даже с правильными strides. Допуск только
на сумму весов недостаточен: для весов `0.5` и `0.5 + 2⁻²³` и переноса
последней кости на миллион единиц ошибка позиции достигает `0.125`.
Это проверка математической границы, не наблюдение масштаба игровой сцены.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-skinning-fix/Test-CPU.ps1 -Name fresh-contract-check
```

Стенд сохраняет собственную копию исходных зависимостей и общей реконструкции
в новом каталоге результатов. В `source.json` фиксируются их хеши.

Проверка отрисованной геометрии описана в
[руководстве стенда](../docs/skinning-fixture.md). Для сравнения нужны
два полных runtime из одной исходной версии: baseline и renderer с v2.

## Вычислительное ядро на GPU

[Test-GPU.ps1](Test-GPU.ps1) запускает собственный Vulkan-стенд с уже
собранным `gpu_skinning.spv`. Подготовка сверяет неизменность shader-исходников
с закреплённым upstream и точное совпадение SPIR-V с массивом в сгенерированном
заголовке renderer. Vulkan headers, import library, shader, наш стенд и
общие CPU-выражения сохраняются в новом каталоге с хешами.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-skinning-fix/Test-GPU.ps1 -Name fresh-gpu-check
```

Нужны собранные shader-артефакты отдельного checkout
`local-data/rtx-remix/renderer-skinning-build/source`, MSVC x64 и дискретный
GPU с Vulkan 1.3. Перехода на программное устройство нет. Validation layer
не включается; результат не является отчётом Vulkan validation.

Стенд выполняет B1, B2, B3, B4, B5, B8 на 3 и 325 вершинах. Для каждого
набора проверяются исходные strides, исправление только весов и полный v2.
Палитра содержит переносы, неравномерное масштабирование и shear; проверяются
позиции и нормали. Незаполненные области, выходные offsets, padding и лишние
потоки последней группы должны сохранить начальное значение. Нормированные
B1–B4 дополнительно сравниваются с общим эталоном Fixed.rfx.

Это прямые compute dispatch: CPU-порог renderer здесь не участвует.
Проверка устанавливает поведение GPU-ядра при заданных `SkinningArgs`.
Передачу этих аргументов через Remix API/bridge, выбор ветви полного renderer
и результат растеризации проверяет отдельный графический стенд.

`events.jsonl`, `result.json`, `stderr.log`, `memory.json` сохраняют завершение
всех dispatch, параметры устройства и ограничение ресурсов. Watchdog учитывает
рабочую и private-память собственного процесса вместе с оболочкой, останавливает
его при 900 МиБ или 120 секундах. Буферы освобождаются после завершения GPU;
при зависшем драйвере внешний watchdog ограничивает и ожидание очистки.

## Сравнение сохранённых пакетов

[Test-GPUPackets.ps1](Test-GPUPackets.ps1) использует тот же Vulkan transport
и тот же неизменённый SPIR-V для всех вершин сохранённых
[SKP1-пакетов](../docs/skin-packets.md). `-Runs` — имена локальных каталогов
захвата в `local-data/rtx-remix/runs`, разделённые запятой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-skinning-fix/Test-GPUPackets.ps1 -Name fresh-packet-gpu-check -Runs capture-a,capture-b
```

Допускаются до восьми запусков, 128 пакетов и 64 МиБ входных SKP1 суммарно.
Подготовка проверяет имена, длины и соответствие заголовков packet-журналу,
копирует входы в новый каталог и сохраняет SHA256 каждого файла. Полный
parser повторно проверяет пакеты перед вычислением. `packet-gpu-source.json`
сопоставляет номера копий с исходными run/file и фиксирует исходники стенда,
общую реконструкцию, pinned dependencies и границы проверки. Сам журнал
захвата не считается доказательством соответствия выбранному shader.

Четыре варианта в `variants` и `capturedVariants` идут в следующем порядке:

| Вариант | Вход и смысл |
| --- | --- |
| `stock-strides` | Исходные позиции, нормали, веса и палитра; шаги до патча |
| `corrected-strides` | Те же входы; оба шага из v2, без нормализации весов адаптером |
| `baked-identity-kernel-control` | Готовые вершины общей формулы Fixed; одна единичная кость с весом 1 |
| `signed-palette-zero-remainder` | Исходные вершины и все явные веса; знаковые матрицы и дополнительное нулевое влияние |

Поля `remixapi_HardcodedVertex` заполняются через настоящий заголовок SDK:
64 байта на вершину, normal offset 12, color offset 32. Проверяются позиции
и направления нормалей каждой вершины, неизменность входных байтов, включая
UV/color и API padding, а также выходные offsets, padding и лишние GPU lanes.
Топология сохраняется при подготовке; compute shader её не читает.
Пакеты обрабатываются порциями до 4096 вершин с теми же матрицами.
Отдельный B4-пример содержит 4101 вершину и проверяет переход между порциями.

Каждый GPU-результат сравнивается с настоящим общим CPU-заголовком Remix.
Допуск позиции: `1e-4 + 2e-6 × abs(cpuCoordinate)`, нормали: `2e-5` на
компоненту. Это допуск вычислительной проверки, а не допуска модели к submit.
Также записываются максимальные абсолютные ошибки относительно `Bake`.
`differentVertices` считает вершины с ошибкой позиции больше `1e-4` либо
ошибкой нормали больше `2e-5`; это численный индикатор, не оценка видимости.
Контроль готовых вершин требует ошибки позиции не более
`1e-5 + 2e-6 × abs(bakedCoordinate)` и нормали не более `2e-5`.

Тринадцать синтетических случаев охватывают B1–B4, отрицательные и ненормированные
веса, малое изменение последнего веса при большом переносе, неравномерный
масштаб и shear. Их статистика отделена от фактических игровых входов:
синтетический B1–B3 не доказывает наличие этих вариантов в захваченной сцене.

Третий вариант — контроль геометрии и API layout через единичное skinning-ядро.
Он не вызывает unskinned Remix API draw и не доказывает работу bridge,
материала, original shader normal output, камеры, rasterization или lifetime
renderer mesh. Порог выбора CPU/GPU полного renderer также не проверяется.
Для стенда действуют те же ограничения GPU, watchdog и освобождения ресурсов,
что и для `Test-GPU.ps1`.

## Все исходные веса через неизменённое вычислительное ядро

Собственный [winx_skin_packet_gpu.h](../winx_skin_packet_gpu.h) кодирует
каждое исходное влияние как `abs(weight)` и выбранную положительную либо
отрицательную 3×4 матрицу. Последнее дополнительное влияние указывает на
нулевую матрицу. Вычисленный renderer остаток поэтому не меняет позицию
или нормаль, независимо от его положительного либо отрицательного знака.
Исходные B1–B4 становятся API B2–B5; палитра из N матриц занимает 2N+1,
максимум 33. Для B5 необходимы оба исправленных шага v2.

Геометрические вершины, веса и индексы этого представления не зависят от
позы. В следующем кадре достаточно передать новую палитру. Это позволяет
сохранить mesh handle; идентичность экземпляра, время жизни native owner
и история motion vectors требуют отдельных проверок.

Представление сохраняет выражение деформации, но не обещает одинакового
округления CPU и GPU. Проверяются те же численные допуски позиции и нормали,
что и для неизменённого ядра. Случаи с большим переносом отдельно показывают
разницу арифметики. Нефинитный остаток отвергается. Отказ общей деформации,
нулевая нормаль, неизвестный shader/material или неподтверждённый владелец
не становятся допустимыми благодаря перекодированию весов.

`Test-RemixSkinning.ps1 -SignedWeights` задаёт отдельное полное кадровое
сравнение с отрицательными и ненормированными весами, общей формулой Fixed
как эталоном и неизменной skin-сеткой между двумя позами. Его результат
отделён от прямого compute dispatch и от работы с игровыми моделями.
