# Стенд геометрии Remix Skin

[Test-RemixSkinning.ps1](../Test-RemixSkinning.ps1) запускает отдельную
искусственную сцену через явную пару client/server и выбранный renderer.
Результат сохраняется в новом `local-data/rtx-remix/skinning-fixtures/<Name>`.
Скрипт проверяет SHA256 входных DLL/EXE, копирует исходники и зависимости
в каталог опыта и запрещает повторный запуск уже начатого состояния.
По умолчанию сравниваются силуэты; `-MotionHistory` выбирает отдельную проверку
истории движения, описанную ниже.

## Что сравнивается

В каждом кадре одновременно видны эталонная геометрия с вычисленными
позициями и проверяемая геометрия. Их мировые переносы различаются на
3 единицы по x; при z=5 это ровно 288 пикселей окна 960×540.
Для каждой пары «число весов, поза» снимается последовательность
эталон → skin → эталон. Одновременный эталон позволяет отделить деформацию
от изменения субпиксельного jitter между кадрами.

`-MaximumBones 1..4` выбирает число влияний. Палитра содержит четыре
искусственные кости, проверяются две разные позы. Веса неотрицательные
и нормированы; это не корпус игровых ресурсов. Нормали постоянные, поэтому
сравнение силуэтов не доказывает корректность деформации нормалей.

`-Subdivisions 1` создаёт исходный треугольник из трёх вершин с различными
индексами костей. `-Subdivisions 24` создаёт 325 вершин и 576 треугольников,
интерполирует веса между углами и использует единый порядок костей.
В закреплённом renderer CPU-путь `dispatchSkinning` допускает не более
256 вершин, а также требует доступную для CPU позицию без ожидающей GPU-записи.
Следовательно, большой вариант исключает эту CPU-ветвь по условию в исходнике.
Это вывод из исходника соответствующего бинарника, не трасса GPU-команд.

## Запуск и ограничения

Сначала можно собрать стенд без renderer:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/Test-RemixSkinning.ps1 -Name fresh-skin-test -MaximumBones 4 -Subdivisions 24 -BuildOnly
```

Для запуска того же подготовленного каталога передают `-RunBuilt`, те же
`-Name`, `-MaximumBones`, `-Subdivisions`, а также:

| Параметры | Вход |
| --- | --- |
| `-ClientDll`, `-ClientSha256` | x86 bridge client |
| `-ServerExecutable`, `-ServerSha256` | согласованный x64 bridge server |
| `-RendererDirectory`, `-RendererSha256` | полный runtime и хеш его `d3d9.dll` |

Стенд открывает графическое окно; во время снимков оно должно быть видно.
Размещение в игре и запуск игровой сцены для этого опыта не требуются.

`-MaximumWorkingSetMiB` по умолчанию равен 4096 и допускает 256..16384.
Лимит конкретного запуска выбирают по текущим ресурсам, а не по верхней
границе параметра. [Get-SystemMemory.ps1](../Get-SystemMemory.ps1) читает
доступную физическую память и запас commit без WMI.
Через интервалы ожидания 100 мс скрипт суммирует working set и private bytes
своего клиента, оболочки и сервера, найденного по точному пути внутри каталога
опыта. Этот параметр ограничивает оба показателя. Дополнительно
`-MinimumAvailableMemoryMiB` (по умолчанию 512) сохраняет запас доступной
физической памяти. Для commit требуется 5 ГиБ перед запуском и не меньше
512 МиБ во время работы. Начальные значения и дальнейшие измерения записываются
в результат. При превышении лимита или исчерпании запаса
клиент и сервер немедленно останавливаются; по истечении 150 секунд сначала
получают запрос закрытия. Между измерениями возможен
выход выше порога; это контроль с остановкой, не жёсткая квота ОС.
Внешние сборки и аналитические процессы нужно учитывать дополнительно
в общем бюджете из CONTRIBUTING.md. Прерванный результат не принимается.

Диагностическая конфигурация задаёт один compiler thread, отключает
предварительную компиляцию шейдеров и использует канал client размером 32 MB.
Для режима indirect=0 также нужен `rtx.graphicsPreset = 4` (Custom):
обычный Auto/Low/Medium/High/Ultra preset может позднее включить NRC
и заменить значение indirect из файла. Поэтому файл конфигурации сам по
себе не доказывает эффективный режим; проверяется и журнал renderer.
Эти настройки стенда не являются рекомендуемым игровым профилем.

`-HalfResolution` включает NIS (`upscalerType=2`) с `resolutionScale=0.5`.
Внутренний кадр запрашивается в 480×270, окно и снимки остаются 960×540.
Параметры задаются и в начальной конфигурации, и через API после прогрева.
Один `resolutionScale` при `upscalerType=None` не уменьшает внутренний кадр
закреплённого renderer. Половинный профиль не гарантирует, что вся
инициализация renderer уложится в бюджет памяти.

Для парного сравнения оба runtime должны использовать одинаковый профиль.
Порогам анализатора всё равно должны соответствовать эталонные силуэты;
влияние upscaling не скрывается ослаблением критериев. Старый замороженный
стенд без этого аргумента нужно пересобрать в новом каталоге, чтобы применить
`-HalfResolution`.

```powershell
python tools/WinxRemix/analyze_remix_skinning.py local-data/rtx-remix/skinning-fixtures/fresh-skin-test --output local-data/rtx-remix/skinning-fixtures/fresh-skin-test/verdict.json
```

Анализатор требует нормальное завершение, полную последовательность снимков,
объявленную топологию и разные эталонные позы. Пороги IoU: 0.90 для
проекции эталона, 0.98 для одновременных эталонов и 0.97 для skin/эталона;
контрольные силуэты должны содержать больше 100 пикселей.
Новый вердикт записывается только в отсутствующий файл. Неполный запуск
сохраняет `exit.json`, `memory.json` и журналы, но не считается проверкой skin.

## История движения

`-MotionHistory -Subdivisions 24` проверяет previous/current позиции через
диагностическое изображение векторов движения. `-MotionKind` выбирает сценарий:

| Режим | Деформация | Анализатор |
| --- | --- | --- |
| `Translation` — по умолчанию | Одинаковый перенос обеих костей | [analyze_skin_motion_history.py](../analyze_skin_motion_history.py) |
| `Rotation` | Одинаковый поворот обеих костей вокруг Z | [analyze_skin_motion_rotation.py](../analyze_skin_motion_rotation.py) |
| `Islands` | Разные матрицы костей и разные веса двух частей одной сетки | [analyze_skin_motion_islands.py](../analyze_skin_motion_islands.py) |
| `Camera` | Неподвижные кости и геометрия; камера движется по X/Z и вращается вокруг Z | [analyze_skin_motion_camera.py](../analyze_skin_motion_camera.py) |

В `Translation` и `Rotation` для каждой из двух исходных
пар весов — `[0.25, 0.75]` и `[-0.25, 1.25]` — общий signed-адаптер создаёт
постоянную геометрию из 325 вершин. Правый объект движется за счёт палитры,
левый эталон — за счёт обычной мировой матрицы. История у этих объектов
независимая; сравнение выполняется в одном кадре.

Последовательность `Translation` включает видимость в albedo, неподвижность, горизонтальное
движение, движение по двум осям и возврат к неподвижности. В движении палитра
меняется каждый кадр. Флаг игнорирования motion blur у instance не установлен;
сам эффект размытия выключен, чтобы сравнивать диагностические значения.
Камера неподвижна, jitter выключен, используются полное разрешение и B2.
Исключение — сценарий `Camera`, где изменяется только матрица вида.
Перед переходом от albedo к измерениям стенд дожидается видимости обоих
объектов в своём окне; число Presents само по себе не доказывает готовность
renderer. Это ожидание входит в общий лимит времени запуска.
`-MaximumBones` должен оставаться равным 2; `-SignedWeights` и `-HalfResolution`
с этим режимом не совмещаются, поскольку оба профиля весов уже входят в тест.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/Test-RemixSkinning.ps1 -Name fresh-motion-test -MotionHistory -Subdivisions 24 -BuildOnly
```

Затем запускают этот каталог с `-RunBuilt`, теми же параметрами режима,
проверенной парой runtime и выбранным по доступной памяти бюджетом, как выше.
Для результата используется анализатор выбранного сценария:

```powershell
python tools/WinxRemix/analyze_skin_motion_history.py local-data/rtx-remix/skinning-fixtures/fresh-motion-test --output local-data/rtx-remix/skinning-fixtures/fresh-motion-test/verdict.json
```

Анализатор `Translation` сравнивает внутренние участки треугольников размером 24×24 пикселя.
Debug view 21 кодирует абсолютные компоненты смещения: 0.24 и 0.18 пикселя
соответствуют значениям 61 и 46 в восьмибитном изображении. Эталон и Skin
должны отдельно попасть в эти значения с допуском 2; среднее расхождение
между ними ограничено 2, максимальное — 4. Неподвижные фазы должны вернуться
к нулю, а albedo подтверждает наличие обоих объектов.

В `Rotation` углы чередуются между положительным и отрицательным значением;
проверяются амплитуды 0.004 и 0.007 радиана. Жёсткий эталон получает тот же поворот
в instance transform. Каждый пиксель участка 40×32 сравнивается с парным пикселем
Skin и с аналитическим полем вращения при данной камере. Проверяется изменение
вектора по поверхности: одинаковое среднее значение недостаточно.

В `Islands` одна постоянная сетка содержит два независимых участка по 325 вершин.
Веса постоянны внутри участка, но различаются между ними: `[0.25, 0.75]` и
`[0.625, 0.375]` для положительного профиля, `[-0.25, 1.25]` и `[1.5, -0.5]`
для знакового. Кости получают противоположные переносы и повороты. Для каждого
участка отдельный жёсткий эталон использует взвешенную аффинную матрицу двух
костей; такая матрица эквивалентна деформации участка с постоянными весами.
Его геометрия и идентичность тоже остаются постоянными.

Анализатор `Islands` проверяет два участка 16×16, разные движения частей сетки
и аналитическое преобразование каждого пикселя из текущей позы в предыдущую.
Оба новых сценария включают albedo, покой, две фазы движения и возврат к покою.
Допуск парного сравнения — 2 в среднем и 4 в максимуме; отдельный аналитический
эталон ограничивает среднюю ошибку 1.5 и максимальную 4.

В `Camera` для каждого профиля весов выполняются albedo, покой, перенос камеры
по X, поворот вокруг Z, перенос по Z и возврат к покою. Геометрия, палитра и
мировые матрицы обоих объектов постоянны. Анализатор рассчитывает предыдущее
положение каждого пикселя через известную проекцию; для движения по глубине
учитывается отношение предыдущей и текущей дистанции до плоскости `z=5`.
Одинаковое смещение двух боковых объектов при перспективе не предполагается.
Внутренние участки 24×24 проверяются отдельно для Skin и жёсткого объекта;
допуск аналитического сравнения — 1.5 в среднем и 4 в максимуме.

Камера API ставится перед первым контрольным D3D draw кадра. Закреплённый
renderer принимает первое обновление каждого типа камеры за кадр; более
поздний `SetupCamera` может вернуть `SUCCESS`, не заменив принятую камеру.
Диагностический канал 21 содержит экранное движение с учётом предыдущей камеры,
поэтому неподвижные объекты при движении камеры должны давать ненулевое поле.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/Test-RemixSkinning.ps1 -Name fresh-island-test -MotionHistory -MotionKind Islands -Subdivisions 24 -BuildOnly
```

При последующем `-RunBuilt` сохраняют `-MotionKind Islands` и передают ту же
проверенную пару runtime. Для вращения аналогично выбирают `Rotation`,
для движения камеры — `Camera` и его анализатор.

```powershell
python tools/WinxRemix/analyze_skin_motion_islands.py local-data/rtx-remix/skinning-fixtures/fresh-island-test --output local-data/rtx-remix/skinning-fixtures/fresh-island-test/verdict.json
```

После команд удаления ресурсов стенд ожидает событие устройства D3D9 с пределом
десять секунд. Launcher удерживает дескрипторы всех найденных собственных server
процессов и проверяет их коды завершения, даже если server вышел до последнего
измерения. Ненулевой код server отклоняет результат.
Фактический выход подтверждается сигналом удерживаемого дескриптора процесса;
особенности ожидания и проверка без GPU описаны в
[завершении процессов](process-lifetime.md).
Подтверждение остановки bridge может предшествовать выходу его процесса;
для этого ожидания существует отдельный [патч клиента](../skinning-bridge/README.md#ожидание-остановки-сервера).

Эти проверки используют восьмибитное изображение абсолютного движения и не
читают float-буферы GPU. Непрерывно меняющиеся внутри треугольника веса,
одновременное движение камеры и костей, повороты камеры вокруг X/Y,
ненормированная сумма весов, DLSS/TAA и история всех игровых моделей требуют
самостоятельных эталонов.
