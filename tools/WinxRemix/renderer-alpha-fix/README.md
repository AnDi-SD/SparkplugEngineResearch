# Emission прозрачных поверхностей в Remix renderer

Наш [alpha-emission-v1.patch](alpha-emission-v1.patch) сохраняет собственное
свечение материала при `rtx.enableStochasticAlphaBlend = True`. В закреплённой
версии Remix такая поверхность продолжает обход луча до обычного вычисления
emission и теряет этот вклад. Геометрия, цвет вершин и alpha при этом могут
правильно доходить до renderer.

Это изменение внешнего renderer. Оно не содержит имён моделей, уровней,
текстур или восстановленной игровой логики. Исходная версия, хеш патча и
контрольные суммы затронутых файлов находятся в [manifest.json](manifest.json).
Хеши исходников вычисляются после нормализации CRLF в LF.

## Накопление света

GBuffer накапливает отдельный линейный RGB-вклад от переднего слоя к заднему:

```text
T = 1; E = 0
для каждого принятого прозрачного слоя:
    E += emission * alpha * T * attenuation
    T *= 1 - alpha
```

Здесь `emission` вычисляет существующий материал Remix после его texture/vertex
операций. `attenuation` сохраняет ослабление из текущего состояния обхода луча.
Alpha-test и отбрасывание полностью прозрачного слоя выполняются существующей
логикой до накопления. Порядок вызовов `DrawInstance` не задаёт порядок слоёв:
его определяет глубина пересечений.

В composite вклад `E` добавляется без повторного умножения на alpha. Если
накопленная непрозрачность останавливает обход, позднее обычное вычисление
emission для того же stochastic-слоя подавляется, чтобы не прибавлять его дважды.

Буфер `RGBA16F` выделяется отдельно: восемь байт на пиксель внутреннего разрешения.
Существующий `AlphaBlendRadiance` разделяет память с другим ресурсом и для этого
накопления не используется. Новый буфер обнуляется вместе с alpha GBuffer и
принадлежит общему набору ресурсов renderer.

## Подключение

Патч рассчитан на pin из manifest. Применять его следует в отдельном checkout
с этой версией исходников и окончаниями строк LF:

```powershell
git -C <renderer-source> -c core.autocrlf=false apply --check <absolute-path-to-alpha-emission-v1.patch>
git -C <renderer-source> -c core.autocrlf=false apply <absolute-path-to-alpha-emission-v1.patch>
```

Нужна полная x64 Release-сборка renderer, включая изменённые GBuffer и composite
шейдеры. Используется процесс сборки закреплённого upstream через `meson compile`.
Этот патч не заменяет [исправление шагов skinning](../renderer-skinning-fix/README.md)
и не меняет API/bridge. Готовый renderer помещается в `.trex/d3d9.dll` отдельного
runtime с совместимой парой x86 client / x64 bridge. Установка в игру автоматически
не выполняется.

## Проверка на собственной геометрии

[Test-EmissionLayers.ps1](Test-EmissionLayers.ps1) собирает
[собственный стенд](test_emission_layers.cpp), копирует runtime в новый каталог
и запускает четыре пары панелей. Каждой группе прозрачных слоёв соответствует
непрозрачная панель с независимо рассчитанным суммарным emission.

Проверяются один слой, прозрачный слой перед непрозрачным, несколько цветных
слоёв и остановка при почти полной непрозрачности. Геометрия подаётся в прямом
и обратном порядке. Постобработка, освещение, туман и объёмное освещение отключены;
константы материалов учитывают [преобразование gamma 2.2](../docs/development.md#цвета-материалов-remix).

Нужны MSVC x86, установленный Windows SDK, pinned Remix headers в каталоге
зависимостей WinxRemix, совместимый Vulkan GPU, Python и Pillow для анализа.
`RuntimeDirectory` указывает на отдельную закреплённую пару client/bridge с
подкаталогом `.trex`; её бинарные хеши проверяются до запуска. `Renderer` и его
SHA256 задаются явно, поэтому один стенд подходит для baseline и исправленной DLL.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-alpha-fix/Test-EmissionLayers.ps1 -Name fresh-emission-check -RuntimeDirectory <paired-runtime> -Renderer <renderer-dll> -RendererSha256 <sha256>
python tools/WinxRemix/renderer-alpha-fix/analyze_emission_layers.py fresh-emission-check
```

Для проверки другой собранной пары моста дополнительно передают все четыре
параметра: `-ClientDll`, `-ServerExecutable`, `-ClientSha256` и `-ServerSha256`.
Оба бинарных хеша проверяются до подготовки; затем пара заменяется только
в новом каталоге опыта. Версии протокола клиента и сервера должны совпадать.
Остальные зависимости берутся из `RuntimeDirectory`, фактические хеши пары
сохраняются в `profile.json`.

Результаты сохраняются в `local-data/rtx-remix/material-fixtures/<Name>`.
Повторно использовать имя нельзя. Для baseline анализатор поддерживает
`--expect stock-failure`; по умолчанию он требует успешного сравнения.
Снимки нужно также просмотреть: автоматический анализ проверяет внутренние
участки панелей размером 21×21, а не весь кадр. Допуск среднего RGB — 2 из 255.
До сравнения обязательны полный журнал, освобождение созданных API-ресурсов,
нормальное завершение стенда/bridge и отсутствие оставшихся собственных процессов.
После команд отрисовки и удаления ресурсов стенд ставит событие D3D9 и ждёт
его подтверждения с пределом десять секунд. Подтверждение записывается отдельно
от возврата API-вызовов.
Launcher подтверждает выход клиента и сервера через сигнал удерживаемого
дескриптора. [Общий обработчик ожидания](../docs/process-lifetime.md) учитывает
случай, когда код выхода появился до окончания очистки DLL.

Запуск измеряет доступную память, учитывает собственные процессы и оставляет
резерв системе. Предел опыта — 110 секунд и 4 ГиБ private/working памяти;
срабатывание защиты означает незавершённую проверку. Окно стенда выводится на
передний план; снимок допускается только для его видимой клиентской области.

## Границы

Численно проверены прямые видимые поверхности без тумана и объёмного освещения.
Нулевая alpha и отклонённый alpha-test не создают emission; переключение stochastic
alpha сохраняет результат после возврата. При отключённом stochastic alpha
renderer по-прежнему может трактовать частично прозрачный слой как непрозрачный.

Для тумана и объёмного освещения используется ослабление на выбранной глубине
alpha-поверхности. Это приближение для нескольких слоёв на разных глубинах;
их точное объёмное интегрирование этим патчем не доказано.
`rtx.stochasticAlphaBlendDiscardBlackPixel` должен оставаться выключенным:
его проверка чёрного освещения предшествует добавлению нового emission.

Отражения и преломления, длительная история TAA/DLSS, смена разрешения и все
варианты GBuffer требуют самостоятельных проверок. Успешное завершение стенда
не доказывает полное освобождение внутренних объектов renderer и не означает
готовность всей игры или выпуск runtime.
Закреплённый client ждёт завершения server только три секунды после handshake
остановки, затем может принудительно завершить его с кодом 1. Сообщение об
успешной очистке в журнале не заменяет проверку кода завершения процесса;
такой исход стенд отклоняет.
Отдельный [патч ожидания bridge](../skinning-bridge/README.md#ожидание-остановки-сервера)
увеличивает этот предел до десяти секунд. Он не входит в патч emission и требует
собственной сборки клиента; проверка фактического кода выхода остаётся обязательной.
