# USD-захват внешней геометрии и материалов

[api-usd-v1.patch](api-usd-v1.patch) исправляет два пути захвата в закреплённом
Remix renderer: внешний Opaque-материал без исходной D3D9-текстуры и вершины
со Skin, переданным через Remix API. Оба случая могут приводить к ошибке доступа
в исходном экспортёре. Причины и контракт результата описаны в
[USD-захвате](../docs/usd-capture.md).

[animation-v1.patch](animation-v1.patch) дополняет его исправлениями
многокадровой записи трансформаций, представления палитры костей и схемы
привязки материалов. Его применяют после `api-usd-v1.patch`; версия и
контрольные суммы указаны в [animation-manifest.json](animation-manifest.json).

[buffers-v1.patch](buffers-v1.patch) применяют следующим: он исправляет запись
цветов, сокращение изменяющихся буферов, число граней по времени и стандартные
индексы костей D3D9. Его контрольные суммы находятся в
[buffers-manifest.json](buffers-manifest.json).

[zero-scale-v1.patch](zero-scale-v1.patch) сохраняет нулевую кость адаптера
знаковых весов как точный нулевой масштаб и проверяет результат записи анимации.
Контрольные суммы и зависимости указаны в
[zero-scale-manifest.json](zero-scale-manifest.json). Порядок полного набора:
`api-usd-v1.patch`, `animation-v1.patch`, `buffers-v1.patch`, `zero-scale-v1.patch`.

Это наш адаптер экспортёра внешнего renderer. Восстановленные исходники
Sparkplug/Winx, игровые ресурсы и имена моделей в патч не входят.
Версия исходников и SHA256 файлов с окончаниями LF указаны в
[manifest.json](manifest.json). Уведомления upstream о лицензии сохраняются.

## Материал

Экспортёр находит фактический внешний `OpaqueMaterialData` и копирует его
константы и пути текстур в принадлежащую захвату структуру. Асинхронная запись
USD не зависит от времени удаления API-материала. Постоянный цвет без текстуры
допустим; отсутствующий путь не записывается как фиктивный asset.

Для заданных резидентных текстур создаются отдельные DDS, а USD содержит
относительные ссылки. Если текстура задана, но ещё не резидентна, журнал
сообщает пропуск: такой результат не подтверждает полный материал. Сохраняются
константы цвета, emission, alpha, roughness/metallic, thin film, displacement,
Subsurface, sprite sheet и sampler. Передача дополнительных полей Subsurface
из x86 требует отдельного [патча bridge](../skinning-bridge/subsurface-test/README.md).

## Skin

Число влияний берётся из фактической геометрии подсетки. Все API-веса переносятся
явно, включая последний; только исходный путь D3D9 достраивает последний вес
как `1 - sum`. Нормализация и удаление отрицательных весов не выполняются.

Для данного pin внешний API оставляет `SkinningData.numBonesPerVertex` нулевым
при создании прототипа и присоединяет геометрию позже. Исходный D3D9 заполняет
это поле при `finalizeSkinningData`. Экспортёр использует это различие для выбора
формата хранения весов. При обновлении upstream этот критерий нужно заново
сверить с порядком создания геометрии.

## Применение и проверка

Патч применяют к отдельному checkout указанного pin с окончаниями LF:

```powershell
git -C <renderer-source> -c core.autocrlf=false apply --check <absolute-path-to-api-usd-v1.patch>
git -C <renderer-source> -c core.autocrlf=false apply <absolute-path-to-api-usd-v1.patch>
```

Нужна согласованная x64-сборка renderer: меняется структура данных между
capturer и USD exporter. Используется `meson compile` в подготовленном окружении
upstream. Патч не заменяет [исправление Skin](../renderer-skinning-fix/README.md)
и [emission прозрачных слоёв](../renderer-alpha-fix/README.md); их изменения
не пересекают файлы этого патча. Автоматической установки в игру нет.

После захвата обязательны конец экспорта, завершение GPU-команд и процессов,
повторное открытие составной USD-сцены и разрешение всех связанных файлов.
Проверяют геометрию, привязки материала, его значения, содержимое DDS и
mip-уровней. Для Skin дополнительно вычисляют вершины через `UsdSkel` по
сохранённым связям скелета и анимации и сравнивают с независимой деформацией.

На собственной геометрии проверены жёсткая сетка, значения Opaque по умолчанию,
albedo/emission текстуры с mip-уровнями и статическая поза с двумя влияниями
и нормированными весами. Сравнение только внешнего вида кадра для этих выводов
не использовалось.

## Границы

Полный захват игровых сцен с `-AutoSurfaceRoles`, многокадровый захват через
GPU, все варианты количества и суммы весов, все текстурные каналы, Translucent и
Portal пока не подтверждены. Неподдержанный внешний тип материала отмечается
в журнале. Сохранение sampler override, ignore-alpha и всех различий alpha
между экземплярами без потерь также не заявлено.

Ненулевые значения новых полей Subsurface и текстура радиуса требуют проверки
всей цепочки с исправленной парой bridge. Успешные CPU-тесты serializer и
сборка этой пары не заменяют GPU-захват и повторное чтение USD.

## Проверка весов в USD без GPU

[Test-UsdWeights.ps1](Test-UsdWeights.ps1) проверяет собственные наборы весов
через CPU-библиотеку USD. Нужны Windows, локальный USD с Python bindings и
совместимый с ними Python. `UsdDirectory` указывает на каталог с `lib/python`,
`lib` и `bin`; зависимости автоматически не устанавливаются.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/WinxRemix/renderer-usd-fix/Test-UsdWeights.ps1 -Python <compatible-python.exe> -UsdDirectory <usd-distribution> -Output <new-result.json>
```

Проверяются 1–4 влияния при палитре из четырёх костей, отрицательные веса и
суммы, отличные от единицы. Результат `SkinPointsLBS` и `SkinningQuery` на
анонимной сцене сравнивается с независимой суммой преобразованных позиций.
Исходные веса и индексы должны сохраняться. Существующий файл результата
отклоняется; исторические захваты не изменяются.

Закреплённый USD выполняет эту сумму без неявной нормализации, включая случай
одного влияния. Проверка подтверждает семантику USD и эталона чтения. Она
не выполняет захват и не подтверждает деформацию в renderer.

## Проверка самого экспортёра без GPU

[CPU-тест экспортёра](offline-test/README.md) вызывает собранный `GameExporter`,
сохраняет собственные сцены и повторно читает их через USD. В отличие от проверки
семантики весов выше, здесь выполняется реальная запись экспортёром.

С `animation-v1.patch` проверены 1–4 явных влияния при палитре из четырёх костей,
отрицательные и ненормированные веса, три кадра вращений с равномерным и
неравномерным масштабом, интервалы видимости и сокращение вершинных буферов.
Проверяются также значения и типы 33 констант Opaque, привязки материала и
12 относительных ссылок на собственные DDS.

Экспортёр создаёт операцию трансформации один раз и записывает её временные
значения. Кости палитры представлены независимыми корнями `joint0`, `joint1`
и далее, в исходном порядке. Это устраняет искажения от искусственного
подчинения всех костей первой. Их названия обозначают позиции в палитре;
исходная игровая иерархия по этим данным не восстанавливается.

Этот тест не вызывает capturer и не проверяет GPU-запись DDS: файлы текстур
создаёт собственный генератор. Матрицы с исходным shear, произвольным вырожденным или
отрицательным масштабом, а также интерполяция между захваченными кадрами
требуют отдельных проверок. Масштаб в `UsdSkelAnimation` хранится как `half3`;
произвольные исходные значения не обещают точного сохранения без округления.

Сохранение исходного массива нормалей и совпадение деформированных позиций
не означают совпадения деформированных нормалей: стандартный USD и Fixed.rfx
используют разные матрицы при масштабе.
[Ограничение нормалей](../docs/usd-capture.md#нормали-после-деформации)
требует отдельной проверки целевого renderer; патч не подменяет исходные нормали.

## Динамические буферы

Сокращение буферов сохраняет один порядок вершин на всём интервале.
Если набор используемых индексов меняется, `buffers-v1.patch` оставляет
полные исходные массивы. То же правило действует при изменении длины
исходных массивов атрибутов: USD удерживает предыдущий массив между отсчётами
разной длины, а сокращение до одинакового размера внесло бы лишнюю интерполяцию.
Если меняется только порядок или число треугольников, а набор вершин и длины
атрибутов остаются прежними, сокращение продолжает работать.
Это сохраняет соответствие позиций, UV, нормалей, цветов и весов при
разных временных отсчётах этих атрибутов.

Цвет и прозрачность каждого отсчёта записываются отдельными массивами.
Постоянный цвет всей сетки остаётся одним значением с интерполяцией `constant`
и не проходит сокращение по индексам вершин. Число граней записывается
на тех же отсчётах, что и индексы треугольников.
Временный массив сокращения принадлежит `VtArray` и освобождается вместе
с владельцем. Отдельной неосвобождаемой аллокации на каждый буфер нет.

Если D3D9 не задаёт буфер индексов костей, экспортёр создаёт `0..N-1` для каждой
экспортируемой вершины. Длина этого массива учитывает сокращение геометрии.
Сценарий `DefaultJoints` проверяет его согласованность с весами и реальную
деформацию USD для 1–4 влияний.

Сценарий `Dynamic` проверяет конечные треугольники в 16 сценах, включая
промежуточные отсчёты, постоянный цвет, изменение длины массивов и числа граней.
Сценарии `VariableSkin` и `VariableSkinDefaultJoints` отдельно проверяют
рост и уменьшение массивов анимированной сетки: позиции, веса и индексы костей
сохраняют согласованную длину, а USD-деформация совпадает с независимым расчётом.
Переключение интерполяции цвета между `constant` и `vertex` требует
отдельной проверки.

## Представление весов WinxRemix

`SignedAdapter` вызывает общий `EncodeSignedSkin`, который подаёт в API модули
весов, положительную и отрицательную палитры и дополнительную нулевую кость.
Исходные 1–4 влияния становятся 2–5, а палитра из четырёх костей — девятью.
Экспорт сохраняет эту палитру, все индексы и явные веса, включая нулевой последний.

Стандартный `UsdSkelAnimation::SetTransforms` отвергает нулевую линейную часть
матрицы. Без обработки этого случая весь отсчёт анимации остаётся незаписанным.
`zero-scale-v1.patch` задаёт для такой аффинной матрицы масштаб `(0, 0, 0)`,
единичное вращение и её исходный перенос. Прочие кости проходят обычное
разложение USD. Ошибка записи любого отсчёта теперь даёт ошибку экспорта.

CPU-сценарий сравнивает повторно прочитанную деформацию с исходными знаковыми
весами, а не только с перекодированными массивами. Это подтверждает экспорт
представления адаптера на записанных позах; полный захват через GPU, чтение
USD как модификации Remix и произвольные вырожденные матрицы остаются
отдельными проверками.
Отдельный режим `SignedAdapterStatic` проверяет одиночный кадр со значениями
USD по умолчанию вместо временных отсчётов; он использует тот же executable.
