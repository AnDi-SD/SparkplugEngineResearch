# Диагностика второго персонажа

ActorProbe — собственный диагностический host. Он запускает один изолированный
оригинальный x86 EXE под отладчиком для исследования отдельных операций.
Принятый сетевой прототип P описан отдельно в
[руководстве прототипа](prototype-runtime.md); диагностические режимы не
расширяют автоматически его игровые возможности.

## Сборка и конфигурация

Нужны Windows x64, .NET SDK с targeting pack .NET 8 и отдельная полная копия
игры с собственными Media, Saved и INI. EXE должен иметь SHA256
`3F022480BF55045DA4BF692E4BC8862ED38FC024E8A964A558FBDFDF646DFC4F`,
I386 и image base 00400000; live-сигнатуры проверяются отдельно.

```powershell
dotnet build tools/WinxCoop/WinxCoop.ActorProbe.csproj -c Release -o artifacts/actor-probe -m:1
```

Пример соседнего WinxCoop.ActorProbe.exe.json:

```json
{
  "Executable": "X:\\ActorCase\\game\\WinxClub.exe",
  "WorkingDirectory": "X:\\ActorCase\\game",
  "MediaDirectory": "X:\\ActorCase\\game\\Media",
  "OutputDirectory": "X:\\ActorCase\\results-01",
  "DurationSeconds": 180,
  "SampleEvery": 15,
  "Mode": "observe"
}
```

Также допускается `--config <путь>`. Все пути — абсолютные ASCII;
OutputDirectory должен отсутствовать. Длительность — 5–600 секунд.
Probe сверяет фактический native MediaPath с конфигурацией.
Для временного выбора Media можно использовать
[XpGameProbe](xp-game-probe.md), передав ActorProbe как --game.
Внешний timeout должен превышать внутренний: для 600 секунд подходит
--observe-ms 635000 у актуального helper с пределом 3700000.
Параллельные опыты с одним значением MediaPath не допускаются.

## Режимы

| Mode | Проверка |
| --- | --- |
| observe | Уровень, локальный игрок, координаты и владельцы без мутаций игрового мира |
| native-call-check | Один постоянный bool-предикат wxCharacter, восстановление legacy x86 context и продолжение цикла |
| visual-actor | Отдельный граф Блум и native Actor, idle/walk/jump, движение wrapper, удаление и повторное создание |
| visual-unload | Первый цикл удаляет и создаёт модель снова; второй ждёт штатного выхода из уровня |
| control-observe | Чтение штатных команд на границах ввода и обновления мира, включая короткие изменения jump-held |
| controller-reset | Один штатный reset типизированного локального контроллера после устойчивого idle и 120 последующих проверок |
| template-create | Ограниченный опыт с проверенным шаблоном: прекращает свой процесс при неподтверждённом включении компонентов в игровой цикл |
| template-init | Create, scoped init и удаление своего экземпляра в одном native interval с проверками до продолжения игрового цикла |
| template-idle | Scoped init, затем наблюдение исходного scheduler: отдельные Character и MoveCtrl должны получать обновления; при успехе — 30 обновлений и штатное удаление |
| template-near-idle | Та же проверка с размещением своего Instance Root штатной функцией в точке устойчивого локального игрока до возобновления scheduler |
| template-near-walk | Свой command и исходный MoveCtrl: 12 нейтральных обновлений, 6 команд ходьбы, 12 нейтральных; фактическое чтение команды, итоговая поза и удаление |
| template-near-turn | Та же ограниченная проверка с направлением pi/2 на шесть обновлений; штатный расчёт угла и изменение ориентации |
| template-bloom-idle | Отдельный проверочный derived-шаблон с BloomFSM: scoped init, штатное размещение, 30 нейтральных обновлений и удаление |
| template-bloom-walk | Та же отдельная BloomFSM с проверкой собственного ввода и ходьбы 12/6/12 |
| template-bloom-turn | Та же BloomFSM с шестью командами направления pi/2 и native расчётом ориентации |
| template-bloom-jump | Нейтральная подготовка, удержание своего запроса прыжка на четыре обновления, отпускание и наблюдение native траектории/приземления |

Для режимов `template-*` нужны `TemplateFile` и `TemplateSha256` из подготовленного
проверочного корпуса. Режимы не являются универсальным загрузчиком шаблонов.
Они не доказывают управление независимым персонажем. `controller-reset`
не меняет позу извне и не подтверждает телепортацию или серверную коррекцию.

`template-near-idle` вызывает cdecl `00599200(instance, x, y, z)` в том же
интервале, что создание и scoped init, после проверок типа и владения.
Размещение допустимо только при общем проверенном SystemRoot и устойчивом
локальном кадре. Контрольные остановки между вызовами только читают состояние:
наблюдаются root, текущий и предыдущий кэши контроллера, нулевая связь с
платформой, membership и сохранность локального игрока/камеры. Файл шаблона,
поля LOD и флаги активации не меняются; ручных scheduler ticks нет.
Успех означает ограниченную активацию при нейтральной собственной команде,
а не доказанные grounding, столкновения, ходьбу или прыжок.

Для `template-near-walk` и `template-near-turn` записываются только три DWORD
собственного command: `04` magnitude, `08` relative direction, `14` reference
heading. Остальные байты сверяются после записи. Jump `1A`, Node, motion flags,
FSM state и глобальный ввод не меняются. Считаются сопряжённые оригинальные
Move updates, а не только входы в функцию. После шести команд направление
снимается; native consumer, rates, cached positions и root basis наблюдаются
отдельно. Один приём позы по сети этим не проверяется.

Адрес `004F8A45` — общий эпилог Notify, достижимый и без вызова Move.update.
Для него недостаточно одноразовой точки останова по потоку. Диагностика сначала
наблюдает свой настоящий `RET` (`004FAADC` или `004FAB08`) с исходным ESP,
затем точный caller с ESP+4 и собственным receiver. Известное более глубокое
вложенное Notify только журналируется и повторно ставит тот же ожидающий probe;
неизвестная пара прекращает опыт. Это механизм наблюдения, не подмена возврата.

Derived Bloom использует отдельный pin: 4281 байт, SHA256
`517238FA954F087A22ED7DFEE090800A85718761187D5A8C7188AC67B4F3DA9A`.
Он сохраняет тело Seresa, Character Type1/Name41, Traits, Animator и Move,
заменяя StudentsFSM на штатный BloomFSM. Это ещё не внешний облик второй Блум.
Допуск требует явных `TemplateFile`/`TemplateSha256` и подходящего режима;
stock walk/turn этот шаблон не принимают. Сначала `template-init` проверяет
Create/init/delete в одном интервале, включая отдельные command/Actor/state
bindings и сохранность локальных Character/FSM/input/PRS. Значение kind128
наблюдается после init; исходный Students kind40 не переносится в Bloom.

`template-bloom-idle` требует фактически установленный kind0. Изоляция local
state и global counter проверяется до первого возобновления scheduler. После
возобновления counter только наблюдается: его равенство прежнему значению не
требуется. Команда не записывается; её неожиданное конечное изменение даёт
отрицательный результат с удалением на следующей безопасной границе. Успех
нейтрального режима не подтверждает прыжок или отсутствие сюжетных эффектов.

`template-bloom-jump` допускает только собственную kind0/state0 после устойчивых
12 нейтральных обновлений. Записываются `04/08/14` и один байт `1A`, ровно
13 адресованных байтов; остальные сохраняются. Удержание действует четыре
обновления, затем запрос отпускается без повторной подачи. Верхний предел —
136 обновлений всего; успешное наблюдение заканчивается раньше после native
цепочки состояний, подъёма, падения и шести спокойных кадров приземления.
Пределы и числовые допуски принадлежат диагностике, не восстановленной игре.

Точки `5268B0`, `524AA0`, `526977` и `4FB11C` подтверждают собственные binding,
стек и прохождение штатного окна построения команды. Внутренний код protected
helper остаётся непрозрачным: точная инструкция чтения `1A` не установлена.
Ответ проверяется по реальным состояниям, rates и итоговой позе MoveCtrl;
состояние FSM, скорость и координаты адаптером не задаются.

Дополнительный read-only observer в режиме прыжка сравнивает candidate до/после
`4F9D30` и `4F9190`, а также исходный query result без присвоения ему смысла.
Он сохраняет исходные frame/parent/platform и требует парных callsite returns.
Наблюдение коррекции и приземления не заменяет отдельную проверку блокирования
стены или конкретного препятствия.

В visual-actor каждый цикл удерживает модель 2400 world updates. Время зависит
от частоты цикла и загрузки. Положение обновляется раз в три world update:
это 20 Гц только при 60 world update/с. Демонстрационное движение — собственный
producer, не сетевая репликация или восстановленная физика прыжка.

## Граф и жизненный цикл

Локальная инвентаризация учитывает типизированные Node и их владение, без
интерпретации каждого renderable как Skin. Свежий удалённый граф проверяется
строго: известные vtable, согласованные child/parent links, все Skin bones
внутри своего дерева, отсутствие aliases локальных узлов, света и collision
relations в выбранных ветвях. Отброшенные предки должны иметь единичные PRS.

SMO загружает штатный loader. Native Attach переносит render/skeleton ветви
в собственный wrapper. Отдельный native Actor создаёт свои контроллеры и
обновляется существующим AnimationManager. SAN blidsh.san, blwa.san и
bljusm.san получает штатный getter wxAnimationManager. Перед переключением
вызывается StopAll. Волосы загружаются отдельно и Hair_Master крепится к своему Head.
Перед подключением к сцене штатный AlphaManager применяет RGB текущего уровня
из PlayerProfile к собственным материалам. Кэши ambient должны оставаться
нулевыми в момент этого вызова: иначе он меняет также выбранный Light.
Результат сверяется с локальными материалами; локальные материалы сохраняются.
Вторые Player.spt, UserInput и камера не создаются.

Node используют 16-битные intrusive counts. Адаптер учитывает только свою
приобретённую ссылку; удаляют объекты штатные полиморфные deleting destructors.
Обычная очистка: StopAll Actor, DeleteActor, Detach wrapper, release адаптера.
Перед unload wrapper должен иметь ровно два владельца: адаптер и parent.
Адаптер снимает свою ссылку; StopAll/DeleteActor/Detach удаляет граф до
продолжения исходного входа. Animation cache удаляет SAN напрямую, поэтому
retain клипа не заменяет предварительную очистку.

Вызовы выполняются на исходном главном потоке после проверенного SceneManager
RET. Pre-unload batch выполняется перед первой инструкцией проверенного entry
и восстанавливает исходный стек и legacy context. Неизвестный граф, неверный
owner, вложенный unload или незавершённый вызов прекращают собственный опыт.
Такой отказ не считается успешной проверкой.

Граница `0045A802` завершает распространение мировых преобразований узлов от
SystemRoot. Она пригодна для установленных native calls, но сама по себе не
является границей всей игровой симуляции. Пропуск этого обхода не подтверждает
отключение клиентских AI, физики, взаимодействий или сюжетных эффектов.

## Результаты

events.jsonl содержит наблюдения и native calls, report.json — результат,
known exit code, cleanup процесса, ready samples и состояние модели.
Наблюдения ограничены 512 снимками, журнал — 16 MiB.
Внешний helper отдельно подтверждает восстановление MediaPath. Его child —
управляемый host; исходной игрой владеет внутренний DebuggerHost.

Успех режима — ограниченный диагностический результат. Поле `stageAComplete`
остаётся false и не отменяет отдельную игровую приёмку A/P. Видимость моделей,
управление, камера, анимации, unload и отсутствие повторных сюжетных эффектов
проверяются в соответствующем игровом сценарии. Завершение собственного
процесса учитывается отдельно от штатного удаления созданных native объектов.

Результат читается вместе с `configuration.Mode`: `nativeCallCheckPassed`
относится к отдельному `native-call-check`, а `commandMovement.passed` — к
конкретной проверке собственного ввода. Консервативный общий флаг
`independentMovementQualified=false` сохраняет границу полной приёмки E1;
он не отменяет положительный ограниченный результат команды и физического ответа.
