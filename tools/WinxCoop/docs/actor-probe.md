# Диагностика второго персонажа

ActorProbe — собственный диагностический host этапа A. Он запускает один
изолированный оригинальный x86 EXE под отладчиком. Постоянный игровой адаптер
и сетевой кооператив ещё не приняты.

## Сборка и конфигурация

Нужны Windows x64, .NET SDK с targeting pack .NET 8 и отдельная полная копия
игры с собственными Media, Saved и INI. EXE должен иметь SHA256
`3F022480BF55045DA4BF692E4BC8862ED38FC024E8A964A558FBDFDF646DFC4F`,
I386 и image base 00400000; live-сигнатуры проверяются отдельно.

```powershell
dotnet build tools/WinxCoop/WinxCoop.ActorProbe.csproj -c Release -o artifacts/actor-probe -m:1
```

Пример соседнего WinxCoop.ActorProbe.exe.json:

```json
{
  "Executable": "X:\\ActorCase\\game\\WinxClub.exe",
  "WorkingDirectory": "X:\\ActorCase\\game",
  "MediaDirectory": "X:\\ActorCase\\game\\Media",
  "OutputDirectory": "X:\\ActorCase\\results-01",
  "DurationSeconds": 180,
  "SampleEvery": 15,
  "Mode": "observe"
}
```

Также допускается `--config <путь>`. Все пути — абсолютные ASCII;
OutputDirectory должен отсутствовать. Длительность — 5–600 секунд.
Probe сверяет фактический native MediaPath с конфигурацией.
Для временного выбора Media можно использовать
[XpGameProbe](xp-game-probe.md), передав ActorProbe как --game.
Внешний timeout должен превышать внутренний: для 600 секунд подходит
--observe-ms 635000 у пересобранного helper с пределом 900000.
Параллельные опыты с одним значением MediaPath не допускаются.

## Режимы

| Mode | Проверка |
| --- | --- |
| observe | Уровень, локальный игрок, координаты и владельцы без мутаций игрового мира |
| native-call-check | Один постоянный bool-предикат wxCharacter, восстановление legacy x86 context и продолжение цикла |
| visual-actor | Отдельный граф Блум и native Actor, idle/walk/jump, движение wrapper, удаление и повторное создание |
| visual-unload | Первый цикл удаляет и создаёт модель снова; второй ждёт штатного выхода из уровня |
| control-observe | Чтение штатных команд на границах ввода и обновления мира, включая короткие изменения jump-held |
| controller-reset | Один штатный reset типизированного локального контроллера после устойчивого idle и 120 последующих проверок |
| template-create | Ограниченный опыт с проверенным шаблоном: прекращает свой процесс при неподтверждённом включении компонентов в игровой цикл |
| template-init | Create, scoped init и удаление своего экземпляра в одном native interval с проверками до продолжения игрового цикла |

Для `template-create` и `template-init` нужны `TemplateFile` и `TemplateSha256` из подготовленного
проверочного корпуса. Режим не является универсальным загрузчиком шаблонов.
Он не доказывает управление независимым персонажем. `controller-reset`
не меняет позу извне и не подтверждает телепортацию или серверную коррекцию.

В visual-actor каждый цикл удерживает модель 2400 world updates. Время зависит
от частоты цикла и загрузки. Положение обновляется раз в три world update:
это 20 Гц только при 60 world update/с. Демонстрационное движение — собственный
producer, не сетевая репликация или восстановленная физика прыжка.

## Граф и жизненный цикл

Локальная инвентаризация учитывает типизированные Node и их владение, без
интерпретации каждого renderable как Skin. Свежий удалённый граф проверяется
строго: известные vtable, согласованные child/parent links, все Skin bones
внутри своего дерева, отсутствие aliases локальных узлов, света и collision
relations в выбранных ветвях. Отброшенные предки должны иметь единичные PRS.

SMO загружает штатный loader. Native Attach переносит render/skeleton ветви
в собственный wrapper. Отдельный native Actor создаёт свои контроллеры и
обновляется существующим AnimationManager. SAN blidsh.san, blwa.san и
bljusm.san получает штатный getter wxAnimationManager. Перед переключением
вызывается StopAll. Волосы загружаются отдельно и Hair_Master крепится к своему Head.
Перед подключением к сцене штатный AlphaManager применяет RGB текущего уровня
из PlayerProfile к собственным материалам. Кэши ambient должны оставаться
нулевыми в момент этого вызова: иначе он меняет также выбранный Light.
Результат сверяется с локальными материалами; локальные материалы сохраняются.
Вторые Player.spt, UserInput и камера не создаются.

Node используют 16-битные intrusive counts. Адаптер учитывает только свою
приобретённую ссылку; удаляют объекты штатные полиморфные deleting destructors.
Обычная очистка: StopAll Actor, DeleteActor, Detach wrapper, release адаптера.
Перед unload wrapper должен иметь ровно два владельца: адаптер и parent.
Адаптер снимает свою ссылку; StopAll/DeleteActor/Detach удаляет граф до
продолжения исходного входа. Animation cache удаляет SAN напрямую, поэтому
retain клипа не заменяет предварительную очистку.

Вызовы выполняются на исходном главном потоке после проверенного SceneManager
RET. Pre-unload batch выполняется перед первой инструкцией проверенного entry
и восстанавливает исходный стек и legacy context. Неизвестный граф, неверный
owner, вложенный unload или незавершённый вызов прекращают собственный опыт.
Такой отказ не считается успешной проверкой.

## Результаты

events.jsonl содержит наблюдения и native calls, report.json — результат,
known exit code, cleanup процесса, ready samples и состояние модели.
Наблюдения ограничены 512 снимками, журнал — 16 MiB.
Внешний helper отдельно подтверждает восстановление MediaPath. Его child —
управляемый host; исходной игрой владеет внутренний DebuggerHost.

Успех режима — ограниченный диагностический результат. stageAComplete остаётся
false: видимость двух Блум, обычное управление, активная камера, отсутствие
повторных сюжетных эффектов, реальные анимации и unload требуют приёмки в игре.
