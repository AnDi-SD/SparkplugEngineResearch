# Диагностика второго персонажа

ActorProbe — собственный диагностический host. Он запускает один изолированный
оригинальный x86 EXE под отладчиком для исследования отдельных операций.
Принятый сетевой прототип P описан отдельно в
[руководстве прототипа](prototype-runtime.md); диагностические режимы не
расширяют автоматически его игровые возможности.

Отдельные E3 режимы боя, PlayerTraits и общего HP описаны в
[диагностике общих ресурсов](shared-resources-probe.md).

## Сборка и конфигурация

Нужны Windows x64, .NET SDK с targeting pack .NET 8 и отдельная полная копия
игры с собственными Media, Saved и INI. EXE должен соответствовать встроенному
точному профилю оригинальной PC-версии: I386 и image base 00400000.
Целостность файла и live-сигнатуры проверяются отдельно.

```powershell
dotnet build tools/WinxCoop/WinxCoop.ActorProbe.csproj -c Release -o artifacts/actor-probe -m:1
```

Пример соседнего WinxCoop.ActorProbe.exe.json:

```json
{
  "Executable": "X:\\ActorCase\\game\\WinxClub.exe",
  "WorkingDirectory": "X:\\ActorCase\\game",
  "MediaDirectory": "X:\\ActorCase\\game\\Media",
  "OutputDirectory": "X:\\ActorCase\\results-01",
  "DurationSeconds": 180,
  "SampleEvery": 15,
  "Mode": "observe"
}
```

Также допускается `--config <путь>`. Все пути — абсолютные ASCII;
OutputDirectory должен отсутствовать. Длительность — 5–600 секунд.
Probe сверяет фактический native MediaPath с конфигурацией.
Для временного выбора Media можно использовать
[XpGameProbe](xp-game-probe.md), передав ActorProbe как --game.
Внешний timeout должен превышать внутренний: для 600 секунд подходит
--observe-ms 635000 у актуального helper с пределом 3700000.
Параллельные опыты с одним значением MediaPath не допускаются.

## Режимы

| Mode | Проверка |
| --- | --- |
| observe | Уровень, локальный игрок, координаты и владельцы без мутаций игрового мира |
| native-call-check | Один постоянный bool-предикат wxCharacter, восстановление legacy x86 context и продолжение цикла |
| visual-actor | Отдельный граф Блум и native Actor, idle/walk/jump, движение wrapper, удаление и повторное создание |
| visual-unload | Первый цикл удаляет и создаёт модель снова; второй ждёт штатного выхода из уровня |
| control-observe | Чтение штатных команд на границах ввода и обновления мира, включая короткие изменения jump-held |
| client-dispatch-observe | Восемь штатных обновлений готовой Alfea: typed delivery, обходные callbacks, отдельные AI, камера, ввод, physics и animation; без подавления игровых действий |
| client-authority-gate | Ограниченный опыт с выборочным пропуском gameplay `1E`, отдельного вызова AI и передачи animation tag в состояние персонажа; камера и явно выбранные UI-классы сохраняют обновление |
| controller-reset | Один штатный reset типизированного локального контроллера после устойчивого idle и 120 последующих проверок |
| template-create | Ограниченный опыт с проверенным шаблоном: прекращает свой процесс при неподтверждённом включении компонентов в игровой цикл |
| template-init | Create, scoped init и удаление своего экземпляра в одном native interval с проверками до продолжения игрового цикла |
| template-idle | Scoped init, затем наблюдение исходного scheduler: отдельные Character и MoveCtrl должны получать обновления; при успехе — 30 обновлений и штатное удаление |
| template-near-idle | Та же проверка с размещением своего Instance Root штатной функцией в точке устойчивого локального игрока до возобновления scheduler |
| template-near-walk | Свой command и исходный MoveCtrl: 12 нейтральных обновлений, 6 команд ходьбы, 12 нейтральных; фактическое чтение команды, итоговая поза и удаление |
| template-near-turn | Та же ограниченная проверка с направлением pi/2 на шесть обновлений; штатный расчёт угла и изменение ориентации |
| template-bloom-idle | Отдельный проверочный derived-шаблон с BloomFSM: scoped init, штатное размещение, 30 нейтральных обновлений и удаление |
| template-bloom-walk | Та же отдельная BloomFSM с проверкой собственного ввода и ходьбы 12/6/12 |
| template-bloom-turn | Та же BloomFSM с шестью командами направления pi/2 и native расчётом ориентации |
| template-bloom-jump | Нейтральная подготовка, удержание своего запроса прыжка на четыре обновления, отпускание и наблюдение native траектории/приземления |
| template-bloom-body-init | Полная модель Блум со своими Character/BloomFSM/Animator: scoped init, проверка графа и удаление до возобновления игрового цикла |
| template-bloom-body-hair-init | Та же операция с native Attach волос к собственному Head до инициализации Animator |
| template-bloom-body-idle / template-bloom-body-hair-idle | Полная модель без волос или с волосами: 30 нейтральных обновлений исходного scheduler, наблюдение графа и материалов, удаление |
| template-bloom-body-walk / template-bloom-body-hair-walk | Собственный ввод ходьбы 12/6/12 на полной модели без волос или с волосами |
| template-bloom-body-turn / template-bloom-body-hair-turn | Шесть команд направления pi/2 с проверкой штатной ориентации полной модели |
| template-bloom-body-jump / template-bloom-body-hair-jump | Собственный запрос прыжка, native траектория и приземление полной модели |
| template-bloom-body-hair-live | Два считаемых native обновления, затем отдельное нейтральное окно для внешности, основного управления, камеры, паузы и штатной выгрузки |

Для режимов `template-*` нужны `TemplateFile` и `TemplateSha256` из подготовленного
проверочного корпуса. Допуск сопоставляет точное содержимое, размер, layout
дескрипторов и явный режим. Stock-шаблон, BloomFSM на теле Seresa и полная модель
Блум имеют отдельные допуски; разрешение одного режима не переносится на другой.
Body-режимы требуют явных файла и значения из метаданных соответствующего корпуса.
Произвольный шаблон того же размера не принимается. Успех относится к выбранной
операции; полная приёмка E1 и сетевая игра проверяются отдельно. `controller-reset`
не меняет позу извне и не подтверждает телепортацию или серверную коррекцию.

`template-near-idle` вызывает cdecl `00599200(instance, x, y, z)` в том же
интервале, что создание и scoped init, после проверок типа и владения.
Размещение допустимо только при общем проверенном SystemRoot и устойчивом
локальном кадре. Контрольные остановки между вызовами только читают состояние:
наблюдаются root, текущий и предыдущий кэши контроллера, нулевая связь с
платформой, membership и сохранность локального игрока/камеры. Файл шаблона,
поля LOD и флаги активации не меняются; ручных scheduler ticks нет.
Успех означает ограниченную активацию при нейтральной собственной команде,
а не доказанные grounding, столкновения, ходьбу или прыжок.

Для `template-near-walk` и `template-near-turn` записываются только три DWORD
собственного command: `04` magnitude, `08` relative direction, `14` reference
heading. Остальные байты сверяются после записи. Jump `1A`, Node, motion flags,
FSM state и глобальный ввод не меняются. Считаются сопряжённые оригинальные
Move updates, а не только входы в функцию. После шести команд направление
снимается; native consumer, rates, cached positions и root basis наблюдаются
отдельно. Один приём позы по сети этим не проверяется.

Адрес `004F8A45` — общий эпилог Notify, достижимый и без вызова Move.update.
Для него недостаточно одноразовой точки останова по потоку. Диагностика сначала
наблюдает свой настоящий `RET` (`004FAADC` или `004FAB08`) с исходным ESP,
затем точный caller с ESP+4 и собственным receiver. Известное более глубокое
вложенное Notify только журналируется и повторно ставит тот же ожидающий probe;
неизвестная пара прекращает опыт. Это механизм наблюдения, не подмена возврата.

Derived Bloom на теле Seresa сохраняет Character Type1/Name41, Traits, Animator
и Move, заменяя StudentsFSM на штатный BloomFSM. Это отдельная проверка
контроллера без внешнего облика второй Блум.
Допуск требует явных `TemplateFile`/`TemplateSha256` и подходящего режима;
stock walk/turn этот шаблон не принимают. Сначала `template-init` проверяет
Create/init/delete в одном интервале, включая отдельные command/Actor/state
bindings и сохранность локальных Character/FSM/input/PRS. Значение kind128
наблюдается после init; исходный Students kind40 не переносится в Bloom.

`template-bloom-idle` требует фактически установленный kind0. Изоляция local
state и global counter проверяется до первого возобновления scheduler. После
возобновления counter только наблюдается: его равенство прежнему значению не
требуется. Команда не записывается; её неожиданное конечное изменение даёт
отрицательный результат с удалением на следующей безопасной границе. Успех
нейтрального режима не подтверждает прыжок или отсутствие сюжетных эффектов.

`template-bloom-jump` допускает только собственную kind0/state0 после устойчивых
12 нейтральных обновлений. Записываются `04/08/14` и один байт `1A`, ровно
13 адресованных байтов; остальные сохраняются. Удержание действует четыре
обновления, затем запрос отпускается без повторной подачи. Верхний предел —
136 обновлений всего; успешное наблюдение заканчивается раньше после native
цепочки состояний, подъёма, падения и шести спокойных кадров приземления.
Пределы и числовые допуски принадлежат диагностике, не восстановленной игре.

Точки `5268B0`, `524AA0`, `526977` и `4FB11C` подтверждают собственные binding,
стек и прохождение штатного окна построения команды. Внутренний код protected
helper остаётся непрозрачным: точная инструкция чтения `1A` не установлена.
Ответ проверяется по реальным состояниям, rates и итоговой позе MoveCtrl;
состояние FSM, скорость и координаты адаптером не задаются.

Дополнительный read-only observer в режиме прыжка сравнивает candidate до/после
`4F9D30` и `4F9190`, а также исходный query result без присвоения ему смысла.
Он сохраняет исходные frame/parent/platform и требует парных callsite returns.
Наблюдение коррекции и приземления не заменяет отдельную проверку блокирования
стены или конкретного препятствия.

В visual-actor каждый цикл удерживает модель 2400 world updates. Время зависит
от частоты цикла и загрузки. Положение обновляется раз в три world update:
это 20 Гц только при 60 world update/с. Демонстрационное движение — собственный
producer, не сетевая репликация или восстановленная физика прыжка.

## Граф и жизненный цикл

### Пассивная модель

Режимы `visual-*` используют отдельный пассивный Actor. Их устройство отличается
от полного native Character в body-режимах ниже.

Локальная инвентаризация учитывает типизированные Node и их владение, без
интерпретации каждого renderable как Skin. Свежий удалённый граф проверяется
строго: известные vtable, согласованные child/parent links, все Skin bones
внутри своего дерева, отсутствие aliases локальных узлов, света и collision
relations в выбранных ветвях. Отброшенные предки должны иметь единичные PRS.

SMO загружает штатный loader. Native Attach переносит render/skeleton ветви
в собственный wrapper. Отдельный native Actor создаёт свои контроллеры и
обновляется существующим AnimationManager. SAN blidsh.san, blwa.san и
bljusm.san получает штатный getter wxAnimationManager. Перед переключением
вызывается StopAll. Волосы загружаются отдельно и Hair_Master крепится к своему Head.
Перед подключением к сцене штатный AlphaManager применяет RGB текущего уровня
из PlayerProfile к собственным материалам. Кэши ambient должны оставаться
нулевыми в момент этого вызова: иначе он меняет также выбранный Light.
Результат сверяется с локальными материалами; локальные материалы сохраняются.
Вторые Player.spt, UserInput и камера не создаются.

Node используют 16-битные intrusive counts. Адаптер учитывает только свою
приобретённую ссылку; удаляют объекты штатные полиморфные deleting destructors.
Обычная очистка: StopAll Actor, DeleteActor, Detach wrapper, release адаптера.
Перед unload wrapper должен иметь ровно два владельца: адаптер и parent.
Адаптер снимает свою ссылку; StopAll/DeleteActor/Detach удаляет граф до
продолжения исходного входа. Animation cache удаляет SAN напрямую, поэтому
retain клипа не заменяет предварительную очистку.

### Полная модель и штатный Animator

Body-шаблон содержит прежние шесть дескрипторов с заменённым путём тела на
`Characters\Bloom\bloom_jeans.smo`. Native loader сохраняет полный граф модели,
включая её предков; проверяются собственные Node, Head, Skin bones, материалы и
взаимные связи Character/MoveCtrl/BloomFSM/Animator. Свой Animator создаёт свой
Actor и его контроллеры. Исправление ориентации пассивного wrapper к полному
графу автоматически не применяется. Встроенные световые узлы остаются частью
native графа; равенство цвета материалов не доказывает отсутствие иных эффектов
освещения.

В hair-режимах штатный loader сначала загружает отдельный `bloom_hair.smo` в
изолированный граф. Проверка отделяет визуальное поддерево Hair_Master от
оставшегося корня и его света. После native Create собственного экземпляра
диагностика находит его Head до инициализации Animator и создания его Actor. Callback выбора
родителя только читает игровой граф; dispatcher записывает выбранный указатель
в один собственный слот аргумента с проверкой чтением. Native Attach переносит
Hair_Master к Head до scoped init. Машинный код вызова остаётся неизменным.

Этот attachment — явная дополнительная операция. Без его плана сохраняются
обычная последовательность create/init/delete либо retain и прежние индексы
результатов; дополнительный выбор родителя и Attach не выполняются. Полный
граф с волосами обнаруживает тот же штатный Animator. Второй Actor и ручное
обновление анимации не создаются.

Оставшийся источник волос удерживается одной собственной ссылкой. При retained
режиме он удаляется после первого фактического original world; при init-only —
после scoped удаления экземпляра. Затем освобождается собственная RW-страница
пути, когда native вызовы уже не могут заимствовать её. Прикреплённые волосы
принадлежат графу экземпляра и удаляются вместе с ним. Отдельного удаления
Hair_Master после передачи владельцу нет.

Цвет материалов полного тела и волос устанавливает обычное штатное обновление
игры. Probe читает ambient собственных и локальных материалов, сопоставляя Skin
по исходному Mesh и проверяя отсутствие общих Skin/Material объектов. Для этой
ветки собственная формула цвета и вызов пути AlphaManager пассивной модели не
используются. Полные префиксы материалов содержат изменяемые поля; их равенство
не требуется между разными игровыми обновлениями.

Однократное начальное размещение выполняет native функция экземпляра. Дальше
положение рассчитывает штатный MoveCtrl по собственному command. Диагностика
не пишет runtime координаты, скорость, FSM state или глобальный ввод. Короткие
body/hair walk, turn и jump сохраняют описанные выше границы записи intent и
проверки фактического native потребления.

### Отдельное окно удержания и выгрузки

`template-bloom-body-hair-live` завершает два считаемых нейтральных обновления
Character/Move/Bloom, проверяет граф, цвет и освобождение остаточного источника
волос. Затем начинается отдельная фаза удержания с нейтральным собственным
вводом. Счётчики короткого опыта в ней не продолжаются; каждый world проверяет
владение, связи компонентов и membership. Native gameplay и анимация продолжаются
обычным циклом. После первых двух world конечные точки наблюдения снимаются при
следующем попадании: менеджер восстанавливает исходную инструкцию, а повторная
подписка не создаётся. Точки WorldRET и защиты перед unload сохраняются.
Предел фазы — 36000 world updates и общий срок конфигурации,
не более 600 секунд. Эта фаза сама по себе не является проверкой ходьбы или прыжка.

Регистрация шаблона в TemplateManager удерживает ссылку менеджера. Отдельный
указатель в instance её не заменяет. Перед длительным удержанием адаптер
добавляет одну собственную ссылку: штатный выход из меню может очистить
регистрации и отпустить ссылку менеджера при возврате на тот же уровень.
Проверка различает собственную ссылку и наличие шаблона в ограниченном списке
менеджера. Список читается при изменении счётчика и перед удалением; тип шаблона
и его счётчик проверяются каждый world. Перед native удалением адаптер ровно
один раз отпускает свою ссылку. Короткие режимы сохраняют прежний срок жизни.

Пауза разделяет готовность к игре и время жизни сцены. Captured PlayingLevel
должен сохраняться в ограниченном стеке, а локальные profile, компоненты, input
и camera — сохранять своих владельцев. Верхнее состояние flow может остаться
тем же; его смена не служит обязательным признаком паузы. Проверка захватывает
типизированный штатный GameTimer в состоянии `0` и читает его pause byte
`+0x40` в допустимом диапазоне `0/1`. Требуется переход `0→1`, одна непрерывная
пауза не менее пяти секунд и затем `1→0` с возвратом реальной игровой готовности:
тот же PlayingLevel, подходящий input context и отсутствие pending transition.
Произвольное время неготовности считается отдельно и не заменяет native pause.
Probe не вызывает Pause/Start и не записывает поля таймера. Эти условия задают
проверяемый сценарий; описание алгоритма не подтверждает прохождение приёмки.
Основным персонажем и камерой управляют обычным игровым вводом; видимый результат
подтверждается отдельно от проверок указателей.

Перед штатной выгрузкой проверенный entry останавливается до первой инструкции.
После проверки владельцев instance/template/stream native batch удаляет их в
этом порядке. Собственные наблюдатели отключаются до удаления; освобождённые
поля компонентов и старого локального игрока больше не читаются. Исходный entry
продолжается с сохранёнными legacy context, стеком и адресом возврата. Вложенная
выгрузка или незавершённый вызов прекращают опыт.

На более позднем настоящем WorldRET освобождается страница вызова и проверяется
отсутствие сохранённых числовых адресов компонентов в живом менеджере. После
выгрузки используется отдельное наблюдение текущего flow, без прежнего snapshot
персонажа. MainMenu определяется по точному native типу, getter и регистрации;
успех требует готового меню в двух последовательных world и непрерывного
наблюдения этого меню 30 секунд. Для конфигурации нужен срок, достаточный
для загрузки, паузы, возврата и наблюдения меню. Timeout и завершение процесса
не заменяют native cleanup или эту проверку.

Вызовы выполняются на исходном главном потоке после проверенного SceneManager
RET. Pre-unload batch выполняется перед первой инструкцией проверенного entry
и восстанавливает исходный стек и legacy context. Неизвестный граф, неверный
owner, вложенный unload или незавершённый вызов прекращают собственный опыт.
Такой отказ не считается успешной проверкой.

Граница `0045A802` завершает распространение мировых преобразований узлов от
SystemRoot. Она пригодна для установленных native calls, но сама по себе не
является границей всей игровой симуляции. Пропуск этого обхода не подтверждает
отключение клиентских AI, физики, взаимодействий или сюжетных эффектов.

## Клиентская рассылка и выборочное подавление

`client-dispatch-observe` подключает наблюдателей после загрузки Alfea и
проверки локальных владельцев. Восемь полных native world updates ограничены
бюджетом 50000 callbacks и глубиной вложенности 64. Typed entry связывается
с точкой доставки и native RET10 по главному потоку, стеку, получателю,
сообщению и адресу возврата. Гистограммы сохраняют predicate, force и результат
ветвления. Начальный список объектов не является набором стабильных сетевых ID.

Отдельно наблюдаются pending callbacks, secondary Notify, AIManager, ввод,
Physics, Animation, IntelliCam и события Animator. Нулевой счётчик означает,
что путь не попался в этом коротком интервале. Восемь обновлений не доказывают
отсутствия редких событий. Прямые native вызовы в этом режиме не добавляются,
игровые данные и регистры наблюдателем не меняются.

`client-authority-gate` использует тот же ограниченный интервал для явной
проверочной политики. Она сохраняет штатные predicates и pending callbacks,
но пропускает выбранные вызовы после проверки их версии, ABI и владельцев.
Изменяется продолжение исполнения собственного проверочного процесса;
оригинальный EXE на диске, сообщения, flags и таймер не переписываются.
Счётчики отделяют пропущенный вызов от выполненной native доставки.

Эта политика не охватывает автоматически прямые сервисы, подписки, таймеры,
очереди событий и взаимодействия через другие сообщения. Сохранённые UI-классы
тоже могут обрабатывать действия пользователя. Успешный короткий опыт не
является доказательством клиентского режима без игровых последствий.
Загрузка, camera/input, визуальное воспроизведение, длительная работа и выгрузка
требуют отдельной проверки перед включением такого пути в сетевой адаптер.

## Длительное клиентское представление

`client-presentation-probe` и `client-presentation-live` используют отдельную
native-политику для загруженной Alfea28. Она проверяет владельцев сцены, input,
профиля и компонентов, физические таблицы контроллеров и граф штатных часов.
Другие сцены и неизвестные callbacks прекращают опыт. Эти режимы не включаются
автоматически в принятый сетевой прототип P.

Typed-уведомления сохраняются для камеры и UI. AI, Physics, отдельные прямые
сервисы, взаимодействия с целью и игровые события Animator подавляются в своих
источниках. Получатели игровых уведомлений дополнительно фильтруются через
их native Notify-слоты; очередь продолжает удалять обработанные сообщения.
Разрешённые lifecycle-коды не заменяют восстановление исходных слотов перед
выгрузкой. AnimationManager, проверенные Actor/UV-контроллеры, камера, HUD,
Flow, штатные часы и сбор ввода продолжают работать. Raw Actor callbacks
отделены от обновления позы и блокируются отдельно.

Клавиатурный Escape сохраняет штатный путь записи команды и открытия DiaryMenu.
Отладочные ветви общего input helper пропускаются отдельно от этого пути.
Для данного профиля требуется существующий keyboard owner и сброшенный target
latch устройства. Пауза проверяется по настоящему готовому DiaryMenu над тем же
PlayingLevel и типизированному GameTimer. Одна потеря фокуса тоже останавливает
таймер, поэтому не считается проверкой меню.

Локальная Блум остаётся на захваченной позиции: клиент собирает ввод, но не
исполняет собственную игровую симуляцию. Это ожидаемо до подключения применения
серверного состояния. Эти режимы не передают команды по сети, не применяют
снимок мира и не реализуют общий HP или инвентарь. Работа анимационной системы
не означает, что уже синхронизированы чужие игровые действия.

Код фильтров размещается в собственных RX-страницах, счётчики — в отдельных
RW-страницах. До публикации проверяются исходные байты, RTTI и отсутствие
пересечений с наблюдателями. Перехваты снимаются до первой инструкции штатной
выгрузки. Освобождение страниц допускается на более позднем WorldRET после
проверки исходных участков, GP-регистров и committed-стеков потоков процесса.
Неполная проверка запрещает освобождение. После unload прежние player/scene
объекты не читаются; проверяется только свежий Flow и готовое MainMenu.

Конечный probe требует300 полных world updates, восстановления и отложенного
освобождения; он не заявляет штатный unload. Live ограничен600секундами и требует
команды движения/прыжка, изменение камеры, паузу меню не менее5секунд, возврат,
настоящую выгрузку и30секунд непрерывного MainMenu. Видимость и удобство
управления принимаются отдельно от native-счётчиков. Timeout и закрытие процесса
не заменяют эти условия.

## Результаты

events.jsonl содержит наблюдения и native calls, report.json — результат,
known exit code, cleanup процесса, ready samples и состояние модели.
Наблюдения ограничены 512 снимками, журнал — 16 MiB.
Внешний helper отдельно подтверждает восстановление MediaPath. Его child —
управляемый host; исходной игрой владеет внутренний DebuggerHost.

Успех режима — ограниченный диагностический результат. Поле `stageAComplete`
остаётся false и не отменяет отдельную игровую приёмку A/P. Видимость моделей,
управление, камера, анимации, unload и отсутствие повторных сюжетных эффектов
проверяются в соответствующем игровом сценарии. Завершение собственного
процесса учитывается отдельно от штатного удаления созданных native объектов.

Результат читается вместе с `configuration.Mode`: `nativeCallCheckPassed`
относится к отдельному `native-call-check`, а `commandMovement.passed` — к
конкретной проверке собственного ввода. Консервативный общий флаг
`independentMovementQualified=false` сохраняет границу полной приёмки E1;
он не отменяет положительный ограниченный результат команды и физического ответа.
