# Локальная сборка сеанса E7

[Build-SessionBundle.ps1](../Build-SessionBundle.ps1) подготавливает новую папку
для запуска `WinxCoop.SessionHost.exe`. Это локальная сборка приложения, а не
дистрибутив игры или проверка совместного прохождения. Скрипт не запускает игру,
не устанавливает .NET, не меняет реестр и не собирает native-компоненты.
Отдельную игровую копию создают по [руководству подготовки](preparation.md),
а шаблон персонажа приложение формирует из её файлов. Игровые ресурсы
в папку программы не включаются.

## Входы

Нужны Windows, .NET SDK с поддержкой соответствующей целевой платформы,
удерживаемое от изменений дерево исходников и уже проверенные native-сборки.
Native-проверки запускаются отдельно через
[Build-NetworkChecks.ps1](../Build-NetworkChecks.ps1). Основная native-папка
должна содержать актуальные результаты всех14 suites и компоненты выбранной
архитектуры. Дополнительно нужна x86-сборка `XpGameProbe.exe`, полученная с
`-IncludePrototype`; этот помощник остаётся x86 и в папке программы x64.

`OutputDirectory` должен отсутствовать. Его родительская папка должна уже
существовать и быть обычным локальным каталогом. Используйте абсолютный путь
ASCII длиной до140 символов: остаётся запас для временных путей MSBuild.
Предыдущие папки не обновляются и не удаляются.

Пример с условными именами заранее проверенных native-папок:

```powershell
& .\tools\WinxCoop\Build-SessionBundle.ps1 `
    -Architecture x64 `
    -OutputDirectory X:\WinxBuilds\Session-x64-v1 `
    -NativeBuildDirectory X:\WinxBuilds\Native-x64-v2 `
    -XpProbeBuildDirectory X:\WinxBuilds\Native-x86-v2
```

Для профиля совместимости с Windows7 предусмотрена отдельная сборка
x86/.NET6. По умолчанию она содержит
свой runtime, включая Windows Desktop и runtime обоих исполняемых приложений:

```powershell
& .\tools\WinxCoop\Build-SessionBundle.ps1 `
    -Architecture x86 `
    -OutputDirectory X:\WinxBuilds\Session-Win7-x86-v1 `
    -NativeBuildDirectory X:\WinxBuilds\Native-x86-v2 `
    -XpProbeBuildDirectory X:\WinxBuilds\Native-x86-v2 `
    -SelfContained $true
```

Режим x64 по умолчанию использует установленный .NET8 Windows Desktop runtime;
`-SelfContained $true` включает его в папку. В обоих режимах `Configuration`
по умолчанию равен `Release`. Параметр относится к managed publish; входная
native-сборка квалифицируется отдельно. Старый лаунчер P и его V3/IPC3 сюда не
подставляются. Наличие автономного runtime не подтверждает работу конкретной
гостевой ОС: Windows7 и физическая LAN для нового E7-пути ещё требуют приёмки.

## Порядок и проверяемые границы

Host и Actor публикуются последовательно с одинаковыми RID и режимом runtime.
Для обоих выбирается один набор Microsoft.NETCore.App и
Microsoft.WindowsDesktop.App. Скрипт передаёт
`WinxCoopBundleDesktopRuntime=true`: только в этом режиме Actor получает
Windows TFM и явную ссылку на Windows Forms framework. Он сохраняет
`OutputType=Exe`; `UseWindowsForms`, его неявные imports и выводной тип WinExe
для Actor не включаются. Обычные отдельные Actor-проекты остаются NET8 либо
NET6 без этой ссылки, а проекты общего Core не меняют свои TFM.
Для каждого проекта, включая его ссылки, создаются отдельные промежуточные
пути в новом соседнем каталоге `OutputDirectory.build-XXXXXXXX`. Обычные
проектные `bin/obj` не используются. Логи и временная сборка сохраняются.

Папки publish объединяются только при побайтовом совпадении общих файлов.
Отличающиеся `System.*`, runtime или другие одноимённые зависимости вызывают
ошибку. Runtimeconfig обоих приложений должны содержать одинаковые имена и
версии Core/WindowsDesktop, а также одинаковый режим поставки runtime.
Actor с зависимостью от
установленного runtime не выдаётся за автономное приложение внутри автономной
папки UI. Локализованные satellite assemblies ограничены `en`. Если publish всё
же требует подпапки, сборка останавливается и сохраняет результат для разбора;
нужные файлы не отбрасываются ради плоского manifest.

Скрипт проверяет PE-архитектуру native DLL и EXE. Исключение только
`XpGameProbe.exe`, который обязан быть native x86. Результаты CTest и исходная
папка CMake проверяются, затем входные файлы удерживаются открытыми для чтения.
Это проверка выбранных входов. Соответствие native-бинарников удерживаемому
исходному cohort и полноценная игровая приёмка остаются обязанностью владельца
предварительной квалификации; скрипт не восстанавливает историю компиляции по
одному успешному журналу CTest.

`WinxCoop.SourceProfile.json` содержит совместимый для x64/x86 SHA256-профиль
исходников. В него входят Core, Actor, SessionRuntime/Host, native-подсистемы,
проектные определения, обе ветви .NET6/.NET8 и их compatibility shims. Общие
SparkBase/Network inputs, quoted includes и соседние реализации `.cpp`
добавляются консервативно. Канонический ввод хеша — UTF8 без BOM, заголовок
`WinxCoop.SourceProfile/v1`, затем строки `relative/path<TAB>SHA256<LF>` в
ordinal-порядке. Документы, результаты сборок, private-материалы и игровые
ресурсы в профиль не входят. Это локальный профиль совместимости исходников,
а не дополнительный сетевой codec и не доказательство тождественности
поведения разных версий .NET.

После publish профиль проверяется повторно. Последним записывается
`WinxCoop.SessionBundle.json`: версия1, архитектура, SHA256 профиля и список
имён файлов верхнего уровня с SHA256 и типом `native`, `managed`, `executable`
или `data`. Не более512 файлов. Включаются лицензия и благодарности проекта;
уведомления runtime из publish сохраняются. `RuntimeBundle` приложения затем
сверяет manifest и удерживает собственные read pins перед запуском компонентов.

Если команда завершается ошибкой, новая частичная папка и её соседняя сборочная
папка сохраняются. Manifest не выдаётся до завершения проверок. Для следующего
запуска выбирается новое имя папки; автоматической очистки или смешивания с
предыдущим результатом нет.
