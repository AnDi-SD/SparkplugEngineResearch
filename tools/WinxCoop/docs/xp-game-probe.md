# Проверка оригинальной игры в XP и Windows 7

`tests/XpGameProbe.c` — самостоятельный диагностический helper для одноразовой
XP/Windows 7 x86 VM. Он запускает выбранный оригинальный EXE и наблюдает его ограниченное
время. Это не игровой адаптер WinxCoop и не проверка кооператива.

## Сборка и запуск

Нужны MSVC x86 и Windows SDK. Helper не использует CRT; entry point —
`ProbeEntry`, subsystem — `WINDOWS,5.01`. Для отдельной сборки из x86 Developer
Command Prompt, при существующей папке `artifacts`:

```bat
cl /nologo /TC /O1 /GS- /Zl /W4 tools\WinxCoop\tests\XpGameProbe.c /Foartifacts\XpGameProbe.obj /Feartifacts\XpGameProbe.exe /link /NODEFAULTLIB /ENTRY:ProbeEntry /SUBSYSTEM:WINDOWS,5.01 /MACHINE:X86 kernel32.lib advapi32.lib
```

В таблице импорта ожидаются только `KERNEL32.dll` и `ADVAPI32.dll`. Direct3D
загружается через `LoadLibraryA` из системного каталога, без `d3d9.lib`.
Сборка сама по себе не подтверждает совместимость с XP: нужны проверка PE и
реальный запуск в гостевой системе.

Аргументы — абсолютные ASCII-пути длиной меньше `MAX_PATH`:

```text
XpGameProbe.exe --game "Z:\Game\WinxClub.exe" --media "Z:\Game\Media\" --report "Y:\game-attempt-01.json" --observe-ms 180000
```

При запуске без аргументов helper читает соседний `XpGameProbe.exe.args` с теми
же параметрами. Обязательны `--game`, `--media` и `--report`; опциональный
`--observe-ms` задаёт время наблюдения в миллисекундах. Значение по умолчанию —
`40000`, допустимы десятичные целые от `1000` до `900000` включительно.
Повтор параметра, знак, дробная запись, пустое значение и переполнение
отклоняются до загрузки Direct3D, изменения реестра и запуска игры.
Файл ограничен 1024 байтами и допускает только ASCII
и обычные пробелы/переводы строк. Достаточно открыть сам helper в Explorer;
терминал, ввод клавиш программой и учётные данные не нужны. Парсер сохраняет
завершающую обратную черту внутри кавычек буквально. В `MediaPath` всегда
записывается строка с завершающей обратной чертой.

Каталог `--media` и исходный EXE должны существовать. EXE запускается через
`CreateProcessA` с явным application path и своим каталогом как working
directory. Аргументы игре не добавляются. EXE, ресурсы и драйверы helper не меняет.

Отчёт создаётся через `CREATE_NEW` до записи реестра. Уже существующий файл не
перезаписывается. Для каждого запуска нужен новый путь; до завершения опыта
файл может быть пустым. Нормальный отчёт — ограниченный JSON до 8 KiB.

## Что измеряется

Helper записывает версию ОС, фактический путь загруженного системного `d3d9.dll`,
результат `Direct3DCreate9`, описание adapter 0, display mode, HAL/REF capabilities
и `CheckDeviceType` для текущего windowed display format. HRESULT записывается
как беззнаковое 32-битное число; поля `*Called` показывают, был ли вызов вообще.
Он не создаёт собственное окно или Direct3D device и не подменяет renderer игры.
Ошибка графической диагностики не запрещает наблюдать реальный запуск EXE.

Наличие runtime DLL, успешный `Direct3DCreate9` и режим software vertex processing
не доказывают работу полного software renderer. HAL сохраняет hardware
rasterization; REF — отдельный программный reference device. См. [типы устройств
Direct3D 9](https://learn.microsoft.com/en-us/windows/win32/direct3d9/device-types).

Для VBoxVGA в VirtualBox 7.2 аппаратное 3D не поддерживается. Windows 3D path
Guest Additions требует Vista или новее; работа XP desktop и shared folders
сама по себе не подтверждает Direct3D. См. [настройки display
VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/working-with-vms.html)
и [Guest Additions](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/guestadditions.html).

Для Windows 7 использовать VBoxSVGA, включённое 3D и WDDM-драйвер Guest
Additions, соответствующих версии хоста. 128 MiB видеопамяти — подходящая
начальная настройка; сам объём памяти не доказывает работу игры. Игру, helper
и его `.args` следует скопировать на локальный диск гостя, сохраняя отдельные
конфигурацию и сохранения. Отчёт может записываться в общую папку.

[DirectX June 2010](https://www.microsoft.com/en-us/download/details.aspx?id=8109)
добавляет необязательные старые SDK-библиотеки, например D3DX и XAudio.
Необходимость этого пакета определяется отсутствующими зависимостями игры;
драйвер виртуального GPU и системный Direct3D проверяются отдельно.

## Реестр и владение процессом

Непосредственно перед запуском меняется только значение
`HKLM\Software\Konami\Winx Club\MediaPath`. Helper:

1. По отдельности создаёт/открывает `Konami` и `Winx Club`, сохраняя dispositions.
2. Сохраняет наличие, тип и точные байты прежнего `MediaPath`, до 8192 байт.
3. Записывает явный `REG_SZ` media path. При ошибке доступа игра не запускается.
4. После выхода/timeout восстанавливает прежний тип и байты либо удаляет только
   созданное значение, если оно отсутствовало. Результат перечитывается.
5. Закрывает handles и удаляет только собственные созданные ключи, если они
   пусты. Непустые ключи сохраняются с ошибкой rollback в отчёте; рекурсивного
   удаления нет. `LanguageID` только читается, настройки безопасности не меняются.

Игре даётся настроенное время наблюдения, по умолчанию 40 секунд, не более
900 секунд. Отчёт сохраняет заданный предел как `child.observationLimitMs`
и фактическое время ожидания как `child.observationMs`. Затем helper завершает только процесс,
созданный именно его `CreateProcessA`, и ждёт до 5 секунд освобождения. PID-поиск,
завершение чужих/дочерних процессов и управление VM отсутствуют. Не следует
принудительно закрывать сам helper до завершения rollback: аварийное завершение
процесса или выключение гостя не выполняет его cleanup.

Все ошибки rollback/закрытия handles отражаются отдельно. Код выхода helper:

| Код | Значение |
| --- | --- |
| 0 | EXE был создан, собственный процесс остановлен, MediaPath восстановлен; это не результат gameplay |
| 3 | Нельзя записать полный свежий отчёт, включая ошибки аргументов до открытия файла |
| 4 | Отчёт записан, но операция или rollback не завершены корректно |

`probeCompleted=true` не означает, что игра нарисовала кадр. Собственный timeout
и завершение после заданного предела — ожидаемый ограничитель, отражённый в `child`.
Для игровой проверки нужен снимок настоящего окна, точная ошибка либо загрузка
уровня и проверка управления. Поле `gameplayAccepted` всегда `false`: helper
самостоятельно не делает такого вывода.
