# Сопровождение документации

Скрипты используют только публичные файлы репозитория. Игра, SQLite, сеть и закрытый архив не нужны.

```powershell
python tools/RepositoryMaintenance/catalog.py
python tools/RepositoryMaintenance/check_docs.py
python tools/RepositoryMaintenance/class_coverage.py
python tools/RepositoryMaintenance/class_coverage.py --json
```

`catalog.py` строит списки классов, оглавления тематических папок, полный Markdown-каталог и `docs/catalog.json`. Данные классов берутся из публичного `docs/reference/classes.json`. Для проверки без записи используйте `catalog.py --check`.

`check_docs.py` проверяет локальные Markdown-ссылки и заголовки, наличие целей в публичном составе, полноту навигации и ссылки классов на карточки/исходники. Ссылки в закрытые и прежние исследовательские каталоги считаются ошибкой. В Git используются tracked и неигнорируемые новые файлы; в экспортированном дереве — только публичные корни.

`class_coverage.py` без записи считает зарегистрированные классы с существующими исходниками и прямым определением `class` или `struct`. Вывод показывает `x из y (z%)` всего и отдельно для движка и игры; `--json` даёт те же числа и результат проверки для внешнего журнала прогресса. Отсутствующий путь, ссылка за пределы репозитория или только forward declaration завершают проверку с кодом `1`. Это показатель наличия исходников: полнота методов, соответствие игре и рабочая интеграция из него не следуют. Для проверки другого реестра можно задать `--registry PATH`; пути исходников в нём остаются относительно корня этого репозитория.

Новая тематическая статья получает содержательный заголовок `#` и располагается в нужной категории. После её изменения запустите генератор и проверку. Редакторский текст выше `<!-- catalog:start -->` в README категории сохраняется; список статей ниже обновляется автоматически.

Новый класс добавляется в `classes.json` с известными ID и платформами. `registrationBaseIds` описывает регистрацию, не физический layout C++-наследования. Ссылка на исходники должна вести к имеющемуся определению, а не к одному forward declaration.
