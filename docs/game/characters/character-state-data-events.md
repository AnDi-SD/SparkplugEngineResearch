# CharacterState: управляющие записи и события анимации

## Управляющие записи v12

Offsets hex. На обеих платформах state14 указывает на character; от него
move находится PC12C/PS2138. Имена полей аналитические, не original symbols.

| Классы | PC | Поведение |
| --- | --- | --- |
| FrogJumping | 520E50 | Обнуляет move word4 только при state byte3C=0; значения1/255 сохраняют move |
| MinotaurStunned | 521B60 | Обнуляет move byte60 иword4 в этом порядке |
| GolemAttackState | 523690 | Обнуляет DWORD по `+0x04` связанной записи |

### `wxGolemAttackState` на PC

В таблице `0x006F9220` класса `0x1B610315` слот `+0x30` ведёт к
`0x00523690`. Метод читает связанный `wxCharacter` по `+0x14` состояния,
затем адрес записи по `+0x12C` персонажа. Он записывает нулевой
DWORD по `+0x04` записи и возвращается через `RET 4`. Остальные байты
записи и обе исходные записи сохраняются. Смещения обозначают обращения
в PC-коде, имя и полный размер целевой записи открыты.

[Аналитический интерфейс](../../../Winx/Code/wxGolemAttackState.h)
проверяет primary и числовые связи 64-байтового состояния,
304-байтового префикса персонажа и 16-байтового префикса записи.
Возвращаемый `bool` показывает, прошли ли захваты эти проверки.

## Имена событий v15

Входная цепочка одинакова: argument1C→event10→указатель на строку.

| Класс | PC / PS2 | Точное событие и запись |
| --- | --- | --- |
| BirdFlyingState | 517C40 / 2E5480 | `event_takeoff`: character byte PC26C/PS2278=0 |
| GhoulJumpingState | 51AD60 / 2E5010 | `air`: в move три word PC1C8/1CC/1D0, PS21D4/1D8/1DC получают0/43BB8000/0; следующий byte PC1D4/PS21E0=1 |
| TrollMovingState | 51A680 / 2F8D40 | `event_air_begin` →state byte3D=1; `event_air_end` →0 |
| YetiMovingState | 51A0C0 / 2F00D0 | Те же два события меняют state byte3C |

### `wxTrollMovingState` и `wxYetiMovingState` на PC

Для `wxTrollMovingState` (`0x16744A8E`) слот `+0x3C` таблицы
`0x006F91D8` указывает на `0x0051A680`. Для `wxYetiMovingState`
(`0x2A7B1428`) тот же слот таблицы `0x006F90C8` указывает на
`0x0051A0C0`.

Обработчики читают указатель по `+0x1C` аргумента и затем указатель
на имя по `+0x10` полученной записи. Сначала сравниваются 16 байт
`event_air_begin` вместе с завершающим нулём. При совпадении метод
записывает байт `1`. Иначе проверяются 14 байт `event_air_end`
вместе с завершающим нулём. При совпадении метод записывает байт
`0`. Порядок сравнения и запись совпавшего значения сохраняются,
даже если байт уже содержит это значение. Смещение записи у Troll
`+0x3D`, у Yeti `+0x3C`. При другом имени состояние сохраняется.

Переносимый интерфейс принимает 64 байта состояния, два префикса
связанных записей и 16 байт имени. Он проверяет primary и соответствие
адресных слов предоставленным записям. Возвращаемый `bool` показывает,
прошли ли захваты эти проверки.

## Граница PS2 strcmp

Обработчики исполнены после SQ-пролога до LQ-эпилога с заданными borrowed
входами. Настоящий strcmp вызывается с entry40A8A8,без замены результата.
Для string address сalignment1 он сам выбирает байтовую ветвь40A9D8;
сalignment8 — 64-битную ветвь40A96C. Обе ветви исполнены и записаны в trace.
Исходные литералы загружены по своим реальным адресам и сверены с PC.
