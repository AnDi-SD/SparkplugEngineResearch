# CharacterState: разрешения и режимы переходов PC/PS2

## Общий потребитель отметки

- Нулевой handle возвращает1 и сохраняет оба слова.
- Ненулевой handle, совпавший со вторым ненулевым словом, возвращает1,
  обнуляет второе и также первое, если оно совпадает.
- Иначе совпадение первого ненулевого слова возвращает1 и обнуляет первое.
- Если совпадений нет, возвращает0 и сохраняет оба слова.

## Группы разрешений v13

Все offsets ниже hex, значения target/current в таблице — десятичные.
`h`=state24, `current`=state10. Имена без префикса wx.

| Классы | Условие и эффект |
| --- | --- |
| Blast,DateReaction,SpiderAttack,Dispel,Hurt,OpenSecretPassage,WayToGo | h=0 →1, иначе Q |
| BasicMoving | target10/11 либо current≠9 либо h=0 →1; иначе Q |
| FishMoving | current=0 либо h=0 →1; иначе Q |
| FrogJumping,IceGargoyleAttack,KnutAttack | target10 либо h=0 →1; иначе Q |
| GhoulAttack | target9/10 либо h=0 →1; иначе Q |
| GolemAttack | target28 либо h=0 →1; иначе Q |
| TrixAttack | target10/17/28 либо h=0 →1; иначе Q |
| TrollAttack | target22/28 либо h=0 →1; иначе Q |
| GhoulJumping | target23 →0; иначе Q |
| Jumping | target3/4/5/23/31/41 →0; иначе Q |
| TrollMoving,YetiMoving | h≠0 и ненулевой byte3C/3D соответственно →Q; иначе1 |
| Vulnerable | current28 →raw byte3C; иначе h=0 →1, h≠0 →Q |
| YetiAttack | При current≠10 target10/33 разрешены сразу; остальные пути h=0 →1, иначе Q |
| IceWormAttack | packed character bits&7F80 равны0400/0500 →Q; иначе1 |
| GettingCollectible | Q и byte1D=0; Q вызывается первым |

Общие PC addresses не заменяют PS2 доказательство: отдельные PS2 тела
квалифицированы самостоятельными вызовами. Точные class/slot/address и входы
находятся в contract и selections.

| Классы | Собственная проверка |
| --- | --- |
| Attacking | target1 и low nibble packed character word=3 →0; иначе raw byte3C |
| FastAttack | То же исключение target1; иначе unsigned word3C≥word40 |
| ChargedAttack | Запрет target27/29/32 и target1 при low nibble=3 |
| Crouching | Запрет target1/3/4/5/8 |
| BloomDying,Missile | Возвращают raw byte3C, включая255 |
| DroidAttack | target10 либо byte3C≠0 →1; иначе0 |
| MikaelWandring,MinotaurMoving | byte3C=0 →1, иначе0 |
| LadderSlide | Разрешены только target0/10/14 |
| Ladder | target39 запрещён и обнуляет byte61 связанного move-record; остальные разрешены |
| SpiderHurt | При нулевом указателе по chain character→machine→otherCharacter→machine возвращает1; иначе raw byte4C |
| Dialogue,Reading | game-record word1B0 не равен70/71 соответственно |
| Falling | profile byte512 запрещает target3/4/5; target23 всегда запрещён; остальные требуют byte40≠0 либо target14/16/17 |
| PickFlower | target10 либо h=0 разрешены сразу; иначе Q. При разрешении обнуляет profile word504 |

### `wxTrollAttackState` на PC

Слот `+0x34` таблицы `0x006F9120` класса `0x03D479EB` ведёт к
`0x0051A290`. Полные DWORD `0x16` и `0x1C` возвращают `AL=1`
сразу. Для остальных аргументов метод читает ожидающий handle по
`+0x24` состояния. Нулевое слово даёт `AL=1`.

При ненулевом handle метод берёт указатель на `wxAnimationController`
по `+0x18` и вызывает `0x004FB330` с флагом потребления `1`.
Helper сравнивает полные слова, начиная с mark3 по `+0x174`, затем
проверяет mark9 по `+0x170`. При совпадении обоих сначала обнуляется
mark3, затем mark9. При единственном совпадении обнуляется совпавшее слово.
Совпадение даёт `AL=1`, иначе `AL=0`. Состояние Troll и остальные
байты контроллера сохраняются. Handle используется для сравнения слов.

[Аналитический интерфейс](../../../Winx/Code/wxTrollAttackState.h)
проверяет тип 64-байтового префикса состояния. В ветви вызова helper
он проверяет адресную связь и primary 392-байтового захвата контроллера.
Значение результата содержит наблюдаемый `AL`. Отказ в проверке
оставляет результат пустым и сохраняет предоставленные байты.

### `wxShadowBeastAttackState` на PC

Слот `+0x34` таблицы `0x006F9E00` класса `0x0B6B139A` ведёт к
`0x00522990`. Полный DWORD `10` возвращает `AL=1` до чтения состояния.
Для остальных аргументов метод читает handle по `+0x24` и адрес
`wxAnimationController` по `+0x18`. Затем он вызывает `0x004FB330`
с этим handle и флагом потребления `1`. Нулевой handle также попадает в
этот вызов, где даёт `AL=1` без чтения меток.

Для ненулевого handle общий потребитель сначала проверяет слово mark3
по `+0x174`, затем слово mark9 по `+0x170`. Он записывает ноль только
в совпавшие слова. При двух совпадениях порядок записи `+0x174`, `+0x170`.
Хотя старшие биты `EAX` зависят от пройденной ветви, результат операции
задан байтом `AL`: `1` при совпадении, `0` при промахе.

[Аналитический интерфейс](../../../Winx/Code/wxShadowBeastAttackState.h)
проверяет primary 88-байтового захвата состояния. Для ветви вызова он
проверяет связь с отдельным 392-байтовым захватом контроллера, включая
адрес, primary и непересечение диапазонов. Handle сравнивается как сырое
слово. Все байты состояния и остальные байты контроллера сохраняются.
Ошибочная привязка возвращает пустой результат до изменения захвата.
Архивные случаи подтверждают `AL` и итоговые слова двух меток. Историческая
область контроллера содержала метки теста с нетипизированным префиксом.

### `wxLadderState` на PC

Слот `+0x34` таблицы `0x006F8608` класса `wxLadderState`
(`0x298847B5`) указывает на `0x005161A0`. При полном DWORD аргумента
`39` метод читает указатель по `+0x14` состояния, затем указатель
по `+0x12C` объекта `wxCharacter`. По последнему адресу метод
записывает `0` в байт `+0x61` и возвращает `AL=0`. Для всех других
значений аргумента метод возвращает `AL=1` сразу после сравнения.
Оба выхода снимают четыре байта аргумента.

Переносимый запрос использует 60-байтовый префикс состояния. В режиме
`39` он дополнительно проверяет адрес и primary 304-байтового захвата
`wxCharacter`, затем совпадение второго указателя с адресом
предоставленного 98-байтового префикса изменяемой записи. Имя и тип
этой записи остаются открытыми. Результат представлен байтом `AL`.

### `wxFastAttackState` на PC

Слот `+0x34` таблицы `0x006F83A8` класса `wxFastAttackState`
(`0x74F073D7`) указывает на `0x005144C0`. Для полного входного слова `1`
метод читает указатель на персонажа из `+0x14` состояния и слово по
`+0x140` персонажа. Младшая тетрада `3` даёт `AL=0` до сравнения
полей состояния. В остальных случаях `AL=1`, если беззнаковое слово
`+0x3C` не меньше слова `+0x40`. Иначе `AL=0`.

Переносимый запрос принимает 68-байтовый префикс состояния. Для входа `1`
он использует 324-байтовый захват `wxCharacter` с primary `0x006F6438` и
указанным в состоянии адресом. Другие входы используют только захват
состояния. Результат представлен байтом `AL`.

### `wxChargedAttackState` на PC

Слот `+0x34` таблицы `0x006F83F8` класса `wxChargedAttackState`
(`0x06C1726B`) указывает на `0x00514720`. Для полного входного слова
`1` метод читает указатель на персонажа по `+0x14` состояния и слово
по `+0x140` персонажа. При младшей тетраде `3` он возвращает `AL=0`,
при остальных значениях `AL=1`. Для других входных слов метод
возвращает `AL=0` при точном совпадении с десятичным `27`, `29` или
`32`, иначе `AL=1`.

Переносимый запрос читает 72-байтовый префикс состояния. При входе
`1` он использует 324-байтовый захват `wxCharacter` с primary
`0x006F6438` и проверяет совпадение его адреса с указателем из
состояния. Результат записывается байтом `AL`.

### `wxDroidAttackState` на PC

Слот `+0x34` таблицы `0x006FA020` класса `wxDroidAttackState`
(`0x4EAE224C`) указывает на `0x005238D0`. Точное совпадение полного
DWORD аргумента с десятичным `10` сразу даёт `EAX=1`. Для других
значений метод читает один байт состояния по `+0x3C`. При ненулевом
байте он возвращает `EAX=1`, при нулевом `EAX=0`. Оба выхода
снимают 4 байта аргумента.

Переносимый запрос проверяет primary в предоставленном 68-байтовом
префиксе и возвращает полный DWORD результата. При неподходящем primary
место результата сохраняет исходное значение. Контракт относится к
одному слоту PC.

### Сырой результат слота `wxMissileState` на PC

У `wxMissileState` (`0x29B0FF3A`) слот `+0x34` таблицы `0x006F8BE0`
ведёт к короткому методу `0x00518780`. Метод загружает байт `+0x3C` в
`AL` и снимает четыре байта аргумента без чтения этого аргумента. Байт
сохраняет все восемь битов, включая значения `0x00` и `0xFF`.
Оригинал сохраняет старшие 24 бита `EAX`.

Таблица `0x006F8210` класса `wxBloomDyingState` содержит тот же адрес
в этом слоте. [Аналитический интерфейс](../../../Winx/Code/wxMissileState.h)
проверяет таблицу `wxMissileState` в переданном 64-байтовом захвате,
возвращает только сырой `AL` и сохраняет весь захват. Допуск относится
к одному слоту и одной таблице на PC.

## Режимы v14

| Классы | Результат |
| --- | --- |
| Attacking,FastAttack | 0 при target0/4/8/10/18, иначе1 |
| BloomDying,Dying,LadderSlide,Try2Hoist | 1 |
| Falling | target1 →1, иначе0 |
| GettingCollectible | target2 →1, иначе0 |
| PhysicalAttack | target9 →1, иначе0 |
| Jumping,GhoulJumping | target0/3 →2, иначе1 |
| Hurt | 0 при target0/19/20/21/22/23/24/29/30; также target4 при machine word PC14C/PS2158=4; остальные1 |

PC jump tables Attacking/Hurt и PS2 explicit compares сопоставлены по
перечисленным ветвям и соседним значениям, а не объявлены массивом bool.

### `wxFallingState` на PC

Слот `+0x38` в таблице `0x006F86F8` класса `wxFallingState` (`0x3DD27374`)
указывает на `0x00516C40`. Метод сравнивает весь DWORD из `[ESP+4]` с `1`,
возвращает `0` или `1` в полном `EAX` и снимает 4 байта аргумента.
Поля объекта не участвуют в вычислении. Переносимый интерфейс принимает
и возвращает `uint32_t`. Имена исходного типа и его значений пока открыты.

### `wxJumpingState` на PC

Слот `+0x38` таблицы `0x006F82B0` класса `wxJumpingState`
(`0x756B123A`) указывает на `0x0051AD20`. Полный DWORD из `[ESP+4]`
со значением `0` или `3` даёт `EAX=2`. Остальные значения дают
`EAX=1`. Метод снимает четыре байта аргумента. Вычисление зависит
только от аргумента.

Слот `+0x38` таблицы `0x006F92F0` класса `wxGhoulJumpingState`
указывает на то же тело. Переносимые методы обоих классов используют
одну скалярную операцию и возвращают полный `uint32_t`.

### `wxGettingCollectibleState` на PC

Слот `+0x38` таблицы `0x006FB5B8` класса `wxGettingCollectibleState`
(`0x0E7D22C6`) указывает на `0x00534580`. Метод сравнивает весь DWORD
из `[ESP+4]` с `2` и возвращает `EAX=1` при совпадении, иначе `EAX=0`.
Метод снимает четыре байта аргумента. Вычисление зависит только от
аргумента. Переносимый интерфейс принимает и возвращает `uint32_t`.

## Границы описания

`MinotaurStunnedState`, PC521B20/PS2305BB0: при target11 сначала Q. Если он
вернул0, настоящий вызов PC512E40/PS22C8D60 получает this и argument0.
Остановились на входе этой зависимости; последующий return1 виден статически,
но полный путь не выполнен. Если первый Q вернул1, метод вызывает Q второй раз.
Для ненулевого совпавшего handle первый вызов потребляет отметки, второй
возвращает0. При h=0 оба вызова возвращают1. Это подтверждено PC/PS2 и не
«исправлялось» под ожидаемое поведение вьювера.

PC:400 полных возвратов и3 остановки на зависимостях. PS2:367 полных возвратов,
36 ограниченных исполнений. Для Falling,GettingCollectible,OpenGate,
MinotaurStunned исключены SQ-прологи и LQ-эпилоги; PickFlower входит в выбранного
по target преемника исходной ветви с SQ в delay slot. Все точные entry/stop,
входные регистры и исходные инструкции сохранены. Ни один успешный game callback
не подставлялся. Borrowed records не объявляются нормальной связкой всей игры.
