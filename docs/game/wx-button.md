# wxButton: состояние и выбор узла

`wxButton` имеет ID `0x69F878BA` и физически продолжает
[spButton](../reference/classes/sp-button.md). Регистрационная база совпадает
с этой цепочкой. Восстановлены ограниченные PC операции конструктора,
копирования, клонирования, собственного переключения состояния, обновления
выбранного узла и собственного `Notify(0x1C)` с payload `1`. Другие коды
и режимы собственного протокола остаются явными неквалифицированными границами.

## Собственные данные и жизненный цикл

Нативный размер равен `0x1A8` на PC и `0x1A4` на PS2. Смещения ниже относятся
к исходным объектам; переносимый C++ subtype не накладывается на их память.

| PC | PS2 | Поле и запись конструктора |
| --- | --- | --- |
| `+60` | `+5C` | На PC ключ сопоставления с HUDPart; записывается `0` |
| `+64` | `+60` | Массив 64 байта, записывается только начальный NUL |
| `+A4`, `+E4`, `+124`, `+164` | `+A0`, `+E0`, `+120`, `+160` | Четыре массива по 64 байта, в каждый записывается `empty` с NUL |
| `+1A4` | `+1A0` | Сырой байт разрешения собственного обновления, записывается `1` |

Остальные байты этих массивов и хвостового выравнивания конструктор не
инициализирует. Аналитическое представление принимает исходные байты выделения
явным входом и сохраняет незаписанные участки. Его стандартное нулевое хранилище
не означает, что оригинальный allocator обнуляет память.

После конструктора `spButton` собственный конструктор записывает разрешающий
байт, вызывает удаление из engine manager, затем регистрацию в game GUI manager.
Слово и строки инициализируются после этих вызовов. Деструктор сначала вызывает
внешнюю очистку GUI manager, затем выполняются деструкторы базовых классов.
Содержимое manager, его уведомления и время жизни singleton не входят в этот
восстановленный фрагмент.

Копирование сначала выполняет копирование `spButton`, переносит слово `+60`,
затем вызывает эквивалент `strncpy(...,64)` для массивов в порядке
`+64`, `+124`, `+164`, `+A4`, `+E4`. После первого NUL остаток каждого назначения
заполняется нулями. При отсутствии NUL копируются все 64 байта, дополнительного
терминатора нет. Байт `+1A4` и следующие три байта не копируются. Поэтому обычное
копирование сохраняет прежнее разрешение назначения, а clone сохраняет
конструкторское значение `1`. После переноса данных вызывается внешняя операция
clone manager с ID `wxButton`; её результат не используется.

Уведомление регистрации `0x2715` сопоставляет слово `+60` с ключом
[wxHUDPart](wx-hud-part.md) `+13C`. Назначение пяти строковых полей для поиска
HUD и навигации пока не определено данной реализацией. Проверенный teardown
использует нулевое слово `+60`;
произвольные значения этого поля не квалифицированы как вход внешней очистки.

## Уведомление регистрации

Для входящего `0x1C` с payload `1` кнопка синхронно рассылает
`[0x2715,0,0,3,this,0,0,0]` через общий broadcast helper. Sender этого кадра —
сама кнопка. После возврата тот же исходный входящий кадр передаётся
квалифицированному базовому обработчику `spButton`.

Условие собственного режима после рассылки повторно не проверяется. Callback
может изменить код и payload исходного кадра: базовый обработчик видит текущие
значения. В частности, замена на `0x18` с выходной ячейкой вызывает базовую
запись указателя на кнопку; замена payload на `0` при сохранённом `0x1C`
продолжает базовую инициализацию. Собственный bool-reply режим `wxButton`
при этом повторно не исполняется.

При сохранённом `0x1C` база выполняет поиск `PUSHED`, NORMAL, DISABLED,
HIGHLIGHTED и `GUICollision` с общей логикой Node/CollisionInfo. Это не вызывает
собственное обновление выбора `wxButton`: индекс, pressed и разрешающий байт
не пересчитываются этим путём.

Текущая квалификация требует существующий живой `spSubscriptionManager`,
стабильные manager/subscriptions и Entity-root, фактические базовые Node
и корректные графы CollisionInfo. Отсутствующий manager приводит к явной
границе до базового вызова. Холодное создание manager, остальные собственные
ветви и PS2 исполнение этой операции остаются открытыми.

## Переключение состояния

Собственный PC virtual slot `+30` принимает полное 32-битное значение:

| Значение | Сырой enabled | Сырая подсветка |
| --- | --- | --- |
| `0` | `1` | `0` |
| `1` | `0` | Сохраняется |
| `2` | `1` | `1` |
| Прочие | Сохраняется | Сохраняется |

После любой ветви вызывается виртуальное обновление выбора, включая неизвестное
значение состояния. Базовым `spWidget` и `spButton` этот дополнительный slot
не приписывается.

## Собственное обновление выбора

При нулевом разрешающем байте операция сразу возвращается. Иначе она:

1. Скрывает прежний выбранный узел рекурсивно. Проверки его прежней активности,
   останавливающей базовый `spWidget`, здесь нет.
2. При ненулевом pressed и существующем узле `PUSHED` выбирает его, сохраняя
   прежний индекс. Иначе записывает индекс `1` для выключенной кнопки, `2` для
   подсвеченной либо `0` и выбирает соответствующий узел базового Widget.
3. Если выбранного узла нет, использует NORMAL, сохраняя уже выбранный индекс.
4. В порядке NORMAL, DISABLED, HIGHLIGHTED рекурсивно скрывает каждый
   существующий узел, который отличается от текущего выбранного.
5. При нулевом pressed также рекурсивно скрывает существующий `PUSHED`.
6. Показывает текущий выбранный узел с сырым байтом visible, только если
   корневой Node имеет установленный флаг `Enabled` (`0x200`).

Между внешними вызовами повторно читаются pressed, указатели состояний,
выбранный узел и visible. Изменение разрешающего байта после входа не отменяет
уже начатое обновление. Позднее изменение активности корневого Node влияет на
последний показ.

Квалификация относится к действительным базовым Node, стабильному корневому
указателю и действительным графам с живыми объектами. Замена Entity-ссылки
внутри callback, неизвестные производные overrides и изменение структуры графа
остаются открытыми. Отсутствующий root при существующем выбранном узле вызывает
явный отказ переносимой реализации; это не восстановленная защита оригинала.

PS2 layout и собственные тела выделены независимо, но исполнение этих операций
на PS2 пока не квалифицировано. Полнота `wxButton`, его сериализация, HUD
протоколы, навигация и работа интерфейса в игре не заявляются.
