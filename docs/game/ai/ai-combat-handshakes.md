# AIAction: подтверждение команды состоянием персонажа

## Входы и общая последовательность

Все offsets/адреса шестнадцатеричные, номера состояний и интервалы десятичные.
Вход — явно заданные отдельные borrowed записи action, owner, character,
command, character state machine, timer. Нормальный startup персонажа не
заявляется. Как и в предыдущем пакете, указатели не подменяют игровые вызовы:
алгоритм читает их сам. Проверяются все байты всех шести записей.

У всех выбранных действий собственный state находится в PC/PS2 `3AC/3B0`,
признак уже начавшегося состояния — byte `3BC/3C0`.
Наблюдаемое состояние персонажа читается по цепочке:
PC `action+20 → owner+144 → character+124 → machine+130`;
PS2 `24 → 154 → 130 → 13C`.

| Действие/подсостояние | Ожидаемое состояние персонажа | Command byte |
| --- | ---: | --- |
| GolemAttack 1 | 3 | 20 |
| GolemAttack 2 | 4 | 21 |
| SpiderAttack 1 | 3 | 21 |
| SpiderAttack 2 | 3 | 20 |

Когда ожидаемое состояние закончилось, собственный byte обнуляется и выполняется
разная завершающая работа:

| Путь | Подтверждённый результат завершения |
| --- | --- |
| GolemAttack 1/2 | state=0; срок `PC3B0/PS23B4 = now + RNG % 301 + 200`, арифметика uint32 |
| SpiderAttack 1 | один результат RNG расходуется; state=4; `PC3B0/PS23B4=0` |
| SpiderAttack 2 | state=0; `PC3B4/PS23B8=0` |

## Границы описания

PC entry: Golem `5B80C0`, Spider `5B3CB0`, ShadowBeast `5BA600`; все пути
возвращают true через original v7. PS2 Golem `24DDC4→24E088`, Spider
`262910→262CD4`, ShadowBeast `261C24→262020`. Входные A3=3 у Golem и A1=1
у ShadowBeast взяты из предшествующих инструкций пролога. S0 устанавливает
сам dispatcher; SQ/LQ не эмулируются. Выбранные пути не исполняют R5900
специфическую плавающую арифметику соседних ветвей. Методы RNG вызываются
целиком с настоящим return, а не заменённой функцией.
