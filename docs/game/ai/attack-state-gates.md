# AIAction: command-байты и raw state-record

Два полных PC helper используют собственный байт `3BC` и raw DWORD из
borrowed state-record, чтобы изменить command или собственные поля действия.
Это отдельные операции [Spider](../../reference/classes/wx-spider-attack-ai-action.md)
и [ShadowBeast](../../reference/classes/wx-shadow-beast-attack-ai-action.md),
а не восстановление всех фаз Update или целого AI-класса.

Typed receiver содержит связь `own20→owner144→actor`. У actor читаются
`124` — указатель на state-record и `130` — указатель на command-record.
Native-класс и владелец state-record неизвестны. Из него используется только
полный DWORD `130`, сравниваемый с литералом `3`; смысл этого числа не назван.
Значения `00000103` и `80000003` отличаются от `3`, хотя их младший байт равен `3`.
Структурные actor/state views определяют только предоставленные диапазоны
памяти и не устанавливают native-тип, constructor или физическое наследование.

В Spider сначала читаются собственный `3BC`, затем owner/actor и state-word;
command читается только при `3BC=0`. В Shadow command-pointer читается
безусловно перед собственным `3BC` и state-word. Command-байт равен `20` для
Spider и `22` для Shadow. Сохраняется именно порядок каждой операции.

| Собственный байт `3BC` | Полный state DWORD `130` | Изменения |
| --- | --- | --- |
| `0` | Не равен `3` | Command-байт становится `1` |
| `0` | Равен `3` | Command-байт становится `0`, затем собственный байт `3BC=1` |
| Любой ненулевой | Не равен `3` | Байт `3BC=0`, затем DWORD `3AC=0`, `3B4=0`; Shadow дополнительно записывает DWORD `3B0=0` |
| Любой ненулевой | Равен `3` | Данные сохраняются |

Весь байт `3BC` участвует в проверке на ноль: `80` и `FF` также ненулевые.
Его запись имеет ширину один байт; padding `3BD..3BF` сохраняется.
Неизбранные собственные поля, raw DWORD `3A8`, command-байты и прочие
borrowed records остаются неизменными. Command является захваченным raw
record `703090`, а не восстановленным именованным native-классом.
Записи делегируются существующим конкретным raw-storage API `StoreByte20`
и `StoreByte22`, без замены на общий Reset или callback результата.

Portable API хранит полный предоставленный raw-снимок действия отдельно
от собственного C++ base/layout. Сохранённые native address bits остаются
непрозрачными данными; borrowed owner/Host передаются отдельными логическими
связями. Они не получаются преобразованием encoded address в C++ pointer.
Наш storage Host расширяет прежний C++ интерфейс только raw-чтениями
`state124` и `stateWord130`; это не native-наследование и не поставщик
результата выполнения helper.

Профиль по умолчанию отказывает до обращения к storage. Явный аналитический
профиль требует правильного captured primary, пустого portable current/owned
action graph и живых непересекающихся записей, стабильных в пределах вызова.
Это условия допуска; они не определяют native-поведение на null, stale,
aliasing pointers или при изменениях/reentry внутри вызова. Аналитический
отказ не обещает rollback и не превращает отдельные raw-чтения в атомарный
snapshot. Исходный C++-тип возврата helper не установлен; EAX — диагностика,
а результат portable API относится только к нашему допуску.

Наш ограниченный trace перечисляет ordered data reads/stores и отображает
portable identities в предоставленные native tokens только в replay driver.
Trace не является native ABI, машинными PCs, stack trace или источником
значений для самой операции. Каждая replay-строка восстанавливает отдельное
предоставленное состояние: такое сравнение не устанавливает выполнение
native-последовательности на одном и том же C++ instance. Проверки повторных
вызовов и смены borrowed bindings на сохранённом portable instance отдельны.

Полные Update, Entry/Exit, construction/destruction, owning graph, Clone/Copy,
PS2 и игровое поведение остаются открытыми. Наличие этих двух полных helper
операций не закрывает ни целый класс, ни AI-подсистему.
