# Свойства скалярных полей wxSwampPlatformRing

PC-регистрация связывает четыре имени с отдельными полями binary32:

| Имя | Смещение | Чтение | Запись |
| --- | --- | --- | --- |
| Angular Speed (deg) | `0x124` | `FLD dword [this+124]`, `RET` | DWORD аргумента в поле, `RET 4` |
| Transition Duration (s) | `0x128` | `FLD dword [this+128]`, `RET` | DWORD аргумента в поле, `RET 4` |
| Floating Ratio | `0x12C` | `FLD dword [this+12C]`, `RET` | DWORD аргумента в поле, `RET 4` |
| Submerged Ratio | `0x130` | `FLD dword [this+130]`, `RET` | DWORD аргумента в поле, `RET 4` |

Это имена издателя свойств. Они не доказывают преобразование единиц, ограничение диапазона, дальнейшую арифметику или использование конкретным игровым caller. Setter сохраняет все32бита аргумента. Getter загружает binary32 в ST0 и оставляет одно значение в x87-стеке после возврата; это не целочисленный getter. Указанные тела не вызывают другие функции и не изменяют соседние поля.

`wxSwampPlatformRing` предоставляет собственный аналитический API captured values. Prefix содержит308байт и четыре поля; он не является native C++ объектом и не определяет `sizeof`. Аналитический getter возвращает десять байт extended payload, а setter — полный изменённый prefix. Сам API не воспроизводит аппаратный x87-стек или native C++ сигнатуру. Нормальные конечные binary32 и оба signed zero расширяются точно; существующий общий `float80_rtz::FromFloat` служит только для такого точного расширения. Арифметика округления к нулю из этого helper здесь не используется.

Профиль требует соответствующую PC primary table и конечные нормальные binary32 либо signed zero во всех четырёх полях и в новом аргументе. Subnormal, infinity, NaN и неизвестные профили возвращают явный отказ без изменения output. Это ограничение анализа, а не дополнительная проверка оригинального setter. Никаких clamp или нормализации значений не добавлено. Prefix output может совпадать с input; запись сохраняет остальные304байта и три соседних scalar поля.

Проверочная последовательность хранит receiver между независимыми getter/setter/getter вызовами для каждого поля. Подготовка CPU/стека и очистка x87 между вызовами принадлежат вызывающей исследовательской обвязке; они учитываются отдельно от эффектов оригинального callback. Возврат float-getter должен сохраняться с его фактическими ST0 payload, FPCW, FPSW, FPTAG и TOP до такой очистки.

Физическое наследование, полный layout, native C++ return ABI, конструктор и lifetime в текущем запуске, движение платформы, прочие методы, PS2 и gameplay остаются открытыми. Публичное определение класса и принятая ограниченная операция не означают завершённый класс.
