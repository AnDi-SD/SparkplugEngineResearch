# wxCylindricalDoor: два опубликованных свойства на PC

`wxCylindricalDoor` публикует свойства `Locked` и `Opened by proximity`.
Их callbacks читают и записывают raw bytes receiver по `+0x176` и `+0x175`
соответственно. Setter берёт младший байт DWORD-аргумента на стеке и завершает
вызов `RET 4`. Getter переносит байт в AL и завершает вызов обычным `RET`.
Здесь нет нормализации ненулевого значения, проверок диапазона, вызовов других
методов, PE writes или операций FPU. Верхние биты EAX и исходные C++ типы
возвращаемых значений по этим callbacks не устанавливаются.

Аналитический API принимает явно выбранный PC-профиль и captured prefix
`0x177` с primary table `0x00700AB0`. Он сохраняет raw values `0..255` и
явно усекает DWORD setter-аргумента до младшего байта. Запись одного свойства
сохраняет другое свойство и все неизвестные байты. Input/output могут
совпадать. Отказ профиля, чужой primary table или неизвестный property ID
оставляет output без изменений. Это контракт captured values; буфер не
представляет native C++ объект и не разыменовывает захваченные pointer words.

Composed сценарий читает оба байта, записывает `Locked`, повторно читает оба,
записывает `Opened by proximity` и снова читает оба. Так отдельно наблюдаются
усечение аргумента, readback и сохранение соседнего свойства. Стадирование
output описывает итоговые значения, а не native write-attempt trace.

Историческая factory allocation измерена как `380` байт; минимум, затронутый
этими двумя свойствами, равен `0x177`. Constructor/factory/lifetime не
восстанавливаются этим API. Смысл неканонических raw byte values, ограничения
редактора, production callers, открывание и движение двери, прочие свойства,
PS2 и целый класс остаются вне этой операции. Поздняя ошибка исторического
lifecycle не отменяет отдельно установленные factory/RTTI stages и не
используется как evidence новых property calls.
