# wxTargetManager: ресурс стрелки и ограниченное владение

`wxTargetManager` имеет ID `0x3582501B` и базу `spBaseObject`. Собственный
PC factory выделяет `0x54` байта; кроме основного vptr присутствует интерфейс
singleton по смещению `+10`. Переносимый класс сохраняет поведение этого
ограниченного пути и отдельно описывает нативное размещение в ABI record.
PS2 factory и конструктор устанавливают тот же тип и размер; приведённая ниже
динамическая квалификация относится к PC.

Конструктор публикует singleton до инициализации списка и собственного
загрузчика ресурса. Список первоначально пуст. Слова `+20/+24/+28`, байты
`+2C/+34/+50` и слова `+38/+3C/+40/+44/+48/+4C` обнуляются. Выравнивание
`+2D..+2F`, `+35..+37`, `+51..+53` не записывается. Переносимый объект не
приравнивается к нативному heap layout.

## Инициализация ресурса

Собственная операция инициализации выполняет следующую последовательность:

1. Через общий `wxAssetManager` строит путь категории `14`, подкатегории `0`,
   с ёмкостью `255`. Литеральное имя — `arow.smo`, именно с таким написанием.
   При стандартном каталоге путь равен корню плюс `SFX\arow.smo`.
2. Передаёт путь внешней операции загрузки настоящего `spResourceManager`.
   Этот Load остаётся явно обозначенной границей: файловая загрузка модели
   данным исходником не реконструируется.
3. Сравнивает загруженный указатель с текущим ресурсом `+30`. При различии
   освобождает прежнюю ссылку, приобретает новую и заменяет поле. При
   совпадении число ссылок не меняется.
4. Текущему `spNode` задаёт локальный масштаб `(2,2,2)`, выставляет локальную
   dirty-маску `1` и вызывает отключение с рекурсией.
5. После отключения получает текущий корень Scene через заимствованный
   engine/scene prefix и вызывает настоящий общий `AttachChild`.

Переносимая реализация непосредственно использует общие BuildPath,
`spNode.SetScaleForAnalysis`, `MarkLocalTransformDirtyForAnalysis`,
`SetEnabledForAnalysis`, `AttachChildForAnalysis` и `DetachChildForAnalysis`.
Успешный callback не заменяет собственный конструктор, загрузочную операцию
менеджера или Node-потребителей.

Квалифицированы живые обычные `spNode`, успешная загрузка, стабильные сервисы
и bindings, корректный AssetManager catalog и граф без нативной ассоциации
Scene. Каждый Node имеет один canonical binding. Сам корень и внешние
владельцы живут дольше менеджеров. Null load, ленивое создание полного
engine/scene, неизвестные Node overrides, reparenting с другого родителя,
глобальные мутации из внешнего Load и renderer startup остаются открытыми.

## Владение и завершение

Нативная ссылка хранится в отдельном 16-битном слове объекта `+8`. Новая ссылка
менеджера и новая связь с родителем приобретают по одной ссылке. Поэтому
свежий Node после обычного конструктора имеет две ссылки. Повторная загрузка
того же Node и Attach к тому же родителю не создают новых ссылок или элементов
списка детей.

При замене ресурса собственная загрузочная операция освобождает только ссылку
менеджера на прежний Node; она не отсоединяет его от родителя. Старый Node
может остаться ребёнком корня с одной ссылкой. Это поведение сохраняется.

Ограниченный Reset очищает текущие слова и пустой список, отсоединяет ресурс
`+30` от родителя, повторно читает поле, освобождает ссылку менеджера и
обнуляет поле. Для свежего Node это две последовательные потери ссылки и
вызов настоящего Node destructor при достижении нуля. При наличии внешней
ссылки Node остаётся жив. Повторный Reset пустого менеджера допустим.
Destructor выполняет Reset, освобождает пустое хранилище списка и
безусловно очищает singleton; удаление более раннего экземпляра не
восстанавливает singleton другого живого экземпляра.

`wxTargetNodeBindingForAnalysis` хранит общий source Node и отдельный
`referenceCount8`. Это явная техническая замена владения, а не нативная ABI:
`shared_ptr::use_count()` не используется как число нативных ссылок. Изменения
счётчика для собственных связей менеджера и родителя воспроизводятся отдельно;
внешние владельцы должны согласованно поддерживать своё число ссылок.
Сумма приобретаемых ссылок не должна пересекать `65535`; потеря связи с Scene
не должна удалять Node до освобождения ссылки менеджера. Несогласованные
счётчики и переполнение AddRef отклоняются как отдельные неквалифицированные
входы. Для проверки настоящего удаления единственные сильные C++ владельцы
Node — canonical binding и связи графа; caches сохраняют binding или weak
reference. Достижение нуля проверяется истечением `weak_ptr`.

Copy использует буквальный корневой no-op и не переносит состояние менеджера.
Clone сначала конструирует новый менеджер с новой загрузкой ресурса,
регистрирует соответствие и затем выполняет этот Copy. Он публикует новый
singleton; состояние исходника сохраняется.

## Открытые пути

Квалификация Reset/destructor ограничена отсутствующими дополнительными
объектами `+38/+40/+44/+4C`, как после конструктора. Их активные ветви,
ведение списка целей, update, выбор и эффекты не считаются восстановленными.
Notify игнорирует прочие коды, но `0x2712` и `0x2713` вызывают собственные
активацию и деактивацию. Пока их исходные тела не квалифицированы, переносимый
вызов сообщает `UnqualifiedActivation` или `UnqualifiedDeactivation` и не
подменяет их успешной операцией host. Это отказ адаптера, а не восстановленный
нативный результат.

Ограниченный constructor с готовыми каталогом и Scene root не доказывает
полный холодный startup singleton из игрового consumer. Весь класс, PS2
исполнение, файловая загрузка модели и игровая готовность остаются открытыми.
