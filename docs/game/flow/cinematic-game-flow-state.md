# CinematicGameFlowState: сообщения и переключение ввода

`wxCinematicGameFlowState` зарегистрирован с ID `0x137337B1`; физический
родитель PC — `wxGameFlowState` с нулевым смещением. Размер оригинального
PC объекта — `0xE4`. Переносимая [реализация](../../../Winx/Code/wxCinematicGameFlowState.h)
описывает ограниченный набор операций; её размещение и имена методов
аналитические. PS2 и запуск видеопроигрывания этим контрактом не описаны.

Конструктор сохраняет работу родителя с заимствованным вводом и собственным
таймером, обнуляет слова `7C/80/88` и байты `84/DE/E0`, подписывает объект
на группу `0x10`. Затем для 82 записей очищает только бит0 общего слова
флагов и соответствующий локальный байт начиная с `8C`; после цикла снова
записывает `84=0`. Та же последовательность доступна отдельной операцией
сброса. Старшие31 бита общих слов сохраняются.

Путь `3C[64]`, байт `DF` и padding конструктор не инициализирует. Их
содержимое не следует выводить из нулевых значений других полей.
Copy использует пустую операцию базового класса. Clone создаёт новый объект,
включая новый таймер, подписку и повторное изменение82 общих флагов;
состояние исходного объекта не переносится. Деструктор снимает подписку
из текущего общего менеджера, затем выполняет разрушение родителя.

## Собственные операции PC

| Операция | Порядок |
| --- | --- |
| Notify | Только для кода `0x27A3` и нулевого младшего байта payload записывает `84=0`; остальные поля и сообщения не обрабатывает. |
| Виртуальный слот20 | Захватывает владельца ввода, читает его `1C`, вызывает Reset. Повторно читает `1C` у захваченного владельца, вызывает SetMode(6), затем записывает `84=1`, `E0=0`. |
| Виртуальный слот24 | Снимок `E0`, затем `7C`; синхронная рассылка `0x27DC` в группу `0x13`; новое чтение владельца ввода и его `1C`, Reset; `84=0`, `E0=0`. |

Замена глобального владельца внутри Reset слота20 не заменяет уже
захваченного владельца. Изменение его `1C` учитывается вторым чтением.
Слот24 получает владельца после рассылки, поэтому учитывает изменение
глобальной ссылки в обработчике сообщения. Финальные записи обоих слотов
выполняются после внешних вызовов и могут перезаписать изменения обработчиков.

## Полное слово хвоста сообщения

В PC слоте24 инструкция `PUSH ECX` сначала записывает32-битный receiver
в локальное слово стека. Следующая запись заменяет только его младший байт
значением `E0`. Общий построитель сообщения читает всё слово:

```text
tail = (native_receiver & 0xFFFFFF00) | E0
```

Таким образом, хвост не равен расширенному нулём байту `E0`. Переносимая
операция требует явную привязку исходного32-битного receiver и отказывает
до рассылки и изменения ввода, если привязки нет. Адрес переносимого C++
объекта для этого не используется. Поля общего сообщения передаются
через существующие `SendBroadcastNotificationForAnalysis` и
`spSubscriptionManager`; следующие подписчики наблюдают тот же кадр,
включая допустимые изменения его слов предыдущим подписчиком.

Менеджер подписок принадлежит приложению и должен существовать во время
создания, рассылки и разрушения объекта. Изменение подписок во время
рассылки и повторный вход не квалифицированы. Ввод предоставляется через
явную заимствованную границу Reset/SetMode: она не является восстановлением
`wxUserInput` или `wxInputDevicePC`. Загрузка, конфигурация роликов и
собственный слот30 остаются открытыми; слот30 переносимой реализации
явно отказывает.
