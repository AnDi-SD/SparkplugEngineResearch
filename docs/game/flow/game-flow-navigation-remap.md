# Game flow: навигация HUD и переназначение ресурсов PC/PS2

## Навигация

PC `5D6E70..5D7134`, PS2 `33B910..33C228` — обработка навигации между
элементами HUD. В PC selection вынесен в helper`5D6BE0..5D6CAF`; PS2 встраивает
его ветви в четыре направления. Таблицу 56 STX имён этот метод не читает.
Связь с ней предполагалась в промежуточном сообщении, но не подтвердилась.

Подтверждённый порядок:

1. Обновить собственный task timer. Если input magnitude не больше `0.5`
   либо quiet NaN, записать byte `38=1` и закончить.
2. При нулевом byte `38` и ненулевом deadline `34` продолжить только когда
   unsigned timer current строго больше deadline. Равенство не запускает retry.
3. Получить окно по view. Начальный widget берётся из `134`; при null окно
   запрашивается ещё раз и используется его `138`.
4. Выбрать направление по углу и получить соответствующий inline link.
   Любая подстрока `empty` останавливает traversal.
5. Найти link target в заново полученном окне. Отсутствующий target завершает
   попытку без изменения deadline. Для enabled target отправить `27D1` с
   payload `10,0`, затем снова получить окно и выбрать target. Только после
   этих вызовов прочитать timer current и записать `current+500` в deadline.
6. Disabled target заставляет повторить lookup по тому же borrowed link,
   затем продолжить уже с найденного widget. Счётчик увеличивается после
   такого перехода. Возврат к исходному widget завершает обход, когда счётчик
   не меньше `20`; это не общий предел длины любой цепочки.
7. В завершённой активной ветви записать byte `38=0`, включая отсутствие
   target, link `empty` и остановившийся цикл.

Общая PC-операция находится в
[wxGameFlowNavigation.cpp](../../../Winx/Code/wxGameFlowNavigation.cpp),
[контракт](../../../Winx/Code/wxGameFlowNavigation.h) и
[borrowed HUD host](../../../Winx/Analysis/Host/wxGameFlowNavigationHost.h)
отделены от реализации окна. Типизированные Menu callers сохраняют physical
GameFlow prefix без this-adjustment; владелец исходной C++-декларации пока
не установлен. Поэтому реализация оформлена standalone operation.

Timer pointer и адрес/lifetime borrowed link должны сохраняться через
синхронные вызовы; содержимое link может меняться и читается повторно.
Portable API принимает конечный угол и положительные конечные bounds.
Неподдерживаемый угол может быть отвергнут после обновления таймера и получения
окна; такой отказ не объявляется native return. Собственный guard прерывает
`4096` failed hops, чтобы не зависнуть на цикле, который не возвращается к
исходному widget. Завершённые изменения при таком отказе не откатываются.

## Направления: нельзя безусловно объединять PC и PS2

Номера0..3 здесь означают ветви кода; экранные «вверх/вниз» не присвоены без producer угла.

| Ветвь | PC link offset | PS2 link offset |
| ---: | ---: | ---: |
| 0 | `A4` | `A0` |
| 1 | `E4` | `E0` |
| 2 | `124` | `120` |
| 3 | `164` | `160` |

PC central bound — float global`742EC4`; остальные helpers`524380 /5243C0 / 524400` используют отдельный global`740AC4`. PC вычисляет `3*q` в x87 без промежуточного float32 store. PS2 сравнивает с literal raw=`4016CBE4`.

На двух граничных float32 входах направления различаются:

| Raw angle | PC | PS2 |
| --- | ---: | ---: |
| `4016CBE4` | 3 | 1 |
| `C016CBE4` | 2 | 1 |

## Переназначение пяти числовых кодов

PC `5D6CB0` (protected entry), PS2 `33B430`. Сначала получить код текущего
нижнего состояния `s` через `wxGameFlowController`; `p` — **signed** word
`wxPlayerProfile+514`. Значение/сюжетное имя `p` пока не присвоено.

| Input | Условие | Output |
| ---: | --- | ---: |
| 24 | `s==3` | 53 |
| 44 | `s==3` | 52 |
| 49 | `s==17` | 55 |
| 43 | `p<7 && s!=40` | 5 |
| 5 | `s==39` | 54 |
| 5 | иначе `p<7` | 43 |
