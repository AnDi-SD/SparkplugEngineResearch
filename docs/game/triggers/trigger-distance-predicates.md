# Триггеры: реальные потребители геометрического helper

| Класс / PC v19 / PS2 v19 | Порог высоты | Сравнение square |
| --- | ---: | --- |
| CT02OpenDoor / 546D30 / 3A3960 | 100 | float `<20000` |
| GiantBoulderTrigger / 545E50 / 3AD970 | force1 | float `<160000` |
| CTCombinationLock / 548C80 / 3A48B0 | 500 | uint32 square `<word128/134` |
| PhoneTrigger / 548C80 / 3B35B0 | 500 | тот же PC код, отдельное PS2 тело |
| ChangeCharacterPlacement / 541040 / 39BD00 | 300 | uint32 square `<word128/134` |
| GenericSideQuest / 591110 / 3D5DF0 | 100 | uint32 square `<word128/134` |
| DragonFlowerTrigger / 53BF20 / 3AA4C0 | 100 | float square `<converted unsigned word128/134` |
| GenericTrigger / 590640 / 3AC890 | 100 | gate byte124/130, затем uint32 square `<word128/134` |

Смещения и адреса шестнадцатеричные; числовые пороги десятичные. Не переименовываем
word128 в обычный линейный radius: эти потребители сравнивают именно square.
Перевод единиц координат здесь не устанавливался.

CT02OpenDoor/GiantBoulder получают два Node из собственных PC148/14C и
PS2160/164. Остальные используют сохранённый глобальный профиль
`765AD4 / 49FC7C`: profile2B4→record24→Node. Второй Node обычно берётся из
this18; GenericSideQuest использует this24→record24. В фикстуре альтернативный
источник содержит другие координаты, поэтому ошибочная привязка дала бы иной
результат. Глобальный cache miss и normal construction не исполняются.

PC GenericTrigger проходит исходный защищённый переход `590643`. Дополнительное
наблюдение чтения памяти для gate0 иFF зафиксировало оригинальную инструкцию
`40744C: mov al,byte ptr [esi+124]`. Gate0 возвращает false, gateFF допускает
геометрию. Размер чтения — ровно один байт; защищённая логика не заменена.

## Проверка GiantBoulderTrigger на PC

В class ID `0x55E957F4` слот `+0x4C` таблицы `0x006FD000` ведёт к
`00545E50`. Ссылки по `+0x148` и `+0x14C` дают две записи точек. Метод
передаёт их в `00597660` с force=1 и tolerance=0. Helper читает XYZ точек,
а `00597600` обнуляет обе временные копии Y на стеке. В исходных точках
сохраняются все координаты.

Сравнение использует точность мантиссы x87 в 64 бита и округление к
ближайшему. Сумма квадратов разностей Z и X остаётся в расширенном
формате до сравнения с `160000.0f`. Равенство даёт EAX=0. Значение ниже
порога даёт EAX=1.

Аналитический интерфейс принимает две переданные XYZ-позиции в формате
`spNode::Vector3` с конечными нормальными float или знаковыми нулями по
модулю до 16384. Отказ при выходе за эту область сохраняет выходное
значение. Объекты и их связи остаются у вызывающего кода.
[Исходник проверки](../../../Winx/Code/wxGiantBoulderTrigger.cpp)

## Проверка CT02OpenDoor на PC

В class ID `0x28734422` слот `+0x4C` таблицы `0x006FD150` ведёт к
`00546D30`. Первая запись точки берётся из `+0x14C`, вторая из `+0x148`.
Через `00597660` обе позиции передаются в `00597600` с force=0 и
tolerance=100. Helper зануляет временные Y на стеке при `|dy| < 100`.
При `|dy| = 100` вертикальная разность участвует в сумме.

Разности, произведения и сумма `(dz² + dx²) + dy²` вычисляются в x87
с мантиссой в 64 бита и округлением к ближайшему. Сравнение с
`20000.0f` выполняется в расширенной точности. На пороге возвращается
EAX=0. Только результат ниже порога даёт EAX=1.

Аналитический интерфейс читает два переданных `spNode::Vector3` с
конечными нормальными координатами или знаковыми нулями по модулю до 16384.
Отказ за пределами профиля сохраняет выходное значение. Активация двери,
связывание точек, жизненный цикл и PS2 остаются открытыми.
[Исходник проверки CT02OpenDoor](../../../Winx/Code/wxCT02OpenDoor.cpp)

## Проверка сохранённой позиции wxPivotingDoor на PC

У класса `0x4AC3694A` слот `+0x4C` таблицы `0x006FBDE0` ведёт к
`0x00539C60`. После проверки нулевого байта `+0x169` и разрешения
ссылки на узел игрока участок с `0x00539C90` читает сохранённые XYZ двери
по `+0x190/+0x194/+0x198` и XYZ узла по `+0x74/+0x78/+0x7C`.

Из координат двери вычитаются координаты игрока. При `|dy| < 200`
разность Y заменяется положительным нулём. Обе границы, `+200` и
`−200`, участвуют в расчёте. Сумма `(dz² + dy²) + dx²` вычисляется
с 64 значащими битами x87 и округлением к ближайшему чётному
(`FPCW=037F`). Порог `+0x128` читается как беззнаковое 32-битное целое
и сравнивается в расширенной точности. Метод даёт `AL=1`, если квадрат
расстояния меньше порога или равен ему.

[Аналитический интерфейс](../../../Winx/Code/wxPivotingDoor.h) принимает
раздельные захваты двери и уже полученного узла размером 460 и 128 байт.
Координаты могут быть нормальными значениями binary32 с модулем до 16384
или нулями обоих знаков. При отказе выходное значение сохраняется.
Поиск узла, активация двери, жизненный цикл и PS2 находятся за границей
этого интерфейса.

## Границы описания

171 разных исполнения прошли с первого раза:79 полных PC методов,12 полных
PS2 методов CT02OpenDoor/GiantBoulder и80 собственных PS2 компонентов остальных.
Пилот15 за1,259s,пакет156 за10,946s внутри процессов. Два дополнительных PC
наблюдения защищённого gate не считаются новыми входами основного пакета.

PC PhoneTrigger разделяет адрес и входы с CombinationLock:повторное выполнение
не делалось. PS2 PhoneTrigger имеет отдельное тело и13 собственных проверок.
Унаследованные aliases остальных потомков из разведочной таблицы не получают
дополнительных оценок за тот же общий метод.
