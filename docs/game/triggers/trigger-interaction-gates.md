# PivotingDoor, PushButton, SnowPile: выбор взаимодействия

## PushButton

PC53B250 отвергает ненулевой byte149. Затем настоящий597660 вычисляет
горизонтальное расстояние: первый Node — player, второй — own Node+18,
force=1, tolerance=0. Требуется строго `squaredDistance < uint32(this128)`.
После этого настоящий597220 вызывается с обратным порядком own/player,
threshold binary32 `3F333333` (0,7), ignoreY=1, negate=0.
Следовательно, ось направления берётся у Node игрока, а вектор идёт от него
к объекту. Обе стадии выполнены на оригинальном PC коде; args наблюдались
без подмены результатов.

## SnowPile

18 PC вызовов: mode9/10/11/FFFFFFFF, gate0/1/255, границы расстояния24/25/26,
высота99/±100. Три PS2 вызова сmode10 дошли до false-выхода3C0FCC,15 остальных
остановились на настоящем inherited entry с правильным A0. Ни его SQ frame,
ни результат общей геометрии не подставлялись. Смысловое имя поля6F8 пока
не установлено.

Шесть updates: каждый из трёх классов PC20→25 / PS215→20. Новых C++ классов
и полностью закрытых классов нет; прирост относится к знанию этих методов.
Отложены PS2 Pivot conversion/MOVZ/conditional-delay accumulator и Push SQRT;
продолжать их можно после отдельной квалификации исследовательского CPU.
