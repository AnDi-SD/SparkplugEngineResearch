# wxHUDPart: сбор кнопок, поиск и выбор

`wxHUDPart` имеет ID `0x7F2E3F1A`, регистрационную и физическую базу
[wxEntity](../reference/classes/wx-entity.md). Собственный PC конструктор
передаёт в базу слово Entity `+20=1`; стандартный factory `wxEntity` передаёт
`3`. Переносимая реализация использует общие `wxEntity`,
[wxButton](wx-button.md) и `spSubscriptionManager`.

## Данные и уведомления

PC объект имеет размер `0x148`. Конструктор обнуляет диапазон `+128..+146`:
границы pointer-vector, начальную и выбранную кнопки, два слова и три байта.
Allocator storage `+124` и выравнивание `+147` не записываются. Эти нативные
участки не выдаются за физическое размещение переносимого C++ объекта.

| PC поле | Ограниченный контракт |
| --- | --- |
| `+128/+12C/+130` | Начало, конец и предел массива заимствованных `wxButton*` |
| `+134` | Начальная кнопка для переключения состояния |
| `+138` | Последняя выбранная кнопка |
| `+13C` | Ключ сопоставления с собственным словом кнопки `+60` |
| `+140` | Слово, передаваемое внешнему HUD manager при регистрации |
| `+144/+145` | Два сохраняемых сырых байта |
| `+146` | Байт, предотвращающий повторную инициализацию |

Собственный `Notify` обрабатывает `0x2715` и `0x1C`, прочие коды игнорирует.
Для `0x2715` sender должен быть живым `wxButton`. При совпадении его слова
`+60` с ключом Part указатель добавляется в конец массива, если такого
указателя ещё нет. Сравнение ключей точное 32-битное, уникальность определяется
адресом кнопки. Порядок первых подходящих уведомлений сохраняется. Part
не приобретает ссылку и не удаляет кнопки.

Нативный производитель этого сообщения — собственный `wxButton.Notify(0x1C)`
при payload `1`. Он рассылает кадр
`[0x2715,0,0,3,button,0,0,0]` через SubscriptionManager. Ключ рассылки `3`
отделён от ключа Part в `+13C`. Переносимый consumer работает через общий
[broadcast helper](../../Sparkplug/Code/SparkBase/spBroadcastNotification.h)
и настоящий общий manager. Ветвь `wxButton.Notify(0x1C,payload=1)` использует
тот же helper и затем передаёт исходный кадр базовому обработчику кнопки;
остальные собственные режимы `wxButton` остаются открытыми.

При `0x1C` и ненулевом `+146` обработчик возвращается. Нулевое значение
вызывает нативный путь подписки на ключ `3` и регистрации во внешнем
`wxHUDManager`. Его полный startup не квалифицирован. Текущий исходник
сообщает об этой границе и сохраняет нулевой байт; успешная инициализация
не имитируется.

## Поиск и выбор

Поиск сравнивает action-строку `spButton` с запросом как точную C-строку.
Возвращается первое совпадение в порядке массива. Сравнение учитывает регистр;
пустой запрос может найти первую пустую строку. При отсутствии совпадения
возвращается null. Живые кнопки и корректные завершённые строки — предусловия;
null query отклоняется переносимой реализацией.

Выбор получает живую кнопку, которая может отсутствовать в массиве:

1. Если прежняя начальная кнопка существует и отличается от кандидата, ей
   вызывается собственный `SetState(0)`.
2. После возврата читается текущий индекс кандидата `+50`. Кандидат всегда
   записывается в выбранную кнопку `+138`. При индексе `1` начальная кнопка
   `+134` очищается, при остальных значениях становится кандидатом.
3. Текущей начальной кнопке, если она есть, вызывается `SetState(2)`.
4. Всем элементам массива по порядку вызывается собственное обновление выбора.

Получатель каждого виртуального вызова захватывается перед вызовом. Граница
массива читается после возврата. Изменение индекса кандидата во время первого
вызова влияет на решение второго шага. Замена текущего элемента массива после
начала его обновления не меняет уже захваченного получателя. Квалифицированы
живые фактические `wxButton`, стабильное хранилище массива и заимствованные
графы базовых Node. Перевыделение массива внутри callback, неизвестные overrides
и замена Entity-ссылки остаются открытыми.

## Копирование и очистка

Копирование разных объектов сначала выполняет ограниченный `wxEntity.Copy`.
Непустой массив назначения освобождается; затем указатели источника добавляются
в прежнем порядке. Они остаются заимствованными. Переносятся начальная кнопка,
ключ, байт `+145`, байт `+144` и слово `+140`. Выбранная кнопка `+138`, байт
инициализации `+146` и нативное выравнивание не копируются. Clone сохраняет
собственный тип и конструкторские значения пропущенных полей. Self-copy
отклоняется как отдельный неквалифицированный вход.

Собственное удаление освобождает хранилище массива до отписки от ключа `3`.
Переносимый код вызывает общий `spSubscriptionManager.UnsubscribeForAnalysis`
на явно предоставленном manager. Этот заимствованный контекст должен оставаться
текущим и жить дольше Part. После отписки отдельно разрешается внешний HUD
manager, затем повторно читается текущий ключ Part и передаётся вместе с
полученным handle в удаление. При неквалифицированном resolve исходник сообщает
границу; успешное удаление не имитируется. После квалифицированного вызова
следуют повторная очистка массива и базовый teardown.

Нативно квалифицирован собственный префикс очистки до ленивого создания
`wxHUDManager`: массив освобождён, отписка выполнена, заимствованные кнопки живы.
Полный destructor после внешней границы, rendering/camera startup HUD manager,
PS2 исполнение, сериализация и весь класс остаются открытыми. Физические адреса
allocator, стратегия роста `std::vector` и весь нативный heap не являются
контрактом переносимого контейнера.
