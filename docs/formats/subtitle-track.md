# Данные spSubtitleTrack

`spSubtitleTrack` читает последовательно непрерывный бинарный payload.
Структура потока одинакова в известных PC и PS2 readers. Все 32-битные слова
и float32 хранятся в little endian; version/header magic в этой операции нет.
Полное контейнерное окружение и расширение файла здесь не устанавливаются.

| Порядок | Содержимое |
| --- | --- |
| 1 | `uint32 recordCount` |
| 2 | `recordCount` записей по 16 байт |
| 3 | `uint32 blobByteCount` |
| 4 | `blobByteCount` непрозрачных байтов |
| 5 | `uint32 tableCount` |
| 6 | Для каждой таблицы: `uint32 entryCount`, затем `entryCount` пар по 8 байт |

16-байтная запись состоит из четырёх слов. PS2 reader читает слова 1 и 4
как uint32, слова 2 и 3 через float32 helper. В PC сохраняются те же четыре
байтовых представления. Роль этих значений в показе субтитров пока не установлена;
переносимый reader хранит исходные биты, включая IEEE payload.

Каждая 8-байтная пара таблицы содержит uint32 key и uint32 blobOffset. После
чтения оригинал заменяет offset указателем `blobBase + blobOffset`. Таблица
не сортируется, повторяющиеся keys сохраняются. Lookup выбранной таблицы
возвращает указатель из первой пары с равным key; отсутствие key возвращает null.
Точный алгоритм получения key из текста и смысл выбора таблицы не установлены.

Blob копируется без перекодирования. Lookup возвращает char pointer, но reader
не проверяет нулевые терминаторы и не определяет кодировку. Формат не требует
от reader удалять дополнительные байты после последней таблицы.

Переносимый reader дополнительно проверяет оставшиеся байты, размеры массивов,
положение blobOffset внутри blob и явный host бюджет. При ошибке не публикуется
частично загруженный объект; поток может уже продвинуться. Эти проверки и
атомарная публикация относятся к нашей обвязке: оригинал не проверяет возврат
каждого stream read и может оставить частично заполненные массивы.
