# Формат SMO / FFPS

SMO — little-endian контейнер сериализованного объектного графа Sparkplug. В одном файле могут находиться модели, меши, материалы, текстуры, узлы, skin, коллизии и вспомогательные объекты.

## Заголовок

FFPS-заголовок занимает `0x20` байт:

| Смещение | Тип | Смысл |
| --- | --- | --- |
| `0x00` | `char[4]` | `FFPS` |
| `0x04` | `UInt32` | Версия serializer, `0x26` |
| `0x08` | `UInt32` | Назначение точно не установлено; возможная метка экспорта/сеанса, не доказанная checksum |
| `0x0C` | `UInt32` | Объявленный размер файла |
| `0x10` | `UInt32` | Платформенная маска: общий `0x01`, PC `0x02`, PS2 `0x08` |
| `0x14` | `UInt32` | Абсолютное начало области данных, `DataStart` |
| `0x18` | `UInt32` | Размер области данных, `DataSize` |
| `0x1C` | `UInt32` | Число записей каталога, `ObjectCount` |

Нормальное соотношение: `DataStart + DataSize == FileSize == фактический размер файла`. PC принимает маску при `mask & 0x03`, PS2 — при `mask & 0x09`.

## Каталог

Каталог начинается по смещению `0x20`. Запись имеет переменную длину:

```text
UInt32 entryMarker
UInt16 nameByteCount
Byte[nameByteCount] имя с нулевым завершением
UInt32 typeHash
UInt32 logicalOffset
UInt32 serializedSize
```

После последней записи следует нулевой `UInt32`. Физическое смещение тела: `DataStart + logicalOffset`. Размер может включать вложенное поддерево; полностью вложенные интервалы допустимы. Расстояние до следующего logical offset не заменяет `serializedSize`.

## Объект и поля

Обычное тело начинается с `[UInt32 typeHash][char[4] SBOO]`, затем идут секции полей `spDataBlockSerializer`.

Первый байт поля: младшие пять бит задают type, старшие три — код размера payload. Если type равен `0x1F`, полный type находится в следующем байте.

| Код размера | Длина payload |
| --- | --- |
| `0` | 0 |
| `1` | 1 |
| `2` | 2 |
| `3` | 4 |
| `4` | 8 |
| `5` | Следующий `UInt8` |
| `6` | Следующий `UInt16` |
| `7` | Следующий `UInt32` |

Номер поля имеет смысл внутри serializer-секции соответствующего класса. Унаследованные секции не следует смешивать с полями производного объекта.

## Ссылки и идентичность

Relationship связывает объекты по ID и может содержать inline-сериализацию. Повторные ссылки должны сохранять идентичность одного объекта. Точный порядок создания, кэш и владение описаны в [ReadReference](../engine/resources/read-reference.md).

Проверка ожидаемого типа ссылки в нашем строгом decoder не означает, что оригинальная функция проверяет свой аргумент `expectedClassID`: в известном PC-пути этот аргумент игнорируется. Ограничения оригинального reader и безопасного инструмента нужно различать.

## Model, Skin и геометрия

`spModel` содержит секцию `spRenderable` с material/fog relationships и `AlphaSortEnable`/`Priority`, затем собственную секцию с mesh relationship и необязательным `ProjectionGroup`. PRS задаёт окружающий узел или static render object. `spSkin` добавляет палитру костей и inverse bind matrices.

В mesh data различаются сериализованный stride и runtime stride. Геометрия PC и PS2 не взаимозаменяема: PS2 имеет собственные DMA/VIF-данные, PC — свои платформенные и общие представления. Границы берутся из структуры объекта, а не поиском сигнатуры внутри файла.
