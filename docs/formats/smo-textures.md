# Текстуры внутри SMO

`spTextureData` различает источники и платформенные представления. Встроенное PC Direct3D BGRA32 — один из вариантов, а не универсальное устройство каждой текстуры.

## PC Direct3D BGRA32

Известный путь встроенных данных: поле 3 источника, поле 1 производной Direct3D-секции, поле 0 первого mip. В payload mip находятся:

| Смещение | Данные |
| --- | --- |
| `0` | `UInt8`, наличие native-данных |
| `1` | `UInt32`, ширина |
| `5` | `UInt32`, высота |
| `9` | `UInt32`, native format flags; `0` для рассматриваемого BGRA32 |
| `13` | `UInt8`, наличие пикселей |
| `14` | `UInt32`, ширина mip |
| `18` | `UInt32`, размер строки `width * 4` |
| `22` | `UInt32`, высота mip |
| `26` | BGRA, `width * height * 4` байт |

Размер обёртки поля зависит от кода размера. Последовательности вроде `0x32E3`/`0x43E3` включают заголовок поля и байты длины; они не являются отдельными форматами пикселей. Абсолютное смещение внутри всего объекта нельзя переносить на другую обёртку.

## Изменение длины

Изменение размеров изображения затрагивает данные mip, размеры enclosing fields, inline-объектов, записи FAT и общий размер файла. Одной замены пикселей недостаточно. Нетронутые ID и opaque fields должны сохраняться.

Native-путь может сохранять точные NPOT-размеры. Его не следует смешивать с отдельным cross-platform upload, где действуют другие правила нормализации. Незаписанные mip-уровни и явно присутствующая mip-цепочка также различаются.

## Другие представления

Существуют legacy cross-platform BGRA, дополнительные Direct3D mip-уровни, внешние источники и PS2 palette/32-bit формы. Полное преобразование PS2 swizzle здесь не описано. Наличие структурного чтения не означает доступности записи всех этих вариантов.
