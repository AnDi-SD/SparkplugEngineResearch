# PC и PlayStation 2

Статус: предварительные наблюдения. Текущий локальный каталог игры ранее изменялся, поэтому окончательные выводы требуют чистых образов обеих платформ.

## Что наблюдается сейчас

| Область | PC-корпус | Ресурсы `_ps2` | Уверенность |
|---|---|---|---|
| Контейнер | `FFPS`, little-endian каталог | также наблюдается `FFPS` | высокая для изученных файлов |
| Поле `0x10` | встречаются `1`, `2`, `3` | встречаются `8`, `9` | наблюдение, смысл неизвестен |
| Mesh marker | `E0`/`E1` декодируются для известных layouts | есть дополнительные `E1` preamble/boundary cases | подтверждена разница, структура не завершена |
| Vertex layout | serialized stride иногда меньше runtime stride | требуется отдельная выборка | частично подтверждено |
| Texture/material | известные варианты читает TextureTool | соответствие layouts ещё не сведено | открыто |

Сам факт одинаковой внешней сигнатуры не доказывает полностью одинаковый serializer или renderer path. Варианты следует выбирать по структуре и полям файла, а не только по имени `_ps2`.

## Текущие группы расхождений

На частично изменённом смешанном корпусе строгий mesh scan выделяет как минимум:

- 494 объекта с пока неизвестным PS2 `E1` preamble;
- 137 объектов с PS2 boundary variant;
- 45 объектов primitive type `2`, которые могут встречаться независимо от платформы;
- 680 signature mismatch/stale offset, вероятно связанные с изменениями части файлов.

Эти числа нужны как regression baseline, но не должны использоваться для оценки распространённости вариантов в оригинальной игре.

## План чистого сравнения

1. Снять SHA-256 manifest нетронутой PC-установки.
2. Отдельно зафиксировать текущую рабочую/модифицированную папку.
3. Получить manifest PS2-образа и описать способ извлечения без публикации ресурсов.
4. Запустить одну ревизию `SmoViewer.Inspect scan --json` на всех трёх наборах.
5. Сравнить header variants, class IDs, mesh markers, primitive types и diagnostic groups.
6. Выбрать минимальные воспроизводимые структуры и создать синтетические fixtures без игровых данных.

## Критерий подтверждения платформенного варианта

Ветка parser для PC/PS2 считается обоснованной, если одновременно выполнены условия:

- признак находится внутри файла и стабилен на нескольких независимых ресурсах;
- границы всех прочитанных блоков сходятся без signature scan;
- decode не ломает уже подтверждённый корпус другой платформы;
- различие отражено synthetic test;
- при необходимости runtime-поведение подтверждено игрой или executable analysis.

До этого новые случаи должны завершаться понятной диагностикой, а не попыткой автоматически угадать layout.
