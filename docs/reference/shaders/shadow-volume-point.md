# ShadowVolumePoint: вершины теневого объёма

[ShadowVolumePoint.hlsl](../../../Sparkplug/Shaders/PC/ShadowVolumePoint.hlsl)
описывает vertex shader `ShadowVolumePointVS` из внешнего PC-ресурса
`ShadowVolumePoint.vsh`, профиль `vs_1_1`. Программа выбирает исходный
или вытянутый относительно point light конец вершины теневого объёма.

## Вход, константы и выход

| Данные | Назначение |
| --- | --- |
| POSITION.xyz | Позиция вершины P |
| POSITION.w | Коэффициент выбора конца объёма |
| c0–c3, view_proj_matrix | Четыре вектора проекции |
| c4.xyz, LightPos | Положение источника L |
| c5.x, Range | Минимальное расстояние вытянутого конца от источника |
| Выход POSITION | Проекция выбранного конца |
| Выход COLOR0 | Постоянный RGBA (1,0,1,1) |

Пусть r — длина P−L. Вытянутый конец лежит на том же луче
на расстоянии max(r,Range) от L. Для w=0 выбирается этот конец,
для w=1 сохраняется исходная вершина. Другие значения w дают
линейную комбинацию; исходник не вводит отдельную boolean-проверку.
Точное выражение приведено в
[обзоре shader resources](../../engine/materials/shader-contract.md).

В финальной проекции перенос c3 прибавляется с коэффициентом единица.
Входной w уже использован как коэффициент выбора вершины и не служит
обычной однородной координатой матричного преобразования, как в
[Basic](basic.md). При совпадении P и L исходная последовательность
rsq/rcp не получает новой защитной ветви.

## Runtime и границы

У [Shadow manager](../../engine/rendering/scene-render-runtime.md#spshadowvolumemanager--spdxshadowvolumemanager)
подтверждён поиск `ShadowVolumePoint` и handles параметров
view_proj_matrix, LightPos и Range. Его lookup, создание программы,
построение непустой геометрии объёма и итоговая тень — разные этапы.

Постоянный COLOR0 не означает, что в игре обязательно видна пурпурная
поверхность: color write, depth/stencil и порядок проходов задаются caller.
Восстановленная формула не является готовым RT shadow adapter и не
подтверждает полный непустой shadow pass во всех сценах.
