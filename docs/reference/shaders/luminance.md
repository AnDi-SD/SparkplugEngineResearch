# Luminance: выделение ярких значений

[Luminance.hlsl](../../../Sparkplug/Shaders/PC/Luminance.hlsl) восстанавливает
pixel shader `LuminancePS` из внешнего PC-ресурса `Luminance.psh`.
Исходный профиль — `ps_1_1`. Программа использует одну выборку Image
из s0 по входному TEXCOORD0.

## Вход и результат

| Данные | Смысл |
| --- | --- |
| Image, s0 | Исходный RGBA |
| c0.xyz | Коэффициенты скалярной яркости |
| Выход COLOR0.rgb | Исходный RGB, умноженный на шестнадцатую степень яркости |
| Выход COLOR0.a | Alpha исходной выборки |

Сначала вычисляется dot между RGB выборки и c0.xyz. Четыре последовательных
возведения результата в квадрат дают степень 16. Это существенная часть
алгоритма: линейная модуляция яркостью, как в BlurLuminancePS,
дала бы другое изображение.

Финальная инструкция переноса alpha в исходном ASM выполняется совместно
с записью RGB. Она сохраняет alpha выборки; степень яркости на неё
не переносится. Компонента c0.w в dot не участвует.
Коэффициенты не объявляются фиксированными весами Rec.709 или иного
стандарта: их значения предоставляет вызывающий код.

## Runtime и ограничения

Соседняя [карточка Blur](blur.md) описывает четырёхвыборочный вариант
яркостной обработки. Общие границы исходных выражений и последующего
графического конвейера приведены в
[shader contract](../../engine/materials/shader-contract.md).

Конкретный target, порядок postprocess passes, фильтрация, формат цвета
и ограничения legacy pixel registers не определяются этой стадией.
Наличие файла и восстановленного выражения не устанавливает все игровые
условия его вызова и не квалифицирует соответствующий проход Remix.
