# BallisticPFX: частицы по времени

[BallisticPFX.hlsl](../../../Sparkplug/Shaders/PC/BallisticPFX.hlsl) восстанавливает
семантику внешнего `BallisticPFX.vsh`: vertex shader профиля `vs_1_1`
с entry point `BallisticVS`. Программа вычисляет движение частицы,
размер точки и цвет. Семантика NORMAL здесь обозначает скорость,
а не геометрическую нормаль.

## Данные стадии

| Вход или константа | Назначение |
| --- | --- |
| POSITION, float4 | Исходная позиция частицы |
| NORMAL.xyz | Начальная скорость |
| TEXCOORD.xy | Время рождения и время жизни |
| c0–c3 | Векторы view-projection |
| c4.xyz, c5.xyz | Начальное и конечное ускорение |
| c6, float4 | Позиция камеры для расчёта размера |
| c7 | Текущее время, loop, начальный и конечный размер |
| c8.x | Ширина framebuffer |
| c9, c10 | Начальный и конечный RGBA |
| Выходы POSITION, PSIZE, COLOR0 | Проекция перемещённой частицы, размер точки и цвет |

Константы исходной программы в c11 задают коэффициенты, включая
десятичное `0.166667f`. Это округлённое значение, а не точное 1/6.
Восстановление не должно заменять его иной константой интегрирования.

## Особенности вычисления

Возраст уменьшается на один lifetime только при достижении конца жизни
и loop не меньше 0.5. Повторного вычитания или modulo нет. Позиция содержит
линейный, квадратичный и кубический по времени вклады; знак последнего
зависит от разности начального и конечного ускорения.
Точные выражения приведены в
[контракте BallisticPFX](../../engine/effects/ballistic-shader.md).

Размер использует расстояние от исходной позиции, а не от уже перемещённой
частицы. Расстояние четырёхмерное: разность w также участвует.
Проекция перемещённой позиции, напротив, добавляет перенос как для w=1.
Маска размера включает обе границы нормированного возраста 0 и 1;
вне этого интервала движение и цвет продолжают вычисляться.
Цвет линейно интерполируется без добавленного ограничения возраста.

## Runtime и границы переноса

Формулы также представлены в общем аналитическом
[spBallisticShader.h](../../../Sparkplug/Analysis/PC/spBallisticShader.h).
Они отличаются от отдельного
[CPU-пути quads](../../engine/effects/ballistic-cpu-draw.md).
Повторная деформация уже подготовленных CPU-вершин меняет поведение.

Нулевые lifetime и расстояние не получают новой защитной ветви в описании
исходной программы. Ограничения аналитического интерфейса, точность GPU
rcp/rsq/MAD, квантование COLOR0 и растеризация точек — отдельные границы.
Наличие этой программы не подтверждает её использование в каждом игровом
кадре, целиком восстановленный класс эффекта или готовое представление
частиц в Remix.
