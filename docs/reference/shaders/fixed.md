# Fixed: Skin, свет и режимы цвета

[Fixed.hlsl](../../../Sparkplug/Shaders/PC/Fixed.hlsl) описывает vertex и pixel
стадии внешнего PC-шаблона `Fixed.rfx`. Восстановленные entry points —
`FixedVS` и `FixedPS`; исходные профили — `vs_1_1` и `ps_1_1`.
Это семейство специализаций, а не один неизменный VS bytecode.

## Специализация и входы

Менеджер строит shader key, добавляет параметры специализации и флаги
выходных TEXCOORD, затем компилирует текст шаблона. `BlendWeightCount`,
`ColorMode`, `LightCount`, `LightType`, `bUseSpecular` и `bHasUVTransform`
управляют выбором выражений. Они не должны автоматически считаться
оставшимися runtime-константами с одинаковыми регистрами во всех вариантах.
Связанный путь описан в
[генерации шейдера](../../engine/materials/shader-generation.md)
и [составлении исходника](../../engine/materials/shader-compile.md).

| Данные vertex stage | Назначение |
| --- | --- |
| POSITION, NORMAL | Позиция и нормаль до деформации |
| BLENDWEIGHT, BLENDINDICES | Сохранённые веса и индексы до четырёх влияний |
| BlendMatrices, 16 float4x3 | Палитра преобразования Skin |
| view_proj_matrix, VPTransform | Проекция rigid и деформированной ветвей |
| view_matrix | Позиция и нормаль для view-space освещения |
| AmbientCol, LightMatDiff, LightMatSpec | Уже подготовленные светоматериальные коэффициенты |
| LightPos, LightDir, LightAttenuation, LightInner/Outer | Параметры выбранных источников |
| MatDiffuse, MatSpecularPwr, ConstColor, COLOR0 | Материальные и вершинные входы режимов цвета |
| TEXCOORD0, UVTransform | Основа всех включённых UV-выходов и их матрицы |

Результат VS — clip position, COLOR0 и включённые TEXCOORD0–7.
Регистр каждого параметра зависит от скомпилированной специализации;
нужна её фактическая таблица констант, а не номера от соседнего варианта.
Смысл native uploads описан в
[shader constants](../../engine/materials/shader-constants.md).

## Алгоритм и особенности

При нулевом числе весов используется rigid projection. Ветви с одним–четырьмя
влияниями сохраняют взвешенную сумму позиции и нормали по палитре;
нормаль затем нормализуется. Порядок матриц и трактовка всех сохранённых
весов приведены в [контракте Skin](../../engine/animation/skin-deformation.md).
Подстановка обычной нормализации суммы весов меняет исходный результат.

Нулевая ветвь описывает сам шаблон. Автоматический
[PC shader manager](../../engine/materials/shader-manager-key.md)
для key с нулевым числом весов возвращает NULL до поиска и генерации.
Существование ветви в HLSL не означает её автоматического выбора менеджером.

Освещение зависит от типов и порядка выбранных источников. В частности,
не-specular point attenuation масштабирует весь накопленный RGB,
включая предыдущие вклады; spot не сводится к той же ветви с новым радиусом.
Некоторые направления получают нормализацией float4 до извлечения xyz.
Полные выражения, specular и численные особенности собраны в
[контракте Fixed](../../engine/materials/shader-contract.md#fixedrfx-значимые-правила).

ColorMode4 складывает свет и вершинный RGB, но берёт alpha из MatDiffuse.
ColorMode5 умножает свет на вершинный цвет и использует произведение alpha.
Поэтому эти режимы нельзя заменить одним универсальным albedo multiply.
Таблица остальных режимов находится в том же контракте.

Все включённые UV начинаются с TEXCOORD0. Перед своей UVTransform
третья компонента устанавливается в единицу; деления на результат z нет.
Исходные TEXCOORD1–7 не становятся независимыми источниками этих выходов.

FixedPS возвращает входной COLOR0 и сам не читает текстуры. Его наличие
не объясняет другие texture stages или материал конкретного draw.

## Связь с runtime и границы

Класс [spPCEffectTemplate](../classes/sp-pc-effect-template.md) связывает
RFX shader records с compiler boundary. Перенос в Remix должен отдельно
сохранить деформацию, текущие constants, материал, alpha и UV.
Ограниченный live ColorMode4 path не означает поддержку всех специализаций
Fixed, сцен и анимаций. Восстановленная стадия и её карточка также не
доказывают, что вся палитра или произвольный shader key допустимы в игре.
