# wxAudioEmitter

Игровой источник звуковых событий персонажа. Class ID `CCABEFEA`; регистрационная и физическая база — `wxEntity` (`796A1869`). [Код](../../../Winx/Code/wxAudioEmitter.cpp), [интерфейс](../../../Winx/Code/wxAudioEmitter.h) и [host](../../../Winx/Analysis/Host/wxAudioEmitterHost.h) разделяют восстановленную логику и отсутствующие подсистемы игры.

## Идентичность и состояние

| Свойство | PC | PS2 |
| --- | --- | --- |
| Размер | `194` | `1B0` |
| Constructor | `587A50` | `3CAC60` |
| Factory | `407B20` | `3E6950` |
| Vtable | `701B94` | `495530` |
| Обработчик тега | `586C60` | `3C7DE0` |
| Ресурс | `124` | `130` |
| Два byte-флага | `15C`, `15D` | `174`, `175` |
| Три копируемых слова | `180`…`188` | `190`…`198` |

Точные оболочки размера объекта находятся в [PC layout](../../../Winx/Analysis/PC/wxAudioEmitterAbi.h) и [PS2 layout](../../../Winx/Analysis/PS2/wxAudioEmitterAbi.h). Поля native-контейнеров оставлены непрозрачными. PC constructor вызывает `wxEntity(true)`, инициализирует ресурс нулём, создаёт контейнеры, обнуляет оба флага и три слова. PS2 подтверждает физический вызов `wxEntity` и указанные собственные записи. Конструктор и удаление контейнеров переданы host; переносимый класс не выдаётся за native ABI.

PC Copy `581E80` сначала копирует базу. При отказе базы собственных действий нет. После успеха отдельно копирует/освобождает owned resource получателя, переносит только byte `15D` и слова `180`…`188`, затем вызывает пустой hook `5B7A00` с class ID. Флаг `15C` и контейнеры не копируются этой функцией. Clone идёт через factory, регистрацию clone и Copy. Уничтожение `586E30` освобождает owned resource и собственные контейнеры перед базой. Семантика содержимого ресурса остаётся обязанностью host.

Обработчик уведомлений `587010` для code `1C` вызывает инициализацию `586FD0`, для `1E` — внешний обработчик `584690`. Code `2711` вызывает `585FF0(true)` только при ненулевом byte `15D`. Эти маршруты представлены в переносимом классе, тела зависимостей остаются host-вызовами.

## Выбор звука по тегу

Вход получает имя из `[message+1C]+10` и variant от контроллера анимации. Глобальное состояние игры трактуется как signed 32-bit. Поиск разрешён при `state<=37`, `41<=state<=49` или `state==70`. В остальных состояниях метод сразу возвращается. В разрешённой ветви ключ содержит имя, variant без изменения и константу `1000000`.

PC comparator `581840` сравнивает имена по unsigned bytes до завершающего нуля. При одинаковом имени `variant` сравнивается как signed integer, но `0` и `10` не упорядочиваются ни с каким другим variant. Третье слово ключа в comparator не используется. Это отношение нельзя бездумно заменить обычным `std::map` comparator: эквивалентность с `0`/`10` не транзитивна. Поэтому поиск по native-контейнеру выполняет host, а правило сравнения представлено отдельной функцией.

Если запись отсутствует, звук не вызывается. Если её тип равен `10`, передаётся первый элемент её набора специальному звуковому пути. Для остальных типов вычисляется `random % count`. При `count>1` совпадение с previous index заменяет индекс следующим с переходом в ноль; после этого previous index обновляется. При `count==1` random всё равно вызывается, но previous index остаётся прежним. Пустой набор в этой ветви нарушает предусловие оригинала: там деление на ноль, и восстановленный метод не добавляет придуманную обработку.

## Границы проверки

На оригинале выполнены PC/PS2 пробы маршрута из контроллера анимации и фильтра состояния до входа в lookup; PC constructor/clone/delete выполнены целиком. Последующие операции выбора записи, random, no-repeat и устройства восстановлены по статическому PC disassembly `586CEA`…`586DC9` и проверены узким C++ тестом; сквозная проверка с оригинальной звуковой системой пока отсутствует. PS2 parity этой части не объявляется. Остальные ветви большого обработчика уведомлений `587010` и создание/загрузка звуковых наборов остаются host-границей. `vfunc_0C` передаёт эти сообщения host и не имитирует неизвестные ветви.

Публичный контекст маршрута — [события анимации](../../game/characters/character-animation-events.md).
