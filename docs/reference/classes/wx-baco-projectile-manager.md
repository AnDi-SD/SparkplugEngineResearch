# `wxBacoProjectileManager`

`wxBacoProjectileManager` имеет Class ID `6F925DB7` и регистрационную базу
[`wxProjectileManager`](wx-projectile-manager.md) (`7DB63B02`), наследуемую от
`wxEntity`. Общая база частично восстановлена, но адаптер этого потомка ещё не
связан с её контрактом сцены и pool; переносимый класс использует
`spNamedObject` и реальную запись RTTI общей базы. Его исходники находятся
в [Winx/Code](../../../Winx/Code/wxBacoProjectileManager.cpp), сценовые
зависимости — в [host-интерфейсе](../../../Winx/Analysis/Host/wxBacoProjectileManagerHost.h).

| Контракт | PC | PS2 |
| --- | ---: | ---: |
| Размер | `1E4` | `200` |
| Vtable | `6F7D00` | `49ACA0` |
| Notify | `50B170` | `2FE9C0` |
| Setup | `50FB80` | `2FE8F0` |
| Update | `50F680` | `2FE890` |
| Fire по направлению | `50FA20` | `2FE3E0` |
| Fire в игрока | `50FAB0` | `2FE520` |

Разметка 32-битных объектов приведена отдельно для [PC](../../../Winx/Analysis/PC/wxBacoProjectileManagerAbi.h)
и [PS2](../../../Winx/Analysis/PS2/wxBacoProjectileManagerAbi.h). PC хранит два
указателя снарядов в `1D0/1D4`, неизвестное поле в `1D8` и два указателя сцены
в `1DC/1E0`. PS2 использует смещения `1E0/1E4`, `1E8`, `1EC/1F0`.
Назначение третьего указателя пока неизвестно. Исходный PC factory, пустой
clone и оба пути удаления уже прошли исполнение в оригинальной игре; PS2
конструктор и vtable проверены статически. Собственные активные ветви ниже
установлены разбором кода обеих платформ, но не полным игровым прогоном.

Уведомление `1C` вызывает Setup, `1E` — Update; остальные коды игнорируются.
Setup привязывает объект к сцене, находит два объекта эмиттера, создаёт ровно
два снаряда и затем вызывает настройку общей базы. Их поиск, создание и
настройка связанного `wxProjectile` оставлены в host-интерфейсе; эти операции
ещё не являются переносимой реализацией полного сценового контракта. Update
вызывает update каждого ненулевого снаряда в порядке слотов и возвращает true.

Fire по направлению сначала проверяет сцену, нормализует входной вектор,
ищет первый ненулевой снаряд с нулевым признаком активности и запускает его
из позиции первого эмиттера. Если оба заняты, выстрела нет. Fire в игрока
вычитает позицию первого эмиттера из позиции игрока, нормализует вектор,
заменяет вертикальную компоненту на `0.5`, нормализует повторно и передаёт
результат обычному Fire. Нормализация следует общему helper `41D2D0` на PC,
который обнуляет вектор длиной не более `0.001`. У снаряда активность и
запуск пока представлены через host-вызовы к оригинальным virtual methods.

Переносимая версия не копирует и не клонирует живой pool: проверен только
пустой native clone. Host должен жить дольше настроенного менеджера, поскольку
его destructor освобождает созданные снаряды через host. Повторный Setup,
ошибки выделения, базовый pool `wxProjectileManager`, полный scene lifecycle
и игровые эффекты попадания требуют отдельной сверки с оригиналом.
