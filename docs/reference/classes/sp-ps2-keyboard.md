# spPS2Keyboard

Зарегистрированный PS2-класс `0xA217BC14`, физическая и регистрационная
база — [spPS2InputDevice](sp-ps2-input-device.md). Factory `001F1650`
выделяет `0x50` байт, вызывает общий конструктор платформенной основы
и устанавливает primary `004915E0`, secondary `00491604` в `+14`.
Установленный префикс включает byte `+44=0`; bytes `+45..+4F` эта
ветвь не инициализирует. Размер переносимого C++-объекта отличается.

В поставленной PS2-версии физические запросы клавиатуры имеют постоянные
результаты. Boolean slots 1/2 и целочисленные slots 3/4 возвращают 0,
slot 5 ничего не делает, float slot 6 возвращает `+0.0`. Ready
`001F14E0` возвращает 1 независимо от byte `+44`. Initialize
`001F14F0` записывает туда 1 и также возвращает 1. Эти операции не
опрашивают аппаратуру; их постоянные ответы воспроизводят оригинал.

Логические команды проходят через общий сбор физических кодов
[spInputDevice](sp-input-device.md). Переносимый адаптер связывает
эти маршруты с подтверждёнными физическими запросами класса и хранит
заимствованные callbacks только в течение жизни клавиатуры.

Clone `001F1570` создаёт новую клавиатуру и использует общий физический
copy именованного объекта `00105DC0`. Копируется имя; активные пары,
рабочие коды и byte `+44` источника этим copy не переносятся. Поэтому
инициализированная клавиатура клонируется с byte `+44=0` и пустым
списком активных пар. Деструктор `001F1500` восстанавливает таблицы
класса и передаёт освобождение платформенной основе; собственного
аппаратного release в нём нет.

Группы привязок общего input-слоя пока не восстановлены. Полный native
startup менеджера и пути отказа allocator не закрыты переносимым factory.
