# wxAudioListener

Игровая сущность, которая связывает `wxEntity` с `spAudioListener`. Class ID `0982734A`; регистрационная и физическая база — `wxEntity` (`796A1869`). [Код](../../../Winx/Code/wxAudioListener.cpp), [интерфейс](../../../Winx/Code/wxAudioListener.h) и [host](../../../Winx/Analysis/Host/wxAudioListenerHost.h) отделяют подтверждённый порядок операций от ещё не восстановленных аудиоменеджеров.

## Раскладка и жизненный цикл

| Свойство | PC | PS2 |
| --- | --- | --- |
| Размер | `148` | `160` |
| Constructor | `587D80` | `3CEF70` |
| Factory | `407B80` | `3E6850` |
| Vtable | `701BE4` | `4954F0` |
| Ссылка на listener | `124` | `130` |
| Встроенный контейнер | `128` | `134` |
| Байт инициализации | `144` | `150` |

[PC layout](../../../Winx/Analysis/PC/wxAudioListenerAbi.h) и [PS2 layout](../../../Winx/Analysis/PS2/wxAudioListenerAbi.h) описывают native-оболочки. Конструктор обеих платформ вызывает `wxEntity(true)`, создаёт собственный контейнер, обнуляет флаг и получает ссылку на `spAudioListener`. PC удерживает ссылку счётчиком по `+8`; PS2 подтверждает тот же порядок. Переносимый объект хранит только смысловые поля; он не воспроизводит ABI контейнера и счётчика.

PC `Copy` (`587D40`) вызывает `wxEntity::Copy` (`4D9700`) и после успеха — регистрационный hook класса. Собственную ссылку, контейнер и флаг он не копирует. Clone создаёт новый экземпляр, регистрирует соответствие и вызывает этот `Copy`; потому clone получает собственную ссылку и остаётся неинициализированным. PC factory, RTTI и clone выполнялись на оригинале. Удаление clone в исследовательском прогоне остановилось в общей аудиозависимости `44FAA0` при отсутствующем контексте, поэтому полный нативный цикл не заявлен.

Деструктор PC `587E30` при нулевом global `765C00` вызывает последовательно `4217E0`, `48F0C0` и при ненулевой связи entity `40FB60`. Затем уничтожает контейнер, отпускает ссылку listener и вызывает базовый деструктор. Когда global ненулевой, первые три вызова пропускаются; очистка собственных ресурсов остаётся. Значение global и внутреннее поведение трёх вызовов пока не установлены. В коде они представлены отдельными обязательными host-операциями.

## Уведомление и инициализация

PC обработчик `587F60` реагирует только на код `1C` и вызывает `587EE0`. Тот проверяет байт `+144`: при ненулевом значении сразу возвращается. Иначе последовательно вызывает `410050` с entity `+24` и текущим объектом, `421A60` со ссылкой listener и менеджером `755274+1C`, затем `48FAD0` со ссылкой listener и менеджером `755268`; после этого записывает `1` в байт. PS2 `3CE4A0` подтверждает код `1C`, проверку флага `+150` и тот же порядок вызовов. Их точная семантика и владение глобальными менеджерами требуют исходного игрового контекста; host не заменяет их искусственной логикой.

Проверка `WinxAudioListenerTests` охватывает порядок вызовов, однократную инициализацию, clone/Copy, оба пути уничтожения и layout-контракты. Воспроизведение полного аудиоэффекта в игре пока не выполнено.
