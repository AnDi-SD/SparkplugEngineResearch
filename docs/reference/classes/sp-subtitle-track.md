# spSubtitleTrack

Класс владеет бинарными данными и таблицами поиска субтитров. Восстановлены
собственные операции чтения, поиска, очистки и жизненного цикла для корректных
входов PC. Общие исходники —
[spSubtitleTrack](../../../Sparkplug/Code/Sparkplug/spSubtitleTrack.h),
бинарная структура — [формат payload](../../formats/subtitle-track.md).

Class ID `0x0FD11616`, регистрационная и физическая база `spNamedObject`
(`0x44DE07FD`), далее `spBaseObject`. Класс присутствует на PC и PS2.
Названия API и полей переносимой реализации аналитические.

## Хранение и владение

Оригинальный объект занимает `0x30` байт на PC и PS2.

| Смещение | Содержимое |
| --- | --- |
| `+0x00` | Базовый `spNamedObject`, `0x14` байт |
| `+0x14` | Непрозрачный байт, исходно `0` |
| `+0x15` | Три неинициализируемых байта выравнивания |
| `+0x18` | Владеющий указатель на blob |
| `+0x1C` | Количество записей по 16 байт |
| `+0x20` | Владеющий указатель на записи |
| `+0x24` | Количество таблиц |
| `+0x28` | Индекс выбранной таблицы |
| `+0x2C` | Владеющий указатель на массив таблиц |

Все собственные указатели, counts и выбранный индекс изначально нулевые.
Каждая таблица содержит count и отдельный владеющий массив пар key/pointer.
Reader размещает записи, blob, массив таблиц и каждую таблицу отдельно.
Чтение сохраняет ранее установленные выбранный индекс и байт `+0x14`.

Lookup линейно просматривает выбранную таблицу и возвращает первый совпавший
key, не обращаясь к 16-байтным записям. Возвращённый char pointer заимствован
из blob и действует до очистки/разрушения объекта.

Clear освобождает blob, записи, каждый массив пар и массив таблиц. Затем
обнуляет шесть собственных слов `+0x18..+0x2C` и байт `+0x14`; имя остаётся.
Деструктор вызывает Clear, затем разрушает `spNamedObject`.

Clone создаёт новый пустой объект и вызывает унаследованный NamedCopy.
Копируется имя; собственные массивы, выбранный индекс и байт не копируются.

## Переносимый контракт и границы

`LoadForAnalysis` использует общую реализацию `spStream`. Владение native
массивами выражено через vector; ссылки в таблицах хранят blob offsets и
преобразуются в указатель при Lookup. Проверки размеров, offsets, конечного
host бюджета и атомарная публикация относятся к нашему адаптеру.
Стандартный предел оставшейся части входа — 8 МиБ; метаданные множества
пустых таблиц могут занимать до шести байтов host памяти на байт такого входа.

После успешного Load повторное чтение разрешается после Clear. Этот host
протокол не объявляется оригинальной проверкой: native reader при повторном
вызове без Clear перезаписывает указатели, не освобождая старые массивы.
Переносимый Lookup возвращает null для отсутствующей/неверно выбранной таблицы;
оригинал требует корректного индекса и графа указателей от caller.

Показ текста, связь 16-байтных записей со временем, управление выбором таблицы,
смысл байта `+0x14` и кодировка blob остаются открытыми. У PS2 отдельно
квалифицируется integer lookup на явно заданных уже загруженных таблицах;
полное исполнение PS2 reader и всего игрового класса не утверждается.
В этих PS2 проверках аргумент key имеет каноническое знаковое расширение
32-битного слова до регистра: native `LW` так же расширяет key таблицы перед
сравнением. Для произвольного ненулевого старшего регистра совпадение не обещается.
