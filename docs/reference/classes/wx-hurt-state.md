# wxHurtState

`wxHurtState` физически наследует [`wxCharacterState`](wx-character-state.md).
Class ID — `0x37C025BF`, selector — `10`. Нативный объект PC и PS2 имеет размер
`0x40`: после базовых `0x3C` байт расположен собственный байт `+0x3C`, начально
нулевой, и три байта выравнивания. Значение байта используется входом; исходное
имя и более широкое назначение пока неизвестны. Переносимый C++ объект не
имитирует нативный ABI.

Вход захватывает контроллер из PC `owner +0x124 → +0x130` либо PS2
`owner +0x130 → +0x13C`. Вариант в младших четырёх битах request key выбирает
первое преобразование:

| Вариант | Преобразование key |
| --- | --- |
| `1`, `3`, `4`, `6`, `7` | `key & 0xF07FFF8F` |
| `5` | `key & 0xF07FFFFF` |
| `8` | `key & 0xFFFFFFF0` |
| Остальные | Проверки собственного байта, controller `+0x60` и float `+4` |

Для остальных вариантов ненулевые байты state `+0x3C` и controller `+0x60`
вместе с `(key & 0x180000) == 0` выбирают
`(key & 0xF17FFFDF) | 0x1000050`. Иначе используется controller float `+4`:

| Сравнение | Преобразование key |
| --- | --- |
| Значение `< 0.2f` | `key & 0xF07FFF8F` |
| Иначе значение `< 0.5f` | `(key & 0xF07FFFDF) | 0x50` |
| Иначе | `(key & 0xF0FFFFDF) | 0x800050` |

PC повторно читает float для второго сравнения; PS2 сохраняет первое значение
в F1. Сравнения упорядоченные: нечисловой PC вход проходит последнюю ветвь.
Поведение общего EE FPU для нечисловых и денормализованных значений этим
переносимым профилем не заявлено.

После выбранной ветви вход всегда формирует `(key & 0xFF98807F) | 0x8000`,
ищет анимацию и запускает её с `mode=false`, `interrupt=true`. Completion
records для найденного handle сбрасываются; предикат владельца выбирает fade
selector `0` либо `2`. Нулевой или прежний handle тоже запускается. Старый
pending перед этим не освобождается; новый записывается после consumer callback.
Виртуальный update обнуляет слово `+4` прямого контроллера действий владельца,
PC `owner +0x12C`, PS2 `owner +0x138`. Это отдельный путь от контроллера,
использованного при выборе ключа.

Permission `0x34` возвращает `true` без consumer для нулевого pending; иначе
вызывает consuming completion query. Permission `0x38` возвращает числовой
результат `0` для кодов `0`, `19..24`, `29`, `30`, а также для кода `4`, если
поле режима PC `owner +0x124 → +0x14C` / PS2 `owner +0x130 → +0x158` равно `4`.
В остальных случаях результат `1`. Поле режима читается перед выбором кода.

Остальные transition/event/reset slots наследуются от базы. Copy пустой и не
изменяет собственный байт. Clone создаёт объект с нулевым байтом и начальной
базой; базовый Reset сохраняет собственный байт. Необходимые foreign consumer и
owner службы передаются через явный host. Отсутствие binding вызывает ошибку
нашего адаптера, без предполагаемого успешного результата.
