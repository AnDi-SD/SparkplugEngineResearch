# spTransformConstEval

Класс преобразует входящие position, rotation и scale. Реализация PC и
аналитический API находятся в [общих исходниках](../../../Sparkplug/Code/Sparkplug/spTransformConstEval.h).
Наличие компонента не означает замыкания всего игрового исполнения.

Class ID — `0x68BCC047`, регистрационная и физическая база — `spTransformEval`
(`0x87B0E260`), далее `spEvaluator` и `spBaseObject`. Класс зарегистрирован на
PC и PS2; исходные названия методов и заголовков не установлены.

## Хранение и владение

Оригинальный объект занимает `0x68` байт на обеих платформах.

| Смещение | Содержимое | Начальное значение |
| --- | --- | --- |
| `+0x00` | Базовый префикс `0x10` байт | По конструктору базы |
| `+0x10` | Вектор скорости position | `(0,0,0)` |
| `+0x1C` | Ось rotation | `(0,0,1)` |
| `+0x28` | Угол rotation | `0` |
| `+0x2C` | Встроенный `spFunctionEval`, `0x38` байт | По его конструктору |
| `+0x60` | Поле type этого же `spFunctionEval` | `0` |
| `+0x64` | Байт включения position | `0` |
| `+0x65` | Байт включения rotation | `0` |
| `+0x66` | Два байта выравнивания | Не записываются |

Поле `+0x60` не является отдельным флагом scale: это смещение `+0x34` внутри
встроенного scalar evaluator. Его нулевой type отключает scale, любой ненулевой
type вызывает scalar sampling. Дополнительного владеющего указателя на evaluator
нет. Деструктор разрушает встроенный evaluator, затем базовую часть.

Clone создаёт новый объект и вызывает у источника унаследованный Copy. Собственные
векторы, угол, scalar payload и флаги остаются фабричными значениями.

## Операция PC

Виртуальная операция принимает float time, три адреса входящих и исходящих
PRS и три адреса байтов validity. Она обрабатывает position, rotation, scale
именно в этом порядке. Ненулевые байты включения нормализуются в выходном
validity до `1`; отключённый канал получает validity `0`, его payload сохраняется.

Position вычисляется как входящее значение плюс `time × velocity`. В PC
промежуточное произведение X сохраняется на x87 до прибавления position;
произведения Y и Z сначала записываются во float32. При отмене близких значений
это даёт разные результаты даже для одинаковых компонентов.

Rotation использует quaternion `(axis × sin(angle/2), cos(angle/2))` и умножает
его слева на входящий quaternion. Время на угол не влияет, нормализация оси
и результата не добавляется.

Scale вызывает встроенный scalar evaluator с time и записывает его результат
во все три компонента, заменяя входящий scale. Время встроенного evaluator
может измениться согласно его type; другие поля const evaluator операция не
переписывает.

## Платформы и аналитические границы

`EvaluateInPlaceForAnalysis` сохраняет контракт входящих PRS. Удобный
`EvaluateForAnalysis` задаёт входящий position `(0,0,0)`, identity quaternion и
scale `(1,1,1)`; это явно выбранные начальные значения переносимого API.
Проверка конечных чисел перед изменением — дополнительная защита host.

PC translation моделирует указанные x87 float stores и default round-to-nearest.
Для rotation используется общий компонент с host sin/cos вместо x87 FSIN/FCOS;
соответствие ограничено квалифицированными конечными входами. Полное совпадение
для всех углов, иных режимов округления, NaN/Inf и exception state не утверждается.
Scalar evaluator использует уже восстановленный общий `spFunctionEval`.

У PS2 подтверждены собственные поля, порядок каналов и передача параметров.
Translation выполняет float32 умножение каждого компонента, а rotation содержит
операции EE COP1 accumulator. Переносимая реализация полного PS2 arithmetic
для этого класса пока не предоставляется; PC формулы не объявляются точной
заменой PS2.
