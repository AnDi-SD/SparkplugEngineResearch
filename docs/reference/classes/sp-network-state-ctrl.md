# `spNetworkStateCtrl`

PC-контроллер очереди событий и переходов сетевого состояния. Class ID —
`0x487634AB`, регистрационная и физическая объектная база — `spBaseObject`
(`0x415352A1`). В известном каталоге PS2 зарегистрированного аналога нет;
поведение PC не приписывается PS2.

Общая реализация — [spNetworkStateCtrl.h](../../../Sparkplug/Code/Sparkplug/spNetworkStateCtrl.h)
и [spNetworkStateCtrl.cpp](../../../Sparkplug/Code/Sparkplug/spNetworkStateCtrl.cpp).
[PC ABI](../../../Sparkplug/Analysis/PC/spNetworkStateCtrlAbi.h) отделён от
переносимого C++ layout. Путь исходного файла, объявления и исходные имена
операций неизвестны; `ForAnalysis` обозначает наши имена.

## Поля и владение

PC-объект занимает `0x34` (52 байта). Таблица содержит семь объектных слотов:
удаление, уведомление, Clone, Copy, RTTI getter и два запроса типа. Операции
очереди и переходов вызываются отдельно от этой таблицы.

| PC offset | Поле | Constructor |
| --- | --- | --- |
| `00–0F` | объектная база | инициализация `spBaseObject`, padding не обнуляется |
| `10` | собственный объект critical section | новое выделение размером 28 байт |
| `14` | byte признака перехода | `0` |
| `15–17` | padding | не записывается |
| `18`, `1C` | целевое и предыдущее состояния | `0xFFFFFFFF`, `0xFFFFFFFF` |
| `20` | текущее состояние | `0` |
| `24` | служебное слово allocator списка | не записывается |
| `28` | собственный sentinel двусвязного списка | новый пустой список |
| `2C` | число событий | `0` |
| `30` | результат перехода | `0` |

Constructor инициализирует базу, поля и список, затем создаёт critical section.
Destructor сначала непосредственно освобождает storage critical section,
затем узлы очереди и sentinel, затем объектную базу. Виртуальный destructor
critical section и `DeleteCriticalSection` при этом не вызываются. Хранимые
события — значения `uint32`, собственных игровых объектов в узлах нет.

Уведомление — унаследованный no-op. Copy возвращает true без переноса полей
или событий. Clone создаёт свежий экземпляр через текущую factory-среду,
регистрирует пару и вызывает виртуальный Copy источника. Источник сохраняет
своё состояние и очередь; клон имеет отдельный пустой список и отдельную
critical section. При отказе виртуального Copy созданный клон удаляется.

## Таблица переходов

Evaluate читает текущее состояние. Подтверждённая таблица использует числовые
значения ниже; исходные имена enum неизвестны.

| Текущее состояние | Событие | Цель | Результат `30` |
| --- | --- | --- | --- |
| `0` | `4` | `1` | `0` |
| `1` | `5` | `2` | `0` |
| `1` | `6` | `4` | `3` |
| `1`, `2`, `3` | `8` | `4` | `4` |
| `2` | `7` | `3` | `0` |

Каждый принятый переход записывает прежнее **текущее** состояние в `1C`,
цель в `18`, byte `14 = 1` и результат в `30`. Сам Evaluate не записывает
текущее состояние `20`. Значения `3` и `4` результата не объявляются
логическими true/false и не получают неподтверждённых имён ошибок.

Событие `0` в состояниях `1`, `2`, `3` выполняет действия соответствующего
состояния без перехода. В состоянии `0` оно ничего не делает. Состояние `4`
и значения вне `0–3` не принимают событий этой таблицы.

При непринятом событии Evaluate сохраняет **все** поля перехода, включая
byte `14` и результат `30`. При событии `0` они также сохраняются. Это
наблюдаемая особенность игры: признаку перехода нельзя приписывать автоматический
сброс после обработки события.

## Действия состояния

Каждое действие отдельно разрешает текущий `spNetworkManager`, включая lazy
создание при пустом global. Используется текущий manager, который может
отличаться от объекта, ранее создавшего контроллер.

| Состояние | Действия в порядке вызовов |
| --- | --- |
| `1` | операция manager `004513A0` — начало соединения; возвращаемое значение игнорируется |
| `2` | операция manager `00450B70`, затем повторное разрешение manager и операция `004516F0(1)` |
| `3` | операция manager `00450B60` — обновление timer |
| прочие | отсутствуют |

Исходные имена двух операций состояния `2` неизвестны. Они оставлены
отдельными foreign-вызовами с адресами, без подмены предполагаемой семантикой.
Если первый вызов заменяет текущий global manager, второй использует уже
новый объект.

## Немедленная обработка и очередь

Request входит в critical section. При нулевом byte второго аргумента
добавляет событие в хвост списка и выходит из critical section. При любом
ненулевом byte выполняет Immediate **под той же critical section**, затем
выходит. Возвращаемый регистр ветви добавления содержит incidental указатель;
общий bool-результат Request не установлен.

Immediate выполняет Evaluate. Если результат `30` ненулевой, возвращает его,
**не записывая** текущее состояние. При нулевом результате и ненулевом byte
`14` записывает цель `18` в текущее состояние `20` и выполняет действия цели.
Затем возвращает текущее значение результата `30`; чужое действие может
повторно вызвать контроллер и изменить его до возврата.

Pump входит в critical section, при пустой очереди выходит и завершает
работу. Иначе снимает ровно **одно** событие с начала списка, освобождает
узел и выходит из critical section. Затем выполняет Evaluate. При ненулевом
byte `14` записывает цель в текущее состояние и выполняет её действия,
**включая случай ненулевого результата `30`**. Возвращаемый регистр Pump не
объявляется bool-результатом.

Эти различия сохраняются. Например, событие `8` в состоянии `1` при Immediate
оставляет текущее состояние `1`, цель `4` и результат `4`. То же событие через
Pump записывает текущее состояние `4`. После обычного принятого перехода
неизвестное событие повторяет действия сохранённой цели, поскольку byte `14`
остаётся ненулевым. Событие `0` при таком состоянии может вызвать действия
дважды: внутри Evaluate и при последующей обработке сохранённого признака.

## Граница общего компонента

[spNetworkStateCtrlHost](../../../Sparkplug/Analysis/Host/spNetworkStateCtrlHost.h)
предоставляет ОС-lock, освобождение его storage, текущий manager и его чужие
операции. Это наш адаптер; состояние, переходы, очередь и порядок действий
находятся в общем восстановленном классе. Factory и Clone требуют host.
Существующий объект сохраняет своего host при замене factory-среды;
Clone использует новую среду.

Переносимая защита отвергает отсутствие host или обязательной critical section.
RAII освобождает portable lock также при исключении чужого host; это наша
защита, а не установленный exception rollback оригинала. Конкуренция потоков,
настоящий сетевой backend и полный игровой цикл этой реализацией не доказаны.

[SparkplugNetworkStateCtrlTests](../../../Sparkplug/Tests/spNetworkStateCtrlTests.cpp)
проверяет жизненный цикл, RTTI, Copy/Clone, очередь, таблицу переходов,
сохранение признака и результата, различие Immediate/Pump, повторное разрешение
manager, повторный вход из чужого действия и владение host.
