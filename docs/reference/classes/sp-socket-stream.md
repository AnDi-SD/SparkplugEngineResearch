# spSocketStream

PC-поток поверх сетевого объекта. Общие исходники —
[spSocketStream](../../../Sparkplug/Code/SparkBase/spSocketStream.h).
Реконструкция содержит собственные операции и требует явного
[сетевого host](../../../Sparkplug/Analysis/Host/spSocketStreamHost.h).
Работа с ОС и действительным сокетом принадлежит адаптеру.

## Идентичность и данные

Class ID `1ED8677D`, физическая база `spStream`, native размер `30` hex.
PS2-регистрация в известных образах отсутствует.

| Смещение PC | Содержимое | Конструктор |
| --- | --- | --- |
| `1C` | owned сетевой объект с двумя интерфейсами | новый `spDXNetwork` |
| `20` | тип сокета | `1` |
| `24` | адрес | `FFFFFFFF` |
| `28` | слово порта | `0000FFFF` |
| `2C` | byte blocking | `0` |

Padding `2D..2F` не инициализируется. При замене сетевого объекта порт
копируется как zero-extended uint16 в слово `28`; blocking сохраняется.
Portable layout и ownership не являются исходным x86 ABI.

## Виртуальные операции

`Open(name)` возвращает false. `Open(mode,name)` игнорирует имя и сначала
открывает сетевой объект с типом из `20`. Mode `1` вызывает bind, затем listen
только при типе `1`. Mode `2` вызывает connect. Другой mode возвращает false
после открытия сетевого объекта. После успешной выбранной ветви передаётся
raw blocking byte. Каждый отказ немедленно возвращает false; закрытия или
отката предшествующих операций нет.

`Close` передаётся сетевому объекту. `WriteData` вызывает send и возвращает
false только для результата `-1`; ноль, короткая отправка и другое отрицательное
значение проходят как успех. `ReadData` и stream-to-stream virtual slot
возвращают false. `Seek`, запрос позиции и запрос размера возвращают true,
не меняя объект и выходной параметр. `GetBuffer` возвращает null.

## Невиртуальные операции

`ReceiveStreamForAnalysis` получает по 500 байт и вызывает `WriteData`
целевого потока для каждого результата, кроме `-1`, включая ноль.
Результат ровно 500 продолжает цикл; короткий результат завершает его успешно.
При отказе записи или приёма возвращается false. Уже записанные данные
остаются в целевом потоке. Формат заголовка сетевого пакета здесь не добавляется.

`SendStreamForAnalysis` вызывает `GetSize`, затем `GetBuffer` у source и send
сетевого объекта. Статус `GetSize` игнорируется; возвращается исходный integer
результат send. Если source не записал размер, native использует неизвестное
слово стека. Portable API даёт этому слову явный аналитический seed.

Замена owned сетевого объекта удаляет старый через его secondary interface,
затем переносит тип, адрес и порт нового. Sentinel ошибки не заменяет старый
объект: создаётся и отправляется ошибка с аргументами `0,1,9`, файлом
`spSocketStream.cpp` и строкой `51`.

Accept сначала вызывает сетевой accept. Null даёт null без создания потока.
Ненулевой результат создаёт новый поток и вызывает замену его сетевого объекта.
Результат замены игнорируется. Поэтому sentinel ошибки возвращает ненулевой
новый поток с его исходным сетевым объектом после сообщения об ошибке.

## Копирование, удаление и границы

Clone создаёт новый поток и новый сетевой объект, регистрирует пару и вызывает
унаследованный Copy. Copy переносит только данные `spNamedObject`; собственные
поля, logical origin и diagnostic stream name не копируются. Конструктор,
клонирование, ошибка замены и принятие соединения сохраняют указанный порядок
выделения и удаления. Деструктор удаляет сетевой объект перед базой без `Close`.

Наши проверки — `SparkplugSocketStreamTests`. Собственные операции используют
общую реализацию `spMemoryStream` и явные внешние сетевые службы.
Portable защитные ошибки для null factory/adoption и приёма вне диапазона
`0..500` не выдаются за поведение оригинала. Изменение времени жизни сетевого
объекта во время `GetBuffer`, произвольные отрицательные размеры приёма,
реальный сетевой обмен и многопоточное взаимодействие остаются открытыми.
