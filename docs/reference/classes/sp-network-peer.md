# `spNetworkPeer`

PC-объект пары TCP/UDP-потоков и общего буфера отправки пакетов.
Class ID — `0x18B4576B`, регистрационная база — `spBaseObject`
(`0x415352A1`). В известном каталоге PS2 соответствующей регистрации нет;
PC-поведение не переносится на PS2.

Общая реализация — [spNetworkPeer.h](../../../Sparkplug/Code/Sparkplug/spNetworkPeer.h)
и [spNetworkPeer.cpp](../../../Sparkplug/Code/Sparkplug/spNetworkPeer.cpp),
точный PC layout — [spNetworkPeerAbi.h](../../../Sparkplug/Analysis/PC/spNetworkPeerAbi.h).
Путь исходного заголовка, C++-объявления и имена операций не установлены;
`ForAnalysis` обозначает наши названия. Переносимый C++ layout отличается от PC.

## Поля и владение

Объект PC занимает `0x24` (36 байт). Первые семь слотов — объектные операции;
собственные Open, Close, отправка и принятие TCP-потока вызываются отдельно.

| PC offset | Поле | Начальное состояние |
| --- | --- | --- |
| `00–0F` | база объекта | общая инициализация `spBaseObject` |
| `10` | uint16 ID | `BAD0` |
| `12` | byte, устанавливаемый при принятии TCP-потока | `0` |
| `13` | byte готовности, записываемый Server Ready | `0` |
| `14` | собственный TCP `spSocketStream` | новый поток, type `1` |
| `18` | собственный UDP `spSocketStream` | новый поток, type `0` |
| `1C` | uint32 времени, записываемый извне | `0` |
| `20` | собственный `spMemoryStream` | новый поток, Open с именем `packet buffer` |

Constructor создаёт TCP, затем UDP, затем memory stream. Значения endpoint и
blocking принадлежат общему [spSocketStream](sp-socket-stream.md); Peer при
создании меняет только type. Настройка адреса/порта и запись ID/времени
являются внешними producer-операциями, их исходные имена не восстановлены.
Server Ready записывает `0` или `1` в byte `13`; переносимая явная точка
этой записи — `SetReadyByteForAnalysis`. Это название нашего producer API,
а не найденное объявление исходного метода Peer.

Destructor вызывает Close TCP и UDP, игнорирует результаты, удаляет TCP и
UDP в этом порядке, затем закрывает и удаляет memory stream, после чего
разрушает базу. Собственный Close также вызывает оба Close и всегда
возвращает true. Он не сбрасывает ID, byte `12`, время или буфер.

Copy — унаследованная успешная операция без копирования данных. Clone создаёт
свежий Peer через текущую factory-среду, регистрирует пару и вызывает Copy
источника. Клон получает свои потоки, начальные ID/bytes/время и пустой буфер;
соединения и данные источника не копируются. При отказе виртуального Copy
клон удаляется. Уведомление объекта — унаследованный no-op.

## Открытие и принятие TCP-потока

`OpenForAnalysis(tcpOnly)` вызывает `Open(2, null)` TCP-потока. При успехе и
нулевом raw byte `tcpOnly` открывает таким же способом UDP. Любое ненулевое
значение, включая `255`, пропускает UDP. Отказ завершает операцию без отката
уже выполненных действий. Он разрешает текущий NetworkManager и его debug;
при наличии debug пишет `Opening connections failed`, категория `Network Peer`,
уровень `0`. Результат — результат последнего выполненного Open.

`AdoptTcpForAnalysis(stream, udpPort)` принимает владение TCP-потоком:

1. Удаляет прежний TCP-поток **без собственного Close**.
2. Сохраняет новый указатель и записывает byte `12 = 1`.
3. Копирует адрес нового TCP-потока в UDP-поток; UDP-порт получает
   zero-extended переданное uint16. Тип и blocking UDP сохраняются.
4. Вызывает UDP `Open(2, null)` и возвращает его результат.

Отказ открытия UDP сохраняет заменённый TCP, byte `12` и новый UDP endpoint.
Нулевой входной указатель находится за пределами валидного native-контракта;
переносимая версия отвергает его явно.

## Отправка существующего пакета

`SendPacketForAnalysis(packet, usePeerDestination)` сначала проверяет raw byte
подключения сетевого объекта **TCP-потока**, в том числе для UDP-пакета.
При нуле разрешает текущий debug, при наличии пишет `Failed: no connection`
с категорией `Network Peer`, уровнем `0`, и возвращает `-1`. Пакет и буфер
до этого выхода не меняются.

При подключённом TCP:

1. Ненулевой `usePeerDestination` записывает ID Peer в `packet.Destination`.
2. MemoryStream Reset обнуляет логический размер и позицию, сохраняя capacity.
3. Вызывается общий [NetworkPacket Write](sp-network-packet.md); его
   логический результат игнорируется.
4. Выполняется GetSize с игнорируемым результатом.
5. Ненулевой raw `UseTcp` выбирает TCP, нулевой — UDP; общий SocketStream
   SendStream передаёт буфер. Возвращается его исходный signed integer.

Нулевой результат, короткая передача и отрицательные результаты сохраняются.
Peer не дописывает оставшийся хвост и не превращает частичную отправку в
полную. Заголовок передаётся общим сериализатором, raw `UseTcp = 255`
сохраняется в wire bytes и выбирает TCP.

## Создание и отправка пакета

`SendForAnalysis(packetSource, type, data, size, tcp, useBroadcastDestination,
field1, field2)` создаёт свежий пакет, заполняет его общей операцией
[Packet Fill](sp-network-packet.md) и вызывает SendPacket
с нулевым `usePeerDestination`, затем удаляет временный пакет. Порядок native
аргументов сохраняется: флаг находится **перед** двумя uint32-полями.
Bool результата Fill оригинальный caller игнорирует.

| Поле пакета | Значение |
| --- | --- |
| `Source` | первый uint16 аргумент `packetSource` |
| `Destination` | ID Peer при нулевом флаге; `FFFF` при ненулевом |
| `PacketType` | переданный uint16 |
| `UseTcp` | переданный raw byte |
| `PacketDataField1`, `PacketDataField2` | последние два uint32 аргумента |
| `Size`, `Data` | переданный размер и данные |

Расположение Source/Destination установлено по фактическим wire bytes:
при первом аргументе `ABCD` и ID Peer `1234` первые четыре байта равны
`CD AB 34 12`. При ненулевом флаге — `CD AB FF FF`. Это поведение не
заменяется предполагаемым смыслом аргумента «адресат» в вызывающем коде.

## Граница компонента

[spNetworkPeerHost](../../../Sparkplug/Analysis/Host/spNetworkPeerHost.h)
создаёт свежие SocketStreams и предоставляет разрешение текущего debug и
журнал. Packet, MemoryStream и SocketStream используются из общих
восстановленных исходников. Сетевые операции ОС предоставляет их собственная
внешняя служба. Существующий Peer сохраняет своего host при замене factory-среды;
Clone использует текущую среду.

`SparkplugNetworkPeerTests` проверяет состояния, порядок операций, точные bytes
отправки, обе ветви транспорта, принятие TCP и удаление. Сравнение с оригиналом
использует явные ответы чужого сетевого интерфейса; исходные собственные методы
Peer и общие native Packet/MemoryStream/SocketStream выполняются.

Работа настоящих сокетов, полная цепочка Manager/Server/DGE, конкуренция
потоков, неполные TCP-записи и rollback исключений не считаются закрытыми.
При размере больше `256` native Fill уже записывает заголовок, сообщает
ошибку и возвращает false, но Peer продолжает SendPacket. Последующий Write
может читать за границей native allocation. Portable Peer сохраняет явное
исключение для этого диапазона до вызова Fill; эта защита не считается
эквивалентным исполнением unsafe native ветви. Исходные ограничения размеров
у более высоких callers остаются отдельной задачей. Отказ native factory при
нехватке памяти и ошибка уничтожения чужой службы не моделируются успешной
пустой операцией.
