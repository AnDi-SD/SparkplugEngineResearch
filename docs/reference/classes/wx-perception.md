# `wxPerception`: поиск цели и ограниченный Copy

`wxPerception` (`3A3277D4`) зарегистрирован с базой `spBaseObject` и
физически строится через неё на PC и PS2. Размер native объекта — `7C`
байт. Восстановленная часть находится в [общем исходнике](../../../Winx/Code/wxPerception.cpp);
платформенные layouts отделены в [PC ABI](../../../Winx/Analysis/PC/wxPerceptionAbi.h)
и [PS2 ABI](../../../Winx/Analysis/PS2/wxPerceptionAbi.h).

## Поиск ближайшего объекта

PC `4F1910` и PS2 `36EBC0` читают owner по `+10`, затем его позицию через
`owner+24 → entity+24 → Node+20`. Если owner отсутствует, возвращается null.
Пустой список также даёт null; позиция owner читается до проверки списка.

Цели обходятся в порядке списка. Позиция каждой цели читается через ту же
цепочку и записывается в `+30/+34/+38` перед сравнением расстояния.
Минимальное квадратное расстояние выбирается по `<=`, поэтому при равенстве
побеждает последняя цель. После обхода в этих трёх полях остаётся позиция
последней просмотренной цели. При null owner или пустом списке поля не меняются.
Конструктор их не инициализирует; переносимая модель хранит это состояние
как отсутствие значения, а не как выдуманный нулевой вектор.

PC складывает `z²+y²+x²` с широкими промежуточными значениями x87 и сохраняет
принятый минимум как float32. PS2 использует последовательность
`MULA.S y*y`, `MADDA.S x*x`, `MADD.S z*z`. Равенство этих вычислений для
произвольных float не установлено. Численный профиль по умолчанию принимает
целые координаты от `-1024` до `1024`, исключая отрицательный ноль:
разности не превышают `2048`, а все квадраты и их сумма точно представимы
в float32. Дробные, нечисловые и выходящие за эту область входы явно
отвергаются в этом профиле аналитической проверкой. Эта проверка — граница адаптера проекта,
а не дополнительная ветвь оригинальной игры.

Явный профиль `PcFiniteNearest64` отдельно реализует PC-порядок для конечных
float32, включая знаковые нули и subnormal. Он использует общую программную
арифметику x87 с 64 значащими битами и округлением к ближайшему чётному,
сравнивает широкое расстояние с уже сохранённым float32-минимумом и записывает
новый минимум только после принятого сравнения. Промежуточный `double` здесь
недостаточен: расстояние `1+2^-60` различимо от `1` в оригинальном x87.
Округление сохранённого минимума также может отвергнуть геометрически более
близкую следующую цель или принять более далёкую. Эти особенности сохранены.
Если все расстояния больше `FLT_MAX`, результат остаётся null, хотя позиция
последней просмотренной цели записывается. Этот профиль не расширяет область
PS2, не моделирует NaN/Inf, иные control words, exception/status или hardware.

PC хранит pointer на sentinel в `+18`, forward link находится в `link+0`.
PS2 использует встроенный sentinel `+18` и forward link `link+4`.
Порядок списка и заимствованные цели задаёт `BindForAnalysis`;
native наполнение и сопровождение списка пока не восстановлены.
Внешние owner/entity/Node передаются через обязательный
[host-контракт](../../../Winx/Analysis/Host/wxPerceptionHost.h).

## Ограниченный PC Refresh

`RefreshBoundedPcForAnalysis` описывает PC `4F1F30` с уже построенным настоящим
[`wxGameTimer`](wx-game-timer.md). Любое ненулевое paused byte `40` у таймера
возвращает native false до изменений Perception, включая `68/6C/40` и список.

При unpaused timer ненулевое поле `68` проверяет `6C`: нулевое `6C` очищает
`68`; ненулевое `6C` очищается вместе с `68` только при unsigned `now > 6C`.
Равенство сохраняет оба слова. При нулевом `68` поле `6C` не проверяется и не
очищается. Это наблюдаемая роль `6C` как 32-битного срока внутри данного
метода; общий смысл непрозрачного `68` не присваивается по догадке.

Затем собственный scan `4F1C70` очищает byte `40`. Null owner завершает его,
и Refresh возвращает native true. Ненулевой owner доходит до Asset/Scene
поиска; переносимая операция возвращает `UnqualifiedOwnerScan` после уже
выполненного prefix, сохраняя список. Аналитический deadline, не представимый
32-битным словом при нужной проверке, явно отвергается. PC профиль не включает
PS2 Refresh, холодный timer или native наполнение списка.

## Copy, reset и владение

PC `4F20D0` и PS2 `36ED40` сначала сбрасывают destination, затем вызывают
базовый Copy. Reset очищает список до отключения owner и обнуляет только
owner, сохраняя скалярные поля. Успешный Copy присваивает owner источника,
копирует контейнер и следующие поля:

| Поля | Размер |
| --- | --- |
| `24/28/2C/30/34/38/3C/44/4C/50/54/74` | 12 слов |
| `40/48/70` | 3 байта |
| `68/6C` | 2 непрозрачных слова |

`58/5C/60/64/65/78` не копируются и сохраняют состояние destination.
Проверенная переносимая область Copy ограничена пустыми контейнерами и
нулевыми непрозрачными ссылками `68/6C`. Остальные случаи явно отвергаются;
универсальный shallow copy этих ссылок не объявляется восстановленным.
Собственный clone создаёт новый объект, регистрирует mapping и применяет
тот же ограниченный Copy. Пустой factory/RTTI/clone/delete PC сопоставлен
с оригиналом. Численный constructor PS2, populated Copy, полный lifetime
в игровой сцене, уведомления, видимость и остальная система восприятия
остаются открытыми.

`WinxPerceptionTests` проверяет порядок чтений, равные расстояния,
последнюю просмотренную позицию, null/empty пути, границы численного
профиля, ограниченный Copy, сохранение пропущенных полей, self-copy,
порядок отключения owner и отказ неподдержанных случаев. Отдельные PC-проверки
различают x87 и обычные float/double вычисления, округление на половине шага,
запись минимума, subnormal, знаковые нули и очень большие конечные координаты.
