# wxAnimationLoader

Выбирает наборы анимаций по текущему коду уровня и передаёт команды загрузки или освобождения `wxAnimationManager`. Class ID `7ABF4B41`, физическая и регистрационная база — `wxEntity` (`796A1869`). Собственных native полей нет.

Реализация: [wxAnimationLoader.cpp](../../../Winx/Code/wxAnimationLoader.cpp), [интерфейс](../../../Winx/Code/wxAnimationLoader.h). Ещё отсутствующие `wxEntity`, источник текущего уровня и `wxAnimationManager` подключаются через обязательный [host-интерфейс](../../../Winx/Analysis/Host/wxAnimationLoaderHost.h). Имена `ForAnalysis` обозначают наш API, а не восстановленные исходные имена методов.

## Жизненный цикл и события

Constructor вызывает `wxEntity(true)` и устанавливает vtable. Наборы при создании не загружаются.

Notification читает первый uint32 сообщения. Только code `1D` запускает загрузку наборов текущего уровня; остальные сообщения игнорируются, без пересылки. Повторные сообщения повторяют команды загрузки: собственных признаков «уже загружено» или счётчиков ссылок у класса нет.

Destructor сначала выполняет освобождение наборов **текущего на этот момент уровня**, затем вызывает destructor базы. Он не запоминает уровень предыдущей загрузки и не проверяет, была ли она вообще. Clone и объект, не получавший уведомления, также выполняют освобождение при уничтожении.

Copy сначала вызывает Copy базы. При отказе сразу возвращает false. При успехе вызывает native служебный clone marker и возвращает true; PC marker пустой. Собственных полей для копирования нет, команд загрузки или освобождения в Copy тоже нет. Переносимый clone создаёт новый объект и выполняет Copy через существующий `spCloneManager`.

## Диспетчеризация наборов

`ApplySetForAnalysis(set, load)` заново получает текущий singleton `wxAnimationManager`, при его отсутствии требуется оригинальное ленивое создание. Ненулевой младший byte `load` выбирает загрузку, нулевой — освобождение. PC-адреса внешних операций — `0059BCB0` и `0059AE80`; PS2 — `00272D50` и `00273BF0`. Возвращаемые значения менеджера не проверяются.

`ApplyCurrentLevelForAnalysis(load)` один раз получает код уровня: PC читает поле `1B0` объекта из global `00755294`, создавая объект при необходимости. PS2 getter `002A8710` также читает `1B0`. Затем команды передаются в порядке таблицы ниже. Менеджер разрешается заново **для каждого набора**, поэтому смена singleton внутри callback влияет на последующие команды. Изменение кода уровня во время callback не меняет уже выбранную последовательность.

Все коды уровней и наборов далее **десятичные**. Порядок значим; например, уровни 11 и 12 различаются порядком 64 и 66. Таблица общая для PC и PS2.

Для уровня 0 и значений вне диапазона 1–50 основная последовательность пуста. Проверка диапазона unsigned; отрицательные значения, представленные uint32, также попадают в этот случай.

1. Только для уровня 11 — освобождение набора **21**.

Эти дополнительные наборы не добавляются при загрузке. Повторное освобождение также повторяет все вызовы. Прямой `ApplySetForAnalysis` передаёт ID без собственной проверки диапазона; допустимость ID определяется контрактом менеджера.

## Границы реализации

Восстановлена собственная диспетчеризация класса. Загрузка файлов, хранение наборов, владение ресурсами внутри `wxAnimationManager`, получение игрового контекста и поведение базы остаются внешними зависимостями. Host должен реализовать их и сохранять порядок вызовов; production-интерфейс не предоставляет заглушек успешной загрузки.

Защищённые PC constructor/destructor рассматриваются отдельно от методов диспетчеризации. Сведения о PS2 описывают её layout и код; полная PS2 EE-транзакция и загрузка анимаций в работающей игре здесь не заявляются.
