# `wxBacoManager`

`wxBacoManager` — объект игрового слоя с Class ID `352C4347`. Регистрационная и физическая база — `wxEntity` (`796A1869`). В [переносимом коде](../../../Winx/Code/wxBacoManager.cpp) использован `spNamedObject` с той же цепочкой RTTI: полный `wxEntity` ещё не восстановлен. PC factory, пустой clone и оба пути удаления исполнены в оригинальной игре. На PS2 constructor и vtable проверены статически.

| Размер объекта | `1EC` | `200` |
| Factory | `407340` | `3E7E70` |

| Notify | `573950` | ещё не сопоставлен |
| Setup / update | `572D60` / `573870` | ещё не сопоставлены |

32-битные поля разделены по платформам: [PC](../../../Winx/Analysis/PC/wxBacoManagerAbi.h), [PS2](../../../Winx/Analysis/PS2/wxBacoManagerAbi.h). Они описывают оригинальные объекты, а не ABI переносимого C++ класса. Конструктор обнуляет подтверждённые поля менеджера; остальные байты не считаются инициализированными. PC хранит динамический массив указателей `128..130`, шесть сроков `1C4..1D8`, время следующей проверки `1DC`, четыре byte-флага `1E0..1E3` и два счётчика `1E4/1E8`. На PS2 проверены записи конструктора в `1CC..1F0`; смысл этих полей в активных методах ещё не проверен. Названия PC-флагов аналитические.

## Подтверждённое поведение PC

Notify с кодом `1C` вызывает настройку сцены, `1E` — update, `273D` добавляет указатель из сообщения по `+10` в массив. Настройка подписывает объект на группу `8`, извлекает из сцены позиции, затем записывает матрицу и назначает первую проверку через `500` единиц времени. Контракт сценового поиска и размещения объектов остаётся открытым. Переносимая версия передаёт сценовую часть [host-интерфейсу](../../../Winx/Analysis/Host/wxBacoManagerHost.h), сохраняя время первой проверки в самом классе.

При проверке позиции игрока используются две точки `(-4097, 950, -1111)` и `(-2722, 950, -736)`. Срабатывает строгое расстояние меньше `400`. Первая точка устанавливает первую пару флагов и три срока `now + 3000 + rand() % 2001`; вторая устанавливает вторую пару, начинает второй счётчик с половины текущего числа указателей и записывает три срока `now + 1000 + rand() % 2001`. Вызовы часов и RNG для каждого срока происходят отдельно. Пока хотя бы одна точка не достигнута, следующая проверка назначается через `500` единиц игрового времени.

Update сравнивает время со следующим сроком строго через `>`, при необходимости повторяет проверку позиции, затем обрабатывает активную первую и вторую группы именно в этом порядке. У каждой группы три ячейки. Просроченная ячейка берёт следующий указатель из массива, увеличивает счётчик и назначает новый срок `now + 1000 + rand() % 2001`. Первая группа обходит первую половину массива, вторая — вторую. При достижении конца своей половины флаг группы сбрасывается. Работа с объектом сцены и отправка сообщения `2725` переданы host; без реализации адаптера физическое появление объектов не происходит. После изменения состояния поведение Copy/clone ещё не измерено, поэтому переносимый clone ограничен исходным пустым состоянием.

Код проверяется целью `WinxBacoManagerTests`: ABI, RTTI/factory, пустой clone, маршрутизация сообщений, строгая граница расстояния, сроки, порядок групп и расходование указателей. Проверка переносимого кода не заменяет исполнение активных ветвей в исходной игре.
