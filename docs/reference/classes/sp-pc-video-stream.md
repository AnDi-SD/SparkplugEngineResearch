# spPCVideoStream

PC-класс `0x1DC67471`, база `spVideoStream`, нативный размер `0x24`. Factory
создаёт конкретный объект. [Переносимая реализация](../../../Sparkplug/Code/SparkplugPC/spPCVideoStream.h)
сохраняет собственный интерфейс PC-версии игры и общий lifetime буфера.

## Собственные методы

В оригинальной таблице primary interface эти операции имеют короткие тела:

| Смещение слота | Наблюдаемое поведение |
| ---: | --- |
| `0x00` | вызывает primary slot `0x04`, затем возвращает true в AL |
| `0x04` | немедленный возврат без действий |
| `0x08..0x1C` | каждый из шести слотов возвращает true в AL |
| `0x20`, `0x24` | возвращает ноль в EAX |
| `0x28` | немедленный возврат без действий |

Это собственные тела оригинала. Возвраты не означают реализованное
декодирование: данный конкретный интерфейс в PC-игре не предоставляет
декодирования. Original API names, смысл аргументов и тип нулевого
результата неизвестны. `NativeHook…ForAnalysis` — аналитические aliases:
leaf-тела не читают аргументы, поэтому их результат можно проверить отдельно.
Они не изменяют собственные поля и не освобождают буфер.

## Clone и освобождение

Нативный clone получает secondary view `this+4`, создаёт новый primary объект
и возвращает secondary view результата. В переносимом коде эти view
нормализованы до одного объекта. Named copy переносит имя; два собственных
байта, слово и owned-буфер остаются defaults нового constructor. Общий
destructor сначала освобождает буфер, затем Named-часть и сам объект.

PS2-реализация `spPS2VideoStream` требует отдельного исследования: одинаковая
база не доказывает одинакового платформенного поведения.
