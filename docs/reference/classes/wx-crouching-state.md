# `wxCrouchingState`

`wxCrouchingState` (Class ID `056B1039`) — состояние приседания с selector `2`, потомок `wxCharacterState`. [Общая реализация](../../../Winx/Code/wxCrouchingState.cpp) сохраняет собственные переходы и выбор анимации PC/PS2. Исходный объект занимает `3C` на обеих платформах и не содержит дополнительного хвоста. Переносимый layout не является игровым ABI.

| Операция | PC | PS2 |
| --- | ---: | ---: |
| Фабрика | `4025A0` | `3F4DA0` |
| Vtable | `6F82F8` | `49A8A0` |
| Вход, PC slot `1C` | `513CB0` | `2C9D70` |
| Выход, PC slot `20` | `513D70` | `2C9C10` |
| Обновление, PC slot `30` | `513C00` | `2C9F00` |
| Проверка перехода, PC slot `34` | `513BB0` | `2CA090` |

Первый вход при установленном byte `1C` меняет ключ на `(key & F027800F) | 00200000`. После lookup освобождает старую анимацию, запускает новую с `mode=false`, `interrupt=true` и сохраняет handle. Затем вызывает внешнюю scene-службу с байтом `0`, очищает once-флаг `1C`, обнуляет word `4` control-объекта и возвращает `false`.

Первый выход при установленном byte `1E` использует `(key & F047800F) | 00400000` и такой же порядок lookup/release/play/store. Scene-служба не вызывается. Очищаются `1E` и control word `4`; результат — `false`. Разрешающие флаги `1F/20` эти ветви не проверяют.

При повторном входе или выходе проверяется завершение текущего handle с потреблением completion-записей. Пока оно не завершено, обнуляется control word `4` и возвращается `false`. После завершения вызывается соответствующий hook [wxCharacterState](wx-character-state.md): вход освобождает handle и вызывает виртуальное обновление `30`, выход освобождает handle. Оба дают `true`.

Обновление читает float из control word `4`. Если `(key & 00007F80) == 00000200`, это поле ключа очищается. При `motion < 0.2f` очищаются биты `4..6`; иначе в них задаётся `50`, сохраняя остальные биты. Равенство порогу и NaN попадают во вторую ветвь. Затем применяется маска `F007FFFF`. При изменении найденного handle выполняются release и playback с `mode=true`, `interrupt=true`; одинаковый handle пропускает их. Само обновление не обнуляет control word `4`.

Переход `34` запрещён для target `1,3,4,5,8`, разрешён для остальных значений. Copy унаследован от `spBaseObject` и пуст; clone получает selector `2`, исходные once-флаги и пустые привязки. Деструктор не освобождает pending-анимацию.

[wxCrouchingStateHost](../../../Winx/Analysis/Host/wxCrouchingStateHost.h) предоставляет control (`owner+12C` на PC, `owner+138` на PS2), анимационные службы и внешний scene-вызов. Полный эффект последнего не восстановлен внутри этого класса; host не имеет успешной реализации по умолчанию. [C++ проверка](../../../Winx/Tests/wxCrouchingStateTests.cpp) охватывает ключи, once-флаги, переходы и последовательность callbacks. Полная сцена и её жизненный цикл остаются внешней зависимостью.
