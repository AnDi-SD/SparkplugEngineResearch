# spDXMouse

PC-мышь `0x72F650C7`, регистрационная и физическая база —
[spDXInputDevice](sp-dx-input-device.md). Реализация содержит опрос буфера,
обработку записей, чтение состояния, startup и управление системным курсором.
COM, конфигурация и окна принадлежат явным host-границам. Factory `004CC4F0`
выделяет объект размером `50C8` и вызывает конструктор `004CC120` с DX-основой.
Основа получает установленный интерфейс менеджера ввода и удерживает его одним
AddRef. Мышь обнуляет window `+88`, сохранённую screen position `+8C/+90` и
оба 20-byte packets, задаёт visibility `+94=1`, exclusive `+95=0`. Event buffer
и абсолютные X/Y `+50C0/+50C4` остаются нетронутыми. Переносимое состояние
помечает X/Y как неизвестные до startup либо явного задания runtime.

Аналитическая RTTI-запись содержит factory. Наш scope
`spDXMouseFactoryContextForAnalysis` предоставляет borrowed host-границу для
создания на текущем потоке и восстанавливает прежнюю границу при выходе из
вложенного scope. Это отдельный host-адаптер, не восстановленный singleton
менеджера ввода. Граница должна жить дольше созданных объектов. Без supplied
контекста RTTI factory сообщает об ошибке; direct `CreateForAnalysis` принимает
границу явно.

Диспетчер Clone `004CC550` создаёт destination тем же конструктором,
регистрирует пару source/destination и вызывает виртуальный Copy источника.
При отсутствии destination или неуспешном Copy возвращает null; неуспешный
Copy уничтожает destination. В наследуемом Copy копируется только имя,
runtime мыши остаётся новым. Отдельный host allocation override позволяет
проверить отсутствие destination и отказ Copy.

Startup `004CC5C0` сначала получает client rectangle окна приложения и записывает
начальные координаты как `(right-left)/2` и `(bottom-top)/2`. Вычитание 32-битное
с переполнением, последующее знаковое деление округляется к нулю. Координаты не
включают left/top. Переданный startup аргумент окна используется позднее для
cooperative level и сохранённого окна опроса.

Затем startup записывает указатель оригинального GUID мыши в `+48`, вызывает
CreateDevice с выходным device `+50` и outer null, задаёт размер capabilities
`+54` равным 44 и вызывает GetCapabilities. Из `Input/mouse_exclusive` файла
`.\config.ini` читается строка в буфер из 128 bytes. Сравниваются первые пять
bytes с `true\0`, включая терминатор и регистр; результат записывается в `+95`.
Поля `+80` и `+88` получают 1 и переданное окно. Следуют mouse data format,
cooperative level с flags 5 для `true\0` либо 6 иначе, buffer property
`{size=20, headerSize=16, object=0, how=0, bufferSize=1024}` с property 1 и Acquire.
После этого `+44=1`, результат true; acquired byte `+45` сохраняется. HRESULT
этих вызовов не проверяются. Device читается повторно перед каждым вызовом.
Host-адаптер отдельно отклоняет отсутствие device перед обязательным
разыменованием и чтение неустановленного configuration byte, сохраняя уже
произошедшие эффекты. Startup устанавливает координаты и сохраняет packets.

Метод `004CC470` непосредственно записывает byte `+95`. Метод `004CC480`
сравнивает новый byte с visibility `+94` и ничего не делает при равенстве.
Для нового ненулевого byte он вызывает ReleaseCapture, SetCursorPos с сохранённой
screen position `+8C/+90` и ShowCursor(1). Для нулевого byte вызывает SetCapture
с окном `+88`, получает и сохраняет GetCursorPos, затем вызывает ShowCursor(0).
В конце сохраняется точное значение нового byte. Возврат Win32 API не управляет
порядком этих действий. Конструктор предоставляет visibility 1 и screen
position 0/0; явное runtime состояние может заменить их.

Буфер начинается в `+98` и содержит до 1024 записей по 20 байт. Запись
включает offset, data и три дополнительных слова, которые этот обработчик
не использует. Current packet в `+5098` содержит три 32-битные относительные
оси и восемь bytes кнопок; changed packet занимает следующие 20 байт в
`+50AC`. Абсолютные координаты находятся в `+50C0/+50C4`.

Poll `004CC730` получает secondary this в `+14`. При нулевом device `+50`
сразу возвращает true. Иначе вызывает GetDeviceData с размером записи 20,
входным count 1024 и flags 0. HRESULT 0 устанавливает acquired byte `+45=1`
и передаёт возвращённые записи обработчику. HRESULT 1 очищает оба packet
и возвращает true, сохраняя acquired byte. `8007000C` и `8007001E` очищают
packet, повторно читают device и вызывают Acquire перед новой попыткой.
Другие ошибки переходят к следующей попытке без очистки. После трёх
неудачных попыток вызывается сообщение об отсутствии acquire, `+45=0`,
возвращается false. Возвращаемый HRESULT Acquire не управляет повтором.

Непроинициализированные абсолютные X/Y нужны только обработчику успешных
записей. Poll с HRESULT 1 либо исчерпанными ошибками не читает их и может
завершиться до startup. При HRESULT 0 host-граница отдельно отклоняет
неизвестные X/Y после выполненного GetDeviceData и установки acquired byte.

Обработчик `004CC1C0` сначала обнуляет относительные оси и весь changed
packet. Offsets 0, 4 и 8 суммируются в оси с переполнением по модулю
`2^32`; offsets 12..19 задают восемь кнопок по bit `80` и отмечают change
byte значением 1. Повторные записи применяются по порядку, нетронутые
кнопки сохраняются. Остальные offsets пропускаются. Оси X/Y прибавляются
к абсолютным координатам, затем вызывается GetClientRect.

Оригинал ограничивает координаты непосредственно значениями right/bottom,
игнорируя left/top. Сначала проверяется верхняя граница и записывается
`upper-1`, затем проверяется отрицательное значение. Поэтому пустая или
отрицательная граница может дать отрицательную координату; это сохраняется.

Physical slots 1/2 читают current/changed buttons для codes 100..107 и
возвращают true только при byte ровно 1. Slot 3 возвращает абсолютные X/Y
для codes 108/109, slot 4 — относительные X/Y/Z для 108/109/110. При
нулевом acquired byte либо неподходящем code возвращается 0. Slot 5
поставленного оригинала пуст, slot 6 возвращает `+0.0`.

Наш borrowed adapter `GetQueriesForAnalysis()` связывает эти шесть slots с
общей логической диспетчеризацией `spInputDevice`: bindings задаются через
`AppendBindingForAnalysis`, а inherited `QuerySlot1..6` и `CommandSlot5`
обращаются к текущему состоянию мыши. Callback provider должен жить не дольше
самой мыши. Активное чтение абсолютных координат до их установления
отклоняется исключением `logic_error`; нулевой acquired byte и неподходящий
physical code сохраняют оригинальный нулевой результат.
