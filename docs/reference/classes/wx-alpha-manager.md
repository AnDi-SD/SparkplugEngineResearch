# wxAlphaManager

Менеджер изменения прозрачности и цвета материалов, затемнения экрана и служебных данных узлов. Class ID `41F81774`, регистрационная и основная физическая база — `spBaseObject`. Реализация: [wxAlphaManager.cpp](../../../Winx/Code/wxAlphaManager.cpp), интерфейс: [wxAlphaManager.h](../../../Winx/Code/wxAlphaManager.h).

Собственная логика общая для инструментов и находится в `WinxAlphaManagers`. Сцена, материалы, таймеры, рисование и объекты пула подключаются через обязательный [host-интерфейс](../../../Winx/Analysis/Host/wxAlphaManagerHost.h). Его структуры — представления внешних объектов для адаптера, а не восстановленные игровые классы или native layout.

Вторичная база участвует в регистрации singleton; её исходное C++-имя неизвестно. Переносимый класс не придумывает для неё отдельную иерархию. Constructor безусловно заменяет singleton текущим экземпляром, destructor безусловно обнуляет его, даже если позже был создан другой экземпляр. Clone создаёт новый менеджер и регистрирует соответствие объектов; унаследованный Copy не переносит состояние эффектов и затемнения.

## Пул, сброс и очистка

Получение объекта обходит пул по порядку и выбирает первый с byte `0C`=0: ставит этот byte в 1 и снимает byte `2C`. Если все объекты заняты, возвращается **последний занятый объект**, без расширения пула и без сброса его byte `2C`.

Reset снимает bytes `0C/2C` и обнуляет pointer `08` у всех объектов пула. У всех 200 записей снимает active/saved, обнуляет node; указатель renderable и остальные поля сохраняются. Также снимается получатель уведомления. Изменённые материалы при Reset не восстанавливаются.

Clear уничтожает объекты пула, узлы списка и все записи эффектов; обнуляет поля `35C/360`, освобождает свою intrusive-ссылку на экранный материал. Материалы сцены при этом также не восстанавливаются. Destructor вызывает Clear, удаляет sentinel PC-списка и завершает базовые объекты.

Переносимая версия хранит записи массивом и пул в vector, а внешний host отвечает за создание/уничтожение объектов и ссылку на материал. После Clear операции с освобождёнными записями отклоняются явной ошибкой: это защита адаптера, не утверждение о безопасном повторном использовании оригинала.

## Затемнение экрана

Используется **системное время**, отдельно от игрового времени эффектов материалов. Запуск сообщает прежнему получателю о прежней конечной alpha, затем устанавливает enabled=1, notified=0, пару alpha, время, длительность и нового получателя. Возможны направления `1 → 0` и `0 → 1`.

В уведомлении `27A3` sender — менеджер, byte значения — `1`, если конечная alpha равна нулю, иначе `0`. Указатель получателя обнуляется **до** callback, notified становится 1 после callback. В PC значимо подтверждён именно младшее byte значения; старшие байты временного слова не инициализируются этим bool-присваиванием.

Рисование работает при enabled!=0 и наличии материала. `elapsed = now - started` вычисляется как uint32 с переполнением. Первая четверть длительности удерживает исходную alpha. Затем идёт линейная интерполяция:

```text
delay = trunc(duration * 0.25)
fraction = elapsed > delay ? (elapsed - delay) / (duration - delay) : 0
alpha = from + (to - from) * fraction
```

Завершение происходит при duration=0 или **elapsed > duration**. Равенство ещё не отправляет уведомление. При конечной alpha=0 снимается enabled; непрозрачное затемнение остаётся включённым. Последний прямоугольник рисуется и в вызове, который снял enabled. Прямоугольник чёрный, размером с viewport, с одинаковой alpha всех четырёх вершин; материал имеет режимы `38=34=2`, `24=0`, включённый byte `6C`, слой с режимом 2 и текстурой по умолчанию на PC. Создание и отрисовка этого внешнего материала явно принадлежат host.

## Запись эффекта материала

Основные смещения записи одинаковы на PC и PS2; размер `74`.

| Смещение | Поле |
| --- | --- |
| `00` | Mode, uint32 |
| `04 / 08` | Borrowed node / renderable |
| `0C` | Active, byte |
| `10 / 14` | Начало lifetime / начало интерполяции |
| `18 / 1C / 20` | Упакованные цвета from / to / current |
| `24` | Длительность интерполяции |
| `28` | Предыдущее состояние сохранено, byte |
| `2C` | Lifetime |
| `30 / 34` | Сохранённые режимы материала |
| `38 / 48 / 58` | Сохранённые два цвета материала и цвет узла |
| `68 / 6C / 70` | Сохранённые поля renderable и режим первого слоя |

Constructor записи задаёт mode=1, node/renderable=null, active=saved=0, время `10=FFFFFFFF`, `14=0`. Цвета, duration, lifetime и backups **не инициализируются**. Нулевое хранилище этих полей в переносимой структуре не является игровым default.

Назначение эффекта принимает только точный class ID `spRenderNode` (`603625D0`). Наличие любого renderable типа `spTextureProjection` (`58DA4026`) или `spShadowProjection` (`750F73D9`) отклоняет весь узел. Выбирается существующая активная запись для renderable либо первая свободная запись. При отсутствии места новый эффект пропускается.

Выбранная запись **сохраняется между итерациями по renderables одного узла**. Последующие renderables перезаписывают её node/renderable и параметры; отдельная запись для каждого из них не выделяется. Существующий saved-backup при повторном назначении сохраняется.

| Параметры назначения | Режим и цвета |
| --- | --- |
| Третий float имеет биты `3F800000` | Mode 4: RGB вспышки → белый, duration из аргумента |
| Duration и lifetime равны `FFFFFFFF`, без предыдущего условия | Mode 5: постоянный RGB из трёх floats, alpha=255, duration=lifetime=0 |
| Иначе | Mode 1 при lifetime=0, иначе mode 2; белый RGB с alpha из первых двух floats |

Преобразование каналов использует усечение и младший byte, без ограничения диапазоном enum/цвета. Общие операции цвета вынесены в host как engine helpers. Рекурсивные методы сначала обрабатывают текущий узел, затем детей в исходном порядке. Рекурсивный вход требует допустимого ненулевого дерева.

## Обновление и восстановление материалов

Обновление обходит все 200 записей. Неактивная запись, mode=0 или время интерполяции `FFFFFFFF` ничего не меняют и возвращают false. Отсутствие материала или исключённый тип renderable возвращает true без освобождения записи; общий обход игнорирует этот результат.

Modes 1/2/4 интерполируют все четыре канала цвета; при elapsed>=duration сразу берётся to. Modes 3/5 берут to без интерполяции. Неизвестный mode сохраняет current, но дальнейшая обработка материала всё равно выполняется.

- Mode 2 при ненулевом lifetime и превышении lifetime меняет местами from/to, переходит в mode 1, перезапускает оба таймера и увеличивает lifetime до duration, если он меньше.
- Mode 1 с ненулевым lifetime восстанавливает материал только при строгом превышении lifetime.
- Mode 4 с нулевым lifetime восстанавливает материал только при строгом превышении duration.

В переходе mode 2 значение current берётся из временного слова, в которое прежний to записан **только на пути интерполяции**. Если этот путь не исполнялся, native читает прежнее содержимое стека. Переносимый host обязан явно предоставить `UnwrittenReverseColorForAnalysis`; ноль или целевой цвет автоматически не подставляются. Это же чтение присутствует в PS2, но содержимое её стека независимо.

При первом применении сохраняются режимы материала, его два цвета, цвет связанного узла, поля renderable и режим первого слоя. Перед проверкой saved всегда вызывается getter цвета `0C`. Затем режим материала `38` становится 4. Mode 4 записывает цвет через setter `08`; прочие modes — через setter `10`, ставят режим `34=2`, поля renderable `1C=1/18=1`, вызывают его refresh и ставят режим первого слоя в 2. Saved становится 1 после этих действий.

Restore работает только при active!=0 и saved!=0. При отсутствующем материале возвращает false и сохраняет flags. Иначе возвращает режимы, оба цвета материала, цвет узла, режим слоя и поля renderable, вызывает refresh, затем снимает active/saved. Порядок setter и callback существенен.

Метод прямого назначения RGB рекурсивно задаёт цвет материала, обновляет цвет связанного узла с dirty bit 8, затем **повторно вызывает тот же setter цвета материала**. Повторный вызов сохранён.

## Классификация узлов по имени

Для узла с именем и первым компонентом выполняется поиск подстрок с учётом регистра:

- `collidable`: flags первого компонента заменяются его младшим byte с установленным bit 8. `collidable_only` прекращает собственную классификацию, но не обход детей.
- `collidable` вместе с `fadeable`: выделяется объект пула с flags=1 и ссылкой на текущий узел.
- `collidable` без `fadeable`: при отсутствии data `0C` ищется первый sibling с `fadeable`; объект flags=1 ссылается на него и прикрепляется к текущему узлу. Подстрока `clip` добавляет flags bit 2 либо создаёт объект с flags=2.
- Без `collidable`, но с `clip` или `nv_`: создаётся объект с flags=2.

При назначении flags=2 поле node10 не очищается; это существенно при повторном использовании объектов пула. Обход детей выполняется независимо от результата собственной классификации.

## Границы реализации

Имена методов `ForAnalysis` — аналитические; исходные объявления C++ не найдены. Host должен сохранять идентичность borrowed объектов, порядок вызовов и состояние views, переживать все менеджеры и clone. Создание экранного материала и объектов пула — реальные обязательные зависимости, без заглушек успеха.

PC Reset содержит защищённую загрузку списка, метод назначения эффекта — защищённое условие после RTTI getter. Продолжения PC и независимый PS2-код устанавливают переносимую логику; исполнение защищённых PC-входов не заявляется. PS2 имеет отличия ABI сцены и floating-point вычислений: переносимая реализация ориентирована на PC, не обещает побитового соответствия EE или всех x87 precision/exception modes. Полная интеграция с renderer и сценой требует host.
