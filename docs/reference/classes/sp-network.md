# `spNetwork`

База сетевых реализаций PC. Class ID — `0x18B4576A`, регистрационная база —
`spCrossPlatform` (`0x20A72504`). Цепочка регистрации продолжается через
`spNamedObject` (`0x44DE07FD`) к `spBaseObject` (`0x415352A1`). В известном
каталоге PS2 класс отсутствует; соответствующий код PS2 не установлен.

[Реализация](../../../Sparkplug/Code/Sparkplug/spNetwork.h) включает отдельные
constructor/destructor, RTTI, null Clone, копирование имени и null getter текста
адреса. Остальные сетевые операции задаёт абстрактный интерфейс. Имена методов
`ForAnalysis`, заголовки, пространство имён и переносимые типы владения — наши
обозначения: исходные объявления C++ не найдены.

## Два интерфейса и поля

На PC основной сетевой интерфейс находится по `+0`, объектный
`spCrossPlatform` — по `+4`. Это подтверждают constructor, destructor и adjustor,
а не только регистрационная база. Переносимый класс сохраняет оба интерфейса,
но его размер и смещения зависят от ABI host. Аналитический
`spNetworkInterfaceForAnalysis` не объявляется восстановленным именем класса.

У базы нет RTTI factory, поэтому отдельный размер native allocation не получен.
[Описание ABI](../../../Sparkplug/Analysis/PC/spNetworkAbi.h) задаёт наблюдаемый
префикс `0x28`; оно не утверждает полный `sizeof(spNetwork)` оригинала.

| PC offset | Поле | После constructor |
| --- | --- | --- |
| `00` | основная таблица | `006EEE50` |
| `04` | таблица объектного интерфейса | `006EEE30` |
| `08` | наследуемая обратная ссылка | `0` |
| `0C` | наследуемый reference count, uint16 | `0` |
| `10` | наследуемое поле BaseObject | `0`; назначение не уточнено |
| `14` | общее имя NamedObject | null |
| `18` | признак подключения, byte | `0` |
| `1C` | тип, uint32 | `1` |
| `20` | адрес, uint32 | `FFFFFFFF` |
| `24` | порт, uint16 | `FFFF` |

Выравнивающие байты `0E..0F`, `19..1B`, `26..27` не инициализируются. Для
[spDXNetwork](sp-dx-network.md) тип `0` означает UDP, `1` — TCP, а адрес/порт
используют host byte order. Базовый constructor не создаёт сокет, не вызывает
WinSock и не меняет данные за наблюдаемым префиксом.

## Основной сетевой интерфейс

В таблице `006EEE50` **первые 16 слотов** ведут на purecall, а слот `40` — на
null-return stub `004A1BF0`. Наличие purecall подтверждено отдельно от нулевой
factory. Переносимая база сохраняет абстрактные методы и собственную null
реализацию последнего слота.

| PC primary offset | Роль по реализации DX |
| --- | --- |
| `00`, `04`, `08`, `0C`, `10` | Open, Connect, Bind, Listen, Accept |
| `14`, `18` | Close, SetBlocking |
| `1C`, `20`, `24`, `28` | AddToSet, RemoveFromSet, ClearSet, Select |
| `2C`, `30`, `34`, `38` | Send, SendTo, Receive, ReceiveFrom |
| `3C` | GetLocalAddress |
| `40` | GetLocalAddressText: у базы возвращает null |

Пустые успешные реализации purecall-методов не добавлены. Вызовы ОС принадлежат
производной реализации и её платформенному адаптеру. Заголовок базы не зависит
от адаптера `spDXNetwork`.

## Объектный интерфейс

Объектные методы получают secondary pointer `complete object + 4`.
PC offsets таблицы не совпадают с аналитическими именами методов `vfunc_*`,
унаследованными из переносимого BaseObject.

| PC secondary offset | Native entry | Поведение |
| --- | --- | --- |
| `00` | `004A1C30` | delete adjustor: вычесть 4 и вызвать complete destructor |
| `04` | `005B7A00` | унаследованное пустое уведомление с одним context аргументом |
| `08` | `004A1BF0` | Clone возвращает null |
| `0C` | `00413120` | унаследованное копирование общего имени |
| `10` | `004A1C20` | вернуть registration record `00762F30` |
| `14` | `00408350` | точная проверка class ID |
| `18` | `00408370` | проверка цепочки базовых регистраций |

Clone не создаёт объект и не добавляет пару в CloneManager. RTTI factory и
property registrar отсутствуют. Проверка типа отличает точное совпадение от
принадлежности цепочке: `spNetwork` подходит ко всем четырём типам своей цепочки,
но не является точным экземпляром `spCrossPlatform` или `spNamedObject`.

## Копирование имени

Copy возвращает true и работает в таком порядке:

1. освобождает имеющуюся ссылку на имя получателя и очищает его поле;
2. читает имя источника и удерживает эту общую ссылку в получателе;
3. завершает наследуемый протокол копирования.

Сетевые поля источника и получателя не копируются и не сбрасываются. Пустое
имя источника очищает имя получателя. Повторное копирование общей ссылки
сохраняет имя и баланс удержаний/освобождений.

**Самокопирование очищает имя.** Оригинал сначала освобождает имя получателя,
поэтому при совпадении объектов читает уже пустое имя источника и возвращает
true. Признак подключения, тип, адрес и порт сохраняются. Это поведение
реализовано в общей базе и наследуется `spDXNetwork`.

Переносимый copy принимает физически именованный объект. Передача объекта без
`spNamedObject` возвращает false как явная защита host; оригинал не содержит
такой проверки и требует валидного указателя на соответствующий подoбъект.

## Освобождение и границы

Destructor `004A1C00` устанавливает основную таблицу базы, записывает её
объектную таблицу по `+4` и передаёт secondary pointer в destructor
`spCrossPlatform`. Затем выполняется наследуемое освобождение имени и
BaseObject. Своих сокетов, буферов, наборов handles и счётчика WinSock база
не освобождает. Её собственные сетевые поля при разрушении не сбрасываются.

Complete deleting destructor `004A1C80` после этой цепочки освобождает
complete object, если установлен младший бит delete-флага. Secondary adjustor
возвращает указатель к началу объекта. Переносимое удаление через оба интерфейса
проходит ту же цепочку владения средствами C++.

Проверены отдельный базовый constructor, именованное и пустое копирование,
замена имени, самокопирование, null методы, уведомление и удаление с сохранением
общего имени у живого получателя. Для RTTI query bodies задавалось явное
состояние записей, сверенное с исходными registration thunks; полный запуск
защищённой глобальной регистрации этим не подтверждён. Полное восстановление
StringManager и неустановленных состояний BaseObject остаётся отдельной задачей.
