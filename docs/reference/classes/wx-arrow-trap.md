# wxArrowTrap

Ловушка с двумя попеременно выпускаемыми стрелами. Class ID `31AE6FA8`, регистрационная и физическая база — `wxEntity` (`796A1869`). Переносимая реализация собственной логики находится в [wxArrowTrap.cpp](../../../Winx/Code/wxArrowTrap.cpp) и [заголовке](../../../Winx/Code/wxArrowTrap.h). Сцена, компонент узла, часы и операции ещё не восстановленного `wxEntity` подключаются через обязательный [wxArrowTrapHost](../../../Winx/Analysis/Host/wxArrowTrapHost.h).

Все адреса и смещения ниже шестнадцатеричные. [PC layout](../../../Winx/Analysis/PC/wxArrowTrapAbi.h) и [PS2 layout](../../../Winx/Analysis/PS2/wxArrowTrapAbi.h) описывают физические объекты отдельно от переносимого состояния.

Constructor вызывает `wxEntity` с аргументом `1`, ставит speed `2000.0`, паузу `1000` мс, флаг расстояния `1`, inherited word `84=1` и сбрасывает собственные массивы. PC поля speed/pause находятся по `128/12C`, PS2 — `134/138`. Copy сначала вызывает Copy базы; только при успехе переносит speed, pause и inherited word `84`. Созданные компоненты и текущая фаза выстрела не копируются. Destructor очищает три слота узлов и освобождает созданные им компоненты, после чего вызывает destructor базы.

Сообщение `1C` запускает setup. Нулевая пауза заменяется единицей. Интервал в секундах равен паузе в миллисекундах, умноженной на `0.001`; один канал, выбранный младшим битом игрового random, получает половину интервала в таймер. Среди непосредственных детей корневого узла ищутся первые два имени, содержащие `fleche_`, и узел с именем, содержащим `arrowstart_`. Позиции этих узлов запоминаются. Ловушка активна, только если найдены все три. Затем для обоих каналов ищется первый узел с render data в поддереве первой стрелы. Если у него уже есть компонент, в его флаг добавляется `2`; иначе компонент создаётся, получает слово `200` и прикрепляется к узлу. После этого вызывается операция базы с корневым узлом и записывается текущее время. Повторный setup в оригинале не очищает ранее найденные указатели перед новым поиском.

Сообщение `1E` обновляет активную ловушку. Если дистанционный флаг установлен, сначала обновляется преобразование entity. Каждый из двух каналов обрабатывается отдельно: фаза `0` накапливает delta time; при достижении интервала ставит фазу `1`, обнуляет таймер и посылает `27D1` группе `11` с `(BB, 0)`. Фаза `1` обновляет преобразование emitter при установленном дистанционном флаге, снова накапливает delta и вычисляет пройденное расстояние `timer × speed`. Пока его квадрат меньше квадрата расстояния от `arrowstart_` до сохранённой позиции стрелы, стрелка движется по нормализованному направлению; её Y берётся непосредственно из сохранённой конечной позиции. При достижении цели записывается конечная позиция, фаза и таймер сбрасываются. В обоих случаях позиция помечается dirty bit `1`. Третий слот выделен в объекте, но цикл Update проходит только каналы `0` и `1`.

Дистанционный virtual slot всегда возвращает true. Он ставит собственный byte в `1`, затем снимает его только когда квадрат расстояния между аргументом и позицией корневого узла **строго больше** `2 000 000`; равенство оставляет `1`. Регистрация свойств PC объявляет `Speed (cm/s)` и `Pause between arrow shot (ms)`, затем делегирует свойства базы.

Конструктор, Copy и дистанционный предикат сопоставлены с ранее выполненными вызовами оригинальной PC игры; полный цикл setup/полёта восстановлен по проверенным диапазонам инструкций PC и PS2 и проверяется переносимым тестом `WinxArrowTrapTests`. Полного исходного прогона сцены с этими узлами пока нет. Значения неинициализируемых native полей, ошибки выделения компонента и детали внешнего `wxEntity` не объявляются восстановленными.
