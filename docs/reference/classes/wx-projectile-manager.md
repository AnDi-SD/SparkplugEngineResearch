# `wxProjectileManager`

`wxProjectileManager` (Class ID `7DB63B02`) наследует `wxEntity`. Частично восстановленный общий класс находится в [Winx/Code](../../../Winx/Code/wxProjectileManager.cpp); таймер, сцена, обновление записи и вызов узла передаются через [host-интерфейс](../../../Winx/Analysis/Host/wxProjectileManagerHost.h). Переносимый объект физически наследует восстановленный `wxEntity`. Его массивы с исходными смещениями служат для анализа и не накладываются на C++ ABI.

| Контракт | PC | PS2 |
| --- | ---: | ---: |
| Размер | `1D0` | `1E0` |
| Vtable | `6F7008` | `49AFD0` |
| Notify | `5061E0` | `2C6590` |
| Copy | `505F10` | `2C6290` |
| Регистрация записи | `506100` | `2C5120` |
| Tick | `5068A0` | `2C6370` |

Исходные [PC](../../../Winx/Analysis/PC/wxProjectileManagerAbi.h) и [PS2](../../../Winx/Analysis/PS2/wxProjectileManagerAbi.h) размеры и смещения хранятся отдельно. На PS2 собственные слова и pool сдвинуты на `0C` относительно PC, а флаг обхода находится в `1CC` вместо `1C0`.

Notify `1C` вызывает настройку, `1E` — Tick, `273F` — регистрацию записи в pool. Проверенные соседние коды не вызывают эти операции. У pool четыре группы по пять указателей. При регистрации код выбирает первый свободный слот **среди первых четырёх** указанной группы; свободный пятый слот не подходит. Затем создаётся native запись размером 12 байт с нулевыми deadline/active и указателем на payload. У связанного узла вызывается `Enable(0,1)`, обнуляются три координаты, устанавливается dirty bit, и во все три поля масштаба записывается число из `160+4*group` (PS2 `16C+4*group`). Только после этого запись помещается в ячейку. Переносимая запись имеет собственный C++ layout; размещение и работу узла предоставляет host.

Деструктор сначала обращается к внешней службе менеджера и обнуляет свой указатель сцены, затем обходит все 20 ячеек в порядке групп и слотов: у каждой непустой записи обнуляет payload, освобождает запись и очищает ячейку. Он не вызывает `Enable` у payload. Точное действие внешней службы ещё не установлено и передано host. Для переносимого кода освобождение выполняет тот же host, который выделил запись. Отказ выделения в оригинале ведёт к разыменованию нулевого адреса; host-контракт требует ненулевую запись, переносимый код аварийно завершает вызов при нарушении контракта.

Tick сначала проверяет паузу GameTimer: ненулевой байт паузы даёт `false`. Без паузы результат `true`. Собственный байт `enabled` разрешает обход всех 20 указателей. Нулевая или неактивная запись пропускается без чтения времени. Для каждой активной записи время читается заново: строгое **беззнаковое** `deadline < now` обнуляет сначала активность, затем срок, после чего вызывает `Enable(0, 1)`. После его возврата код заново получает payload из ячейки, обнуляет позицию узла и ставит dirty bit; масштаб сохраняется. Иначе вызывается внешнее обновление записи с номером группы и слота. Полная настройка сцены и активное обновление ещё требуют восстановления.

После успешного родительского Copy оригинал переносит ровно четырнадцать 32-битных слов по PC-смещениям `128,124,134,138,13C,140,144,148,150,154,158,160,164,168` (на PS2 плюс `0C`). Промежутки, pool и байт `enabled` этот Copy не переносит. Проверка [WinxProjectileManagerTests](../../../Winx/Tests/wxProjectileManagerTests.cpp) покрывает регистрацию и освобождение записи, селективное Copy, границы Tick и порядок вызовов. Источники исходного поведения и точные границы парного прогона PC/PS2 сохранены в `.private/research/probe_projectile_manager_common.py` и `local-data/results/native-cycle-20260910-1900/projectile-manager/common-run1.json`. Полный PC путь регистрации до возврата отдельно проверен с настоящим `spNode`.
