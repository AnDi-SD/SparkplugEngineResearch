# wxAttackingState

Состояние атаки персонажа, производное от [wxCharacterState](wx-character-state.md). Восстановлены регистрация, создание и clone, переходы через виртуальные слоты `1C` и `20`, выбор активной анимации в `30`, проверки `34` и `38`, обработка событий `3C`. Код: [wxAttackingState.h](../../../Winx/Code/wxAttackingState.h) и [wxAttackingState.cpp](../../../Winx/Code/wxAttackingState.cpp).

## Идентичность и объект

| Свойство | PC | PS2 |
| --- | --- | --- |
| Class ID / base ID | `11B50C8E / 44817BC2` | те же |
| Размер и selector `+10` | `40`, `5` | `40`, `5` |
| Factory | `00402600` | `003F4CA0` |
| Vtable | `006F8340` | `0049A850` |
| Constructor | внутри factory | `002C77A0` |
| Clone | `00409250` | `003F4BE0` |

Состояние добавляет один байт `+3C`, который устанавливается обработчиком событий. Конструктор PS2 записывает туда `0`; после вызова PC factory этот байт также равен `0`, а три байта выравнивания остаются неинициализированными. Clone вызывает унаследованный пустой copy-hook, поэтому не копирует текущую анимацию, связи и флаг события.

Физические схемы 32-битных объектов: [PC](../../../Winx/Analysis/PC/wxAttackingStateAbi.h) и [PS2](../../../Winx/Analysis/PS2/wxAttackingStateAbi.h). Переносимый C++ объект не подставляется вместо объекта игры.

## Переходы и анимация

PC-адреса слотов: `1C=00514210`, `20=00514340`, `30=005140A0`. На PS2 соответственно `002C7050`, `002C6E50`, `002C7260`. Оба перехода сначала проверяют глобальный режим атаки: при активном режиме вызывают базовый hook; `1C` предварительно сбрасывает байт `+3C`.

В обычном режиме первый вызов `1C` или `20` выполняет внутреннюю проверку ключа `00513EA0` / `002C6D10`. Она учитывает биты `0x00180000`, младшую тетраду ключа, поле владельца со значением `0.2f`, биты `0x70` и для тетрад `0/3` первый код действия владельца. Результат `true` переводит управление в базовый hook. При `false` класс освобождает старый handle, изменяет ключ (`1C`: очистить `0x00400000`, установить `0x00200000`; `20`: наоборот), применяет глобальный режим, ищет анимацию и запускает её с `(mode=false, interrupt=true)`. Затем сохраняет handle и очищает соответственно флаг `+1C` или `+1E`. `1C` также очищает `+3C`. Повторный вызов при очищенном флаге запрашивает завершение текущей анимации с параметром `true` и ждёт, пока запрос не разрешит базовый переход.

Слот `30` при значении владельца меньше `0.2f` очищает группу битов `0x70`. Иначе для типа ключа `2` выбирает вариант по углу относительно `π/4` и `3π/4`; для других типов устанавливает вариант `0x50`. Затем применяет глобальный режим и очищает биты `0x00600000`. Повторный поиск того же handle не запускает анимацию повторно; при смене handle сначала освобождается старый, затем запускается новый с `(mode=true, interrupt=true)`. PC и PS2 используют разные последовательности масок, которые дают одинаковое конечное значение этой группы битов.

Глобальный режим выставляет `0x00800000` и очищает биты `0x0F000000`; обычный режим очищает `0x0F800000`. Исходное имя и структура глобального объекта пока неизвестны. Ни один из этих переходов не обнуляет owner action-control, в отличие от `wxActionState`.

## Проверки и события

Слот `34` возвращает байт `+3C`, кроме кода `1` при младшей тетраде режима владельца `3`: тогда результат `false`. Слот `38` возвращает `false` для кодов `0`, `4`, `8`, `10`, `18`, для остальных — `true`. Исходный тип числового аргумента не установлен; переносимый интерфейс принимает его как `uint32_t`.

Слот `3C` сравнивает имя внешнего события с `event_orb` и `event_snowball`. Оба события устанавливают байт `+3C`. `event_orb` отправляет код `0` цели при немедленном условии либо разрешении внешнего предиката с `1.0f`. `event_snowball` при положительном счётчике отправляет код `6` и уменьшает счётчик. Остальные события не меняют состояние. Точный исходный тип объекта события неизвестен; переносимый hook принимает непрозрачный указатель.

Внешние поля владельца, глобальный режим, поиск и воспроизведение анимации, а также получатели событий передаются через обязательный [wxAttackingStateHost](../../../Winx/Analysis/Host/wxAttackingStateHost.h). Интерфейс является нашим адаптером; отсутствие нужной привязки вызывает ошибку, а не имитирует успешную работу игры.

## Границы проверки

PC factory и clone проверены выполнением оригинальных методов. Размер, selector, vtable и тело конструктора PS2 сопоставлены статически. Слоты `34/38` исследованы на оригинальных PC и PS2 входах, их возвращаемые значения подтверждены отдельно. Тела `1C/20/30/3C` разобраны по инструкциям PC и PS2; тест переносимого класса проверяет переходы, побочные эффекты, порядок вызовов, события, RTTI и clone. Выполнение всего состояния внутри игры с реальными владельцем и анимационным менеджером пока не заявляется.
