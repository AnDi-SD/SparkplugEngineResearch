# spContactConstraint

PC-регистрация класса имеет ID `04353BD3` и регистрационную базу
`spConstraint` (`86CD6780`). Регистрационная связь не устанавливает физическое
C++-наследование. Аналитический класс хранит предоставленное состояние из
`E4` байт и не воспроизводит native allocation, vptr или конструктор.

В primary table `006E7090` ячейка `1C` выбирает метод `0048B550`.
Метод работает только с собственным receiver и константой нуля; другие
объекты и сервисы он не вызывает. Имя `OwnSlot1CForAnalysis` и названия
полей по смещениям являются нашими аналитическими обозначениями.

| Смещение | Представление | Наблюдаемая роль в операции |
| --- | --- | --- |
| `58` | raw uint32 | Первый выходной счётчик |
| `5C` | raw uint32 | Второй выходной счётчик |
| `88` | raw byte | Младший бит выбирает ветвь; остальные биты сохраняются |
| `8C` | raw float32 | Первый коэффициент |
| `90` | raw float32 | Второй коэффициент; ветвь с нулевым младшим битом его сохраняет |

Операция сначала записывает `58=1`, `5C=0`, затем заменяет отрицательный
конечный коэффициент `8C` положительным нулём. Оба знаковых нуля остаются
побайтно неизменными.

При установленном младшем бите `88` положительный `8C` задаёт `58=2`.
Затем отрицательный конечный `90` также заменяется положительным нулём,
а положительный `90` увеличивает `58` на один. Каждое точное значение
`7F7FFFFF` в `8C` и `90` увеличивает второй счётчик `5C` на один.

При сброшенном младшем бите положительный `8C` задаёт `58=3`; точное
`8C=7F7FFFFF` задаёт `5C=2`. Все байты `90`, включая отрицательные значения,
остаются неизменными. Остальные байты receiver ни в одной ветви не меняются.

`PcCapturedFiniteOwn1C` — явно выбранный аналитический профиль. По умолчанию
операция отказывается от выполнения. Профиль требует правильного raw тега
primary table и двух конечных коэффициентов; оба условия проверяются до
изменения предоставленного состояния. Проверка конечности второго значения
действует и в ветви, где оригинальный метод его не читает. Такой отказ
является нашим ограничением допуска, а не поведением оригинала на NaN или
бесконечности.

Сравнения конечных IEEE32 значений выражены через raw биты, включая
subnormal, знаковые нули и максимальные конечные значения. Эквивалентность
флагов исключений и status word FPU у portable caller не заявляется.
Исходный C++-тип возврата метода не установлен. Результат portable-метода
сообщает только об аналитическом допуске. Наблюдаемый `EAX` остаётся
диагностикой и не получает выдуманного Boolean-контракта.

Отдельный `PcCapturedRawOwn24` допускает аналитический `OwnSlot24ForAnalysis`.
Он переносит 92 сырых байта предоставленного источника в диапазон receiver
`88..E3`: сначала 11 последовательных dword, затем 12 dword в том же
возрастающем порядке. Префикс `00..87`, включая оба счётчика, сохраняется.
Источник передаётся в portable API массивом **по значению**; native-профиль
отдельно ограничен непересекающимися буферами и `DF=0`. Биты NaN, infinity
и закодированных адресов являются данными и не интерпретируются.

Допуск профиля и raw-тега primary проверяется до изменения состояния.
По умолчанию перенос запрещён; прежний профиль `PcCapturedFiniteOwn1C`
также не допускает `24`. Его числовое enum-значение и прежняя операция
`1C` сохраняются. Профиль `PcCapturedRawOwn24` сам по себе не допускает `1C`.

Явный `PcCapturedFiniteOwn1CAndRawOwn24` разрешает обе отдельные операции.
После переноса собственный конечный допуск `1C` всё ещё проверяется до
изменения состояния. Квалификация последовательности `24→1C` ограничена
восемью конечными конфигурациями: знаковые нули, положительные и отрицательные
subnormal, отрицательные коэффициенты и независимые sentinel `FLT_MAX`.
В каждой конфигурации выполняются два вызова на одном receiver: состояние
после `24` передаётся `1C` без промежуточной перезаписи, источник сохраняется.
Это не устанавливает общий native ABI, поведение окружения FPU или solver `20`.
Наблюдаемый `AL=1` у оригинального wrapper не устанавливает исходную
C++-сигнатуру возврата.

Исходники: [класс](../../../Sparkplug/Code/Sparkplug/spContactConstraint.h),
[операция](../../../Sparkplug/Code/Sparkplug/spContactConstraint.cpp),
[наблюдаемые PC-смещения](../../../Sparkplug/Analysis/PC/spContactConstraintAbi.h).
Метод `20`, общий solver, базовый layout, Copy/Clone, владение, полный
жизненный цикл, PS2 и игровая интеграция остаются открытыми.
