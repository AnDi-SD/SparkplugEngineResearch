# spDXInputDevice

PC-основа конкретных DirectInput-устройств: Class ID `0x2C2F3993`,
регистрационная и установленная физическая база `spInputDevice`.
Регистрация не имеет factory; Clone наследует нулевой результат.
Слой восстановления общий для приложений; COM и реальные устройства
заменяются явно выделенной host-границей, сохраняющей порядок вызовов.

Конструктор `004D64A0` вызывает общий конструктор, устанавливает собственные
таблицы, обнуляет bytes `+44/+45`, words `+48/+50`, задаёт word `+80=3`
и byte `+84=1`. Область `+54..+7F` этим кодом не инициализируется.
Из глобального input manager берётся внешний указатель `+28`; он сохраняется
в `+4C`, затем вызывается его AddRef. Создание менеджера и аппаратная
инициализация находятся вне восстановленного конструктора. Наш вход
принимает эту зависимость явно и отклоняет отсутствующий указатель.

Деструктор `004D63E0` сначала вызывает Release ненулевого `+4C`. Затем,
если `+50` ненулевой, при ненулевом byte `+45` вызывает Unacquire устройства
и после этого повторно читает `+50` для Release. Повторное чтение сохраняет
наблюдаемую последовательность при изменении состояния внешним callback.
Освобождение общих списков следует после платформенных ссылок.

Оригинальная вторичная таблица этой основы содержит purecall; состояние
конкретной клавиатуры, мыши или gamepad здесь не придумывается. Восстановлены
подтверждённые поля, владение внешними ссылками, identity и общая
[маршрутизация кодов](sp-input-device.md). Создание настоящего устройства,
polling и именованные группы ввода остаются открытыми.

Исходники: [spDXInputDevice.h](../../../Sparkplug/Code/SparkplugPC/spDXInputDevice.h),
[spDXInputDevice.cpp](../../../Sparkplug/Code/SparkplugPC/spDXInputDevice.cpp).
