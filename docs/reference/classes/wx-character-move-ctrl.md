# wxCharacterMoveCtrl

`wxCharacterMoveCtrl` (`0x680838E4`) физически наследует
[wxEntity](wx-entity.md). PC factory `0x401640` возвращает объект `0x1C18` с
таблицей `0x6F64F8`; getter `0x4F5F10` возвращает запись `0x74E6C8`.
Таблица направляет слот `38` в `0x4F60D0`. Это тело сохраняет исходный
receiver и в конце вызывает `0x4D96A0` с тем же `this` по адресу `0x4F62DE`.
При конструировании native vptr проходит через `wxEntity` (`6F4EB8`), затем
становится `6F64F8`. Соседний `4D9700` — общий Copy `wxEntity`, а не
основание приписывать reset этой более короткой базе.

Восстановленная операция `ResetFieldsForAnalysis` имеет предполагаемое имя.
PC `0x4D96A0` обнуляет слова в порядке
`1BC,1C0,1C4,1B0,1B4,1B8,1C8,1CC,1D0,194,198,19C,188,18C,190`.
Первое слово записывается через исходный защищённый переход
`13B125C -> 13E78F0`, остальные четырнадцать видны в обычном suffix.
Полный исходный вызов с фабричным receiver завершён, включая переход;
первое слово установлено независимо от похожих inline-последовательностей PS2.
Назначения пяти групп по три слова остаются неизвестными. Операция не
выполняет float-арифметику и сохраняет все остальные байты receiver.

## Представленный post-state

Переносимый класс наследует настоящую общую реализацию `wxEntity`, однако
не воспроизводит полный native конструктор `0x1C18`, его внутренние ресурсы
или teardown. Единственный конструктор требует явный `CapturedPostState`:
исходное слово `spEntity+20`, представленные байты базы `28..123` и все
собственные байты `124..1C17`. Общая база сначала использует свой известный
constructor/host-контракт; затем указанные представленные данные копируются
из caller-owned снимка. Native padding, неинициализированные значения и
opaque handles остаются входными байтами, а не придуманными default.

Это отдельное переносимое хранилище: native bytes не накладываются на C++
объект, opaque handles не интерпретируются и не освобождаются как ресурсы.
Уничтожение переносимого хранилища и cleanup общей базы не квалифицируют
собственный native деструктор контроллера. Reset допускает объявленный
post-state с живым receiver; aliasing и конкурентные наблюдения остаются
отдельной границей.

RTTI сохраняет настоящий Class ID и базу. Его переносимый factory равен
null из-за неподдержанной полной конструкции; это не утверждение о native
abstract class. Clone возвращает null, Copy — false до изменений: успешный
унаследованный Copy базы потерял бы собственное состояние. Native Clone,
Copy, исходная конструкция, lifecycle, прочие контроллерные методы и PS2
исполнение остаются открытыми. Полнота класса не заявляется.

## Потребитель Minotaur Attack

Дополнительный профиль `PcMovementWithCapturedControllerReset` у
[wxMinotaurAttackAIAction](wx-minotaur-attack-ai-action.md) сохраняет прежнюю
конечную геометрию фазы 2. После перехода в фазу 3 и записи motion 0 он
заново читает владельца и получает заимствованную typed-привязку
`owner144 -> character12C` к этому post-state. Затем вызывает настоящую
общую операцию reset. Отсутствующая привязка оставляет
`UnqualifiedControllerReset`; успешной заглушки нет. Исходные три профиля
сохраняют прежнюю границу, включая защищённый entry-prefix в профиле
`PcCooldownAndFiniteMovement`.

Прямой original reset и полный original Minotaur Update с настоящим
фабричным контроллером проверены отдельно. Это не устанавливает concrete
actor/entity factory, общий игровой цикл, другие фазы Minotaur или полный
граф construction/ownership.
