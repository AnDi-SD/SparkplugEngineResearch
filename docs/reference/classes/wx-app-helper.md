# wxAppHelper

Координирует настройки приложения, операции с PCK, этапы запуска, обновление подсистем и их завершение. Class ID `41EB3DB5`, база — `spBaseObject` (`415352A1`). Переносимая реализация воспроизводит собственную логику PC; настройки PS2 представлены отдельно.

Исходники: [wxAppHelper.cpp](../../../Winx/Code/wxAppHelper.cpp), [интерфейс](../../../Winx/Code/wxAppHelper.h). Внешние службы подключаются через обязательный [wxAppHelperHost](../../../Winx/Analysis/Host/wxAppHelperHost.h). Фабрика без настроенного host недоступна.

## Объект и lifetime

Адреса и смещения в этой статье шестнадцатеричные, если явно не указано иначе.

| Свойство | PC | PS2 |
| --- | --- | --- |
| Размер | `98` | `98` |
| Constructor | `574EA0` | `277DF0` |
| Factory | `407460` | `3E7B60` |
| Destructor | `574F20`; deleting `575AA0` | `277D60` |
| Clone | `40D3A0` | `3E7AA0` |
| Основная vtable | `700728` | `495A90` |
| Вторичная vtable по `10` | `700724` | `495AB4` |
| Singleton | `755290` | GP-relative `-4478` |

Регистрационная база совпадает с физической основной базой. Вторичный подобъект управляет singleton, но его исходное имя не установлено. [PC ABI](../../../Winx/Analysis/PC/wxAppHelperAbi.h) и [PS2 ABI](../../../Winx/Analysis/PS2/wxAppHelperAbi.h) отделены от переносимого класса.

Constructor записывает себя в singleton, обнуляет слова `74`, `78`, `7C`, `80`, `88`, байты `84`, `8C` и устанавливает float `90`, `94` в 1. Область настроек и контекста `14`–`73` он не инициализирует. Переносимый класс хранит настройки как optional и отвергает обращение до их загрузки или явного задания. Его нулевые начальные context handles не являются установленными значениями оригинальной неинициализированной памяти.

Clone создаёт новый объект с начальным состоянием, регистрирует соответствие в clone manager и вызывает inherited Copy. Поля приложения не копируются. Новый экземпляр заменяет singleton. Destructor любого экземпляра безусловно обнуляет singleton; он сам не выполняет последовательность завершения всех подсистем. Эта последовательность — отдельный метод `ShutdownForAnalysis`.

## Настройки

PC-метод `575400` сначала устанавливает defaults, затем пытается прочитать `winx.ini`. Неудачное открытие оставляет defaults. Внешняя файловая операция включает создание потока, открытие, seek к концу, получение размера, seek к началу, чтение, закрытие и удаление потока. Разбор содержимого принадлежит самому классу.

| Смещение | Ключ | Тип | PC default | PS2 default |
| --- | --- | --- | --- | --- |
| `44` | showCinematics | byte | true | true |
| `45` | fullScreen | byte | true | true |
| `46` | useGamePad | byte | false | true |
| `47` | enableSound | byte | true | true |
| `48` | enableDialog | byte | true | true |
| `49` | enableShadows | byte | false | true |
| `4A` | loadFromPCK | byte | false | true |
| `4B` | buildPCK | byte | false | false |
| `4C` | firstPCKLevel | word | 0 | 0 |
| `50` | loadFromCD | byte | false | true |
| `54` | language | word | 0 | По системному языку |
| `58` | displayType | word | 0 | 1 |
| `5C` | territory | word | 0 | 1 |
| `60` | startLevel | word | 0 | 0 |
| `64`, `68` | Названия не установлены | word | 0 | 0 |
| `6C` | testCinematic | byte | false | false |
| `70` | cinematicToTest | word | 0 | 0 |

Разделители строк — CR и LF; пустые строки пропускаются. Разделение пары происходит по первому `=`. Пробелы не обрезаются, комментарии отдельно не распознаются. Ключи и именованные значения сравниваются без учёта регистра. Пустое значение не меняет default или предыдущую запись. Повторный ключ перезаписывает значение.

Boolean равен true, если **первый** байт — `t` или `T`: `turtle` также даёт true, а `1` и ` true` дают false. Language: `en=0`, `fr=1`, `de=2`, `it=3`, `es=4`; прочие строки дают 0. Display type: `PAL=1`, `NTSC=2`; territory: `eu=1`, `na=2`; неизвестное значение даёт 0. Числовые параметры используют десятичный `strtol` с пределами signed 32-bit и последующим сохранением битового представления в word.

Цикл сохраняет особое условие оригинала: перед очередной строкой прежнее значение числа оставшихся байтов должно быть больше 5. Внутри итерации оно пересчитывается как полный размер файла минус смещение и длина текущего токена. Значения длиной от 101 байта игнорируются. Нативный код копирует ключ до проверки длины; переносимый API принимает ключи короче 100 байт и явно отвергает более длинные. Это наша защитная граница, а не эмуляция опасного копирования в native буфер.

PS2-метод `2755C0` не читает этот INI: он устанавливает собственные defaults и вызывает системное получение языка `437BE0`. Системные значения в десятичной записи `1→0`, `2→1`, `3→4`, `4→2`, `5→3`; остальные дают 0. Этот путь представлен `PS2ConfigurationForAnalysis` и не объединяется с PC defaults.

## Пути и операции PCK

`FormatPackagePathForAnalysis` (`575150`) сначала рассматривает третий байт имени. Если это `1`…`9`, относительный путь получает префикс `<цифра>\`. Например, `CT1_test` превращается в `1\CT1_test`.

Затем независимо проверяются два флага текущего singleton:

1. `buildPCK` записывает `DATA\PCK\<имя>.txt`.
2. `loadFromPCK` записывает `DATA\PCK\<имя>.pck`, перезаписывая результат первого шага.

Если оба флага выключены, выходной буфер остаётся прежним. Переносимый интерфейс сохраняет это через изменяемый `std::string&`. Короткое имя без трёх читаемых байтов и переполнение временного буфера отвергаются явно.

`OpenPackageForAnalysis` (`575220`) форматирует путь, разрешает службу `75529C`, затем при buildPCK вызывает `45B950`, а при loadFromPCK — виртуальный slot `1C` службы `75DB9C`, передавая путь и mode. В конце снова разрешает `75529C`.

`ClosePackageForAnalysis` (`575300`) разрешает `75529C` до форматирования. При buildPCK вызывает `45B9D0` без имени; при loadFromPCK передаёт путь в `45BF10`; затем снова разрешает `75529C`. Проверки флагов выполняются заново после внешних вызовов. PC-операция запроса `5753E0` возвращает `-1`, а `576250` ничего не делает; для этих двух операций не выдумывается отсутствующая работа с файлами.

`LoadResourceTreesForAnalysis` (`574FE0`) открывает переданные имена с category 13, group 0, flags 0. При buildPCK предварительно сохраняет язык файловой службы, проходит языки 0–4 и для каждого открывает/удаляет все найденные потоки, затем возвращает прежний язык. Основной проход выполняется и после этой подготовки: поток передаётся внешнему loader, ненулевой результат добавляется службе `755270`, после чего поток удаляется. Null при открытии или загрузке не прекращает обход остальных имён.

`CheckOneLinersForAnalysis` (`5758B0`) активен при buildPCK. Для каждого из пяти языков открывается `AlfeaOL<язык>` с mode 0; среди 918 дескрипторов выбираются записи kind 79. Их имена разрешаются с category 17, group 0, capacity 500 байт. Проверка файла закрывает успешно открытый поток и удаляет его в обоих исходах; отсутствие файла диагностируется. Пакет закрывается, исходный язык восстанавливается после всех проходов.

`BuildInGamePackageForAnalysis` (`575A50`) при buildPCK открывает `InGame`, вызывает `5D45E0`, затем `5D2640`, закрывает пакет.

## Запуск и обновление

`InitializeForAnalysis` (`576820`) снимает active, подготавливает файловую службу и открывает `Init` с mode 1. Когда buildPCK выключен, между двумя вызовами `417C50` открываются `LOADSCRN`/1, `BLOOM`/2, `INGAME`/1, `SUBTITLE`/1. Поля `14` и `18` связываются с контекстом службы `75529C` по `58`. Затем выполняется последовательность создания/подготовки внешних объектов, настройки ёмкостей 2500 и 1024, запись 2 в глобальное поле `741654` и резервирование четырёх элементов общего контейнера.

`RunStageForAnalysis` (`576A90`) содержит 22 этапа. Индексы ниже десятичные. Исходные имена многих внешних методов неизвестны, поэтому они обозначены адресами, а не предполагаемыми названиями.

| Этап | Собственная последовательность |
| --- | --- |
| 0 | Резервирование scene storage; `7C=-1`; разрешение служб и вызовы `593860`, `4E28C0` |
| 1 | `5A0F20` |
| 2 | Разрешение двух служб через `40E050`, `4DB290` |
| 3 | `5539D0`, virtual `1C`, `4EC030`, `4F0360` |
| 4 | `55C470` |
| 5 | Передача showCinematics в байт `2C` внешнего объекта, затем `5845F0` |
| 6 | Последовательный поиск восьми объектов по ID и вызов их операций; у ID `28C56217` два вызова |
| 7 | Поиск `CCABEFEA`, затем `586FD0` |
| 8 | `417C50`, затем virtual `34` объекта game по `EC` |
| 9–13 | virtual `34` объектов game по `120`, `11C`, `114`, `10C`, `118` |
| 14 | Пустой этап |
| 15 | virtual `34` объекта game по `12C` |
| 16 | virtual `34` объекта game по `110`; закрытие `Init`; `417C50`, `573A00`, `4B9100(0)` |
| 17 | Открытие `MainMenu`/1; virtual `34` объекта game по `F4` |
| 18–20 | virtual `34` объектов game по `F8`, `FC`, `104` |
| 21 | Установка menuReady и закрытие `MainMenu` |

Любой индекс, включая неизвестный, возвращает true. `InitializeMenuForAnalysis` выполняет этапы 17–21 и ещё раз устанавливает menuReady. `ResetMenuForAnalysis` вызывает virtual `3C` объектов game по `F4`, `F8`, `FC`, `104` и снимает menuReady. Получение game выполняется для каждого объекта заново.

`UpdateForAnalysis` (`576270`) всегда возвращает true. При выключенном active обновляются только game (`596410`), служба `7552A0` (`4E2C40`) и virtual `1C` службы `755298`. При active и ненулевом countdown выполняется та же тройка; countdown уменьшается только если внешний байт `75528C→345` ненулевой. При active и нулевом countdown выполняется полный упорядоченный обход служб. Он включает шаг построения пакетов при buildPCK, передаёт время из `755274→7C` в `577B00` и завершается вызовом `413B40` для контекста `755298→44`.

## Пошаговое построение пакетов

`BuildPackagesStepForAnalysis` (`575DD0`) использует статическое состояние, общее для экземпляров. Оно сохраняется после уничтожения helper. Первый индекс — firstPCKLevel минус 1. Пока индекс равен этому начальному значению, очищается массив из 81 показателя памяти, даже если active ещё выключен.

При active выбирается следующий доступный игровой state либо следующий вариант текущей группы. Для уровней 27–29 используются варианты 2–7, для 30–32 — 5, для 33–35 — 8–9; для остальных выбранных states — 1. Выбранный вариант записывается в `765AD4→514`.

При существующем текущем state суммируются размеры внешних блоков памяти, сохраняется максимум для выбранного индекса и выдаются ненулевые показатели в MiB. Затем вызывается смена state `595450`; без текущего state используется `5953E0`. После запроса устанавливается задержка на 20 вызовов. Для индексов 3, 8, 13, 16, 36, 37 на остатке 15 вызывается virtual `24`, а на остатке 5 — virtual `20` соответствующей службы.

Достижение индекса 81 завершает проход: при необходимости освобождается текущий state, выполняются проверки one-liners и построение InGame, завершающие внешние операции и сообщение об окончании. Повторный шаг при индексе 81 ничего не делает.

## Завершение и границы host

`ShutdownForAnalysis` (`575AC0`) сначала вызывает `5975B0`, при выключенном buildPCK закрывает четыре общих пакета и снимает helper с внешнего владельца. Далее проверяет, удаляет и обнуляет singleton-службы в исходном порядке. Game проверяется дважды: уничтожение объекта между этими проверками может заново создать game. Сам helper удаляется внутри этой последовательности, после чего обход остальных служб продолжается. Переносимый метод заранее сохраняет host и после возможного удаления себя больше не обращается к полям объекта. Host должен пережить весь вызов.

Наш host использует числовые идентификаторы оригинальных PC globals, функций и virtual slots как **метки контрактов**. Это не адреса функций современного приложения. Handle имеет размер указателя; операции чтения pointer и word разделены. Значение `8000001C` у текстовой операции обозначает virtual slot `1C`. Неизвестные имена внешних методов не заменены придуманными API. Resolver должен наблюдать текущий singleton при каждом обращении; `create=false` читает его без создания.

Host обязан предоставить реальные внешние операции: файловые потоки, загрузку деревьев, игровые службы, контейнеры scene storage, callbacks и удаление объектов. Объединённые файловые операции сохраняют указанное владение; копирование имён ресурсов в `std::string` заменяет native временное выделение/освобождение. Разбор ASCII-настроек, optional для ещё не заданной конфигурации и guards буферов являются нашими адаптациями. Приложение также разрешает отсутствующий singleton перед вызовом методов, которые обращаются к нему.

Полная игровая сессия и реализации внешних служб этим классом не восстанавливаются. PS2 имеет собственные настройки, файловые операции и отличающиеся виртуальные смещения; её полный runtime-путь здесь не заявляется эквивалентным PC.
