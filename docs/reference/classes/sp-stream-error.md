# spStreamError

`spStreamError` (`0x4D2842F6`) — производный от [spError](sp-error.md) тип
на PC и PS2. Объект занимает `0x28` байт и не добавляет полей к базе:
код находится в `+0x10`, severity в `+0x14`, source/line в `+0x18/+0x1C`,
заимствованный diagnostic name в `+0x20`, ссылка цепочки ошибок в `+0x24`.

Общая реализация: [spStreamError](../../../Sparkplug/Code/SparkBase/spStreamError.h).
Размещение header/TU и имена portable-методов аналитические.

## Форматирование

Собственный formatter выбирает текст по коду причины:

| Код | Текст |
| ---: | --- |
| 4 | `Can't open stream` |
| 5 | `Stream not opened` |
| 6 | `Stream reached EOF` |
| 7 | `Stream already opened` |
| 8 | `Invalid seek in stream` |

Если diagnostic name непустой, к тексту добавляется ` (name)`. Для причины 4
нулевой указатель или пустая строка дают `Can't open stream (NULL)`.
Для остальных четырёх причин имя отсутствует без дополнительного суффикса.
Иные коды вызывают базовый formatter; собственное имя ошибки — `stream error`.
Severity и source добавляют унаследованные методы с виртуальным вызовом
собственного formatter.

Нативный formatter использует общий буфер из 256 байт и явно записывает ноль
в последний байт. Возвращаемый текст содержит не больше 255 байт. При длинном
имени закрывающая скобка может быть отсечена. PC и PS2 имеют одинаковую таблицу
текстов; PS2 пропускает код 9 к базе через дополнительный элемент jump table.
Эти причины независимы от глобальных [stream operation codes](sp-stream.md).

## Жизненный цикл и границы

Factory создаёт пустую ошибку. Clone регистрирует пару объектов и вызывает
пустой copy slot источника; код, severity, source, сообщение и цепочка остаются
значениями нового объекта. Destruction не владеет нативным diagnostic name.

Portable-код использует общую базу `spError`, RTTI и менеджер clone. Владение
сообщением через `std::string` и возврат отдельной строки — адаптация общего
ядра: она не повторяет перезапись общего нативного scratch buffer, его побочные
записи при переполнении или отсутствие реентерабельности. Связь причин с кодами
Win32 и полный жизненный цикл stream/error manager остаются отдельными задачами.
