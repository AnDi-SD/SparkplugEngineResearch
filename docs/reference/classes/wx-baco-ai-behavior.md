# `wxBacoAIBehavior` и общая база `wxBaseAIBehavior`

`wxBacoAIBehavior` имеет Class ID `11EE770A`; регистрационная база —
`wxBaseAIBehavior` (`457334F1`). Оригинальная цепочка конструкторов проходит
через `wxEntity`, `spEntity` и `spNamedObject`. Переносимая реализация находится
в [Baco](../../../Winx/Code/wxBacoAIBehavior.cpp) и
[общей базе](../../../Winx/Code/wxBaseAIBehavior.cpp). База реализована один
раз для будущих потомков; физический `wxEntity` пока представлен только
цепочкой RTTI и `spNamedObject`.

Размер оригинального объекта: PC `1C8` (456 байт), PS2 `1E0` (480 байт).
Различия полей описаны отдельно в [PC ABI](../../../Winx/Analysis/PC/wxBacoAIBehaviorAbi.h)
и [PS2 ABI](../../../Winx/Analysis/PS2/wxBacoAIBehaviorAbi.h). На PC factory
`406DA0`, vtable `6FFB60`, clone `40CE00`; на PS2 factory `3E8D70`,
constructor `228E30`, vtable `4961C0`, clone `3E8CB0`. PC factory,
clone и удаление обоих объектов исполнены в исходной игре; PS2 constructor
и vtable установлены статически.

| Поле Baco | PC | PS2 | Значение конструктора |
| --- | ---: | ---: | ---: |
| Два byte | `1B8/1B9` | `1C8/1C9` | `1/1` |
| Первый word | `1BC` | `1CC` | `500` |
| Второй word | `1C0` | `1D0` | `1500` |
| Два byte | `1C4/1C5` | `1D4/1D5` | `0/0` |

Назначение этих шести полей не установлено. Имена в переносимом коде
аналитические. Незаписанные байты native объекта оставлены непрозрачными.

Сравнение полных таблиц виртуальных методов с `wxBaseAIBehavior` даёт пять
собственных слотов Baco, помимо lifecycle:

| Индекс | PC | PS2 | Граница восстановления |
| ---: | ---: | ---: | --- |
| 14 | `567430` | `228960` | работа со сценой и сообщениями открыта |
| 15 | `566E70` | `2285D0` | проверка состояния и внешние вызовы открыты |
| 16 | `566F50` | `228400` | активный цикл и восприятие открыты |
| 17 | `5632B0` | `227820` | выбор действия `0` с передачей аргумента восстановлен |
| 22 | `566D20` | `228740` | обработка события `1E` и внешние службы открыты |

Слот 17 ищет ключ `0` и вызывает общий переход, передавая в него собственный
аргумент. Он не проверяет флаг блокировки. При отсутствии действия `0`
текущий указатель становится null. Это отдельный путь от базового селектора.
В PC слоте 14 наблюдаются создание `wxWanderAIAction` для ключа `1`,
`wxBacoAttackAIAction` для ключа `2` и `wxHurtAIAction` для ключа `3`;
сценовые этапы вокруг их создания ещё не восстановлены.

Общая база хранит текущее действие, сохранённый ключ и map `uint32 → action`.
Три значения базы при создании равны `125`, `400`, `700`: PC `18C/190/194`,
PS2 `19C/1A0/1A4`; единицы измерения не установлены.
Поиск ключей использует беззнаковый порядок. Выбор действия блокирует ненулевой
ключ при ненулевом флаге; отсутствующий ключ либо null в map приводит к
повторному поиску ключа `0`. Прежнее действие получает exit, затем обновляется
указатель current, затем новое получает enter с исходным параметром. Выбор того
же указателя тоже вызывает exit и enter. Принятый выбор возвращает true даже
при отсутствии резервного действия.

Изменение флага сравнивает и записывает только младший байт аргумента. При
разрешённом изменении и наличии текущего действия сохраняется ключ из самого
действия, после чего запрос выбора получает ключ `0` при включении флага либо
сохранённый ключ при выключении; параметр равен `0`. Если изменение запрещено,
новый байт совпадает со старым, нет текущего действия или установлен запрет
переключения, соответствующие шаги пропускаются. Последние два условия
проверяются уже после записи нового байта.

Переносимая map принимает явно привязанные **заимствованные** действия.
Встроенный `wxAIAction::vfunc_30` пока не принимает аргумент, поэтому для
действий с параметром используется собственный `wxBaseAIBehaviorActionBridge`.
Это адаптер проекта, а не оригинальный игровой класс. Клонирование пустого
контейнера проверено; перенос ненулевого контейнера и его владение остаются
открытыми. Также не восстановлены tick, Notify, нормальная привязка к сцене
и реакции Baco. Эти ограничения отражены в API, а не скрыты успешным тестом.

Свидетельства оригинального поведения и пределы проверок описаны в
[семействе AIBehavior](../../game/ai/ai-behavior-family.md). Переносимая проверка
`WinxBacoAIBehaviorTests` покрывает RTTI/factory, значения конструктора,
пустой clone, поиск, оба пути смены действия, fallback, порядок exit/enter
и блокировку ключей.
