# spGUIManager

Менеджер GUI движка, Class ID `0x73634C2D`, регистрационная база `spBaseObject`
(`0x415352A1`). Класс зарегистрирован на PC и PS2. Ниже описаны установленные
PC-идентичность и отдельные операции. Общие исходники
[spGUIManager](../../../Sparkplug/Code/Sparkplug/spGUIManager.h) реализуют
ограниченный PC-профиль focus/singleton и жизненный цикл с пустыми owned-view
полями. Это не полный GUI startup и не native layout класса.
Поведение этих операций на PS2 не установлено.

## Идентичность PC

| Элемент | Адрес |
| --- | --- |
| Factory | `00452380` |
| RTTI record / getter | `0075F758` / `00451C00` |
| Основная объектная таблица | `006E6D08` |
| Singleton | `0075DB8C` |
| Delete / singleton adjustor | `004524F0` / `00451C10` |
| Размер PC | `50` hex |

Регистрация связывает factory и Class ID. Getter возвращает указанный record;
singleton adjustor вычитает `10` hex. Создающая стадия EngineCore `0041B3B0`
вызывает GUI factory и сохраняет результат в core `+44`. Обновление EngineCore
`0041CD50` передаёт этот объект операции `00451F70`, которая вызывает
клавиатурную операцию `00451A00` с тем же receiver. Отдельный caller
`00437130` разрешает singleton перед `00451AD0`.

## Получатель и клавиатура

Операция `00451AD0` отправляет прежнему получателю уведомление `17`, назначает
новый указатель в GUIManager `+4C` и отправляет новому уведомление `16`.
Повторное назначение того же получателя выполняет обе операции.

Оба уведомления используют один синхронно заимствованный mutable frame.
Для каждого заново назначаются code, sender и остальные известные нулевые
поля. Старый callback видит прежний `4C`; затем исходный desired pointer
перезаписывает изменения этого поля. Изменения `4C`, сделанные новым callback,
сохраняются. Возврат foreign Notify не интерпретируется. Source напрямую
вызывает настоящий `vfunc_0C` получателя, без успешного Host-focus callback.
Фокус заимствованный: назначение не удерживает и не освобождает получателей.
Они должны оставаться живы при каждом последующем обращении к сохранённому
указателю. Уничтожение/неограниченная рекурсия из callbacks не квалифицированы.

Аналитический предел в128 вложенных focus calls останавливает оставшийся
prefix с `ReentryLimit`. Это не native false return. Отказ вложенного вызова
передаётся внешним кадрам; уже завершённые callback effects сохраняются.

Factory-профиль подтверждает null focus и публикацию созданного primary
pointer в singleton после возврата constructor. Native-owned `14/18/1C`
пусты; их типы/заполнение не воспроизводятся этой реализацией. Empty destructor
не вызывает Notify и не освобождает focus receiver. Он безусловно очищает
singleton, даже если уже жив другой, более новый manager. Copy — inherited
literal Base no-op; Clone создаёт fresh manager, публикует его singleton,
регистрирует пару и выполняет этот Copy, сохраняя fresh null focus.

Portable class не назначает смысл/значения остальным native полям. В частности,
input member `24` остаётся отдельной неподтверждённой producing dependency;
constructor-internal callback/publication timing и nonempty view teardown
не следуют из focus/default-профиля. `SetFocusStateForFixture` вводит уже
разрешённый pointer без notification/ownership и не заменяет producer.

Операция `00451A00` требует ненулевые GUIManager `+24` и получателя `+4C`.
У объекта из `+24` вызывается интерфейс по `+14`: slot `04` проверяет нажатие,
slot `08` — изменение клавиши. Физический тип этого объекта остаётся отдельной
границей. Клавиши `28` или `34` выбирают альтернативную таблицу символов;
проверяются индексы `0..99`. Таблицы находятся по `00740170` и `007401D8`.

Для нажатой изменённой клавиши ненулевой символ даёт уведомление `13`,
нулевой — `14` с индексом. Отпущенная клавиша с нулевым символом даёт `15`;
для ненулевого символа уведомления отпускания нет. Sender — GUIManager.
Это GUI-ввод; эти операции не принадлежат
[spNetworkManager](sp-network-manager.md).

Полный constructor/destructor graph, платформенное подключение ввода
и прочие GUI-операции не считаются восстановленными по этим фактам.
