# wxMinotaurDefenseState

Class ID `5D337CF8`, физическая и регистрационная база `wxCharacterState`.
PC и PS2 выделяют `0x44` байт, selector `10` равен `8`. Конструктор обнуляет
byte `3C`; padding `3D..3F` и pointer `40` остаются неинициализированными.
[Заголовок](../../../Winx/Code/wxMinotaurDefenseState.h),
[реализация](../../../Winx/Code/wxMinotaurDefenseState.cpp).

Вход `1C` и выход `20` совпадают по операциям с
[wxShadowBeastDefenseState](wx-shadow-beast-defense-state.md). PC использует
одни и те же машинные тела для обоих классов, PS2 — отдельные тела. Вход
применяет `(key & F0200180) | 00200180`, запускает mode=false и после playback
обнуляет byte `3C`. Завершение входа уведомляет `27D1`, вызывает контроллер
`(1,1)`, затем вызывает базовый вход с виртуальным update. Первая фаза выхода
уведомляет `27D2`, вызывает контроллер `(0,1)`, освобождает pending и применяет
`(key & F0400180) | 00400180`. Повторный выход ждёт consuming completion.
Ожидающие переходы очищают control word `4` и возвращают false.

Update `30` сначала захватывает control `owner12C` на PC / `owner138` на PS2.
При motion `control4 > 0.1` пишет в тот же объект float32 `0.01`
(`3C23D70A`) и задаёт mode `50`; иначе пишет нулевое слово и задаёт mode `0`.
После этого применяет `(key & F00001F0) | 00000180` и ищет анимацию.
Запись control происходит даже при совпадении handle.

Если handle изменился и byte `3C` ненулевой, update потребляет completion
старого pending и нормализует byte в `!complete`. Пока byte остаётся ненулевым,
новая анимация не запускается. Когда блокировка снята, освобождает pending.
Для mode `50` ставит byte `3C=1` **до playback**, запускает mode=false;
для остальных режимов запускает mode=true. В обоих случаях interrupt=true,
после playback сохраняется новый handle. Совпадение handle не потребляет
completion и не нормализует byte.

PC unordered-сравнение motion выбирает нулевую ветвь. Численная область PS2
ограничена обычными конечными float32 и знаковыми нулями; NaN, infinity и
denormal для PS2 не квалифицированы.

[Host](../../../Winx/Analysis/Host/wxMinotaurDefenseStateHost.h) передаёт
заимствованные control, получателя и контроллер. Наследование host-интерфейса
служит повторному использованию одинаковых внешних вызовов и не означает
физического наследования одного игрового состояния от другого. Pointer `40`
требует явной внешней привязки, неизвестная память представлена optional.
Reset сохраняет собственные поля; Copy пуст; clone оставляет контроллер
непривязанным и byte `3C=0`.

Проверка — `WinxMinotaurDefenseStateTests`: переходы, consuming completion,
порог motion, блокировка, порядок внешних вызовов, Reset и clone. Полная
интеграция владельца, consumer и контроллера остаётся открытой.
