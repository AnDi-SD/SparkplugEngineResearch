# `spNetworkMatchmaking`

PC-объект обработки входящих данных соединения с matchmaking server.
Class ID — `0x18B864AC`, регистрационная база — `spBaseObject` (`0x415352A1`).
Физическая объектная база находится в начале объекта; дополнительного
объектного интерфейса в подтверждённом layout нет. В известном каталоге PS2
этот класс отсутствует; реализация PC не приписывается PS2.

Общая реализация — [spNetworkMatchmaking.h](../../../Sparkplug/Code/Sparkplug/spNetworkMatchmaking.h)
и [spNetworkMatchmaking.cpp](../../../Sparkplug/Code/Sparkplug/spNetworkMatchmaking.cpp),
в составе `SparkNetwork`. [PC ABI](../../../Sparkplug/Analysis/PC/spNetworkMatchmakingAbi.h)
отделён от переносимого C++ layout. Путь исходного файла, объявления и исходные
имена операций не установлены; `ForAnalysis` обозначает наши имена.

## Поля и жизненный цикл

Объект PC занимает `0x34` (52 байта). Его таблица содержит семь объектных
слотов: удаление, уведомление, Clone, Copy, RTTI getter и два запроса типа.
Close и Pump — отдельно вызываемые операции, без дополнительных слотов этой таблицы.

| PC offset | Поле | Начальное состояние |
| --- | --- | --- |
| `00–0F` | объектная база | инициализация `spBaseObject`; padding не обнуляется |
| `10` | собственный `spSocketStream` | новый объект |
| `14` | собственный `spMemoryStream` | новый пустой поток |
| `18` | служебное слово `std::string` | constructor не записывает |
| `1C–2B` | inline storage строки | первый байт `0`, остальные не инициализируются |
| `2C`, `30` | размер и ёмкость строки | `0`, `15` |

Назначение строки `18–33` остаётся неизвестным. В подтверждённых операциях
класса она не используется как адрес сервера или настройка протокола.

Constructor инициализирует базу и пустую строку, создаёт `spMemoryStream`,
затем `spSocketStream`. Destructor удаляет memory stream первым, socket stream
вторым, обнуляя каждый указатель, затем освобождает строку и базу.
Собственную операцию Close destructor не вызывает: закрытие socket service
при удалении принадлежит его собственному жизненному циклу.

Уведомление объекта — унаследованный no-op. Copy возвращает true и не копирует
состояние. Clone создаёт новый экземпляр через текущую factory-среду,
регистрирует пару и вызывает виртуальный Copy источника. Новый объект получает
собственные свежие потоки и пустую строку; данные источника сохраняются.
Если виртуальный Copy возвращает false, созданный клон удаляется.

## Закрытие соединения

Close вызывает виртуальный Close socket stream. При ненулевом результате
сразу возвращает true. При отказе разрешает текущий `spNetworkManager`, включая
его lazy factory при null global, и читает указатель debug по `+70`.
При наличии debug пишет сообщение уровня `0` с категорией `spNetworkMatchmaking`:
`Closing connections with MM server failed`. Затем возвращает false.
Memory stream и неизвестная строка здесь не меняются.

## Обработка входящих данных

Pump читает byte соединения вложенного network объекта socket stream.
При нуле или отсутствии memory stream завершает работу. Любое ненулевое
значение byte разрешает обработку. Возвращаемый регистр этой операции
не объявляется логическим результатом.

При разрешённой обработке:

1. Открывает memory stream с диагностическим именем `MM TCP packet buffer`;
   результат Open игнорируется.
2. Вызывает приём socket stream в этот memory stream.
3. При успешном приёме читает размер и выполняет одну из двух ветвей ниже.
4. Закрывает memory stream, в том числе после отказа приёма. Результат Close
   игнорируется. Закрытие освобождает буфер, сохраняя имя, ёмкость и счётчики
   согласно общему поведению [spMemoryStream](sp-memory-stream.md).

**Нулевой размер.** Сначала разрешается текущий NetworkManager и проверяется
его debug. При наличии debug вызывается второй getter того же текущего
менеджера, затем журнал уровня `1`: `0 byte received, connection closed`.
Второй debug не проверяется на null. Далее вызывается собственный Close;
его результат игнорируется. Отказ Close может дополнительно создать сообщение
уровня `0`. При отсутствии debug Close всё равно вызывается.

**Ненулевой размер.** Размер читается ещё раз, затем берётся буфер и выполняется
рассылка дочерним объектам:

| Поле уведомления | Значение |
| --- | --- |
| `code` | `0x22` |
| `word04`, `word08`, `word0C`, `word14` | `0` |
| `sender` | matchmaking объект |
| `word18` | заимствованный указатель на буфер |
| `word1C` | результат второго чтения размера |

Это синхронная передача заимствованных данных. После завершения Pump обычный
буфер уже освобождён; получатель, которому нужны данные позже, должен сохранить
их самостоятельно.

После рассылки строится dump по **первому** размеру: каждый байт форматируется
как `%02X `, затем добавляется пустая строка. Для `00 80 FF` аргумент журнала
равен `00 80 FF `. При построении каждого байта буфер запрашивается снова,
поэтому изменения подписчика могут влиять на dump. Затем разрешается текущий
debug; при наличии выводится `Packet Content:%s`, уровень `1`.

Отказ приёма, включая частично заполненный поток, не создаёт уведомления,
dump или вызова собственного Close. Memory stream всё равно закрывается.
Внутри класса не установлены разбор session protocol, поиск серверов,
назначение адреса или самостоятельная отправка запроса.

## Граница общего компонента

[spNetworkMatchmakingHost](../../../Sparkplug/Analysis/Host/spNetworkMatchmakingHost.h)
предоставляет создание, удаление, состояние и операции чужого socket stream,
разрешение текущего debug, журнал и дочернюю рассылку. `spMemoryStream`
используется из общего восстановленного кода. Factory и Clone требуют
назначенного host. Существующий экземпляр сохраняет своего host при замене
factory-среды; Clone использует новую среду.

Переносимые защиты отвергают отсутствие host или обязательного socket service.
Если подписчик уничтожил буфер или уменьшил его ёмкость ниже читаемого индекса,
построение dump бросает исключение. Это наша защита от невалидного доступа,
а не поведение игры. Изменение содержимого существующего буфера сохраняется.
Native ошибки выделения памяти, exception rollback и удаление самого объекта
во время рассылки остаются вне подтверждённой области.

`SparkplugNetworkMatchmakingTests` проверяет создание, RTTI, Copy/Clone,
закрытие, повторный Pump, ошибки, нулевые и ненулевые ответы, поля уведомления,
изменение буфера подписчиком и владение host. Настоящие сокеты, конкуренция
потоков и полная интеграция с `spNetworkManager` этими проверками не закрыты.
