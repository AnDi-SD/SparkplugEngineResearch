# `wxWayToGoState`

`wxWayToGoState` (Class ID `4623876A`) — состояние с selector `0`, зарегистрированное как потомок `wxCharacterState`. Восстановленные собственные операции находятся в [Winx/Code](../../../Winx/Code/wxWayToGoState.cpp). На PC и PS2 размер исходного объекта — `3C`; дополнительных полей после общей базы нет. Переносимый C++ layout отличается от исходного ABI.

| Операция | PC | PS2 |
| --- | ---: | ---: |
| Фабрика | `5A6790` | `2D5850` |
| Vtable | `706850` | `493740` |
| Вход, PC slot `1C` | `5A6870` | `2D5570` |
| Обновление, PC slot `30` | `523690` | `2D5560` |
| Проверка перехода, PC slot `34` | `5A6770` | `2D56B0` |

Вход меняет ключ caller-owned запроса на `key & F0007F80`, запрашивает анимацию через профиль owner и запускает её с `mode=false`, `interrupt=true`. Старый pending handle перед этим не освобождается. Новый handle записывается только после запуска. Затем у внешнего control-объекта последовательно обнуляются byte `61` и word `4`. Метод возвращает `true`, без ожидания завершения анимации и без изменения once-флагов.

Обновление `30` только очищает word `4` control-объекта. Оно сохраняет ключ, handle и остальные поля. Проверка перехода разрешает любой target при нулевом handle; иначе возвращает результат потребляющего запроса завершения `(handle, true)`. Номер target на результат не влияет. Остальные hooks наследуются от [wxCharacterState](wx-character-state.md).

Copy унаследован от `spBaseObject`: собственное runtime-состояние и привязки не переносит. Clone регистрирует новый объект и вызывает этот Copy, поэтому selector, flags и handle остаются значениями свежего конструктора. Деструктор не останавливает анимацию; сброс базы очищает handle без stop/fade.

[wxCharacterControlStateHost](../../../Winx/Analysis/Host/wxCharacterControlStateHost.h) подключает игровые lookup/playback/completion и control-объект. На PC control расположен по `owner+12C`, на PS2 — по `owner+138`. Смысл byte `61` и исходные имена hooks остаются неизвестными. [C++ проверка](../../../Winx/Tests/wxControlStateTests.cpp) охватывает собственные операции и общий жизненный цикл; полная привязка к игровой сцене остаётся внешней зависимостью.
