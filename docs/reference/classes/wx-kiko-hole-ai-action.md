# wxKikoHoleAIAction

`wxKikoHoleAIAction` (Class ID `872B81BB`) физически наследует
[wxAIAction](wx-ai-action.md). Переносимая
[реализация](../../../Winx/Code/wxKikoHoleAIAction.cpp) описывает ограниченные
собственные Notify и Update. Она принимает явное состояние после construction;
нативные factory, защищённый constructor, привязка обратных ссылок и полный жизненный цикл
не воспроизводятся.

| Идентичность | PC | PS2 |
| --- | --- | --- |
| Размер | `3BC` | `3C0` |
| Factory | `403F80` | `3F08A0` |
| Vtable | `6F9D28` | `499310` |
| RTTI record | `751008` | `4C7DF0` |
| Notify | `522120` | `2E9F70` |
| Update | `5222B0` | `2E9D90` |

PS2-идентичность сохраняется как отдельное статическое свидетельство;
переносимый профиль ниже предназначен для PC. Точные PC offsets и slots
отделены в [ABI](../../../Winx/Analysis/PC/wxKikoHoleAIActionAbi.h).

Собственное состояние PC содержит заимствованные Node по `3A8/3AC`,
word `3B0`, фазу `3B4` и однократный latch `3B8`. Исходные имена неизвестны.
Node передаются типизированно, без преобразования 32-битных адресов игры
в указатели host. Word `3B0` хранится как raw payload; для совпадающего
ненулевого родителя предусмотрена отдельная явная host-связь. Дополнительные
AddRef/Release на этих связях в переносимом профиле не выполняются.

Вход Notify — явный **raw32 frame PC**: 32-битный code по `00`, raw word
payload по `18` и младший byte флага по `1C`. Он не взаимозаменяем с
pointer-sized логическим `spNotificationForAnalysis` на x64. Подписка и
generic broadcast в этот профиль не входят; общая система notifications
не адаптируется неявно. Для неизвестного code достаточно первых четырёх
читаемых байтов.

Notify `2738` проверяет только младший byte сообщения по `1C`. Ненулевое
значение копирует word `18` в `3B0` и выбирает фазу `2`; ноль выбирает фазу
`3`, сохраняя `3B0`. В обоих случаях latch сбрасывается в ноль. Notify
`2721` при **полном word** `18 == 19` сначала ставит фазу `1`, затем
выключает собственный plain Node и его потомков через общую реализацию
`spNode::SetEnabledForAnalysis(false, true)`. Latch сохраняется. Другие
сообщения не вызывают базовый Notify и не читают неизвестный payload.

Update фазы `1` при нулевом latch выключает Node рекурсивно, после чего
ставит latch в `1`. Фаза `3` при нулевом latch получает текущую команду
через заимствованную цепочку owner `144` → character `130`, обнуляет byte
команды `1B`, затем ставит latch в `1`. Повторный Update при ненулевом
latch не повторяет эффект. Фазы вне `1..3` возвращают true без собственных
эффектов. Фаза `2` с ненулевым latch также ничего не делает.

Активная фаза `2` поддержана при raw word `3B0 == 0` и отсутствии
parent у собственного plain Node. Это равенство null/null пропускает native
detach/reparent и parent Update. Метод включает Node и потомков через общую
`SetEnabledForAnalysis(true, true)`, заново получает текущую команду через
owner, ставит её byte `1B` в `1`, затем ставит latch в `1`. Последовательность
Notify `2738` с ненулевым flag и нулевым payload → Update использует те же
собственные методы.

Для равенства с ненулевым родителем caller явно передаёт
`equalParentBinding`: захваченное ненулевое 32-битное значение и заимствованный
типизированный parent. До эффектов проверяются совпадение raw `3B0` с этим
значением и текущего parent собственного Node с переданным объектом. В этом
ограниченном host-профиле parent — plain корневой Node с одним ребёнком,
собственным Node действия; его поддерево содержит не более четырёх plain Node.
Проверки типов, размера и согласованности связей — аналитическое ограничение,
а не дополнительные native проверки. Все объекты остаются живыми и стабильными
на время вызова. Native32 значение никогда не преобразуется в указатель.

При таком равенстве выполняются те же enable/command/latch операции.
Сам parent не включается, не обновляется и не перепривязывается. Notify
`2738` сохраняет только raw payload; он не создаёт и не обновляет binding.
Отсутствующая, несовпадающая или устаревшая связь отказывает до эффектов.
Разные родители, reparent и произвольное разрешение адресов остаются открытыми.

Entry и Clone/Copy имеют явный отказ. Отсутствующий
Node/command — аналитический отказ, а не воспроизведение native crash.
Для Notify `2721/19` фаза `1` уже записана до обнаружения отсутствующего
Node. [Host](../../../Winx/Analysis/Host/wxKikoHoleAIActionHost.h) предоставляет
только доступ к данным команды; он не выбирает исход неизвестного игрового
метода. Общий helper `410050` добавляет указатель действия в optional список
поля BaseObject `04`; это не keyed Subscribe у `spSubscriptionManager`.
Общий [компонент списка](../../../Sparkplug/Code/SparkBase/spBaseObjectReferrers.h)
поддерживает добавление и очистку через явный контекст. Его привязка к
типизированному receiver в Kiko Entry, reparent `421A60`, parent Update,
constructor, derived teardown, PS2-исполнение и игровая интеграция остаются
открытыми.

[Проверка](../../../Winx/Tests/wxKikoHoleAIActionTests.cpp) содержит отказы
на незавершённые операции и replay входов ограниченного PC-профиля.
Наличие исходника не означает полноту класса или готовность AI в игре.
