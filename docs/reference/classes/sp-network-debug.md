# `spNetworkDebug`

PC-отладчик сетевой подсистемы: файловый и консольный журнал, вывод частоты
кадров и текстовый дамп `spNetworkPacket`. Class ID — `0x178ABAB6`;
регистрационная и физическая база — `spBaseObject`. Отдельного PS2-класса
в известном каталоге нет; это не доказывает отсутствие сетевого кода PS2.

Общая реализация — [spNetworkDebug.h](../../../Sparkplug/Code/Sparkplug/spNetworkDebug.h)
и [spNetworkDebug.cpp](../../../Sparkplug/Code/Sparkplug/spNetworkDebug.cpp).
[Описание PC ABI](../../../Sparkplug/Analysis/PC/spNetworkDebugAbi.h) отделено
от переносимого C++ layout. Исходные имена методов и путь файла неизвестны:
названия с `ForAnalysis` обозначают восстановленное поведение.

## Поля PC

Размер объекта — `0x64` (100 байт). Его vtable содержит семь объектных слотов
и два дополнительных: запуск и остановку. Timer расположен внутри объекта,
а не является базой `spNetworkDebug`.

| Offset | Содержимое | Начальное значение |
| --- | --- | --- |
| `00–0F` | `spBaseObject` | общая инициализация базы |
| `10` | byte: консольный вывод | `0` |
| `11` | byte: файловый вывод | `0` |
| `12` | byte: назначение неизвестно | `0` |
| `13` | byte: признак подписки | `0` |
| `14` | собственный поток журнала | null |
| `18` | собственное хранилище блокировки | новый объект `0x1C` |
| `1C–37` | `std::string`, включая служебное слово `1C` | пустая строка, размер `0`, ёмкость `15`; `1C` не записывается |
| `38–5B` | встроенный `spTimer`, размер `0x24` | активен; накопление `0`, старт — `timeGetTime`; ограничение выключено |
| `5C` | заимствованный контекст экранного вывода | null |
| `60` | signed int32: уровень журнала | `1` |

Поле `12`, padding, незаписанное служебное слово строки и исходный тип контекста
не получают придуманных значений. Переносимый компонент использует собственные
типы хранения и явную установку внешних управляющих полей.

## Создание, копирование и остановка

Constructor создаёт блокировку и запускает встроенный таймер. Start снова
записывает время старта, устанавливает активность и создаёт блокировку, если
её уже освободили; возвращает true и не обнуляет накопленное время.

Clone вызывает текущую factory среды, регистрирует пару объектов и выполняет
унаследованный успешный no-op Copy. Настройки, поток, строка, контекст и время
источника не копируются. Прямой Copy, включая self-copy, не меняет получателя.

Stop выполняет операции в следующем порядке:

1. Прибавляет unsigned `timeGetTime() - start` к накоплению и выключает таймер.
2. Закрывает поток, если файловый вывод включён, и удаляет поток.
3. Обнуляет признак файлового вывода.
4. Освобождает хранилище блокировки и обнуляет указатель.
5. При установленном `13` удаляет подписку через внешний менеджер и обнуляет `13`.

Stop не проверяет активность таймера: повторный вызов снова прибавляет время
от прежнего старта. Консольный флаг, `12`, строка, контекст и уровень сохраняются.
Destructor выполняет Stop и освобождает строку и базу. Хранилище блокировки
освобождается напрямую: её destructor/`DeleteCriticalSection` здесь не вызывается.
Переносимый host получает отдельную операцию `FreeLockStorage`.

## Файловый и консольный журнал

Включение файла нормализует byte-флаг в `1`. Только при отсутствии потока
создаёт путь `LogDirectory + suffix`, создаёт поток, вызывает `Open(4, path)`
и `Seek(1, 0)`. Результат Open игнорируется, включая отказ. Отключение
обнуляет флаг и закрывает поток, сохраняя объект. Повторное включение
сохранённого закрытого потока **не открывает его заново** и игнорирует новый путь.
Повторное отключение снова вызывает Close.

Log пропускается, если signed уровень сообщения больше `60` либо оба
флага вывода равны нулю. В остальных случаях:

1. Входит в блокировку `18`.
2. Форматирует сообщение через импортированный `_vsnprintf` с capacity `8191`.
3. Получает часы движка: `rawTicks / divisor + bias`, с unsigned 32-bit wrap.
4. Собирает строку `category + " : " + signed timestamp + " : " + message + LF`.
5. При включённом файле вызывает запись строки с аргументом `0`.
6. При ненулевом консольном флаге выводит ту же строку.
7. Выходит из блокировки.

Timestamp форматируется через `%d`: значения от `80000000` печатаются
отрицательными. Завершение строки — один byte `0A`. Последняя строка остаётся
в объекте и сохраняется после Stop. `LogTextForAnalysis` — дополнительный
вход после форматирования CRT; он выполняет ту же сборку и вывод.

## Частота кадров и уведомления

Notification читает первый uint32 контекста; код `0x1A` вызывает экранный вывод.
Другие коды ничего не меняют. Если встроенный таймер активен, вывод сначала
останавливает и снова запускает его. Затем вычисляет
`elapsed = accumulated / globalDivisor` и float32 `1000 / elapsed`.
После этого сбрасывает накопление в `0` и снова запускает таймер, даже если
на входе он был остановлен.

Число передаётся в импортированный формат `Frame per second: %f`.
Рисование получает `x = 600`, `target = context->field14 + 0x190`, текст
и последний аргумент `0`. При нулевом elapsed результат — положительная
бесконечность; её текстовое представление зависит от внешнего CRT.
Контекст `5C` должен быть назначен до вызова этой операции.

## Дамп пакета

При уровне объекта меньше `2` дамп пропускается. Иначе он выдаёт семь строк
категории `spNetworkPacket`, каждая с уровнем `2`:

| Порядок | Текст сообщения |
| --- | --- |
| 1 | 45 символов `-` |
| 2 | `Source:      %X` |
| 3 | `Destination: %X` |
| 4 | `Type:        %d` |
| 5 | `Data Size:   %d` |
| 6 | `Data:        %s` |
| 7 | 45 символов `-` |

Поля читаются как uint16; данные — последовательность `%02X `, включая
завершающий пробел. Пустые данные дают пустую строку после префикса.
Дополнительного переноса внутри данных нет. TCP-флаг и два uint32-поля
пакета здесь не выводятся.

Каждая строка адресуется заново найденному `engine+70`, который может быть
другим отладчиком или null. Начальная проверка уровня относится к вызывающему
объекту; дальнейшая фильтрация — к получателю каждой строки.

## Платформенная граница

[spNetworkDebugHost](../../../Sparkplug/Analysis/Host/spNetworkDebugHost.h)
явно предоставляет часы, блокировку, поток, CRT, консоль, внешнюю подписку,
экранный контекст и получателя дампа. Factory без аргументов и Clone требуют
назначенного общего host; отсутствие host вызывает явную ошибку. Существующий
объект сохраняет своего host при замене factory-среды.

Проверка компонента — `SparkplugNetworkDebugTests`. Проверяются завершённые
операции, порядок внешних вызовов, точные строки, поля и освобождение владельцев.
Это не проверка настоящего файлового backend, работы экрана или конкуренции
потоков. Полный standalone `spTimer` и его ограниченный режим не объявляются
восстановленными этим компонентом.

Путь оригинала ограничен стековым буфером 200 байт; сообщение с не найденным
terminator после `_vsnprintf`, null-поток, нулевой divisor, null-контекст и
невалидные указатели находятся вне подтверждённой переносимой области.
Host-защиты явно отвергают длинный путь, длинное сообщение и отсутствующие
обязательные службы. При исключении внешнего форматирования, часов или записи
переносимая обвязка освобождает занятую блокировку; оригинальная SEH-ветвь
таким проверкам не приписывается. Null notification переносимо игнорируется; исходный
метод его разыменовывает. Защиты не выдаются за поведение игры.
