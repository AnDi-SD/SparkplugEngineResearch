# `spNetworkManager`

PC-менеджер сетевых служб, очереди пакетов, уведомлений и сетевого ввода.
Class ID — `0x0546DEC1`, регистрационная база — `spBaseObject` (`0x415352A1`).
В известном каталоге PS2 соответствующего класса нет; поведение PS2 не выводится
из реализации PC.

Общий компонент — [spNetworkManager.h](../../../Sparkplug/Code/Sparkplug/spNetworkManager.h)
и [spNetworkManager.cpp](../../../Sparkplug/Code/Sparkplug/spNetworkManager.cpp),
в составе `SparkNetwork`. [PC ABI](../../../Sparkplug/Analysis/PC/spNetworkManagerAbi.h)
отделён от переносимого C++ layout. Исходные объявления, имена методов и путь
файла не установлены; `ForAnalysis` обозначает наши имена восстановленных операций.

## Поля и интерфейсы

Объект занимает `0x1CC` (460 байт). Основная таблица содержит семь объектных
слотов и две операции: запуск и остановку. По `+10` находится дополнительный
singleton-интерфейс: его delete adjustor вычитает `0x10` и удаляет полный объект.
Имя этого исходного C++ типа и форма его объявления остаются неизвестными.

| PC offset | Поле | Начальное состояние |
| --- | --- | --- |
| `00–0F` | объектная база | общая инициализация `spBaseObject` |
| `10` | singleton-интерфейс | собственная таблица менеджера |
| `14`, `15`, `16` | запуск, byte неизвестного назначения, разрешение пересылки | `0`, `0`, `0` |
| `18` | категория журнала | `Network Manager` |
| `1C`, `20`, `24` | собственные server, peer, matchmaking | null |
| `28–37` | блокировка и связная очередь | блокировка, пустой sentinel, count `0` |
| `38`, `54` | bytes неизвестного назначения | `0` |
| `3C–50`, `58–6C` | управляющие слова | `0`; `4C` используется как заимствованный получатель |
| `70`, `74`, `78`, `7C` | debug, текущий пакет, controller, статистика | null |
| `80` | signed код ошибки | `0` |
| `84–19B` | десять `std::string` ошибок, по `0x1C` | тексты ошибок |
| `19C`, `1A0` | собственные блокировка ошибки и таймер | null |
| `1A4`, `1A8` | поправка времени и неизвестное слово | `0` |
| `1AC` | uint16 unique ID | `0` |
| `1B0–1CB` | `std::string` неизвестного назначения | пустая строка |

Padding и служебные незаписанные слова STL не получают придуманных значений.
Статистика, создаваемая при запуске, содержит 28 uint32, первоначально нулевых.
Имена отдельных счётчиков не объявляются исходными именами полей.

Constructor назначает глобальный текущий менеджер. Destructor безусловно
обнуляет этот global, даже если другой объект успел его заменить. Clone создаёт
новый менеджер через текущую factory-среду и регистрирует пару: унаследованный
Copy возвращает true и ничего не копирует. Источник, его службы и настройки
сохраняются; клон получает начальное состояние и становится текущим менеджером.

## Запуск и остановка

Повторный Start при ненулевом `14` возвращает false. Первый Start:

1. Создаёт debug, запускает его и включает файл `SparkNet.txt`.
2. Создаёт server и передаёт ему очередь менеджера.
3. Создаёт peer и записывает его ID `0`.
4. Создаёт controller, нулевую статистику, таймер и блокировку ошибки.
5. Создаёт matchmaking, обнуляет ошибку под её блокировкой, устанавливает `14 = 1`.

Stop сначала удаляет server. Затем под блокировкой извлекает элементы очереди,
пока извлечённый указатель не станет null. **Удаляются только узлы очереди;
оставшиеся пакеты не уничтожаются.** Null-элемент посреди очереди прекращает
очистку раньше конца. Это поведение оригинала сохранено; переносимый host может
учитывать оставшиеся пакеты отдельно.

Далее удаляются peer, controller, статистика и таймер; напрямую освобождается
хранилище блокировки ошибки; удаляется matchmaking. При наличии matchmaking
обнуляется `15`. Затем обнуляются `16` и unique ID, удаляется debug и
обнуляется `14`. Получатель `4C`, текущий указатель `74`, код ошибки, поправка
времени и неизвестные управляющие слова здесь не сбрасываются.

Destructor дополнительно освобождает строку, десять текстов ошибок, хранилище
блокировки очереди, sentinel и базу. Обе блокировки менеджера освобождаются
без вызова их destructor/`DeleteCriticalSection`.

## Ошибки и соединение

Запись ошибки выполняется под блокировкой `19C`, если она имеется. Нулевой
код не создаёт уведомление. Положительный код создаёт уведомление `23`:
`word0C = 1`, sender — менеджер, `word18` — код, `word1C` — текст ошибки;
остальные слова нулевые. Для кодов от 10 используется `Unknown Network Error`.
Десять исходных строк заданы в общей реализации.

Операция начала соединения обнуляет ошибку, открывает server, подключает peer
с аргументом `0`, связывает server с peer и отправляет probe. Отказ server
устанавливает ошибку `3`, отказ подключения — `2`; оба вызывают переход
controller `(6, 1)`. Отказ probe также вызывает `(6, 1)` и сохраняет его ошибку.
Часы, создание потоков и действительный socket lifetime принадлежат внешним службам.

Probe отправляет server ID как destination, type `0`, один байт `2A`, TCP `1`
и три нулевых заключительных слова. Положительный signed результат увеличивает
счётчик `00`; ноль или отрицательное значение увеличивает `1C` и устанавливает
ошибку `4`.

Hello Request использует type `5` и восемь little-endian байт:
`uint32 localMilliseconds`, затем `uint32 0`. Остальные параметры аналогичны probe.
Успех увеличивает счётчик `14`, отказ — `30` и ошибку `4`.

## Пакеты и время

При нулевом `16` Pump сразу возвращает true. Иначе обновляет controller,
читает его фазу под блокировкой, затем обновляет matchmaking. Для фазы `3`
Hello Request отправляется только при строгом unsigned условии
`localMilliseconds > uint32(helloRequests * 5000)`.

За один Pump извлекаются и удаляются максимум 25 ненулевых пакетов:

| Type | Операция |
| --- | --- |
| `2` | счётчик `40`; уведомление `1F` детям, чей Class ID и поле `2C` совпадают с двумя uint32-полями пакета |
| `4` | журнал `Receive GameStart Packet`, счётчик `48`, обработка GameStart |
| `6` | журнал уровня 2, счётчик `50`, обработка Hello Reply |
| иной | журнал неизвестного пакета |

GameStart требует минимум четыре байта. Короткий пакет увеличивает `64` и
возвращает false. При допустимом размере дополнительно увеличивается `48`.
Если первый байт равен `1`, ошибка очищается, uint16 из байтов 2–3 записывается
в unique ID и controller получает `(7, 0)`. Другой первый байт не меняет ID.
Pump игнорирует результат обработчика и уничтожает пакет в обоих случаях.

Hello Reply читает два uint32 из payload. Если хотя бы один нулевой, увеличивает
`6C` и возвращает false. Иначе вычисляет unsigned
`sample = (localMilliseconds - firstWord) >> 1`, записывает sample в общее
кольцо из пяти значений и увеличивает общий индекс по модулю 5. Кольцо разделяется
между экземплярами и переживает Start/Stop. Поправка `1A4` — signed частное
32-битной суммы ненулевых samples и их количества; при отсутствии ненулевых
samples равна нулю. Затем таймер читается повторно и результат записывается в
поле времени peer. Второе слово служит проверкой ненулевого значения.

Чтение часов использует `ticks / globalDivisor`. При активном таймере перед
чтением вызываются его Start и Refresh. Арифметика времени и счётчиков сохраняет
32-битное переполнение.

## Получатели и ввод

Смена получателя сначала отправляет старому уведомление `17`, затем назначает
новый указатель и отправляет ему `16`. Повторное назначение того же указателя
выполняет обе операции. Уведомления несут sender менеджера и нулевые остальные слова.

Ввод доступен при наличии matchmaking и получателя. Клавиша `28` или `34`
выбирает альтернативную таблицу символов; затем проверяются индексы `0..99`.
Для изменённой нажатой клавиши с ненулевым символом отправляется `13` с символом,
с нулевым — `14` с индексом. Отпущенная клавиша с нулевым символом создаёт `15`;
отпускание клавиши с ненулевым символом не создаёт уведомление. Обе таблицы
сохранены в PC ABI. Основной объектный notification slot пересылает сообщение
через базовую службу только при ненулевом `16`.

## Граница компонента

[spNetworkManagerHost](../../../Sparkplug/Analysis/Host/spNetworkManagerHost.h)
предоставляет операции чужих классов, блокировки, таймер, отправку peer,
журнал, подписчиков и embedded input matchmaking. Методы самого менеджера
выполняются в общем компоненте. Factory и Clone требуют назначенного host;
существующий объект сохраняет своего host при замене factory-среды.
Журнал каждый раз получает текущий global; при null создаёт новый менеджер
через factory. Такой экземпляр первоначально не имеет debug. Его переносимое
владение задаёт явное хранилище `ReleaseLazyStorageForAnalysis`; закрывать его
можно после завершения всех заимствованных обращений. Ручное создание нового
менеджера не удаляет ранее созданные экземпляры.

`SparkplugNetworkManagerTests` проверяет завершённые операции, поля, очередь,
точные данные отправки и порядок вызовов. Работа настоящих сетевых служб,
конкуренция потоков, изменение дочернего графа во время рассылки и rollback
исключений оригинала не считаются закрытыми этими проверками.

Переносимые защиты явно отвергают отсутствие обязательной службы, отрицательный
индекс ошибки, нулевой divisor и короткий payload Hello Reply. Они не описывают
поведение игры на невалидных указателях. Lazy factory требует настроенной host-среды.
Исключение host освобождает занятую блокировку переносимой обвязки; оригинальная
SEH-ветвь ей не приписывается. Само наличие исходника не означает полной интеграции
с сетевой подсистемой игры.
