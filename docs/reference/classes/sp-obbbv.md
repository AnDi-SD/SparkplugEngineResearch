# spOBBBV

Описание отдельных известных частей класса. Наличие карточки не означает полного восстановления всех методов.

Общие исходники: [spOBBBV](../../../Sparkplug/Code/Sparkplug/spOBBBV.h).

## Наблюдаемая байтовая структура

Каждый доступный объект занимает 23 байта и имеет сигнатуру
`s0:f1:12|s0:end`:

| Смещение | Размер | Значение |
| ---: | ---: | --- |
| `0x00` | 4 | class ID `0x4DA04889` |
| `0x04` | 4 | `SBOO` |
| `0x08` | 2 | field 1: header `0xA1`, UInt8 payload size `0x0C` |
| `0x0A` | 4 | `Single size.x` |
| `0x0E` | 4 | `Single size.y` |
| `0x12` | 4 | `Single size.z` |
| `0x16` | 1 | terminator собственной serializer-секции `0x00` |

Все значения little-endian. В SMO хранится **полный размер** по трём осям.
Loader обеих платформ вычисляет half-extents как `size * 0.5`, затем сохраняет
длину вектора half-extents как радиус охватывающей сферы:

```text
halfExtents = size * 0.5
boundingSphereRadius = length(halfExtents)
```

Таким образом, показывать 12-байтовый payload как half-extents было бы ошибкой.

## Полный набор полей serializer

Исполняемые файлы подтверждают три идентификатора собственной секции:

| Field | Имя | Payload | Наблюдается в SMO | Поведение serializer |
| ---: | --- | --- | --- | --- |
| 0 | `esfOBBBVPosition` | `Vector3` | нет | локальная позиция; нулевое значение опускается |
| 1 | `esfOBBBVSize` | `Vector3` | 423/423 | полный размер; записывается всегда |
| 2 | `esfOBBBVRotation` | quaternion `(X,Y,Z,W)` | нет | локальное вращение; identity опускается |

Внутри runtime вращение OBB хранится матрицей. Перед записью serializer
преобразует её в quaternion; loader выполняет обратное преобразование. Отсутствие
field 2 не делает объём axis-aligned в мире: внешний transform хранится его
родителем `spCollisionInfo`. Поля 0 и 2 задают дополнительное локальное смещение
и вращение самого box относительно этого transform.

## Значения и подтипы

Структурный подтип ровно один — `obb_size_only`. Все 423 объекта назначены ему с
уровнем уверенности `confirmed`. Векторы размеров являются параметрами, а не
отдельными подтипами.

| Компонента | Минимум | Максимум |
| --- | ---: | ---: |
| X | `3.57227898` | `268.105835` |
| Y | `7.0254817` | `789.820618` |
| Z | `3.09597492` | `298.623352` |

## Viewer и база

`SmoOrientedBoxBoundingVolumeDecoder` строго принимает 12 байт для position/size
и 16 байт для rotation. Для size он возвращает полный размер, вычисленные
half-extents и радиус по формуле executable. В read-only панели
«Показывать восстановленные поля» Viewer выводит field 1 как `obb.size`; если в
будущем встретятся field 0 или 2, тот же инспектор уже покажет их как position и
quaternion без изменения файла.

Команда

```text
SmoViewer.Inspect research-db analyze-class <db> spOBBBV
```

Редактирование намеренно не включено. Для перехода из `read_only_research`
потребуется на копии SMO отдельно проверить изменение size, материализацию
необязательных position/rotation и фактическую collision-геометрию в native
runtime.
