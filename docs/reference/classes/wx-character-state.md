# wxCharacterState

Базовое состояние персонажа, class ID `44817BC2`, регистрационная и физическая база — `spBaseObject` (`415352A1`). Общая реализация находится в [wxCharacterState.h](../../../Winx/Code/wxCharacterState.h) и [wxCharacterState.cpp](../../../Winx/Code/wxCharacterState.cpp). Производный [wxActionState](wx-action-state.md) использует тот же набор полей.

## Layout и владение

PC и PS2 выделяют `0x3C` байт. Точные 32-битные представления отделены от переносимого C++-объекта: [PC](../../../Winx/Analysis/PC/wxCharacterStateAbi.h), [PS2](../../../Winx/Analysis/PS2/wxCharacterStateAbi.h).

| Смещение | Размер | Назначение и начальное значение |
| --- | --- | --- |
| `00` | `10` | Префикс `spBaseObject` |
| `10` | 4 | Селектор состояния, `0` |
| `14` | 4 | Заимствованный owner, null |
| `18` | 4 | Заимствованный получатель команд анимации, null |
| `1C..20` | 5 | Пять отдельных флагов, все true |
| `21..23` | 3 | Padding, значение не задано |
| `24` | 4 | Текущий animation handle, null |
| `28` | 4 | Поле неизвестного назначения, ноль |
| `2C` | 1 | Поле неизвестного назначения, ноль |
| `2D..2F` | 3 | Padding, значение не задано |
| `30..38` | 12 | Три компоненты нулевого вектора |

Размеры и смещения в таблице шестнадцатеричные. Деструктор не останавливает анимацию и не освобождает handle: это отдельная операция перехода. Владение внешними объектами состоянию не передаётся. Clone создаёт новый объект через фабрику, регистрирует соответствие в clone manager и вызывает у источника виртуальный copy-hook. У класса copy-hook унаследован от `spBaseObject` и пуст: runtime-поля, связи и handle не копируются.

## Виртуальные операции

Здесь используются байтовые смещения PC vtable. Для PS2 к ним прибавляется `8`: перед указателями методов находятся два служебных слова. Это аналитические обозначения, а не восстановленные исходные имена. Одноимённые RTTI-методы `spBaseObject` в переносимом коде обозначены по PS2-смещениям и доступны как перегрузки.

| PC slot | Поведение |
| --- | --- |
| `1C` | Освободить текущую анимацию, вызвать виртуальный `30(request)`, вернуть true |
| `20` | Освободить текущую анимацию, вернуть true |
| `24` | Освободить текущую анимацию; аргумента нет |
| `28` | Освободить текущую анимацию, безусловно обнулить handle |
| `2C` | Освободить текущую анимацию, вызвать виртуальный `30(request)` |
| `30` | Пустая операция |
| `34` / `38` | Соответственно true / false |
| `3C` | Пустая операция; исходный тип аргумента неизвестен |
| `40` | Сбросить `1C/1D/1E` в true, `24/28/2C/30..38` в ноль |

Сброс `40` сохраняет selector, owner, получателя команд и разрешающие флаги `1F/20`. Он не вызывает stop/fade.

Освобождение при нулевом handle ничего не делает. Иначе вызывается предикат owner (PC slot `38`, PS2 `40`). При true и отсутствии принудительной остановки получателю передаётся fade с `0.4f`; иначе stop. Только после возврата из вызова поле `24` обнуляется.

Вспомогательный запуск `(handle, mode, interrupt)` сначала сбрасывает completion-записи для handle, если `mode == false`; затем запрашивает тот же предикат owner и вызывает playback с fade-selector `2` при true или `0` при false. Сам helper не записывает поле `24`.

## Границы реализации

Реализованы перечисленные hooks, используемые `wxActionState`, и общая логика остановки/запуска. Остальные невиртуальные методы семейства не объявляются восстановленными. Исходные имена большинства hooks и точные C++-типы внешних объектов неизвестны.

[wxCharacterStateHost](../../../Winx/Analysis/Host/wxCharacterStateHost.h) — наш обязательный адаптер, а не оригинальный класс: он предоставляет внешние lookup, playback, completion, owner predicate и сброс owner control. Его методы не имеют успешных заглушек по умолчанию. Попытка выполнить зависимую операцию без адаптера даёт `std::logic_error`; это диагностика переносимого слоя, не поведение игры. Адреса и порядок вызовов не означают готовности полной системы анимации или state machine.
