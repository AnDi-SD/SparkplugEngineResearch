# `wxDroidWanderAIAction`

`wxDroidWanderAIAction` (`34154F9E`) имеет регистрационного и физического
родителя [`wxAIAction`](wx-ai-action.md). Его PC factory `5BCF90` выделяет
`0x3A8`, вызывает общий конструктор AIAction `58FF00`, затем устанавливает
таблицу `709EB8`; getter `5BCE20` возвращает RTTI `767970`. Дополнительные
поля производного класса этим factory-профилем не обнаружены. Расположенный
рядом `5BCE90` устанавливает другую таблицу `709E70` и не относится к Droid.
[PC layout](../../../Winx/Analysis/PC/wxDroidWanderAIActionAbi.h) отделён от
переносимого C++ объекта.

[Реализация](../../../Winx/Code/wxDroidWanderAIAction.h) восстанавливает пару
операций над текущей командой. Её конструктор явно связывает уже допущенное
состояние с заимствованным owner и host; он не заявляет полную эквивалентность
native construction, Copy или Clone. Общий родитель и его владение настоящие.

## Публикация и очистка команды PC

Первый bool update, PC slot1C/`5BCE40` (переносимое PS2-offset имя24), читает
owner из action20, затем owner144→actor130→command. Он записывает DWORD04
команды в `0`, **заново читает всю цепочку, включая action20**, записывает
byte1C текущей команды в `1` и возвращает AL1. Это не фактический Entry
класса: тот расположен в другом слоте и здесь не квалифицирован.

Exit PC slot2C/`5BCE70` (переносимое имя34_Clear) независимо читает текущую
цепочку и записывает только byte1C в `0`. Он не очищает DWORD04, базовое
clearableWord374 и не вызывает общий base Clear. Значение EAX этого void
метода не получает придуманного bool-смысла. Повторные вызовы выполняют
те же явные записи, включая запись уже имеющегося нуля.

[Host](../../../Winx/Analysis/Host/wxDroidWanderAIActionHost.h) предоставляет
только живые заимствованные чтения и записи данных команды. Он не выбирает
смещения, значения, ветвь или успешный исход операции. Изменение owner либо
его звеньев после первой записи учитывается повторным чтением; следующий
Exit также использует текущую цепочку. Исходные типы и конструкторы
owner/actor/command этим интерфейсом не восстанавливаются.

## Допуск и границы

Профиль по умолчанию — `Unqualified`. Для `PcStableBorrowedCommandData`
caller сохраняет живыми все возможные записи на время синхронного вызова;
currentAction и owned-action список остаются пустыми. До первой записи
проверяются профиль и начальная привязка. MissingOwner/MissingCommand —
аналитический отказ, а не воспроизведение native fault. Если привязка
исчезла после первой записи, эта запись сохраняется: атомарность и rollback
не заявляются. `LastResultForAnalysis` — наше состояние допуска, не native поле.

Неизвестные Notify, complex Tick, фактический Entry, Query, Copy и Clone
имеют явный отказ/Unqualified result. Отказ в void-слоте определяется через
LastResult; он не означает восстановленный native no-op. Generic RTTI factory
требует явного post-construction binding и также отказывает. Copy возвращает
аналитический false; Clone и generic factory вызывают logic_error. Общие известные
literal-boolean слоты сохраняют поведение родителя.

[Проверка](../../../Winx/Tests/wxDroidWanderAIActionTests.cpp) сравнивает полные
`0x74` байта каждой из трёх команд, порядок записей и повторные чтения на
контролируемых входах. Native factory/lifetime служат отдельным доказательством
типа; переносимые состояния, владельцы и размер объекта не приравниваются
к native байтам или allocator counts. Pathfinding, selector, произвольный
граф, аппаратный ввод, PS2, игровой runtime и полнота класса остаются открытыми.
