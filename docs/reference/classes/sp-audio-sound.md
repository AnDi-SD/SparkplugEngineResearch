# spAudioSound

`spAudioSound` имеет ClassID `0x33283899`, регистрационную и физическую базу `spNode` на PC и PS2. PC-объект занимает `0xF8` байт, PS2 — `0x110`. Собственный хвост начинается соответственно с `+B4` и `+C0`.

Конструктор инициализирует 17 последовательных четырёхбайтовых полей одинаково на обеих платформах. Поля с индексами 3, 4 и 8 получают биты `1000.0f`, `1.0f` и `1.0f`; остальные равны нулю. Поле с индексом 5 — читаемый `float` (`PC+C8`, `PS2+D4`), индекс 6 — номер группы (`PC+CC`, `PS2+D8`). Имена остальных полей не установлены; переносимый код сохраняет их как слова без дополнительных смысловых имён. PS2-паддинг `+104..+10F` конструктор не записывает.

Простой getter возвращает поле с индексом 5. Другой getter возвращает его напрямую при нулевом номере группы. При ненулевом номере он обращается к массиву скаляров глобального `spAudioManager` по адресу `manager + 0x1C + group*4` и вычисляет:

```text
groupScalar + ownScalar - groupScalar * ownScalar
```

Ни ограничения результата диапазоном `[0,1]`, ни проверки номера группы в этой функции нет. PC удерживает сумму и произведение на x87 до возврата. Точный порядок — первое чтение кэша группы, первое чтение собственного скаляра, сумма, повторное чтение той же ячейки группы, повторное чтение собственного скаляра, произведение и вычитание. Если значения меняются между чтениями, функция использует оба наблюдения:

```text
firstGroupScalar + firstOwnScalar - secondGroupScalar * secondOwnScalar
```

Первоначальный номер группы выбирает обе загрузки; изменение поля группы между ними не меняет адрес второй ячейки. Переносимая обвязка сохраняет этот порядок двумя вызовами callback и двумя чтениями собственного поля. PS2 использует собственные операции FPU с аккумулятором; общая формула для стабильных значений совпадает, но арифметическая побитовая эквивалентность платформ не заявляется.

Clone создаёт объект заново и вызывает `spNode` modified-copy. Имя, трансформы и восстановленные связи базового класса копируются по его правилам; собственные 17 полей сохраняют значения нового конструктора. Собственный деструктор передаёт освобождение базовому `spNode` и не освобождает отдельные аудиоресурсы.

Восстановленный C++ находится в `Sparkplug/Code/Sparkplug/spAudioSound.*`. Доступ к кэшу групп отделён через обязательный callback `Analysis/Host/spAudioSoundHost.h`. Дополнительная host-проверка отклоняет нефинитные операнды групповой арифметики; ветвь нулевой группы сохраняет исходные биты скаляра. Сохранение NaN-полезной нагрузки — контракт этой обвязки, а не утверждение о полном поведении x87. Методы `ForAnalysis`, shared ownership базового класса и представление неизвестных слов являются аналитической обвязкой.

Конфигурация аудио (`PC 0x004A2A70`, `PS2 0x00123EC0`) остаётся за пределами компонента. На PS2 она записывает два входных слова в `+C0/+C4`; при ненулевом байте `manager+14` вызывает `0x00123400` и сохраняет результат в `+100`. Назначение этих аргументов и операции менеджера здесь не восстановлено. Создание и запуск голосов, банки и работа устройств также остаются открытыми. Компонент подтверждает состояние, расчёт скаляра и собственный жизненный цикл класса, а не весь аудиотракт.
