# wxCharacterRegistry

`wxCharacterRegistry` (`0x6EAA030D`) зарегистрирован с базой
[`spBaseObject`](sp-base-object.md). [Переносимый класс](../../../Winx/Code/wxCharacterRegistry.h)
предоставляет ограниченный PC-селектор на явно заданном состоянии после
создания. Его C++-база обслуживает общий RTTI-протокол и не доказывает исходное
физическое наследование. Исходные имена метода и файлов неизвестны.

## PC-селектор

Захваченный объект занимает `0x2C` байт. Селектор читает cached pointer `+28`.
Ненулевое значение возвращается сразу, без чтения групп. При нулевом cache
он рассматривает только первый элемент внешнего массива `+18/+1C`, затем
первый элемент массива `+4/+8` этой группы. Если один из этих массивов пуст,
результат остаётся нулевым. Если первый массив целей непуст, первый payload
записывается в cache и возвращается. Payload также может быть null.

Вторая группа не рассматривается, даже если первая пуста или содержит null.
После ненулевого кэширования изменение внешних массивов не меняет результат
следующего вызова. После кэширования null следующий вызов вновь рассматривает
первую группу. Тип pointee, предметное значение групп и выбор целей за пределами
этой операции не установлены.

[PC32 view](../../../Winx/Analysis/PC/wxCharacterRegistryAbi.h) сохраняет
неизвестный префикс как bytes и не накладывается на переносимый C++ ABI.
Portable view использует C++17 pointer/count records для внешнего массива,
групп и target pointers. Все записи заимствованы и остаются живыми; селектор
сам выполняет алгоритм, без callback, выбирающего за него готовую цель.

Профиль по умолчанию — `Unqualified`. Явный PC-профиль допускает существующий
типизированный postconstruction capture и корректное borrowed storage.
Missing storage или null первая группа при необходимом обращении дают
аналитический отказ. Он не моделирует native fault, некорректную арифметику
указателей, exception unwinding или rollback. Completed-null — нормальный
результат выбранного оригинального метода.

Тип receiver установлен отдельно от проверки алгоритма: по сохранённым
результатам настоящих factory/getter/vtable, точным текущим таблицам и телам,
а также вызову этого селектора из входа типизированного
`wxWinxFlyAIAction`. Текущие ограниченные вызовы используют захваченное
состояние; они не создают заново native C++ объекты и не доказывают тип
произвольного значения runtime global.

Открыты native constructor/destructor, singleton и producer глобального
указателя, владение и изменение контейнеров, Copy/Clone/notification, физическое
наследование, PS2, холодный запуск и gameplay. Source factory и другие
неквалифицированные операции явно отказывают. Portable destructor не освобождает
заимствованные записи и не воспроизводит весь native lifetime.
