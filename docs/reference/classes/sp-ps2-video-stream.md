# spPS2VideoStream

PS2-класс `0x15747650` наследует `spVideoStream`. Нативная фабрика создаёт
объект размером `0x24`: primary interface находится в начале, Named/CrossPlatform
view — на `+4`. [Переносимая реализация](../../../Sparkplug/Code/SparkplugPS2/spPS2VideoStream.h)
использует общий жизненный цикл [видеопотока](sp-video-stream.md).

Смещения ниже считаются от первой функции primary interface, после двух
служебных слов GCC vtable.

| Слот | Поведение собственного тела |
| ---: | --- |
| `0x00` | непосредственно возвращает true |
| `0x04` | возвращается без действий |
| `0x08..0x1C` | каждый из шести методов возвращает true |
| `0x20`, `0x24` | возвращает ноль |

Эти тела не читают аргументы и не меняют собственные поля. Их исходные имена,
сигнатуры и смысл результата неизвестны; `NativeHook…ForAnalysis` — наши
аналитические aliases. Следующее слово таблицы принадлежит secondary metadata.
Начальный метод отличается от PC, где вызывается следующий virtual slot.
Короткие тела оригинала не предоставляют декодирование видео.

Constructor обнуляет байты `+18/+19`, owned pointer `+1C` и слово `+20`.
Байты `+1A/+1B` остаются неопределёнными. Clone строит свежий объект,
регистрирует вторичные views `+4`, затем вызывает Named copy: переносится имя,
собственный payload и буфер остаются defaults. Буфер освобождается общим
destructor перед Named-частью; освобождение самого нативного объекта выполняется
при положительном signed16 флаге удаления.

ОС и декодер не заменяются аналитическими возвратами. Передача owned buffer
через `AdoptBufferForAnalysis` — наш способ проверить установленное владение;
оригинальный setter и способ выделения буфера ещё неизвестны.
