# wxButterflyMovingState

Class ID `46B6517E`, физическая и регистрационная база `wxCharacterState`.
Native размер PC/PS2 — `70`, selector — `0`. Конструктор обнуляет собственные
vectors/words, byte `6C` устанавливает в `1`. Clone получает эти defaults;
Copy и Reset наследуются из базы и собственные поля не обнуляют. Permission
`34` возвращает false, hook `38` — false. [Переносимый исходник](../../../Winx/Code/wxButterflyMovingState.h)
содержит собственные PC entry, update, фазы и движение; его представление не
заявляет native ABI. Полный игровой граф и собственная PS2 арифметика остаются открытыми.

| Поля | Назначение |
| --- | --- |
| `3C/40/44` | Position, захваченная при входе |
| `48/4C/50` | Целевая position, передаваемая внешнему random-point helper |
| `54` | Отдельная целевая высота |
| `58/5C/60` | Position, захваченная в начале update |
| `64` | Uint32 признак инициализации текущей фазы |
| `68` | Uint32 deadline переключения фазы |
| `6C` | Byte выбора фазы |

Вход `1C` выполняет свою логику при каждом вызове, независимо от прежнего
flag `1C`. Захватывает position owner `24`/node `24` в `3C/40/44`; затем
получает RNG uint32, перечитывает node и задаёт одинаковые scale `30/34/38`.
На PC значение — float32 spill точной суммы
`uint32 * float32(2E4CCCCC) + float32(3F333333)`, приблизительно `0.7..0.9`.
Dirty word node `B0` получает bit `1`. PC пишет scale X/Y, dirty и scale Z
именно в таком порядке. PS2 использует dirty word `B4`, а расчёт масштаба
включает отдельные EE accumulator instructions; их арифметика не приравнена
к PC или generic MIPS.

Затем вход выставляет byte `6C = 1`, переписывает request key как
`(key & F0000050) | 50`, делает lookup, запускает mode=true, interrupt=true,
сохраняет handle, очищает flag `1C` и вызывает базовый вход. База освобождает
только что сохранённый pending и вызывает собственный виртуальный update.
Именно этот release входит в original порядок. Вход не обнуляет собственные
`64` и `68`; повторный вход может сохранить инициализированную фазу, после
базового release оставить pending нулевым и всё равно вернуть true.

Update `30` сначала копирует текущую node position в `58/5C/60`. При ненулевом
deadline и **строгом unsigned** `deadline < clock` заменяет phase byte на
`!oldByte` и обнуляет `64`. Deadline в этом участке сохраняется. Равенство
clock/deadline не переключает фазу; ненулевой byte до переключения не
нормализуется до `1`. Ненулевой byte выбирает PC helper `51F390` /
PS2 `309C60`, нулевой — PC `51F530` / PS2 `3098F0`.

PC helpers при нулевом `64` выбирают animation key `50` или `800050` по фазе.
Changed handle освобождает pending и запускает mode=true, interrupt=true.
Затем random-point helper `5972F0` получает output `48`, radius `200` и
захваченную origin position по значению. RNG задаёт отдельную высоту как
float32 spill `originY + RNG * (60 / 2^32) - 30`. После записи `64 = 1`
новый deadline равен `clock + 1000 + (RNG % 4001)` с uint32 переполнением.

В уже инициализированной PC фазе горизонтальная дистанция до цели меньше
`20` вызывает новый random-point lookup; вертикальная разница с `54`
строго меньше `10` задаёт новую высоту. Эти действия не заменяют deadline.
Фактическое сравнение горизонтальной дистанции использует квадрат и float32
spill X-разности, поэтому это описание порога не объявляет всю арифметику
обычным float32 vector length.

Общий PC movement helper `51F010` нормализует горизонтальное направление к
цели и использует speed `80` при ненулевой фазе, `40` при нулевой. Вертикальная
коррекция работает только при разнице высоты строго больше `10`; speed —
`100` или `50`. Все шаги зависят от clock delta. Orientation использует
отрицательное направление к цели, horizontal local basis node, порог dot
`0.985f`, поворот со скоростью `pi/2` и native vector/matrix helpers. Dot
строго выше порога пропускает orientation update; равенство не пропускает.
Сопоставление PC охватывает конечные геометрические входы с невырожденной
horizontal basis, включая граничные сроки, пороги движения, направление
поворота и округление высоты около midpoint. Высота сохраняет малый origin
до native nearest64 округления и последующего float32 spill; обычная binary64
сумма теряет часть таких входов. Технический [численный адаптер](../../../Winx/Analysis/PC/wxButterflyNumeric.h)
явно отделён от восстановленных hooks. Произвольная точность x87, nonfinite
входы и собственная PS2 EE normalize/accumulator/SQRT этим не установлены.
Равные аргументы native matrix helper ведут к ветви с unwritten stack;
переносимая реализация явно отклоняет соответствующую вырожденную basis.

Нативные части входа и переключения фаз установлены независимо от движения.
PC entry/update cycle сопоставлен с original movement/normalize/trig/matrix
при отдельных нулевых и ненулевых frame delta и явных внешних службах.
[Проверки](../../../Winx/Tests/wxButterflyMovingStateTests.cpp) также сохраняют
clone/Copy/Reset, начальные поля и границу отсутствующего host.
[Обязательный host](../../../Winx/Analysis/Host/wxButterflyMovingStateHost.h)
предоставляет RNG, random-point, node, clock и animation service. Их
реализация, настоящий scene/consumer и полное игровое соответствие класса
остаются открытыми.
