# wxAttackAIAction

`wxAttackAIAction` — производное действие `wxAIAction`, class ID `6515353D` на PC и PS2. [Переносимый класс](../../../Winx/Code/wxAttackAIAction.h) содержит проверенные поля и методы; внешний персонаж, команды, поиск цели, реестр и выбор следующего действия подключаются через [host](../../../Winx/Analysis/Host/wxAttackAIActionHost.h). Это адаптер проекта, а не исходный тип игры. Физические 32-битные представления: [PC](../../../Winx/Analysis/PC/wxAttackAIActionAbi.h), [PS2](../../../Winx/Analysis/PS2/wxAttackAIActionAbi.h).

## Идентичность и поля

| Свойство | PC | PS2 |
| --- | --- | --- |
| Размер / vtable | `3F4` / `708E50` | `3F8` / `492350` |
| Factory | `5AA720` | `244030` |
| Copy / clone | `5AA4D0` / `5AA780` | `243B00` / `243F70` |
| Цель | `3A8` | `3AC` |
| Состояние | `3AC` | `3B0` |
| Срок | `3B0` | `3B4` |
| Следующие два слова | `3B4/3B8` | `3B8/3BC` |
| Дополнительный `wxPathFinder` | `3C8` | `3CC` |
| Флаг | `3F0` | `3F4` |

PC constructor `5AA310` и встроенный в PS2 factory код устанавливают цель=null, состояние=1, срок=0, оба следующих слова=0 и флаг=0. Они вызывают constructor дополнительного `wxPathFinder`. Байты `3BC..3C7` и три байта после флага на PC constructor не заполняет. Их содержимое нельзя считать нулевым. PS2 смещает собственные поля на четыре байта после контейнера базового действия.

`Copy` сначала выполняет base Copy (очистку current и принадлежащих действий получателя), затем переносит ровно слова `3A8/3AC/3B0/3B4` PC. Поле `3B8`, дополнительный `wxPathFinder` и флаг остаются у получателя. Clone создаёт свежий объект и применяет этот Copy; это не побайтовый клон.

## Подтверждённое поведение

- Вход (PC `5AA3B0`, PS2 `243C60`) ставит command byte `1D=1`. При ненулевом owner flag `1C5/1D5` берёт цель из registry, устанавливает состояние 0 и срок 0. Иначе вызывает поиск ближайшей цели, устанавливает состояние 4 и срок `timerBase + ownerMin + RNG % (ownerMax-ownerMin+1)` с 32-битной арифметикой. Затем обнуляет слово `3B8/3BC`. При отсутствии цели вызывает owner selector с key 1 и параметром 0. После возврата selector устанавливает общий интервал 2000 и обнуляет флаг `3F0/3F4`. Формула требует допустимого диапазона ownerMin..ownerMax; повреждённые входы не исследованы.
- Выход (PC `5AA240`, PS2 `243C10`) обнуляет command bytes `1D`, `20`, `21`, `1F` именно в этом порядке, затем очищает цель. Остальные собственные поля сохраняет.
- Запрос цели (PC `5AA2A0`, PS2 `243AA0`) вызывает поиск ближайшей цели. Только если цель не найдена и owner flag равен нулю, запрашивает selector key 0, parameter 0. Этот запрос не записывает цель в поле действия.
- State dispatcher (PC `5AA1D0`) для состояний 0..6 вызывает соответственно исходные virtual slots `23,18,19,20,21,22,24` и возвращает true. Для остальных значений сразу возвращает true. Тела этих семи обработчиков ещё не восстановлены; host получает номер slot. Уведомление `273B` отправляется slot 17 с тем же указателем сообщения, `2754` игнорируется, остальные проходят через базовый notification.

Переносимый класс не хранит и не исполняет дополнительный `wxPathFinder`, не заменяет его фиктивным успешным поиском. Активные обработчики состояния, движение и нормальная игровая последовательность создания персонажа остаются открытыми. Host должен предоставить проверенные зависимости и обработчики; регистрационная factory без привязанного host не создаёт объект. Наличие класса не означает полноценной атаки NPC.

Основа реконструкции: парные контракты construction, modified Copy, command/exit и perception в локальном исследовательском каталоге; PC/PS2 адреса и разница layout проверены независимо. [Общий контракт AIAction](wx-ai-action.md) описывает базовые методы и пределы его реализации.
