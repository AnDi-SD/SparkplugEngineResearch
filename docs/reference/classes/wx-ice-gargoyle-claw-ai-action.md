# wxIceGargoyleClawAIAction

`wxIceGargoyleClawAIAction` имеет идентификатор `0x53F2244B` и физическую базу
`wxAIAction`. Размер объекта — `0x3B8` на PC и `0x3BC` на PS2. PC factory
находится по `0x5AEC30`, таблица из 21 слота — по `0x7091F0`. PS2 factory —
`0x2525E0`, таблица — `0x492810`; перед её 21 слотом стоят два нулевых слова.
Исходные имена файлов восстановленной переносимой реализации предполагаются.

| Поле | PC | PS2 | Начальное значение |
| --- | --- | --- | --- |
| Слово неизвестной роли | `3A8` | `3AC` | `0x3F000000`, представление `0.5f` |
| Заимствованный узел цели | `3AC` | `3B0` | null |
| Фаза | `3B0` | `3B4` | 1 |
| Отметка времени | `3B4` | `3B8` | 0 |

Claw и [Withdrawl](wx-ice-gargoyle-withdrawl-ai-action.md) являются отдельными
наследниками `wxAIAction`. Общая переносимая структура
`wxIceGargoyleAIActionStateForAnalysis` объединяет одинаковые поля и операции;
её имя и композиция принадлежат реконструкции и не задают нативное наследование.

## Общие PC-операции

Entry `0x5AEE80` получает текущий `wxTargetManager`, читает его слово `28`, затем
слово `18` полученной заимствованной записи. В собственное поле `3AC` записывается
этот указатель Node либо null, фаза становится 1, отметка — 0. При null вызывается
селектор владельца с `(0, 0)`. Ни цель, ни её Node не получают новую ссылку.

Переносимый Entry читает `wxTargetManager::CurrentWordsForAnalysis()[2]`
непосредственно. Host предоставляет только привязку слова `18` для этой
идентичности. Известный null и отсутствующая привязка различаются. Текущая запись
может быть получена настоящим `RegisterCandidateForAnalysis` при ненулевом
`flag148`; загрузочный Node ресурса менеджера остаётся отдельным объектом.
Холодная фабрика менеджера и неизвестные привязки имеют явные отказы анализа.

Query `0x5ADBC0` получает Perception владельца через вызов `0x515350(0)` и
исполняет настоящий `FindNearest` `0x4F1910`. При отсутствии результата вызывает
селектор `(0, 0)`. Собственный закэшированный Node не заменяется. Проверки
разрешающего байта владельца здесь нет. В исходнике используются существующие
численные профили общего Perception. После Perception владелец действия
повторно читается для передачи в селектор.

Exit `0x5AEC00` очищает байты команды `20` и `21`, повторно читая владельца
действия и получая команду между записями, затем очищает собственный указатель Node. Фаза, отметка и слово
`3A8` сохраняются. Notify имеет буквальное пустое тело без пересылки текущему
действию. Последний обычный bool update использует общее тело с результатом true.

Copy сначала выполняет общий Copy `wxAIAction`, затем переносит собственные
поля в порядке `3AC`, `3B0`, `3B4`, `3A8`. Указатель Node копируется без AddRef;
Clone создаёт объект с начальными полями и выполняет этот Copy. Деструктор не
освобождает заимствованный Node. Переносимый Copy допускает назначение того же
типа; нативный более широкий тест только на принадлежность `wxAIAction` не
квалифицирует безопасный доступ к хвосту произвольного другого действия.

## Наведение и фазы

Общий PC Update `0x5AE8C0` всегда сначала вызывает слот `4C` — наведение
`0x5AEB40`. После его завершения читает фазу: 0 вызывает слот `44` (`0x5AEDB0`),
1 — слот `48` конкретного класса, остальные значения завершают Update.
Завершившийся нативный Update возвращает true.

Наведение снимает LOCAL-позицию `20` узла владельца и cached WORLD-позицию `74`
сохранённого узла цели. Оно получает команду до вызова общего расчёта yaw
`0x5970B0`, записывает yaw в слово команды `08`, повторно читает владельца
действия и получает его команду, затем
записывает `0x3C23D70A` (`0.01f`) в слово `04`.

Фаза 0 при нулевой отметке выставляет байт команды `20` в 1, получает настоящий
`wxGameTimer` и сохраняет его текущее слово времени `1C`. Нулевое время оставляет
отметку нулевой, поэтому следующий вызов повторяет этот путь. При ненулевой
отметке читается слово `140` из объекта по `owner144/character124`. Условие
`(word140 & 0x7F80) == 0x400` очищает байт команды `20` и переводит фазу в 1;
отметка сохраняется.

Стадия Claw `0x5AEEE0` использует LOCAL Y владельца и cached WORLD Y цели.
Выражение `abs(ownerY - (targetY - 150))` сохраняет промежуточную точность x87.
При результате не больше 50 она записывает motion `04 = 0`, затем обнуляет
отметку и фазу. При результате больше 50 она записывает heading `08 = 0`, если
`ownerY < targetY`, иначе `08 = 0x40490FDB` (float pi), затем motion `04 = 1.0f`.
Между этой записью heading и записью motion владелец действия читается заново.

Второй bool update `0x5AEBF0` вызывает дополнительный слот `50`, проверку
`0x5AEE30`, и после завершения возвращает true. Проверка читает cached WORLD Y
цели: значение меньше float-поля владельца `1CC` вызывает селектор `(2, 0)`;
иначе читается поле `1B4`, и значение больше него также вызывает селектор.
Границы включены; их взаимный порядок не предполагается.
Нижняя ветвь повторно читает владельца действия перед селектором. Верхняя
ветвь передаёт владельца, сохранённого до чтения границ; эти пути различаются
при изменении указателя владельца во время операции.

## Граница реализации

Update по умолчанию имеет профиль `HooksOnly` с явным отказом до наведения.
Профиль `PcFiniteGeometry` включает восстановленные стадии. Для них принят
конечный диапазон координат `[-1024, 1024]`; общий planar helper проверяет X/Z,
а пространственная стадия — свои дополнительные компоненты. Узлы и команды
заимствованы и должны оставаться валидными. Нужен уже созданный `wxGameTimer`.
Проверка границ допускает конечные значения Y и двух границ.

Расчёт yaw переиспользует общий `wxPlanarAngleMath.h`. Нормализация выполняет
общую восстановленную операцию, а импортированный `MSVCR71!_CIacos` заменяется
host `acos`. Сравнения расстояния и высоты переиспользуют общий программный
аккумулятор nearest64, включая малые поправки около строгих границ. Это
ограниченный численный контракт с внешней CRT-границей; произвольная побитовая
тождественность x87/CRT не заявляется.

PS2 ABI и полные таблицы сохранены отдельно; исполнение PS2 стадий и её
арифметика остаются открытыми. Также открыты холодные сервисы, тело селектора,
унаследованные pathfinding/serialization hooks, произвольные состояния базового
класса и работа в игровом цикле. Значение false при отказе переносимого bool
wrapper — диагностический результат анализа, а не приписанный оригиналу ответ.
