# spSystemSettings

PC-класс `0x6A265B0E`, регистрационная и физическая база — `spBaseObject`.
Известная PC-регистрация имеет factory; PS2-регистрация здесь не установлена.
В [общем коде](../../../Sparkplug/Code/Sparkplug/spSystemSettings.h) восстановлены
создание, RTTI, clone и освобождение собственного объекта. Назначение payload
и операции применения настроек остаются неизвестными.

## Хранение и singleton

Нативный размер — `0x114`: базовый объект занимает `0x10`, secondary singleton
support расположен по `+0x10`. Constructor обнуляет 255 байт `+0x14..+0x112`;
байт `+0x113` остаётся таким, каким его предоставил allocator. Это не основание
считать payload строкой, именовать отдельные настройки или читать этот байт
как инициализированное значение. [PC ABI](../../../Sparkplug/Analysis/PC/spSystemSettingsAbi.h)
описывает нативное расположение; переносимая C++-реализация отдельно хранит
известные байты и optional для неизвестного последнего байта.

Создание объекта заменяет опубликованный singleton. Destructor безусловно
обнуляет его: удаление более старого экземпляра также снимает публикацию более
нового живого экземпляра. Статический accessor возвращает нормализованный
указатель на главный объект; он не владеет объектом.

## Clone и границы

Clone создаёт новый объект, регистрирует пару и вызывает унаследованный Base
copy. Собственные байты не копируются: остаются 255 нулей и неизвестный
последний байт. Setter raw-байтов — явно аналитический способ подготовки
входов, исходный игровой API по нему не восстанавливается.

Восстановленная часть не задаёт формат конфигурационного файла, значения
параметров renderer или полную инициализацию игры.
