# wxActionState

Состояние с селектором `25`, производное от [wxCharacterState](wx-character-state.md). Восстановлены собственные переходы, управление animation handle, RTTI и фабричный clone. Реализация: [wxActionState.h](../../../Winx/Code/wxActionState.h), [wxActionState.cpp](../../../Winx/Code/wxActionState.cpp).

## Идентичность и платформы

| Свойство | PC | PS2 |
| --- | --- | --- |
| Class / base ID | `196333F8 / 44817BC2` | те же |
| Размер | `3C` | `3C` |
| Factory | `00402F60` | `003F33A0` |
| Vtable | `006F8D30` | `0049A080` |
| Clone | `00409A20` | `003F32E0` |
| Переход PC slot `1C` | `00519000` | `002C6A00` |
| Переход PC slot `20` | `005190B0` | `002C68A0` |
| Выбор PC slot `30` | `00518F90` | `002C6B50` |

Класс не добавляет полей к базе: после её конструктора устанавливает собственную vtable и записывает `25` в `+10`. Адрес PC `00518F60` — non-deleting destructor, не конструктор; PS2 constructor — `002C6CD0`. Copy-hook пуст, clone сохраняет начальные значения, а не текущую анимацию и связи источника. Деструктор сам не вызывает stop/fade.

## Packed key и выбор анимации

Request принадлежит вызывающему коду. Методы меняют только его первое 32-битное слово; исходное имя структуры неизвестно.

| Операция | Новое значение key | Параметры запуска `(mode, interrupt)` |
| --- | --- | --- |
| Первый шаг `1C` | `(key & F027FF8F) \| 00200000` | `(false, true)` |
| Первый шаг `20` | `(key & F047FF8F) \| 00400000` | `(false, true)` |
| `30` | `key & F007FF8F` | `(true, true)`, только при смене handle |

Lookup использует изменённый key и контекст owner: PC `owner+128`, PS2 `owner+134`. Менеджер анимаций получается через ленивый singleton; в переносимом слое эта внешняя операция принадлежит адаптеру.

Slot `30` сравнивает найденный handle с `+24`. При различии вызывает helper запуска и затем записывает handle. При равенстве повторного запуска нет. В обоих случаях обнуляется owner action-control: PC `*(owner->field12C + 4)`, PS2 `*(owner->field138 + 4)`. Нулевой результат lookup обрабатывается тем же сравнением, без добавленной проверки на успех.

## Переходы `1C` и `20`

`1C` использует разрешающий флаг `+1F` и флаг первого шага `+1C`; `20` — соответственно `+20` и `+1E`.

Если разрешающий флаг выключен, сразу вызывается соответствующий базовый hook. На первом шаге `20` сначала освобождает прежний handle, ещё до изменения key; `1C` такого предварительного освобождения не делает. Затем выполняются преобразование key, lookup и запуск, записывается новый handle, выключается флаг первого шага, обнуляется owner control. Возвращается false.

На следующих шагах вызывается completion-query с текущим handle и буквальным true. При незавершённой анимации обнуляется owner control и возвращается false. При завершённой вызывается базовый hook: `1C` освобождает старую анимацию, виртуально вызывает `30` для следующей и возвращает true; `20` только освобождает анимацию и возвращает true. Ненулевой handle сам по себе не удерживает переход в false.

## Границы подтверждения

PC-переходы и базовые helpers сопоставлены с оригинальными инструкциями на одинаковых входах и контролируемых внешних интерфейсах. Такое сопоставление проверяет состояние, аргументы и порядок вызовов класса, но не заменяет выполнение реального animation manager/controller. Поведение PS2 установлено статически; полное исполнение этих PS2-переходов не заявляется.

Переносимый объект не совместим с native layout и не предназначен для подстановки в память игры. Реальные owner, controller, ленивый manager и state machine ещё требуют подключения через [явный host-интерфейс](../../../Winx/Analysis/Host/wxCharacterStateHost.h). Их реализация не подменена успешными пустыми методами. Имена `vfunc_*` и `*ForAnalysis` аналитические; восстановление этого класса не означает восстановления всей системы персонажей.
