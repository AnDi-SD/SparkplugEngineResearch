# spDXAudioBankEntry: известный конструктор, Name Copy и Clone PC

`spDXAudioBankEntry` имеет ID `0x2CD93375` и регистрационную базу
[`spAudioBankEntry`](sp-audio-bank-entry.md). Настоящий PC factory `4C7950`
выделяет `0x104` байта и конструирует физический Base/Named/AudioBankEntry/DX
объект с первичной таблицей `6F2B34`. Getter `4C75D0` возвращает запись класса
`764C50`. Наличие физического Name не добавляет Named в engine RTTI.

[Переносимый класс](../../../Sparkplug/Code/SparkplugDX/spDXAudioBankEntry.h)
использует этот физический родительский префикс и явный захваченный пустой
профиль. Его C++-размер, указатели и shared Name не являются PC ABI.

## Известное собственное состояние

После полей AudioBankEntry конструктор обнуляет одиннадцать UInt32 по
смещениям `34..5C`, а также слова `64`, `68`, `94`, `E4`, `F4`. Их неизвестный
смысл не заменён вымышленными типами SDK или аудиометодами. Остальные интервалы
сохраняют незаписанное состояние; точное представление отделено в
[PC ABI view](../../../Sparkplug/Analysis/PC/spAudioBankEntryAbi.h).

Особенно важны незаписанные слова `E0` и `98`. Native helper встроенного
участка `64` читает `E0`. Поддерживаемая ветвь имеет захваченное ненулевое `E0`
и null resource-поля: она проходит через `4CF510` к `4CF550`, добавляет бит
`0x10000000` в незаписанное слово `98` и при нулевом `68` возвращает ошибочный
helper-код без перехода к внешней API-ветви. Деструктор записи продолжает
родительское разрушение; helper-код не трактуется как bool деструктора.

Ненулевое `E0` — явное условие захваченного профиля, а не результат
конструктора. Переносимая модель не придумывает значения или поля хранения
для `98/E0` и не реализует `E0=0`/внешние IAT-ветви. Поэтому конструктор требует
marker `NonzeroUnassignedE0WithNullResources`, а portable RTTI factory остаётся
unbound. Это аналитическое ограничение при известном настоящем PC factory.

## Copy, Clone и освобождение

Copy — унаследованная операция над физическим Name. Она сохраняет все
собственные поля назначения. Self-Copy очищает имя в исходном порядке
release-before-source-reread.

Настоящий Clone `4C79B0` создаёт новый DX-объект, регистрирует пару через общий
CloneManager и вызывает Name Copy. Новая запись получает известные значения
конструктора, включая `18=1`, вместо сырых значений источника; имя разделяется.
Source Clone использует ту же общую переносимую реализацию CloneManager и
тот же shared Name helper. Native карта, её byte ABI, lazy глобальный контекст
и глобальное завершение описываются отдельно от переносимого caller context.

В захваченном пустом профиле wrapper `4C7A00` выполняет встроенный helper и
настоящий Named/Base teardown. Флаг `1` освобождает allocation объекта; флаг
`0` завершает объект и оставляет внешнее хранилище caller'у для отдельного free.
Retained name теряет ссылку записи, сохраняя внешний owner и текст. Source
использует настоящее C++-разрушение shared Name и отдельно наблюдаемое владение
host allocation; чтение уже разрушенного C++-объекта не требуется.

Ненулевые COM/SDK указатели, ресурсные буферы, загрузка/воспроизведение,
`E0=0`, неизвестные значения остальных незаписанных полей, последний владелец
native name pool, глобальное время жизни, callbacks/reentry, PS2, непустой bank
producer и целый класс остаются открыты.
