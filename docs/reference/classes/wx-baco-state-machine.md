# `wxBacoStateMachine`

`wxBacoStateMachine` имеет Class ID `78603414` и зарегистрированную базу [wxCharacterStateMachine](wx-character-state-machine.md) (`D32F3AA1`) на PC и PS2. Физическая база в игре совпадает с регистрационной. Переносимый класс также наследует общую машину: четыре созданных состояния привязываются к её слотам `0/3/10/11`. Сценовая настройка всё ещё передаётся отдельному host.

| Свойство | PC | PS2 |
| --- | ---: | ---: |
| Размер | `224` | `230` |
| Factory | `404AC0` | `3EEAA0` |
| Constructor | проверен через factory | `2FF000` |
| Vtable | `6FADE0` | `498890` |
| Поле типа | `128 = 17` | `134 = 17` |
| Setup / флаги / классификация | `52D540` / `52D3B0` / `52D450` | `2FEDB0` / `2FEC30` / `2FEBB0` |
| Notify | `52D6F0` | `2FED40` |

Точные 32-битные представления находятся в [PC](../../../Winx/Analysis/PC/wxBacoStateMachineAbi.h) и [PS2](../../../Winx/Analysis/PS2/wxBacoStateMachineAbi.h). Они не совпадают с layout переносимого C++ класса. PC factory, исходный clone и оба пути удаления были выполнены в оригинале; PS2 constructor и vtable проверены статически. Copy slot обеих vtable указывает прямо на `wxEntity::Copy`, поэтому собственные флаги и четыре состояния этим вызовом не переносятся. Переносимый clone изменённого источника сохраняет пустые состояния нового объекта; остальные поля родительского Copy ещё требуют привязки `wxEntity`.

## Собственные операции

Vtable slot 14 возвращает false. Slot 19 разбирает 32-битный packed key: категория `(key >> 15) & 0xF`, равная `3`, сразу даёт `11`; при отсутствии активного объекта владельца тоже возвращается `11`. Категория `1` при наличии объекта даёт `10`. Затем action byte `(key >> 7) & 0xFF`, равный `8` или `9`, даёт `3`, прочие значения — `0`. На обеих платформах последовательность условий совпадает.

Slot 18 копирует исходное слово флагов в вычисляемое и очищает младшие четыре бита. Внешние флаги по смещениям `20/21` задают соответственно `0x400/0x480`; первый имеет приоритет. Флаги `5F/5C` задают `0x18000/0x8000`; `5F` имеет приоритет. PC и PS2 используют разные маски в отдельных ветвях, но итоговые слова совпадают: различающиеся биты затем принудительно выставляются. Четыре входных флага передаются явно, потому что внешний объект управления ещё не восстановлен.

Slot 17 после внешней подписки на группу `5`, условного вызова службы владельца и базовой настройки создаёт четыре состояния в порядке `wxSpiderMovingState`, `wxSpiderAttackState`, `wxSpiderHurtState`, `wxDyingState`. Каждому записываются machine и контроллер анимации. PC поля указателей — `148/154/170/174`, PS2 — `154/160/17C/180`. Внешние шаги и конкретные фабрики переданы обязательному [host-интерфейсу](../../../Winx/Analysis/Host/wxBacoStateMachineHost.h). Он не предоставляет пустых реализаций. Повторный setup и поведение при ошибке выделения не проверены; переносимый вызов явно отклоняет повтор и null от фабрики.

Notify с кодом `1C` вызывает setup. Код `2717` передаёт третье состояние обработчику; точный контракт обработчика остаётся за host. Остальные коды делегируются базовой машине в игре и потому не объявлены обработанными переносимым leaf-методом. Подтверждённая часть общего протокола переходов доступна через базовый класс; нормальная привязка сцены и активные тела четырёх конкретных состояний остаются отдельной задачей.

Проверка `WinxBacoStateMachineTests` охватывает RTTI/factory, исходный clone, обе ветви классификации, приоритеты и сохранение битов, порядок четырёх состояний и адресата `2717`. Дополнительно 128 ограниченных запусков оригинальных PC методов классификации и вычисления флагов совпали с переносимыми формулами на выбранных входах. Исходные наблюдения и адреса записаны в закрытом исследовательском журнале; игровые файлы не публикуются.
