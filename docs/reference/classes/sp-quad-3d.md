# spQuad3D

`spQuad3D` зарегистрирован в PC-версии с ClassID `0x42B2502F` и регистрационной базой `spBaseObject`. Наличие одноимённого класса в PS2-версии не установлено.

PC-объект занимает `0x30` байт. За префиксом `spBaseObject` находятся две владеющие ссылки (`+10`, `+14`), позиция из трёх `float` (`+18`), ширина и высота (`+24`, `+28`) и цвет `uint32` (`+2C`). Фабрика устанавливает нулевые ссылки, позицию и размеры; цвет равен `0xFFFFFFFF`. Деструктор освобождает ссылку материала `+14` перед ссылкой буфера `+10`. Клонирование создаёт новый объект и вызывает базовое копирование: производные поля и ссылки остаются значениями фабрики.

Отрисовка запрашивает у глобального renderer буфер с форматом `0x900` и массив индексов. При нулевом указателе первого буфера операция возвращает `false`, не запрашивая индексы; при нулевых индексах также возвращает `false`. Остальные ветви строят четыре записи по `24` байта: позиция, упакованный цвет и два `float` UV.

Ориентация квадрата зависит от мировой ориентации камеры. Нормализованное отрицательное третье направление камеры задаёт forward. Первое up — `(0,1,0)`; при `abs(abs(dot(up,forward))-1) <= 0.001f` используется нормализованное второе направление камеры. Затем нормализуются `right = cross(up,forward)` и `up = cross(forward,right)`. Right умножается на половину ширины, up — на половину высоты. Малые векторы длиной не более `0.001f` нормализатор заменяет нулём.

Вершины записываются в следующем порядке:

| Позиция | UV |
| --- | --- |
| center − right − up | `(0,0)` |
| center − right + up | `(0,1)` |
| center + right − up | `(1,0)` |
| center + right + up | `(1,1)` |

Индексы равны `0,2,1,1,2,3`. Если специальный флаг состояния renderer сброшен, выбирается собственный буфер или резервный буфер renderer и устанавливается его матричный токен. Далее всегда применяются материал и вызов draw с аргументами `2,2,4`; его младший байт определяет результат.

Переносимая реализация находится в `Sparkplug/Code/Sparkplug/spQuad3D.*`. Устройства и глобальное состояние явно передаются через `Analysis/Host/spQuad3DHost.h`. Разделяемое владение ресурсами и методы `ForAnalysis` — адаптация host. Вычисления повторяют порядок операций и промежуточных записей исходной PC-функции, но используют `double` для нормализации; побитовая эквивалентность всех x87-входов не заявляется. Нефинитные входы и переполнение геометрии отклоняются дополнительной host-проверкой. ABI-описание не накладывается на объект C++.
