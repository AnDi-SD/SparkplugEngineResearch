## Общий Widget и текстовый потомок

`enabled` — byte28; `highlight` — byte3DPC/39PS2. Коды ниже — реальные
числовые значения сообщений, не предположение о названиях событий ОС.

| Код | Собственное поведение |
| --- | --- |
| 0E,0F,10 | При enabled!=0 переслать исходное сообщение owner+24, затем вызвать базовый GUIObject Notify |
| 11 / 12 | При enabled!=0 поставить highlight1 /0, вызвать собственный virtual refresh; следующий owner-forward остаётся за этой границей |
| 18 | Через базовый Notify записать this по адресу payload+18 исходного сообщения |
| 1C | При Node+18!=0 начать original lookup `NORMAL`; при null Node перейти через базовый Notify к реальному GUIObject Enable, где проба останавливается |
| Необработанный код | Передать базовому GUIObject Notify |

## EditBox: фокус, символы и удаление последнего байта

Код13 передаёт символ в436C60/169920. На PC в стеке передан весь payload word;
PS2 caller использует `LB message+18` и знаково расширяет младший байт.

аргумента между платформами не предполагалось. Полное добавление текста открыто.

## Игровой wxButton и значение булевого ответа

Код1C использует payload+18 как режим:

| Режим | Подтверждённая операция |
| --- | --- |
| 0 | Записать булев ответ в message+1C; определён младший байт1 |
| 1 | Дойти до настоящего broadcast40EC00/1007A0: code2715,key3,payload0/0 |
| 2 | Вернуться без базовой обработки и изменений |

## Учёт и ограничения

Пять классов получают +5 на каждой платформе: Widget40→45/35→40,
TextWidget20→25/15→20,Button35→40/30→35,EditBox20→25/15→20,
wxButton20→25/15→20 (PC/PS2). Полученный балл относится к маршрутизации и
собственным эффектам Notify, не к ещё неизвестным consumer bodies.
