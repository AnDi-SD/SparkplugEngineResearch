# PS2: scalar-подготовка параметров pipeline

EE helper `0x002076E0` готовит две последовательности 16-байтных записей до
формирования VIF-пакета. В общем исходнике
[spPS2PipelineScalarPreparation.h](../../../Sparkplug/Analysis/PS2/spPS2PipelineScalarPreparation.h)
восстановлены ограниченный цикл, выбор исходных слов, порядок вычислений и
обновление счётчика. Имена интерфейса аналитические; это не исходный header,
нативный ABI класса или модель всего PS2 renderer.

## Входы и записи

Первые два аргумента native helper не используются. Остальные:

| Регистр | Смысл |
| --- | --- |
| `a2` | Массив максимум четырёх 32-битных указателей на входные объекты |
| `a3` | Первая выходная последовательность, шаг `0x10` байт |
| `t0` | Вторая выходная последовательность, шаг `0x10` байт |
| `t1` | Адрес существующего 32-битного счётчика |

Из каждого ненулевого входного объекта читаются float-слова `+0x70/+74/+78`,
`+0xD0/+D4/+D8/+DC` и `+0xEC`. Исходные C++-имена этих параметров данный helper
не устанавливает. Его видимое вычисление для одного элемента:

```text
first[0..2] = input[+70,+74,+78]        // три неизменённых слова
first[3]    = DIV.S(-1.0, input[+EC])
second[k]   = MUL.S(255.0, input[+D0+4*k]), k=0..3
*count      = low32(*count + 1)
```

`0xBF800000` и `0x437F0000` загружаются непосредственно как `-1.0` и `255.0`.
Между входными значениями и выходными словами нет clamp, цветовой упаковки или
насыщения. Это не подтверждает, что такие операции отсутствуют дальше по пути.

## Ограниченный цикл и состояние

Цикл прекращается при первом NULL либо после четырёх ненулевых элементов.
NULL не пропускается: более поздние указатели не посещаются. Начиная с этого
элемента обе выходные последовательности остаются нетронутыми. Строки результата
не очищаются перед циклом.

Helper не обнуляет переданный счётчик: после каждой полностью записанной пары
записей он читает текущее слово, прибавляет единицу и записывает младшие 32 бита.
Завершающая запись в глобальное слово `0x004B8330` выполняется в delay slot
`JR ra`, в том числе при NULL в первом слоте. Это зеркало окончательного
счётчика, а не отдельное число успешно обработанных элементов данного вызова.
Определённое возвращаемое значение в `v0` helper не формирует.

Установленный прямой caller `0x00206AAC` передаёт массив со `sp+0x200`, выходы
со `sp+0x140` и `sp+0x100`, счётчик со `sp+0x21C`. Он сам обнуляет счётчик в
delay slot вызова. Это свойство caller, которое нельзя приписывать helper.

Аналитический интерфейс принимает уже захваченные восемь слов каждого входа.
Это представление значений, а не layout исходного объекта и не атомарное чтение
его живой памяти. Выходы и оба счётчика принадлежат caller; их storage должен
быть валиден и не перекрываться. Произвольные native aliases, неверные адреса и
поведение аппаратных faults этим интерфейсом не моделируются.

## Арифметическая граница

`PreparePipelineScalarsForAnalysis` требует явный arithmetic provider с
`DivideSingle` и `MultiplySingle`, принимающими и возвращающими raw 32-битные
слова. Он передаёт provider исходные операнды в установленном порядке и не
подставляет обычный host IEEE `float` как доказанное EE-поведение.

Не подтверждены побитовые результаты оригинального EE `DIV.S/MUL.S`, режимы
округления и status flags для произвольных операндов. Отдельно открыты нулевой
и отрицательный делитель, signed zero, denormals, encoded exponent255,
переполнение/underflow и граничные округления. В оригинальном body нет проверок,
которые отклоняли бы эти значения. Для счётчика установлено low32-обновление;
это не float-to-integer conversion и не saturating arithmetic.

Структурные проверки покрывают ранний NULL, untouched tail, четыре элемента,
порядок arithmetic provider, точное копирование трёх исходных слов,
накопление/wrap счётчика и безусловное зеркало. Несколько точно представимых
host-примеров проверяют связь формул с provider, а не эквивалентность всей EE FPU.
Нового исполнения оригинального helper на PS2/эмуляторе эти проверки не дают.

Этот участок относится к CPU preparation. Последующие
[VU upload containers](../materials/shader-discovery.md) и семантика их
инструкций, конкретный VU unit и GS/GIF state остаются отдельными границами.
