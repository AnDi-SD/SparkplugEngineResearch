# PC BallisticPFX: движение, размер точки и цвет

`BallisticPFX.vsh` — отдельный vertex shader 1.1. Он вычисляет положение
частицы по времени, размер точки и COLOR0. Общая семантическая реконструкция
выражений находится в [spBallisticShader.h](../../../Sparkplug/Analysis/PC/spBallisticShader.h).
Это не восстановление CPU-класса `spDXBallisticPFX` и не новый backend.

## Входной контракт

| Вход | Смысл |
| --- | --- |
| v0, POSITION | Исходная позиция P₀, четыре компоненты |
| v1.xyz, NORMAL | Начальная скорость V₀; направление нормали здесь не хранится |
| v2.xy, TEXCOORD | Время рождения и время жизни T |
| c0–c3 | Четыре загруженных вектора view-projection |
| c4.xyz / c5.xyz | AccelBegin / AccelEnd |
| c6 | Позиция камеры, четыре компоненты |
| c7.xyzw | Текущее время, параметр loop, начальный и конечный размер |
| c8.x | Ширина framebuffer |
| c9 / c10 | Начальный и конечный RGBA |

c11 задан внутри программы: `0.5, 1, 0, 0.166667`. Последний коэффициент —
округлённая десятичная константа float, а не точное математическое 1/6.
Порядок параметров соответствует регистрам; native C++-матрицу нельзя
неявно переинтерпретировать как этот массив.

## Возраст и движение

Сначала `t = CurrentTime − BirthTime`. Если одновременно `t >= T` и
`loop >= 0.5`, из t вычитается T **один раз**. Значение loop меньше 0.5
не включает эту ветвь. Modulo и повторного вычитания нет.
Далее `u = t / T`, а три пространственные компоненты равны:

```text
P = P₀.xyz + t·V₀.xyz + 0.5·t²·AccelBegin.xyz
    + 0.166667f·t²·(AccelBegin.xyz − AccelEnd.xyz)·u
clip = P.x·c0 + P.y·c1 + P.z·c2 + c3
```

Для проекции используется неявная однородная координата 1. Входная P₀.w
не масштабирует перенос c3. Знак кубического вклада следует инструкции
шейдера: AccelBegin минус AccelEnd.

## Размер и цвет

Размер вычисляется через расстояние **исходной**, ещё не перемещённой P₀
до c6. Инструкция dp4 включает разность w:

```text
d = sqrt(sum((P₀[i] − Camera[i])², i=0..3))
size = ((1−u)·ScaleBegin + u·ScaleEnd) · [u>=0] · [u<=1] · Width / d
color = (1−u)·ColorBegin + u·ColorEnd
```

Границы u=0 и u=1 включены. При отрицательном возрасте и после конца жизни
размер обнуляется, однако позиция и выражение цвета продолжают вычисляться;
цвет может выйти за [0,1]. Ограничение и квантование выходного цвета,
диапазон растеризуемого point size, текстуры, blending и видимость частицы
принадлежат следующим этапам. Нулевая маска сама по себе не задаёт поведение
вырожденного деления или бесконечного промежуточного результата.

## Границы реконструкции и перенос

Аналитический интерфейс принимает конечные значения, положительный T
и ненулевое конечное четырёхмерное расстояние. При отказе не меняет выход.
Эти проверки добавлены для исследовательского API; исходный shader их
не содержит. Точность GPU-инструкций rcp/rsq/MAD не заявлена побитовой.
Позиция, point size и цвет сопоставлены с исполнением неизменённого
оригинального байткода через системный D3D9 ProcessVertices; для цвета
учитывается его преобразование в packed ARGB.

Для переноса нужны начальная позиция, скорость, рождение, lifetime
и актуальные константы. Передача исходных вершин как неподвижного меша
теряет движение. Замена размера на расстояние от уже перемещённой позиции
также меняет исходное поведение. Представление точек геометрией в Remix
требует отдельной проверки размера, UV, цвета и смешивания.

У класса эффекта отдельно подтверждён
[CPU-путь quads](ballistic-cpu-draw.md), чья математика отличается.
Связь этого шейдера с конкретными вызовами CPU-производителя, полное
обновление системы частиц и её реальная отрисовка пока не закрыты.
Семантика программы не доказывает, что она использовалась в данном игровом
кадре. PC-контракт не переносится автоматически на PS2.
