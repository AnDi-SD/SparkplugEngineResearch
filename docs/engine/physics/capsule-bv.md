# spCapsuleBV

`spCapsuleBV` зарегистрирован с идентификатором `0x312FABC0` и базой
`spBoundingVolume`. Обе платформы выделяют 120 байт. Физический префикс
BoundingVolume включает `spNamedObject`; это не меняет прямую регистрационную
базу. Путь восстановленных `.h` и `.cpp` предполагаемый.

## Состояние

| Native offset | Содержимое | Начальное значение |
| --- | --- | --- |
| `+14` | тип примитива | 3 |
| `+28` | длина осевого отрезка, float | 1 |
| `+2C` | радиус, float | 1 |
| `+30..50` | локальная матрица 3×3 | единичная |
| `+54..5C` | первый endpoint cache | `(0, −0.5, 0)` |
| `+60..68` | второй endpoint cache | `(0, 0.5, 0)` |
| `+6C..74` | локальная позиция | `(0, 0, 0)` |

Общие BoundingVolume center/radius и собственная форма Capsule — отдельные
поля. Изученная transform-операция не записывает общие bounds и не читает
собственный радиус Capsule.

Clone создаёт новую Capsule, регистрирует пару source/destination и вызывает
унаследованный Named copy. Имя сохраняется; длина, радиус, локальная матрица,
позиция и оба endpoint cache остаются начальными. Отдельное унаследованное
copy не заменяет геометрию уже существующего destination. Endpoint cache
принадлежит Capsule и изменяется на том же объекте.

## Transform

PC slot `+1C` принимает позицию, матрицу ориентации, компонентный scale и
четвёртый аргумент, который в этом теле не читается. Метод возвращается с
`RET 10`. Аналитический общий интерфейс передаёт три используемых значения.

Порядок операции:

1. Локальная позиция умножается на scale по компонентам, преобразуется
   входной матрицей и прибавляется к входной позиции.
2. Локальная матрица умножается слева на входную матрицу; результат заменяет
   входную ориентацию. Восстановленный порядок — `local × incoming`.
3. Выбирается обычный знаковый максимум трёх компонент scale. Длина
   умножается на этот максимум.
4. Второй ряд результирующей матрицы задаёт направления двух половин
   отрезка. Сохраняются исходные нулевые terms первого и третьего ряда.
   Каждый offset дополнительно умножается на соответствующую компоненту
   scale, затем прибавляется новая позиция.
5. Отрицательная половина записывается в первый cache, положительная — во
   второй. Входной scale при раздельных аргументах сохраняется.

PC вычисляет положительную половину из extended произведения длины и
максимума scale; отрицательная половина использует уже записанное float
произведение. Translation X/Y также имеют float store до прибавления
позиции, а Z сохраняет extended значение. В endpoint X extended значение
сохраняется через компонентный scale; Y/Z имеют дополнительные float stores.
Матрица 3×3 вычисляется с отдельным исходным порядком трёх terms для каждой
ячейки. Эти записи влияют на точные float bits.

PS2 отдельно подтверждает начальную форму и аналогичную последовательность
операций transform. Общая реализация пока квалифицирует PC finite arithmetic
при стандартном ближайшем округлении x87. Полный PS2 EE/VU float pipeline,
нечисловые входы и другие режимы x87 остаются за этой границей.

## Аналитический контракт

`TryUpdateCollisionTransformForAnalysis` возвращает `false`, если операция
выходит за представленный finite math slice. Отказ происходит до публикации
endpoint cache и выходных transform-значений. Собственный radius допускает
любые bits, поскольку оригинальная операция его не читает.

`spCollisionInfo::UpdateWorldForAnalysis` публикует свои PRS и bounds перед
виртуальным вызовом примитива и передаёт ссылки на действительные members.
При успешном вызове сохраняется исходный порядок наблюдаемых изменений.
При analytical отказе CollisionInfo возвращает `false` и восстанавливает
свои прежние поля; это политика нашего host boundary, не утверждение о
транзакционности оригинальной игры. Node передаёт отказ вызывающему коду.

Совместимый void alias не имеет канала для статуса. Завершённые аналитические
операции используют Try. Query planes, contacts, intersections и поведение
collision manager этим классом не представлены.
