# Contact: два body и две ordered raw dot-суммы

Этот PC value-профиль ContactConstraint ограничен одной строкой, полным `40=0`, `58=1`, `88=8` и двумя различными заданными body/buffer role tags. Теги инертны: native-указатели не разыменовываются. Для каждого body явно передаются point и шесть raw DWORD по смещениям `8C`, `90`, `94`, `98`, `9C`, `A0`; названия физических величин этим ролям чтения не приписываются.

Первичные строки используют общий [контракт двух body](contact-two-body-row.md). Для body1 все displacement-компоненты перечитываются из F32. В первичной строке body2 X сохраняется в F32, а Y/Z продолжают участвовать как extended; angular X/Y сохраняются в F32 перед сменой знака, Z меняет знак до F32. Новое арифметическое ядро для этого не создаётся.

После F32-записей linear/angular для каждого body вычисляется своя ordered-сумма: `A0*angularZ`, затем `9C*angularY`, `94*linearZ`, `90*linearY`, `98*angularX`, `8C*linearX`. Каждая операция округляется в nearest64. Только после завершения обеих сумм выполняется одно nearest64-сложение D1+D2, соответствующее PC `0048B8AC`. Их нельзя заменить одной flattened-суммой двенадцати слагаемых или точным dot с единственным конечным округлением.

Контактный raw `98` должен быть неотрицателен; затем требуется строгое `-(D1+D2)>Contact98`. Кандидат — смена знака произведения combined*Contact94. Сравнение с уже перечитанным F32 RHS выполняется до F32-конверсии кандидата. Отдельный `rhsStoreSelected` сообщает выбор исходной optional-записи PC `0048B8E6`, включая случай одинаковых итоговых F32-байтов. Это наш диагностический bool, не native return/ABI/CPU-status и не трасса машинных записей C++.

Default-профиль отказной. Явный профиль проверяет captured primary, фиксированные поля, ненулевые различные пары `48/4C` и `6C/70`, остальные нужные теги, точные Manager `7C/80`, scalar `[0.25,4]` и конечные участвующие числа с модулем не больше 16. Нулевая normal допускается: tangent helper и root не вызываются.

Выход — отдельный staged value 480 байт и корректный отдельный diagnostic-объект. Refusal сохраняет оба выхода; success допускает before/output alias. Перекрытие diagnostic со state не входит в API. Физическая база, владельцы carrier, lifecycle, конструктор/startup, native pointer ABI, остальные ветви, полный solver, PS2 и gameplay остаются неизвестными.
