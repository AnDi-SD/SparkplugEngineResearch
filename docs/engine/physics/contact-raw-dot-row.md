# Contact: одна строка и raw dot-ветвь

В PC-профиле ContactConstraint с `40=0`, `4C=0`, `58=1`, `70=0` и полным DWORD `88=8` сначала формируется одна строка для заданного body. Затем блок читает шесть raw DWORD тела по смещениям `8C`, `90`, `94`, `98`, `9C`, `A0`, а также Contact `94` и `98`. Их назначение здесь ограничено установленными ролями чтения; имена физических величин не восстанавливаются по одной формуле.

Общий [контракт первой строки](contact-single-body-row.md) сохраняется. В dot-ветви читаются уже сохранённые F32 linear/angular слова `6C`. Произведения и суммы идут в исходном порядке: `bodyA0*angularZ`, затем `body9C*angularY`, `body94*linearZ`, `body90*linearY`, `body98*angularX`, `body8C*linearX`. После каждого арифметического действия применяется nearest64, а не вычисление одной точной суммы с последующим округлением.

При Contact `98 < 0` ветвь завершается. Иначе требуется строгое `-dot > Contact98`. Кандидат вычисляется как смена знака произведения `dot*Contact94`; его extended-значение должно быть строго больше текущего перечитанного F32 RHS. Только после этого выбирается запись кандидата в F32. Знаки нуля сохраняются, но при сравнении `-0` и `+0` равны.

Выбранная запись может не изменить байты: положительное extended-значение меньше половины минимального F32 subnormal округляется в `+0`. Поэтому наш `rhsStoreSelected` отдельно передаёт выбор исходного события по PC `0048B8E6`. Этот bool является analysis-диагностикой. Он не описывает порядок машинных записей скомпилированного C++, native ABI или возвращаемое значение метода.

`ComputeContactRawDotRowForAnalysis` принимает отдельное value-состояние 384 байта, явные bodyPoint и шесть raw body-слов по значению. Инертные ненулевые теги из captured Contact не разыменовываются. Профиль по умолчанию отказной; явный профиль требует исходную primary-таблицу, перечисленные фиксированные поля, точные Manager `7C/80`, scalar в `[0.25,4]` и остальные участвующие числа finite с модулем не больше 16. Нулевая normal допустима: tangent helper и извлечение корня не вызываются.

При отказе сохраняются и output-состояние, и диагностический объект. Успех вычисляется через staged value и допускает совпадение before/output. Диагностика должна быть отдельным корректным объектом и не перекрывать представление состояния.

Физическая база native-класса, тип point-carrier, native pointer ABI, конструктор, lifetime, граф объектов, другие флаги и строки, PS2, полный solver и поведение игры этим value-контрактом не определяются. Общие integer nearest64 и первая строка используются без новой копии арифметического ядра.
