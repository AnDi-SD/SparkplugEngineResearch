# GUIObject: поиск GUICollision и история состояния контроллеров

## Enable: обе ветви записывают 4

`spGUIObject` slot10: PC `004290B0`, PS2 `00165240`. Метод записывает младший
байт аргумента в `this+28`, затем вызывает настоящий Node Find по имени
`GUICollision`, с двумя аргументами `1,1`. Это поиск подстроки, чувствительный
к регистру: `preGUICollisionExtra` подходит, `guicollision` и `GUI` — нет.

У найденного узла все элементы controller vector получают слово `4` по
смещению `+18`. Это происходит **и при включении, и при выключении**:
две ветви исходного метода одинаково обходят список и записывают это значение.
Иные значения слова не сохраняются методом Enable. Неизвестное назначение
отдельных битов слова не подменяется предполагаемым enum.

14 входов на платформу проверяют 0/1/255/12345680/256, пустой список,
один/три элемента, повтор одного указателя, прежнее значение4, подстроку,
несовпадение регистра, отсутствие имени и пустую строку. Сохраняются порядок
и число исходных записей, guard20 КиБ включает неиспользуемый controller.

## Привязка: накопление массива и восстановление с начала

Метод при наличии прежнего узла сначала удаляет подписку на него и его
непосредственных детей, затем восстанавливает controller words `+18`
из сохранённого в GUIObject массива. Число восстановлений ограничено
меньшим из двух размеров: controller vector старого узла и saved vector.
При смене указателя уменьшает старый 16-битный reference count, вызывает
его deleting destructor при нуле, увеличивает новый count и меняет `this+18`.
При неизменном указателе reference count не меняется, остальные стадии остаются.

| Вызов | Контроллеры A | Контроллеры B | Saved vector |
| --- | --- | --- | --- |
| До вызовов | 1,2,3 | 16,32 | пусто |
| bind A | 4,4,4 | 16,32 | 1,2,3 |
| bind B | 1,2,3 | 4,4 | 1,2,3,16,32 |
| bind null | 1,2,3 | **1,2** | 1,2,3,16,32 |
