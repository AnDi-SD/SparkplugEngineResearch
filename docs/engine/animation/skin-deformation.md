# PC Skin: деформация вершин в Fixed.rfx

`spSkin` формирует палитру `inverseBind × boneWorld`, а `Fixed.rfx` применяет
её к вершинам. Это разные операции: совпадение палитры ещё не означает,
что другой renderer одинаково использует веса, индексы и нормали.
Подготовка палитры описана в [Skin render](skin-render.md), выбор программы —
в [контракте шейдеров](../materials/shader-contract.md).

## Палитра и входные данные

В исходном `Fixed.rfx` массив `BlendMatrices` содержит **16 матриц float4x3**.
Каждая занимает три регистра по четыре float, то есть 48 байт; вся палитра
занимает 48 регистров. Каждый регистр содержит коэффициенты одной выходной
координаты, включая перенос. Это транспонированная аффинная часть матрицы
движка. Native matrix4, shader registers и матрица внешнего API требуют
явного согласования порядка элементов.

`BlendWeightCount` выбирается при генерации шейдера. Восстановленные ветви
деформации охватывают 1–4 влияния. Индексы в shader input представлены как
float; исходные упакованные bytes раскрываются в численные float без
нормализации. Весовые слова при загрузке вершин сохраняются. Нулевой вес
не делает произвольный индекс допустимым: программа может прочитать матрицу
до умножения на вес.

У варианта без весов отдельный путь преобразования через `view_proj_matrix`.
Его нельзя подменять вариантом с одной костью и выдуманной палитрой.

## Позиция

Пусть `P=(x,y,z,w)`, `a[i]` — записанный вес, `M[i]` — выбранная матрица.
Для каждого из 1–4 влияний вычисляется `P × M[i]`; результат имеет три
координаты. Затем:

```text
P'.xyz = Σ a[i] × (P × M[i])
P'.w   = P.w
clip   = VPTransform × P'
```

Все записанные веса участвуют, включая последний и отрицательные.
Шейдер не делит позицию на сумму весов, не заменяет последний вес остатком
и не пересчитывает `P'.w` по сумме. Перенос каждой кости умножается на
исходное `P.w` внутри матричного произведения.

Например, одна единичная кость с весом 2 преобразует `(2,3,4,1)` в
`(4,6,8,1)`. Две единичные кости с весами 0,25 и 0,25 дают
`(1,1.5,2,1)`. Автоматическая нормализация весов изменит эти результаты.

## Нормаль

Нормаль проходит линейную часть тех же матриц, без переноса:

```text
N'.xyz = Σ a[i] × (N.xyz × linear(M[i]))
N'.w   = N.w
N''    = normalize4(N')
Nview  = normalize3(linear(view_matrix) × N''.xyz)
```

Используется обычная линейная матрица кости, **без inverse transpose**.
Поэтому при неравномерном масштабе нельзя заменять её преобразованием
нормалей, выбранным по правилам нового backend. Например, scale `(2,3,1)`
и нормаль `(1,1,0)` дают направление с отношением `y/x = 3/2`.

Четвёртая компонента нормали сохраняется при присваивании `xyz` и входит
в первую нормализацию. Следующая нормализация в пространстве камеры
устраняет общий ненулевой масштаб `xyz`. Для конечной ненулевой нормали
можно сравнивать направления; это не разрешает незаметно менять промежуточные
значения шейдера. Поведение нулевых нормалей, NaN, переполнений и неправильных
индексов не определено этой реконструкцией.

## Общая реализация и её границы

[spFixedShaderSkinning.h](../../../Sparkplug/Analysis/PC/spFixedShaderSkinning.h)
содержит общую C++-реализацию установленных выражений weighted-ветви.
Это семантическая реконструкция шейдера, а не найденный CPU-метод игры.
Она возвращает позицию с сохранённой `w` и нормализованную `float4`-нормаль
до преобразования камерой. Освещение, UV, raster clipping и texture stages
остаются в своих подсистемах.

Следующий этап, преобразование нормали камерой и directional/color-ветвь,
реализован отдельно в [общем контракте освещения Fixed](../materials/shader-contract.md).

Проверки указателей, размеров, конечности и нулевой длины принадлежат
аналитическому интерфейсу. При отказе выход не меняется. Не заявляется
побитовое совпадение с GPU: порядок команд, точность `rsq` и округление
`mad` могут различаться. PS2 skinning этой реализацией не восстанавливается.

## Следствия для переноса

Renderer с неявным последним весом воспроизводит геометрию только при
совместимой сумме, знаках весов и представлении матриц. Малую ошибку суммы
нужно оценивать вместе с величиной преобразованной вершины последней кости:
при остальных одинаковых условиях изменение позиции равно
`(aImplicitLast − aStoredLast) × (P × MLast)`. Один допуск на сумму весов
не ограничивает ошибку в мировых координатах для любой сцены.

Максимум костей внешнего API не расширяет массив из 16 матриц конкретного
`Fixed.rfx`. Поддержка более длинной палитры требует другого установленного
шейдерного контракта. Особенности адаптера находятся в
[документации WinxRemix](../../../tools/WinxRemix/docs/development.md).
