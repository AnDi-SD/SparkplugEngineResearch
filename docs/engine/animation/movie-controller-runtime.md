# MovieTextureController и конкретные VideoStream

## Связь контроллера с материалом

`spMovieTextureController` PC `492EF0`, PS2 `11B1E0` получает материал
из собственного `+1C`, затем VideoStream из material `+70` / `+88`.
Если byte `video+18` ненулевой, метод завершается. При нуле вызывается
первый метод основного video-интерфейса. Null-проверок этих указателей
нет; это не означает, что null допустим для внешнего API.

PS2 конструктор материала `172260` статически подтверждает цепочку:
`20D840` создаёт video, запись `172290` сохраняет его по `+88`;
созданный MovieTextureController сохраняется по `+8C`, а material записывается
в controller `+1C` инструкцией `1722B8`. Здесь этот конструктор не исполнялся.

## Аналитический вызов на PC

У PC-контроллера class ID `0x7487689D`, основная таблица `0x006ECB68`.
Слот `+0x1C` соответствует интерфейсу `spSubController::ApplyForAnalysis(float)`.
В `00492EF0` аргумент со стека остаётся непрочитанным, обе ветви
завершаются одной инструкцией `RET 4` по адресу `00492F01`.

Аналитический контроллер получает заимствованную связь материала с живым
`spPCVideoStream`. При нуле `byte18` он один раз вызывает существующий
`NativeHook00ForAnalysis()`. Опциональное наблюдение сообщает факт этого вызова.
Его результат AL и промежуточные значения EAX принадлежат исходной трассе.
[Исходник контроллера](../../../Sparkplug/Code/Sparkplug/spMovieTextureController.cpp)

В сохранённых PC-вызовах состояния `00`, `01`, `02` и `FF` проверены с
двумя наборами окружения. При нуле наблюдались оба входа `004C7320` и
`0048EAA0`. Во всех восьми случаях полная область связанных объектов
сохранила свои байты. Фабрика, членство в менеджере, владение материалом,
декодирование, воспроизведение и реализация PS2 остаются отдельными задачами.

## Чтение поля ресурса на PC

У `spMaterialMovieTexture` class ID `0x6A24474A`, регистрационная база
`spMaterialTexture` и primary `0x006EA94C`. Слот `+0x1C` ведёт к
`004784D0`. Метод читает адрес связанного ресурса из материала по `+0x68`,
загружает DWORD ресурса по `+0x18` в EAX и выполняет `RET`.

Аналитическое чтение принимает 108 байтов захваченного материала
и заимствованный 28-байтовый префикс ресурса. Оно проверяет PC primary
и совпадение захваченного адреса ресурса со ссылкой материала, затем
возвращает все 32 бита поля. При неверной связи выходное значение сохраняется.
[Исходник чтения поля ресурса](../../../Sparkplug/Code/Sparkplug/spMaterialMovieTexture.cpp)

В четырёх сохранённых PC-сценариях исходный вызов вернул точные сырые значения,
а объектный буфер сохранил все байты. Имя и смысл поля, тип ресурса, владение,
жизненный цикл, вызовы с недействительными ссылками и PS2 остаются открытыми.

## Оригинальные VideoStream

PC объект `spPCVideoStream` имеет основной интерфейс `6F2AC4` и базовую
таблицу `6F2AA8` в под­объекте `+4`, что подтверждено прежней фабрикой.
Первый метод `4C7320` вызывает второй метод таблицы — оригинальный пустой
`48EAA0` — и возвращает AL=1. Остальные биты EAX не объявляются bool.

## Ограничения и подготовка

Оценки +5: MovieTextureController и MaterialMovieTexture на обеих
платформах, spPCVideoStream на PC и spPS2VideoStream на PS2. Базовый
spVideoStream, wxMoviePlayer и MovieLayer не получают косвенного зачёта.
