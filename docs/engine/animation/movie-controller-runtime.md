# MovieTextureController и конкретные VideoStream

## Связь контроллера с материалом

`spMovieTextureController` PC `492EF0`, PS2 `11B1E0` получает материал
из собственного `+1C`, затем VideoStream из material `+70` / `+88`.
Если byte `video+18` ненулевой, метод завершается. При нуле вызывается
первый метод основного video-интерфейса. Null-проверок этих указателей
нет; это не означает, что null допустим для внешнего API.

PS2 конструктор материала `172260` статически подтверждает цепочку:
`20D840` создаёт video, запись `172290` сохраняет его по `+88`;
созданный MovieTextureController сохраняется по `+8C`, а material записывается
в controller `+1C` инструкцией `1722B8`. Здесь этот конструктор не исполнялся.

## Оригинальные VideoStream

PC объект `spPCVideoStream` имеет основной интерфейс `6F2AC4` и базовую
таблицу `6F2AA8` в под­объекте `+4`, что подтверждено прежней фабрикой.
Первый метод `4C7320` вызывает второй метод таблицы — оригинальный пустой
`48EAA0` — и возвращает AL=1. Остальные биты EAX не объявляются bool.

## Ограничения и подготовка

Оценки +5: MovieTextureController и MaterialMovieTexture на обеих
платформах, spPCVideoStream на PC и spPS2VideoStream на PS2. Базовый
spVideoStream, wxMoviePlayer и MovieLayer не получают косвенного зачёта.
