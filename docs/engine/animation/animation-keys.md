# PC SAN: payload → descriptors → preparation → sampling

## Типы записей

| Representation | Position/scale | Rotation | Values stride на ключ |
| ---: | --- | --- | --- |
| 1 | packed Vector3 linear | packed quaternion Slerp | 12 / 16 bytes |
| 2 | packed cubic Vector3 | quaternion + squad control | 60 / 32 bytes |
| 3 | три scalar linear descriptors | три scalar angles | 4 bytes |
| 4 | три scalar cubic descriptors | три scalar cubic angles | 20 bytes |

Scalar descriptors имеют независимые times/counts/caches; первый mode `>=3`
включает три axes. Numeric modes отдельных scalar axes могут быть `3/4`.
Mode `0` payload — один нулевой uint, канал отсутствует. Packed mode `1`
с count `0` — иной, реально встреченный случай: descriptor существует,
но sampler не выставляет validity.

## Reader и общие массивы

Protected reader `0x0043DB90` разрешается через `0x013B11B4` в `0x00450D51`:
initial axis count `1`, затем jump `0x0043DBA3`. Signature:
`this=serializer working state`, arguments stream, track, role, animation;
`ret 0x10`. Для первого scalar descriptor axis count становится `3`.

Для каждого descriptor читаются uint representation, uint count, `count`
float times и `count*stride` raw values. Прямое stream read — vslot `+0x30`;
metadata uint helper `0x00416DA0` использует тот же byte-source.

Times берутся с offset `serializer+0x44` из единого `animation+0x50` buffer.
Values используют один из шести массивов `animation+0x38..+0x4C`, а текущие
cursors находятся в `serializer+0x2C..+0x40`.

| SAN field | Animation storage | Назначение capacity/count hint | Stride |
| ---: | ---: | --- | ---: |
| 6 | `+0x38` | scalar linear values | 4 |
| 7 | `+0x3C` | scalar cubic values | 20 |
| 8 | `+0x40` | Vector3 linear values | 12 |
| 9 | `+0x44` | Vector3 cubic values | 60 |
| 10 | `+0x48` | quaternion linear values | 16 |
| 11 | `+0x4C` | quaternion cubic values | 32 |
| 12 | `+0x50` | все float times | 4 |
| 64 | track array reservation | необязательный reserve hint, не terminator | track `0x44` |

Main reader `0x0043ECC0` выделяет эти массивы по hints. Writer `0x0043DDC0` подтверждает ту же таблицу и суммирует фактические counts. Shared-array capacities должны трактоваться отдельно от числа завершённых tracks.

## Подготовка после чтения

Raw cubic payload **содержит место для coefficients**, но attach пересчитывает
их в общем массиве. Поэтому точное wire payload не равно готовому runtime
значению всех его floats.

Scalar/vector cubic record хранит пять scalar/Vector3 блоков:
value, incoming tangent, outgoing tangent, quadratic coefficient, cubic coefficient.
Для сегмента `i → i+1`, `delta = value[i+1]-value[i]`:

```
c2[i] = 3*delta - (2*outgoing[i] + incoming[i+1])
c3[i] = outgoing[i] + incoming[i+1] - 2*delta
sample = value[i] + u*(outgoing[i] + u*(c2[i] + u*c3[i]))
```

Scalar helper `0x00493160`, vector `0x00493290`. Последняя запись не
пересчитывается. Times здесь не читаются: `u` — уже нормализованная доля
интервала. Incoming tangent используется при preparation, но не при sample
того же сегмента — это не «неизвестный/unused float».

В PC-ветви scalar cubic вызов `0x0047998F` передаёт в `0x00493160`
массив 20-байтовых записей и число ключей. Помощник пишет `c2` и `c3`
в поля `+0x0C` и `+0x10` каждой записи со следующим ключом. При одном
ключе участок сразу возвращается без обращения к содержимому записи.
Для обеих формул промежуточные вычисления остаются в x87 с 64 значащими
битами при `FPCW=037F`. Результаты хранятся в binary32. Вторая формула
сначала складывает incoming следующего ключа и outgoing текущего, затем
вычитает удвоенную разность значений.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationScalarCubicPc.h)
работает с предоставленным массивом. Для прочитанных полей поддерживаются
нули обоих знаков и нормальные binary32 по модулю от `2^-64` до `4096`.
Векторная подготовка, загрузка SAN и вызовы действующего sampler имеют
собственные границы проверки.

В PC-ветви packed cubic вызов `0x004799B2` передаёт в `0x00493290`
массив 60-байтовых записей и число ключей. В каждой записи со следующим
ключом помощник записывает `c2` в `+0x24` и `c3` в `+0x30`, в порядке
Z, X, Y для каждого вектора. При одном ключе указатель массива и содержимое
записи остаются непрочитанными.

При `FPCW=037F` арифметика имеет 64 значащих бита. Для оси Z разность
значений `delta` округляется до binary32 перед обоими умножениями.
Для X и Y разность остаётся в x87 до умножения. Ниже `F32` означает
промежуточную запись с округлением до binary32. Каждая пара задаёт
левый и правый операнды вычитания перед итоговой записью в binary32.

| Ось | Операнды `c2` | Операнды `c3` |
| --- | --- | --- |
| X | `F32(3*delta)`, `F32(2*out+in)` | `in+out`, `F32(2*delta)` |
| Y | `F32(3*delta)`, `F32(2*out+in)` | `F32(in+out)`, `F32(2*delta)` |
| Z | `F32(3*delta)`, `F32(2*out)+in` | `F32(in+out)`, `2*delta` |

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationVectorCubicCoefficientsPc.h)
использует ту же структуру записи, что и вычисление значения на кривой.
Допустимые входы для читаемых полей включают нули обоих знаков и нормальные
binary32 по модулю от `2^-64` до `4096`. Загрузка SAN, подключение к
действующей подготовке кривых и PS2 остаются отдельными операциями.

Quaternion helper `0x004933C0` разрешён в `.rld` body `0x013C1220`.
Для одного ключа control копирует quaternion; protected resolver также
инициализирует referenced constant `0x013B354C` значением `1`. Нулевые исходные
file bytes этой константы нельзя принимать за runtime значение до resolver-а.
Для нескольких ключей helper `0x00464DE0` вычисляет:

```
control[i] = q[i] * exp(-0.25 * (
    log(conjugate(q[i]) * q[previous]) +
    log(conjugate(q[i]) * q[next])))
```

На краях отсутствующий сосед повторяет крайний quaternion. Log/exp
`0x00464C10/0x00464B90` используют threshold `0.001`, не добавляют
normalization/clamp. Squad `0x00464B20` смешивает Slerp endpoints и Slerp
controls с коэффициентом `2*u*(1-u)`.

В PC-ветви packed rotation вызов `0x00479656` передаёт в SQUAD
два quaternion и два контрольных значения из 32-байтовых записей.
Вызов `0x00464B37` интерполирует контрольные значения, а `0x00464B65`
интерполирует quaternion. Последний Slerp `0x00464B6C` получает
результат интерполяции quaternion, результат интерполяции контрольных
значений и подготовленный фактор смешивания.

Участок `0x00464B3C`–`0x00464B5C` читает `u` как binary32. Он вычисляет
`1-u`, умножает на `u` и удваивает произведение сложением. Все три
операции сохраняют 64 значащих бита x87 при `FPCW=037F`. Единственная
запись фактора округляет его до binary32. При `u=0x3EAAAAAB`
результат равен `0x3EE38E39`, а отрицательный ноль сохраняет знак.
Аналитическая операция принимает нули обоих знаков и положительные
нормальные binary32 от `2^-64` до `1`.
[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationQuaternionSquadFactorPc.h)

## Sampling и границы

PC-помощник `0x00478F90` принимает отсортированные метки времени,
число ключей, текущее время и индекс из кэша. Индекс за верхней границей
сбрасывается к первому ключу. Поиск идёт в обе стороны от стартового
индекса. Точное равенство продвигает поиск через одинаковые метки.
Функция возвращает индекс в EAX и записывает коэффициент в binary32.
Вызывающий sampler сохраняет EAX в кэше.

Перед первой меткой результат равен индексу 0 и коэффициенту +0.
На последней метке и после неё массив из одного или двух ключей также
даёт индекс 0 и +0. Для трёх и более ключей возвращается предпоследний
индекс и коэффициент 1.

Внутри интервала функция вычисляет две разности и их частное в x87
с 64 значащими битами при `FPCW=037F`. Единственное округление до
binary32 происходит при записи коэффициента. Для меток `[-1, 2^-25]`
и времени `-2^-25` результат равен `0x3F7FFFFF`.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationKeyIntervalPc.h)
работает с предоставленным массивом. Поддерживаемый числовой профиль
включает нули обоих знаков и нормальные binary32 по модулю от `2^-64`
до `4096`, непустые неубывающие метки и неотрицательный индекс кэша.

Для packed position и scale с representation 1 вызовы `0x00479427` и
`0x0047974E` передают в `0x00479060` два ключа XYZ и уже вычисленный
коэффициент интервала. Помощник умножает первый вектор на `1-u`, второй
на `u`. Для X оба произведения остаются в x87 до сложения. Для Y и Z
каждое произведение сначала сохраняется в binary32, затем складывается
с парным округлённым произведением. Три результата записываются в
binary32. При `FPCW=037F` арифметика x87 использует 64 значащих бита,
а округление идёт к ближайшему чётному.
[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationVectorLinearPc.h).

Аналитический интерфейс принимает нормальные координаты по модулю от
`2^-32` до `4096`, нормальный коэффициент от `2^-32` до `1` и нули
обоих знаков в каждом входе. Оба ключа предоставляются целиком. Выход
можно записать в отдельный вектор или поверх одного из ключей. Этот
интерфейс вызывается напрямую при проверке точных битов. Расчёт интервалов
и действующий sampler сохраняют прежний путь.

Для packed position и scale с representation 2 вызовы `0x00479401` и
`0x00479721` передают в `0x00479110` одну 60-байтовую запись, коэффициент
интервала в binary32 и адрес выходного XYZ. Помощник читает значение,
outgoing tangent и два готовых коэффициента. При выходе он возвращает
адрес результата в EAX и освобождает два аргумента стека.

Для X помощник сохраняет в binary32 сумму с `c2` и следующее произведение
на `u`. Для Y он сохраняет произведение перед сложением с outgoing tangent,
результат этого сложения и последнее произведение. Для Z он сохраняет
первое произведение `u*c3`, сумму с outgoing tangent и последнее
произведение. Прочие шаги выполняются в x87 с 64 значащими битами при
`FPCW=037F`. Выход каждой оси сохраняется в binary32.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationVectorCubicPc.h)
принимает нули обоих знаков и нормальные binary32 по модулю от `2^-32`
до `4096` в читаемых полях. Допустимый коэффициент имеет нулевое значение
или лежит от `2^-32` до `1`. Выход проверен в отдельном XYZ и поверх групп
value, `c2` и `c3`. Подготовка коэффициентов и вычисление интервала принадлежат
своим вызывающим операциям.

В скалярной ветви representation 4 участка `0x0047933D` PC sampler
выбирает 20-байтовую запись. Он читает value, outgoing tangent, `c2` и
`c3`. Коэффициент интервала поступает как binary32. Все три умножения и
три сложения Horner выполняются в x87 с 64 значащими битами при `FPCW=037F`.
Окончательный результат округляется в binary32 при записи `0x0047937B`.
Операция читает готовый полином и опирается на результат выбора интервала.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationScalarCubicSamplePc.h)
принимает нули обоих знаков или нормальные binary32 по модулю от `2^-64`
до `4096` в читаемых полях. Допустимый коэффициент имеет нулевое значение
или лежит от `2^-32` до `1`. Выход допускает совпадение с одним полем записи.

В PC-ветви position с representation 3 участок `0x00479360` читает два
четырёхбайтовых значения и сохранённый коэффициент интервала `u`. До входа
в участок sampler выбирает первый индекс `i` и второй `min(i+1, count-1)`.
Операция вычисляет `(1-u)*left + u*right`. Вычитание, оба умножения и
сложение выполняются с 64 значащими битами при `FPCW=037F`. Первый результат
в binary32 — запись `0x0047937B`. Совпадающие индексы дают два чтения
одного слова.
[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationScalarLinearPc.h)
принимает уже выбранные значения и коэффициент. Скалярные rotation и
scale в собственных ветвях читают соседнее значение по смещению `+4`.

Подготовка PC Slerp по адресу `0x004648C0` принимает два quaternion в
порядке X, Y, Z, W. Она суммирует попарные произведения в порядке
Z, Y, X, W, сохраняя промежуточные значения в x87. Единственная исходная
запись суммы округляет её до binary32. При отрицательной сохранённой
сумме помощник меняет знак этой суммы и каждой компоненты временной
копии второго quaternion. Оба знаковых нуля сравниваются как ноль,
а бит знака сохранённого нуля остаётся в результате. После выбора знака
значения больше единицы ограничиваются до единицы.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationQuaternionSlerpPreparationPc.h)
принимает нули обоих знаков и нормальные binary32 по модулю от `2^-32`
до `4096` при округлении `FPCW=037F`. Выход содержит подготовленную
сумму и временную копию второго quaternion. Коэффициент интерполяции,
тригонометрия и итоговый quaternion относятся к следующей стадии.

PC Slerp сравнивает синус в ST0 с порогом binary32 `0x3A83126F`
в участке `0x0046498B`. При упорядоченном значении строго меньше порога
помощник читает первый quaternion и записывает W, Z, X, Y в поля
`+0x0C`, `+0x08`, `+0x00`, `+0x04`. Компонента Z проходит через
целочисленный перенос, а W, X и Y проходят через загрузку и запись x87.
Для нормальных binary32 и нулей обоих знаков все четыре слова сохраняют
исходные биты. Равенство с порогом передаёт управление расчёту весов.

Сравнение использует полную точность binary80. Значение на один шаг
binary80 ниже порога выбирает копирование, а сам порог и следующий шаг
выбирают продолжение, хотя все три округляются к одному binary32.
Аналитическая операция принимает положительный нормальный binary80 или
ноль любого знака. Вариант продолжения сохраняет предоставленный выходной
буфер. [Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationQuaternionSlerpSmallAnglePc.h)

Участок PC Slerp `0x004649B1`–`0x004649D1` подготавливает аргумент
первого вызова синуса. Он получает уже вычисленный синус в физическом ST0.
В x87 вычисляется `1/sine`, затем обратная величина сохраняется в binary32.
Разность `1-u` и произведение этой разности на `theta` вычисляются в x87.
Аргумент `(1-u)*theta` отдельно сохраняется в binary32 перед вызовом.
`theta` и коэффициент интерполяции `u` поступают как слова binary32.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationQuaternionSlerpFirstWeightPc.h)
при `FPCW=037F` принимает нормальный binary80 синус от `F32(0.001)`
до `1`. Для `theta` и `u` допускаются оба знаковых нуля и нормальные
binary32 от `2^-32` до `F32(pi/2)` и `1` соответственно. Результат содержит
обратную величину и аргумент первого вызова синуса. Сам вызов выполняется
за границей этого участка.

После первого вызова синуса участок `0x004649D6`–`0x004649E9`
умножает физический ST0 на сохранённую обратную величину binary32.
Произведение вычисляется в x87 и записывается как первый вес binary32.
Далее два слова binary32, `theta` и `u`, перемножаются в x87.
Их произведение записывается в binary32 как аргумент второго вызова
синуса. Значения на границе округления сохраняют вклад младших битов
ST0, а малый аргумент второго вызова может стать субнормальным.

После второго вызова синуса участок `0x004649EE`–`0x004649F5`
принимает собственный физический ST0 и умножает его на ту же обратную
величину. Второй вес передаётся взвешиванию в binary80. Профиль с
`FPCW=037F` допускает синусы binary80 в диапазоне от `2^-64` до `1`,
обратную величину binary32 от `1` до `1024` и оба знака нуля в синусах.
Аналитический интерфейс получает результаты двух вызовов синуса
отдельно. [Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationQuaternionSlerpWeightContinuationPc.h)

На участке PC Slerp `0x004649F5`–`0x00464A8F` первый вес берётся из
binary32, а второй поступает в физическом ST0 как binary80. В каждой
компоненте результат складывает взвешенные значения первого и уже
скорректированного второго quaternion. Для X и Y оба произведения
округляются до binary32 до сложения. Для Z произведение второго
quaternion остаётся в x87, для W в x87 остаётся произведение первого.
Выход состоит из четырёх слов binary32. Оригинал читает все входные
слова до записи результата в порядке W, Z, X, Y.

[Аналитический исходник](../../../Sparkplug/Code/Sparkplug/spAnimationQuaternionSlerpBlendPc.h)
принимает входные binary32 со знаковыми нулями или нормальными модулями
от `2^-32` до `4096`. Для второго веса допускаются знаковые нули и
канонические нормальные binary80 с модулем от `2^-64` до `4096`.
Выходной буфер может полностью совпадать с любым входным quaternion.
Весовые коэффициенты поставляются готовыми. Расчёт весов и соединение
стадий в действующем sampler остаются отдельными операциями.

Native packed quaternion/scale и scalar rotation/scale читают next record
без отдельного one-key guard. При finite соседних данных fraction `0`
сохраняет первый ключ. Portable adapter использует bounded repeated endpoint,
а не воспроизводит out-of-bounds read. Negative cache, incomplete scalar
triples, nonfinite/unsorted inputs и unsafe empty cubic preparation отклоняются
или безопасно сбрасываются **явными host guards**, не объявляются native rules.
