# Поиск и загрузка ресурсов Winx Club PC

## Короткий ответ

Исследованная PC-сборка `WinxClub.exe` не выводит корень ресурсов из каталога собственного executable. При запуске она читает 32-битное представление ключа
`HKLM\Software\Konami\Winx Club` и использует строковое значение `MediaPath` как глобальный корень виртуальной файловой системы игры.

Это объясняет конфликт нескольких установок: все копии `WinxClub.exe` обращаются к одному registry key и поэтому видят путь, записанный последней установкой или внешним launcher.

## Подтверждённый путь инициализации

В исследованной PE32-сборке (22 065 152 байта, timestamp файла 2006-01-23) восстановлена следующая цепочка:

1. функция `0x00592F70` освобождает прежнюю строку `MediaPath`;
2. через `RegOpenKeyExA` открывается `HKLM\Software\Konami\Winx Club`;
3. через `RegQueryValueExA` читается `MediaPath`;
4. строка копируется в динамическое поле resource manager по смещению `+0x14`;
5. из того же ключа читается `LanguageID`, после чего выбирается языковой каталог;
6. функция `0x00592C50` собирает полный путь из корня, таблиц каталогов и имени файла.

Если `MediaPath` прочитать не удаётся, найденная ветка вызывает `PostQuitMessage`; fallback к текущему каталогу или каталогу EXE в ней отсутствует. В imports этой сборки также нет типичного для такого fallback вызова `GetModuleFileNameA`.

## Сборка полного пути

Восстановленную функцию `0x00592C50` можно условно представить так:

```c
bool BuildAssetPath(
    char* output,
    unsigned outputCapacity,
    const char* fileName,
    int topDirectoryIndex,
    int subDirectoryIndex);
```

Она последовательно добавляет:

```text
MediaPath
  + TopDirectory[type]
  + SubDirectory[subtype]
  + LanguageDirectory, если категория локализована
  + FileName
```

В таблице верхнего уровня подтверждены `Characters\`, `Sounds\`, `Levels\`, `Menus\`, `Movies\`, `Music\`, `Voices\`, `Scripts\`, `Animations\`, `Fonts\`, `SFX\`, `Saved\`, `OneLiners\` и `Icons\`. Языковой каталог непосредственно используется как минимум для `Voices\` и `OneLiners\`.

Разделитель между `MediaPath` и первым табличным каталогом автоматически не добавляется. Значение реестра должно оканчиваться обратным слэшем: `D:\Games\Winx Club\Data\`, а не `D:\Games\Winx Club\Data`.

## Проверенный пример Bloom

Hair-setup передаёт builder имя `bloom_hair.smo`, индекс верхнего каталога `2` и индекс подкаталога `1`. Таблицы сопоставляют их с `Characters\` и `Bloom\`, поэтому итоговый путь равен:

```text
MediaPath + Characters\ + Bloom\ + bloom_hair.smo
```

Так исследование общего resource manager связывается с отдельно восстановленной [системой волос Bloom](../research/bloom-hair-system.md): hair-код знает короткое имя ресурса, а абсолютный путь строит общий asset manager.

## Поля resource manager

По текущему реверсу:

| Смещение | Наблюдаемая роль |
|---|---|
| `+0x14` | динамическая строка `MediaPath` |
| `+0x18` | числовое состояние языка, связанное с выбором каталога |
| `+0x1C` | `English\`, `French\`, `German\`, `Italian\` или `Spanish\` |
| `+0x20...` | указатели на каталоги первого уровня |
| `+0x6C...` | указатели на дополнительные подкаталоги |

Назначения всех элементов второй таблицы ещё не установлены.

## Практические следствия

32-битные значения на 64-битной Windows можно проверить так:

```powershell
reg query "HKLM\SOFTWARE\Konami\Winx Club" /v MediaPath /reg:32
reg query "HKLM\SOFTWARE\Konami\Winx Club" /v LanguageID /reg:32
```

Для раздельного запуска нескольких установок достаточно перед стартом нужной копии переключать `MediaPath`, например отдельным launcher. Такой launcher может требовать административные права, потому что значение находится в HKLM. Простая схема не гарантирует безопасный одновременный запуск разных версий: пока не проверено, вызывается ли поиск `MediaPath` повторно после инициализации процесса.

## Границы уверенности

Подтверждены registry key, значения `MediaPath`/`LanguageID`, поля manager, основные таблицы и конкретная сборка пути `bloom_hair.smo`. Пока не подтверждены скрытый command-line override, повторное чтение registry во время жизни процесса и полная семантика второй таблицы подкаталогов.
