# CP132 — меньше копирований при записи персонажа

Дата: 2026-09-08. Продолжение [CP131](tool-importer-clean-targets-2026-09-08.md).
Область: текущий clean skinned writer Importer 0.6.1. Список готовых операций
остаётся **16/16**; производительность учитывается отдельно от функциональности.

## Изменение

- Новые временные буферы builder передаются строгому parser через `ParseOwned`.
  Чужие входные массивы по-прежнему не принимаются во владение. Временный document
  в проверке branch builder не выходит за пределы проверки и не меняет буфер.
- Удаление старых inline render/skin/material/mesh/texture ветвей выполняется
  одной перестройкой контейнера. Вложенные выбранные ветви сворачиваются до
  внешней; сохраняются каталог, исходные ширины FFPS headers и порядок байтов.
  Размеры оставшихся предков пересчитываются по всем удалённым диапазонам.
- Проверка BGRA читает строки живого ImageSharp image и исходный span напрямую,
  без дополнительной полной копии текстуры ради callback. Сравниваются все
  каналы, включая RGB прозрачных пикселей; номер первой несовпавшей позиции
  сохранён. Изменение размера остаётся явно запрашиваемым режимом.

Окончательные проверки clean writer, ограничения шаблона, сохранность костей,
collision payloads и установка проверенного output сохранены. Контракты
оригинальных классов и общий texture binding resolver не изменены.

## Измерение на настоящем доноре

[Benchmark](../../research/ImporterPerformanceBench/Program.cs) читает реальный
OBJ Дафны: четыре meshes, 2 158 треугольников, две PNG 1024²/512². Для изоляции
записи ему явно назначены синтетические веса Pelvis игрового skeleton;
это не проверка качества автоматического создания весов.

Release, отключённый tiered JIT, два разогрева и девять измерений на процесс.
До/после используется один и тот же benchmark DLL; меняется только Importer
Core. Старый DLL сохранён из GUI-сборки CP131 до пересборки GUI. SHA обоих Core,
общего benchmark, входов и всех outputs записаны в validation manifest.
[Независимый от writer сравнитель](../../research/validate_importer_performance.py)
проверяет совпадение условий и перечитывает каждый output по SHA.

| Медиана проверенной записи | Flora до → после | Bloom_body до → после |
|---|---:|---:|
| Wall time, мс | 436,4124 → 405,3518 | 435,7731 → 397,8870 |
| Уменьшение wall time | 7,12% | 8,69% |
| Process CPU time, мс | 359,375 → 328,125 | 359,375 → 312,5 |
| Выделенные bytes | 445 736 392 → 332 372 512 | 421 255 408 → 308 952 664 |
| Уменьшение выделений | 25,43% | 26,66% |
| Peak working set процесса, bytes | 201 756 672 → 208 203 776 | 203 763 712 → 202 190 848 |

Это примерно 107–108 МиБ предотвращённых **суммарных выделений** за одну запись,
а не снижение занятой RAM на такую величину. Peak остаётся около 200 МиБ.
Windows CPU counter дискретен; фоновые процессы меняют wall time. Ранние
прогоны с другим benchmark DLL или tiered JIT оставлены диагностическими и в
итоговую таблицу не включены. Ускорение всего GUI или automatic weighting не
заявляется. CUDA для копирования этих CPU-контейнеров не используется.

## Проверки и переиспользование доказательств

- 126 проверок batch removal на шести выбранных SMO: побайтовое сравнение с
  прежним последовательным алгоритмом; nested ranges, обратный порядок,
  повторяющиеся ID, пустой набор, отказ missing ID/root, неизменность источника.
- 22 проверки сравнения пикселей: NPOT, края строк, первый/последний пиксель,
  каждый канал, короткий/длинный payload, неверный размер и явный resize.
- 65 проверок clean replacement на пяти целях CP131, включая десять отказов
  неподдерживаемого шаблона с сохранением прежнего output. Все пять итоговых
  файлов совпали с CP131 по SHA. Поэтому повторные original-PC loads, 304
  bone/matrix сравнения и 30 Viewer SAN poses не запускались: их доказательства
  относятся к тем же байтам. Это переиспользование, а не новый native прогон.
- Два настоящих донорных результата детерминированы и побайтово совпадают
  с прежним Core во всех 44 outputs четырёх итоговых benchmark процессов.
  Эти большие результаты не объявляются новыми native whole-file proofs.
- Importer GUI Release 0.6.1 собран: 0 warnings/errors, 11,33 с.

Один ранний `clean-targets-bulk` запуск после неудачной компиляции мог использовать
старый test binary и исключён из доказательств. Используются только последующие
успешно собранные `clean-targets-bulk-verified` и `clean-targets-final`.

[Validation manifest](../../research/tool-importer-performance-validation-2026-09-08.json)
сохраняет hashes и границы выводов; [assessment CP132](../../research/tool-readiness-assessment-2026-09-08-cp132.json)
не увеличивает ни знаменатель, ни class ledger. Исходные игровые и донорные
файлы, compiled binaries и крупные traces остаются в ignored local-data/temporary
каталогах. Публичная публикация не выполнена.
