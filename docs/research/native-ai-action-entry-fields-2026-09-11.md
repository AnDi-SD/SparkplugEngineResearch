# AIAction: поля входа и общая выбранная цель

Семь новых v10 квалификаций на каждой платформе.64 input cases,все прошли
с первого раза:32 PC полных метода,14 PS2 полных методов и18 PS2 суффиксов
после вложенного вызова. Перед каждым таким суффиксом отдельно исполнялся
PS2 компонент wxCharacterRegistry:ещё18 fresh guests. Итого82 исполнения,
из них46 полных и36 компонентов. Пилот4 случая0,402s,общий пакет60 —4,348s
внутри процессов,без внешнего startup. C++ реализаций этот блок не добавляет.

Методы и поля независимо прочитаны по оригинальным PC/PS2 инструкциям.
Все4000h bytes borrowed storage сравниваются,включая padding и незаписанные
области. Два fill A5/5A,два finite position набора,argument0/FFFFFFFF,
cached target0/12345678 и допустимые для выбранного метода null command
различают собственные изменения и сохранение входов. Указатели не выдаются
за штатно загруженный уровень. Адреса/offsets далее шестнадцатеричные.

## Общая цель

DarcyAttack,IcyAttack,StormyAttack,WinxFly вызывают wxCharacterRegistry из
global PC765AD8/PS2 49FD88. Registry factory4011D0/3F8360 и ID6EAA030D
установлены в исходном каталоге классов. Нужный helper —4E21D0/369B60.
PC cached target находится вregistry28,PS2 вregistry24. Ненулевое значение
возвращается сразу;нулевое при пустом первом массиве остаётся0.

На PC выполняется весь v10 с настоящим helper. Lazy global factory не
исполняется:registry задан явно ненулевым. На PS2 helper содержит SQ/LQ,
поэтому **полная вложенная транзакция не заявляется**. В отдельном fresh guest
исполняется369B6C→369BB0 для cached/empty контекста. Его фактический V0
становится явно записанным входом другого fresh guest,начатого после JAL
в v10. Это два проверенных компонента с указанной связью данных,а не
продолжение остановленного guest или success seam внутри оригинального call.

| Действие | PC полный v10 | PS2 полный вход | Проверяемый PS2 суффикс |
|---|---|---|---|
| DarcyAttack | 5C23D0 | 248790 | 2487B0→2487FC |
| IcyAttack | 5BE230 | 2591D0 | 2591F0→259248 |
| StormyAttack | 5C56F0 | 266580 | 2665A0→2665EC |
| WinxFly | 5BC6A0 | 26D070 | 26D0A8→26D0D4 |

В суффиксе S0=action,V0=выход отдельного registry component. Граница после
собственных stores выбрана до epilogue. Более глубокий cold выбор первой
непустой группы через PS2 index helper29BD50 статически виден,но не
исполнялся этим пакетом. Cached target и пустой массив не доказывают весь
контракт registry. Registry не получает отдельного прироста оценки.

Все четыре действия записывают выбранную цель вaction3A8/PS2 3AC,включая0.
Остальные собственные изменения ниже указаны PC offsets;на PS2 они независимо
соответствуютoffset+4. Это не универсальное правило для любого поля игры.

| Действие | Обнуляемые words | Обнуляемые bytes | Прочие записи |
|---|---|---|---|
| DarcyAttack | 3B0,3B8,3C0,3B4,3CC,400 | 3AC,3F0,45C | word3BC=1,word3D0=2 |
| IcyAttack | 3B0,3B8,3C0,3B4,3C4,410 | 3AC,3AD,3E8,3E9,3EB | word3BC=1,word3C8=2,byte468=1 |
| StormyAttack | 3B0,3B8,3C4,3B4,3C8,3D4 | 3AC,3F4 | word3C0=1,word3D8=2,byte3D0=1 |
| WinxFly | 3AC,3B8,3B0,3B4 | 3BC | — |

PC WinxFly перед registry при ненулевом command обнуляет command word4,
при null command продолжает работу без этой записи. Это подтверждено полным
PC v10. На PS2 такая ветвь видна26D07C..90 до рассматриваемого суффикса;
**совместное исполнение command-clear на PS2 этим пакетом не проверено**.

Icy stores не заполняют pointer поляPC3EC/3F0,ранее прочитанные его destructor.
Незатронутые bytes сохраняютfill. Изученный cached/empty-target v10 не закрывает
этот [вопрос lifetime](native-ai-action-family-2026-09-10.md);произвольные defaults
и исправление оригинальных правил не добавлены.

## Полные простые методы

| Действие | PC / PS2 v10 | Результат |
|---|---|---|
| Help | 5BAF70 /24FD50 | command word4=0;own byte3AC/3B0=0;word460/464=0 |
| GhoulScript | 5A9930 /24D410 | Сохранить node иcommand pointers,закрыть owner gate,сбросить два words,установить15000 |
| Wander | 5AB420 /26C1A0 | Обнулить два words и скопировать три finite position компонента |

Общая цепочка action20/24→owner144/154→character130/13C даётcommand.
Help требует ненулевойcommand. GhoulScript сохраняет такжеnull command:
own3B8/3BC=command;owner24→entity24 даётnode,сохраняемый вown3B0/3B4.
Owner byte14D/15D становится0,own words3A8/3AC и3AC/3B0 обнуляются,
word370/374=15000 decimal. Значение этого поля не переименовано в выдуманную
единицу времени.

Wander обнуляетown3B8/3BC и3BC/3C0,копируетnode20/24/28 вown3A8/3AC/3B0
(PS2 destination+4). Это finite x87 load/store иPS2 LWC1/SWC1;исключительные
float и все различия FP окружения не квалифицированы. Входной v10 argument
в проверенных ветвях не влияет на результат.

## Учёт и повторное использование

14 assessment updates,+5 каждому из семи классов отдельно PC/PS2.
Новых полностью закрытых классов нет. Ранее проверенные resets других действий
не повторялись и не получили новый credit. Новые v11 candidates Golem/Stormy/
Yeti/Icy читают виртуальный command reset;его реальный тип/контекст остаётся
отдельной зависимостью,успешный callback не подставлялся.

[Контракт](../../research/ai-action-entry-field-contracts-2026-09-11.json),
[проба](../../research/probe_ai_action_entry_fields.py). Источники,117 scout
окон,точные snapshots и результаты находятся локально в
`local-data/results/native-cycle-20260911-0730/ai-action-entry-exit/`.
Сами scout окна не означают изученность всех находящихся в них методов;
линейный первый return не доказывает полный CFG. Локальные данные отсутствуют
в обычном Git clone.
