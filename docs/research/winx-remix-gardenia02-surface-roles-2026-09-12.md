# Гардиния 2: точка дефекта и роли поверхностей

На показанном пользователем уступе исправлены два провала: поверхность
рядом с Блум и площадка ниже. Проверка в одном процессе: выключение нашего
слоя метаданных возвращает оба дефекта, включение восстанавливает землю.
Используются stock Remix 1.5.2 и прежняя D3D9-прослойка. Новая DLL не нужна.
Это проверка двух конкретных поверхностей, не завершение поддержки всех уровней.

## Что оказалось причиной

В `2026-09-12-gardenia02-window-repro` пользователь подтвердил исходный дефект.
При переключении этого же процесса на raster поверхность целая. Это
диагностический raster через Remix с активной прослойкой, не pristine D3D9.
USD-захват и исходные D3D9 draws показывают, что геометрия дошла до Remix.

Прежний профиль помечал текстуру травы `FAC245110A8BD959` как decal.
В [Gardenia01](winx-remix-camera-ground-2026-09-12.md) это помогло совпадающим
слоям дороги. Здесь обнаружены два других способа использования материалов:

| Меш | Игровой проход | Исправленная роль |
|---|---|---|
| `A572E833699D8C0C` | Камень `1CAD75BDFFCE6E85`, SRCALPHA/INVSRCALPHA поверх непрозрачной травы `431DD89F9CD83BD0` | Decal включён |
| `E75B321C979EE3E9` | Самостоятельная трава, SRCALPHA/INVSRCALPHA, отдельного основания нет | Decal выключен |

У уступа оба прохода имеют по471 исходному треугольнику и одинаковые
геометрию/трансформацию. CPU-проекция захвата игровой камерой, например
в точке viewport `(570,470)`, находит оба слоя на глубине1034,6793,
vertex alpha0,2192. Камень является верхним слоем, а трава — основанием.
Это порядок, обратный исследованному ранее большому terrain.

У нижней площадки423 треугольника и190 вершин:173 с alpha1,17 с alpha0.
Текстура травы имеет alpha255. В точке `(350,665)` захват содержит только
эту поверхность: глубина1117,4496, интерполированная alpha1. Прозрачный
край нужно сохранить; принудительно делать весь меш непрозрачным нельзя.
Изменение его категории сохраняет исходное смешивание.

## Реализация без замены игровых данных

Наш [mod.usda](../../research/rtx-remix/surface-roles/mod.usda) содержит
только две записи категорий с `preserveOriginalDrawCall=1`. Ни точек,
ни индексов, ни текстур, ни новых трансформаций в нём нет. Значения категории
записаны одинаково на hash prim и дочернем `mesh` для совместимости импортера.

Это штатные [категории Remix](https://docs.omniverse.nvidia.com/kit/docs/rtx_remix/1.3.6-2/docs/toolkitinterface/remix-toolkitinterface-categories.html).
В reference `rtx_mod_usd.cpp::processReplacement` сохраняется original draw,
а `rtx_scene_manager.cpp` применяет к его копии только category flags.
Reference checkout `b81a7b566b1eeb9edb4dc2b3c9d3972e0f253ad4` не совпадает
с точным commit установленного runtime; работоспособность проверена запуском.

`Run-WinxRemix -Mode RTX` включает `SurfaceRoles`. Launcher копирует наш файл
в `rtx-remix/mods/winx-surface-roles/mod.usda` рабочей папки; для изолированных
запусков уровня это их собственный каталог. Hash записывается в `launch.json`.
Новый каталог mods обнаруживается при старте runtime. Создание его после
старта предыдущего процесса не послужило визуальной проверкой.

Общие две texture-категории прежнего профиля остаются; исследованные mesh
overrides уточняют их. Это явный небольшой каталог, а не автоматический
классификатор всех проходов по смыслу. Для следующего расширения следует
различать основание, совпадающий верхний слой и самостоятельную прозрачную
поверхность. Одна категория на всю текстуру недостаточна.

## Повторная проверка

Свежий запуск `2026-09-12-gardenia02-surface-roles`, PID7244, StartLevel2,
Windowed, все прежние девять адаптаций. Пользователь снова дошёл до уступа.
Снимки `fixed-point.png`, `without-roles.png`, `roles-restored.png` показывают
исправлено → дефект → исправлено через `rtx.enableReplacementAssets`.
Других replacement assets в этом запуске нет. Конечное значение — True.

Позиция Блум в сравнении неизменна:
`(580,700378;717,179871;-1499,411987)`. Projection, forward, near/far равны;
камера продолжает малое игровое сглаживание: смещение0,004273 единицы,
максимальное изменение View0,004029. Битового равенства всей View не было.
Обе поверхности восстанавливаются обратимым переключением категорий.

Предварительные live-пробы anti-culling объектов/света, отключения OMM,
backface culling и vertex-captured normals не убрали наблюдаемые провалы.
Отключение decal material blending изменило вид слоя, но дефект сохранился.
Это ограниченные live-пробы; они не доказывают исправность всех кэшей/камер.
Добавление каменной texture-категории исправило уступ, оставив нижнюю
площадку. В итоговый профиль этот глобальный эксперимент не включён.

## Координаты и управление запуском

Первоначальная точка пользователя сохранена до fullscreen-сбоя:
`(576,556274;717,179871;-1499,412598)`.
`winx_remix_state.py --pid PID --player --cameras --output FILE.json`
читает profile `[765AD4]` → player `+2B4` → node `+24`, проверяет известные
vtables и сохраняет node local/world position `+20/+74`. Используется только
ReadProcessMemory. Основание цепочки — `probe_ai_activation_fields.py` и
[PC Node](native-pc-node-world.md), плюс чтение живой игры.

Команда запуска уровня:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File research/rtx-remix/Run-WinxRemix.ps1 -Mode RTX -DebugMenu -StartLevel 2 -Windowed
```

Она не телепортирует к записанным координатам. Новый запуск начал уровень
около `(580,5911;377,7270;-550,1569)`; пользователь вернулся к уступу вручную.
Совпадение раннего оконного снимка с первой точкой на0,29535 единицы не было
доказательством восстановления позиции при запуске. Телепорт не реализован:
для него надо согласованно обновлять узел и игровой контроллер движения.

`Windowed` меняет только INI изолированного StartLevel-запуска. Установленный
fullScreen пользователя сохраняется. Помощник окна больше не вызывает
синхронный Restore для уже видимого окна; минимизированное восстанавливает
асинхронно. Если Windows не даёт фокус, ввод/снимок прекращаются с ошибкой.
В последнем запуске пользователь активировал окно вручную.

## Сбой и оставшаяся работа

В предыдущем fullscreen-процессе PID4740 пользователь увидел несколько
runtime errors и нажал OK, после чего игра закрылась. Причина не установлена:
cleanup bridge сам по себе не доказывает штатный выход. Сохранены исходные
логи и координаты. Изменение помощника окна не объявляется исправлением
этой ошибки. В последующем оконном сравнении такая ошибка не повторилась.

Не закрыты общая классификация поверхностей других уровней, передача
источников света независимо от ракурса, сбор геометрии за игровой камерой
и произвольный возврат к waypoint. Этот случай не даёт оснований менять
игровую камеру или отключать frustum culling.

Проверены Python AST, PowerShell parser, чтение игрока в живом процессе,
загрузка metadata-only mod и обратимое сравнение. Hashes13 неизменяемых
EXE/DLL/шейдерных файлов совпали с прежним evidence; установленные INI и
user.conf совпали с копиями до свежего запуска. Сохранения не откатывались.

[Manifest и hashes](../../research/winx-remix-gardenia02-waypoint-2026-09-12.json).
Большие захваты, снимки и локальный скрипт проекции находятся в
`local-data/rtx-remix/runs/2026-09-12-gardenia02-*` и не публикуются в Git.
