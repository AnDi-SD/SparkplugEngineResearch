# Камера и происхождение visibility-выборки

Измерения 12 сентября до переключения приоритета на общий световой мост.
Это диагностика обвязки, не изменение игровых камер или culling.

`winx_remix_state.py --visibility` читает последний support vector и проверяет
stamp/границы до и после чтения. Даже согласованный asynchronous снимок
**не определяет камеру последнего прохода**. В одной из проверок после основной
сцены с 645 supports другой вызов выбрал 21 support для отдельной ортографической
камеры. Нельзя называть этот последний vector основным или по нему утверждать,
что игра не передала остальные 624 объекта. Назначение каждого дополнительного
прохода нельзя устанавливать только по типу проекции.

`Start-Probe -SceneAudit -DebugMenu` включает необязательное наблюдение original
46D270. После его настоящего возврата записываются input/override/main camera,
scene, frame/draw, исходные матрицы/frustum и полный выбранный vector. Это
не заменяющий culler. Для exact debug EXE при первом Direct3DCreate9 проверяются
путь/base/8-byte prologue, создаётся x86 trampoline двух полных инструкций,
возврат и output оригинала сохраняются. Другие потоки не снимаются. Размер
vector≤4096, лог≤64MiB плюс последняя bounded запись; обычный режим этот detour
не ставит. Рабочий SceneLights также не зависит от detour.

`2026-09-12-scene-audit-gardenia01`: последняя сохранённая сводка 297 основных
выборок, 148 разных views, 1218 уникальных supports. Выборка менялась 87 раз.
81 699 sampled perspective depth-tested draws имели побитово совпадающие
float32 view/projection соответствующей основной камеры;131 разных пар матриц.
Некорректных vectors/null slots/read errors в этой сводке нет.

Дополнительно штатная **Camera Sequence** самого Remix сохранила 1918 кадров,
831 разную пару матриц. За интервал включённой записи 57 135 sampled perspective
draws совпали с принятыми Remix матрицами, 4 разные пары, 124 игровых кадра.
Формат sequence не хранит игровые frame IDs: это подтверждение принятых значений,
а не измерение задержки кадров. В UI Remix независимо совпали позиция и forward;
horizontal 60° у игры соответствует vertical 46.8° при 4:3.

Запись Camera Sequence не использует проблемный USD GameCapturer. Файл содержит
256-byte header с числом записей и 1024-byte frames; первые 128 bytes — две
матрицы. `analyze_camera_contract.py` сравнивает именно float32 bytes и явно
ограничивает вывод sampled областью. Неполная последняя строка живого лога
пропускается, некорректные полные строки не скрываются.

Ранние попытки движения в Гардинии 2 прерывались tutorial/Game Over и не
считаются пройденной проверкой движения. Их файлы сохранены без переписывания.
После прямого указания пользователя этот уровень больше не запускался.

Эти измерения не закрывают сохранение невидимой геометрии для отражений/GI,
все виды камер и всю механику внутри Remix. Они исключают ошибку передачи
основных матриц в проверенной выборке и дают корректную привязку диагностики.
