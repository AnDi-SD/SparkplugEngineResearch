# Выход из двадцати AI-состояний

Блок 42. 80 оригинальных вызовов, PC40/PS240, все завершились с первого
раза: пилот8 /0,559741s, общий пакет72 /4,734275s. Два разных заполнения
12 KiB окружения проверяют все записи и сохранение остальных полей.
Новых C++ классов и новых CPU расширений нет.

## Общие правила и различия

Исследован виртуальный слот11. Обычно структура команд находится через
`action+20 → owner+144 → character+130` на PC; на PS2 это
`action+24 → owner+154 → character+13C`.

У FrogAttack используется сохранённый указатель action `+3E8`, у
MinotaurAttack `+3C0`, у MinotaurDefend `+3B4`; PS2 добавляет 4 к этим
смещениям. В проверке сохранённая структура намеренно отличается от
текущей структуры персонажа. Меняется именно сохранённая; указатель
на неё после выхода остаётся прежним.

Ниже смещения байтов структуры команд, которые оригинал обнуляет.
Их игровым названиям без отдельного evidence новые значения не назначаются.

| Состояния | Обнулённые байты команд | Дополнительные изменения |
|---|---|---|
| Attack | 1D, 1F, 20, 21 | Сброс цели |
| BacoAttack, IceWormAttack | 1D, 20 | Сброс цели |
| DarcyAttack, TrollAttack | 1D, 20–24 | Сброс цели |
| DroidAttack, SpiderAttack | 1D, 20, 21 | Сброс цели и восприятия |
| DroidWander | 1C | Остальные поля сохранены |
| FrogAttack, MinotaurAttack | 1D, 20 | Сохранённая структура; сброс цели |
| Hurt | 5C | Остальные поля сохранены |
| IceGargoyleAttack | 20, 21 | Сброс собственного word 3D8 / PS2 3DC |
| IceGargoyleClaw, IceGargoyleWithdrawl | 20, 21 | Сброс word 3AC / PS2 3B0 |
| IceGargoyleSleeping | 1B | Остальные поля сохранены |
| KnutAttack | 1D, 20–24, 5C | Сброс цели |
| MinotaurDefend | 1D, 1F | Сохранённая структура; сброс цели |

Обычный сброс цели — word action `+3A8`, PS2 `+3AC`; это не общий
сброс всей структуры состояния. Восприятие получает byte `+70=1`,
float `+74=25`, byte `+78=0`. На PC выполняется настоящий getter
`515350` два раза с аргументом false и уже имеющимся perception;
всего 12 таких вызовов. PS2 получает perception напрямую из character
`+160`. Создание недостающего perception не проверялось.

Mosquito очищает movement `+1E0` / PS2 `+1EC`; сам movement берётся
из character `+12C` / PS2 `+138`. Связанный объект и остальные поля
движения сохраняются.

## Проверка и границы

Точные адреса всех 40 методов связаны с ранее подтверждёнными таблицами
классов в selection и контракте. Даже при общем PC адресе разные классы
имеют отдельные входные таблицы и результаты. PS2 случаи проходят полный
метод, включая записи в delay slot перед возвратом; SQ/LQ не нужны.
На PC применён обычный micro лимит, включая защищённый perception getter;
лимиты не увеличивались. Использован только явный non-throwing SEH fixture,
возвраты игровой логики и allocator не подменялись.

Это проверка прямого выхода из состояния при существующих связях.
Она не доказывает полный жизненный цикл AI, допустимость null-полей,
переключение состояния внешним dispatcher или игровые имена всех флагов.
За подтверждённый выход каждой из двадцати пар добавлено по 5 баллов;
пустые методы других классов и ранее проверенные exits не пересчитывались.
