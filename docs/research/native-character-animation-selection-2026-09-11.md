# wxAnimationManager: поиск по packed key и индексированной таблице

Исследован PC selector59A5E0 и его независимое PS2 соответствие273D10.
20 входных сценариев,по одному на каждой платформе: **40 различных проверок**.
PC17 полных возвратов и3 диагностические границы; PS220 post-SQ components,
включая3 диагностические границы. Helper поиска исполнен целиком на обеих
платформах. Стабильные ранее доказанные factory/lifetime повторно не засчитываются.

Адреса, размеры и смещения ниже шестнадцатеричные; индексы таблиц и количества
проверок — десятичные.

## Порядок поиска

Входы: manager,32-bit key,table index. Caller-пример ReadingState передаёт
word0 своего аргумента и character PC128/PS2134. Имена исходных параметров,
тип возвращаемого32-bit значения и названия индексов здесь не установлены.

1. Найти точный key в таблице заданного индекса.
2. Только для index0,если первый поиск не нашёл key,проверить key в таблице66.
3. Если нужной записи всё ещё нет,найти **key0 в исходной таблице**.
4. Прочитать value найденного узла по offset10.

Нулевой value найденной записи возвращается как0; это не промах и не причина
продолжать fallback. При index≠0 таблица66 в качестве альтернативы не посещается.
Если запрашивается key0,он участвует в той же последовательности; повторный
поиск0 при отсутствии default не устраняется оригиналом.

Проверены приоритет основной записи над альтернативной,alternate-hit,
fallback к исходному default,игнорирование alternate для другого индекса,
нулевой payload,индексы0/1/66/67 и unsigned ordering ключей
0/1/7FFFFFFF/80000000/FFFFFFFF с промежуточными промахами2/FFFFFFFE.
Записана последовательность **настоящих вызовов** helper и их ключей.

## Два native layout

Exact allocation из предыдущего construction: PC350,PS2464 bytes.
Здесь представлены68 индексированных таблиц,начиная с PC20,stride0C;
PS224,stride10. Альтернативная таблица66 — PC338/PS2444.
Начальное дерево PC14/PS214 не исследовано этим selector.

| Чтение lookup | PC5E79E0 | PS2274A40 |
|---|---|---|
| Root | tree4→head4 | tree4 |
| Empty child | sentinel сbyte15≠0 | null |
| Left/right | node0/8 | node0/4 |
| Key/value | node0C/10 | node0C/10 |
| End iterator | head изtree4 | адресtree4 |

Оба helper делают unsigned lower-bound и проверяют точное равенство key.
PS2 helpers273E00/273E10 передают iterator/end; default key хранится по
GP−77D8=49C998 и равен0. Все эти инструкции исполнены,не заменены host map.

Входы — явные borrowed roots/nodes. Инициализированы поля,которые читает
lookup; это не доказательство owned insertion,балансировки дерева,загрузки
каталога анимаций или lifecycle вручную заданного графа. Все4000 bytes
контрольной области сохраняются неизменными. Индексы ограничены0..67;
граница caller и поведение при неверном индексе не объявляются проверенными.

## Отсутствующий обязательный default

После последнего find оригинал **не проверяет end**,а готовится читать node10.
PC end указывает на отдельный sentinel. PS2 end=адресtree4,поэтому предполагаемый
payload лежит по tree14,то есть в следующей области. Для index67 это manager468,
за пределами exact allocation464. Это наблюдение диагностического входа,
не доказательство ошибки нормальной игры: наличие default может обеспечивать loader.

В корректных диагностических пробах остановка происходит **до чтения payload**:
PC59A64C,PS2273D74. Проверены возвращённый end iterator,адрес будущего чтения,
порядок поисков и неизменность входных записей. Нулевой результат отсутствующему
default не приписывается. Нормальный каталог с обязательным default и его
построение ещё нужно исследовать.

## Исправление стенда и проверка прежних границ

Первая версия PS2-пробы выбрала stop273D78 — load в delay slot ветвления.
Unicorn выполнил этот load,несмотря на emu_stop из его code hook. Три
диагностических случая получили0/0/CCCCCCCC вместо ожидаемого адреса end и
провалили assertion. Это ошибка выбора границы стендом. Не было исправления
игры или выдачи этих значений за корректный lookup failure.

Сохранены исходный runner,первичные отказы и точная версия scalar wrapper.
Stop перенесён перед branch273D74; повторены только3 затронутых случая,все
прошли за0,059s. Первичные успешные37 случаев не повторялись ради этой правки.
Общий первый пакет38 случаев2,850s,пилот2 случая0,486s.

Общий `research/ps2_scalar_prefix.py` теперь отклоняет stop,который фактически
встречен в delay slot после control transfer. Прямой вход в тот же адрес
другим путём не считается delay slot. Защита проверена ожидаемым отклонением
трёх прежних входов и успешным исполнением трёх исправленных; после уточнения
REGIMM классификации выполнена такая же адресная проверка. Эти дополнительные
проверки стенда не увеличивают число40 различных lookup cases.

Проверены253 сохранённые успешные PS2 stop-sites из40 result files текущего
цикла: ни один не имеет непосредственно перед stop инструкции transfer.
Это ограниченный статический аудит результатов с entry/stop; synthetic RETURN,
отсутствующие поля stop и предыдущие циклы не входят в него. Он не заменяет
проверку достижимости каждого произвольного нового stop.

Промежуточная версия wrapper восстановлена из единственной последующей правки
и сверена с SHA,записанным её regression; прежняя версия до защиты и финальная
версия сохранены отдельно. Первичная синтаксическая опечатка runner исправлена
до запуска native кода; её source также сохранён.

Evidence: `local-data/results/native-cycle-20260911-0730/character-animation-selection/`.

границы. Соседний большой метод273E20,создание/наполнение каталога,имена
индексов,смысл packed key и полный playback/lifetime остаются открыты.
