# Изменение организации исследования после цикла19:00

Поручение пользователя: ускорить восстановление SMO/SAN; свобода алгоритмов
исследования подтверждена. Это изменение процесса после закрытого CP98-цикла,
не пересчёт его результатов или изменение исторических evidence manifests.

Постоянные правила, включая последующее разрешение пользователя использовать
около 1 ГиБ RAM суммарно и регулярные commits, вынесены в
[манифест исследования](research-manifesto.md). Ниже описан конкретный опыт
с двумя реализованными профилями памяти.

## Диагноз

platform ledger ([аудит](native-coverage-recalculation-2026-09-06.md)). Они не

разбивкой рабочего времени. Не каждый повтор лишний, но объём интеграционных
вариантов вырос быстрее охвата новых контрактов.

14 work items имели одинаковый priority0; независимые Actor controls могли
попадать первыми по алфавиту. Очередь теперь начинается full loader/save,
DX mesh materialization, Node resource graph; последующие позиции имеют
различные приоритеты. Зависимости и состав scope не изменены.

## Бюджет памяти стенда

Подготовленный полный renderer занимает0xF364=62308 bytes из прежних65536.
Подбор расположения соседних объектов стал отдельной трудоёмкой задачей.
Добавлен явный integration profile **128KiB heap**, стандартный micro profile
остаётся64KiB. Stack остаётся64KiB. Сохраняются100000 instructions/2s на call,
30s на child,32KiB на engine allocation, запрет host API/GPU forwarding,
проверка pristine EXE, bounds, отсутствие live overlap и учёт освобождений.
Большая arena выбирается до создания нового guest; capped state не возобновляется.
В этом опыте реализованы только размеры 64/128 КиБ. После следующего
поручения пользователя новые явные профили разрешено вводить по необходимости
в пределах общего бюджета 1 ГиБ, проверяя layout и границы до исполнения.
Неудача требует анализа причины; размер heap и память всего процесса
учитываются отдельно.

Это явно изменяет ограничение памяти исследовательского fixture для новых
составных экспериментов. Прежние утверждения «успех внутри64KiB» не расширены
задним числом. Старый default, execution caps и originals сохранены.

Первый опыт: unchanged SMO light corpus-6→whole first lit shader generation→

## Рабочее правило для следующих исследований

1. Основной результат этапа — новое семейство читаемых реальных файлов,
   экспорт, принимаемый original reader, или устранение общего блокера.
   Процент ledger остаётся контрольным показателем; веса не меняются ради роста.
2. Сначала один представитель нового пути. Дополнительные варианты добавляются
   при новой ветви, ошибке либо отличающемся формате; произвольное перемножение
   уже проверенных вариантов не становится самостоятельной серией checkpoints.
3. На изученном участке — изменённые tests и одна связная регрессия. Полная
   сборка/CTest после согласованного блока изменений, исправления общего
   контракта либо при закрытии этапа. Успешные проверки без новой причины не повторяются.
4. После30 минут без нового контракта/новой причины остановки формулируется
   блокер и переключается независимое направление. Инфраструктурная переделка
   получает конкретный пробный сценарий, как128KiB опыт выше.
5. Краткая машинная запись каждого существенного результата; сводный журнал,
   dossier updates и percentages — пакетно к окончанию этапа.

Существующие read/save/семь completion gates остаются критериями полной цели.
Снятие одного fixture-блокера не выдаётся за ускорение всего исследования во
столько же раз. Следующее применение профиля — устранение связных loader/save
препятствий; дальнейшая полировка render-вариантов не получает автоматический
приоритет над импортом/экспортом.
