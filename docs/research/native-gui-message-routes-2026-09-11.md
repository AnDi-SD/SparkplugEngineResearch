# GUI: сообщения Widget, Button, EditBox и wxButton

11 сентября 2026. Блок26 цикла до07:30 МСК. Пять class identities и их
Notify/refresh slots взяты из [первичного GUI-контракта](native-gui-object-family-2026-09-10.md)
и повторно сопоставлены с pristine vtables. Это исследование GUI игры/движка,
без изменения интерфейсов tools и без новых восстановленных C++-классов.

## Проверочный пакет

63 разных входа исполнены отдельно на PC и PS2: **126 успешных выполнений**,
по39 полных возвратов и24 границы настоящих consumer calls на платформу.
Пилот30:1,927s; пакет96:6,328s. Ошибок пилота/пакета не было.
Соседние обработчики исследованы до общего запуска, прежние state-selection
тесты не повторялись: новые вызовы останавливаются у настоящего refresh.

Каждый случай использует свежие заимствованные записи с оригинальной vtable,
guard32 КиБ, отдельные owner/message/event/Node/HUD/profile/GUIManager записи.
Owner имеет настоящий `spGUIObject::Notify` PC4293B0/PS21655D0: для переданных
здесь сообщений его реальное тело выполняется и возвращается. Игровые callbacks
и их результаты не подменяются. Source snapshots, входы и остановки сохранены.
PS2 исполняется с [явными stack SQ/LQ](native-ps2-stack-spills-2026-09-11.md),
с неизменными original bytes и восстановлением caller registers при полном return.

## Общий Widget и текстовый потомок

`enabled` — byte28; `highlight` — byte3DPC/39PS2. Коды ниже — реальные
числовые значения сообщений, не предположение о названиях событий ОС.

| Код | Собственное поведение |
| --- | --- |
| 0E,0F,10 | При enabled!=0 переслать исходное сообщение owner+24, затем вызвать базовый GUIObject Notify |
| 11 / 12 | При enabled!=0 поставить highlight1 /0, вызвать собственный virtual refresh; следующий owner-forward остаётся за этой границей |
| 18 | Через базовый Notify записать this по адресу payload+18 исходного сообщения |
| 1C | При Node+18!=0 начать original lookup `NORMAL`; при null Node перейти через базовый Notify к реальному GUIObject Enable, где проба останавливается |
| Необработанный код | Передать базовому GUIObject Notify |

На `spTextWidget` реально проверена его собственная vtable, указывающая на
то же тело Notify; отдельная придуманная текстовая реализация не вводилась.
Полный NORMAL/DISABLED/HIGHLIGHTED lookup и дальнейшая инициализация этим
пакетом не закрываются. Enabled0/255, соседние сообщения иFFFFFFFF представлены.

## Button: нажатое состояние и сообщение владельцу

В Button добавлены byte58PC/54PS2 (`pressed`) и word54PC/50PS2 — указатель
payload, используемый исходным сообщением. Назначение строки за указателем
этот эксперимент не определяет.

- Код0F при enabled!=0 проверяет слово `+18` записи по указателю
  `message+18`. Только ноль разрешает отправить owner сообщение19 с payload
  из word54/50 и нулевым вторым payload, затем поставить pressed1 и вызвать
  собственный refresh. Реальная отправка и настоящий owner Notify выполнены;
  остановка находится после записи pressed на входе refresh.
- Ненулевое проверяемое слово или enabled0 не выполняют собственное нажатие;
  исходное сообщение далее обрабатывает Widget. Поэтому при enabled!=0 оно
  всё ещё пересылается владельцу общим обработчиком.
- Коды10 и12 при enabled!=0 и pressed!=0 очищают pressed перед refresh.
  Если pressed уже0, управление переходит Widget; код12 тогда обрабатывает
  обычное снятие highlight, а10 пересылается владельцу.
- Код1C с привязанным Node первым ищет `PRESSED`; остановка — настоящий
  Node Find. Остальные сообщения продолжают базовую обработку.

Сохранены фактические owner notifications и различие между новым сообщением19
и пересылкой исходного сообщения. Это не подтверждение всех владельцев кнопок.

## EditBox: фокус, символы и удаление последнего байта

Коды0E/10/11/12 при enabled!=0 только пересылаются owner. В частности,11/12
не повторяют собственные записи highlight обычного Widget. Код0F при enabled
сначала вызывает настоящий GUIManager focus setter451AD0/163FD0 с this;
проба останавливается перед исполнением setter. Manager получен из реального
global75DB8C/49F8A4, но его полный startup и смена фокуса ещё не исполнены.

Код13 передаёт символ в436C60/169920. На PC в стеке передан весь payload word;
PS2 caller использует `LB message+18` и знаково расширяет младший байт.
Вход12345680 даёт соответствующие разные ABI arguments; равенство всего
аргумента между платформами не предполагалось. Полное добавление текста открыто.

Код14 при enabled обрабатывает payload:

- 0D при ненулевой length70PC/6CPS2 уменьшает длину, обнуляет новый последний
  байт buffer68PC/64PS2 и вызывает обновление текста. Проверены длины0/1/3,
  включая полное выполнение настоящего refresh при трёх null TextNodes и
  highlight0. Сохранён guard остального буфера, capacity и receiver.
- 1B и54 при `manager+4C==this` вызывают focus setter с null;
  при другом текущем объекте переходят к обычной базовой обработке.
- Другой проверенный код55 не изменяет буфер или фокус.

Коды16/17 при enabled записывают highlight1/0 перед своим virtual refresh.
При disabled эти ветви возвращаются без записи. Код1C при null root Node
возвращается сразу; у обычного Widget в том же входе вызывается base Enable.
При ненулевом root остановка — первый original NORMAL lookup.

## Игровой wxButton и значение булевого ответа

wxButton самостоятельно поглощает0E/0F/10. Код11 действует только при
enabled!=0 и установленном Node mask200: отправляется сообщение27D1,
payload16/0, текущему player из profile+2B4. PC останавливается на реальном
435D30 с аргументами; PS2 — на373948 перед vtable получателя, с проверенным
32-байтным envelope на стеке. Поиск окна и последующие действия не выполнены.

Код12 обнуляет HUD+14 независимо от enabled; берётся уже заданный cached HUD
global755284/49FDA4. Lazy HUD creation при null global не исследована.

Код1C использует payload+18 как режим:

| Режим | Подтверждённая операция |
| --- | --- |
| 0 | Записать булев ответ в message+1C; определён младший байт1 |
| 1 | Дойти до настоящего broadcast40EC00/1007A0: code2715,key3,payload0/0 |
| 2 | Вернуться без базовой обработки и изменений |

**Старшие три байта булевого ответа не нормализуются.** PC55CD57 меняет
один байт временного stack word, затем копирует слово в message+1C. В данном
вызове исходные старшие байты относятся к переданному указателю message;
получен31001001, а не00000001. PS23739C4 тоже пишет только byte1 во временный
stack slot и переносит word через FPR: при заполнении стека5A получается
5A5A5A01, приA5 — A5A5A501. Обе формы проверены, входные word являются
обычными конечными FPR bit patterns. Семантика неиспользуемых байтов вне
этих контекстов и nonfinite-переносов не заявляется. Это наблюдение исходных
инструкций, не повод переписывать игровой алгоритм или считать весь word
нормализованным Boolean.

## Учёт и ограничения

На платформу остановки распределились так:11 refresh,4 lookup,3 focus,
2 append,2 base Enable,1 broadcast,1 game message. Ни одна из этих остановок
не считается полным возвратом вызывающего обработчика. Проверка интерфейса
пользователя или всей игры не выполнялась.

Пять классов получают +5 на каждой платформе: Widget40→45/35→40,
TextWidget20→25/15→20,Button35→40/30→35,EditBox20→25/15→20,
wxButton20→25/15→20 (PC/PS2). Полученный балл относится к маршрутизации и
собственным эффектам Notify, не к ещё неизвестным consumer bodies.
