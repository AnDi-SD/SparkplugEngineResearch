# Общий writer заголовков полей

Одиннадцатый блок цикла до 07:30 МСК. `SmoDataBlockWriter` больше не содержит
C# выбора size code, упаковки ID и записи UInt8/16/32. Он передаёт параметры
в C ABI общего `spDataBlockSerializer`; копирование payload остаётся host-операцией.
Шестибайтный borrowed output stream не выделяет heap и не реализует грамматику.

## Подтверждённый срез

Свежий `research/validate_tools_field_headers.py` вызывает оригинальные
PC `WriteHeader 4727B0`, helper `4F5AD0`, selector `472730` и завершение
`472B00`. Четырнадцать случаев сравниваются с ABI побайтно: inline/extended ID,
fixed sizes, UInt8/16/32, граничные 255/256 и 65535/65536, UINT32_MAX,
сохранение допустимой ширины reservation. Большие payload не выделяются.
Конструктор и stream fixture настоящих вызовов явные; освобождение списка
fixture не объявляется проверкой оригинального destructor.

Существующий `WriteHeaderWithCodeForAnalysis` сделан доступным обвязке без
изменения тела. Его прежние специальные исправления ID31 и empty field
не выдаются за точное поведение игры: эти входы ABI ограничивает ниже.
Проверка вместимости предпочитаемого size code — host guard перед writer,
который в оригинале доверяет caller и может усечь размер. Если прежняя ширина
не подходит, используется оригинальный автоматический selector.

Пустой payload без явной ненулевой reservation — прежнее сокращение API
инструмента для завершителя секции. Теперь вызывается общий terminator writer,
выдающий `00`. Старый C# encoder выдавал также `07` при номере7; native reader
игнорирует ID у size code0. Тест transaction ошибочно выбирал обычное поле0
вместе с новым каноническим завершителем; выбор уточнён по ненулевому размеру.
Восстановленный игровой код для этого не менялся.

## Приостановленные нестандартные формы

Оригинальный `WriteHeader` при size0 возвращает успех без записи байтов.
ID31,size3 даёт `BF03`, хотя reader требует extended ID. Также оригинал не
сохраняет принудительное extended encoding для ID меньше31. Прежний редактор
умел создавать/сохранять эти формы с собственными исправлениями.

Новая ABI явно отказывает для непустого ID31, настоящего zero-size поля с
UInt8/16/32 reservation и forced extended low ID при подходящей reservation.
Неизменённые непрозрачные байты могут сохраняться существующей transaction;
успех создания либо перекодирования этих форм не имитируется.

По правилу4 ветвь приостановлена, пользователь уведомлён. Предложение:
согласовать отдельный общий lossless-адаптер редактора для этих трёх форм,
с явным происхождением и проверкой настоящим reader. Эталонный writer игры
сохранить. До решения эта возможность не считается готовой.

## Проверка и границы

Адресная C++ suite `DataBlockWriter`:340 checks. Она включает исторические
host-исправления и сама по себе не доказывает native exactness всех входов.
Свежая ABI сверка отдельно подтверждает14 допустимых headers, terminator,
две особенности оригинала, три отказа и resize fallback. Viewer FormatTests
проходят на PC и PS2 меню:9300/2975 assertions. Результаты остальных consumers
и SHA256 перечислены в snapshot блока.

Generic FAT relocation, editing transactions, другие typed resource writers
ещё требуют аудита/переноса. ABI версия2 расширена совместимо. Ни full corpus,
ни готовность всех ядер, ни новая поставка GUI не заявляются.
