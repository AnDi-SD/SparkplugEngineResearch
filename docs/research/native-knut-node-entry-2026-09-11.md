# Knut: полный вход, поиск Node и cached эффекты

36 полных оригинальных вызовов PC5AC9D0/PS225D5C0 подтвердили оставшийся
участок входа KnutAttack. Пакет продолжает
[ранее проверенные registry/поля/сообщения](native-ai-registry-entry-2026-09-11.md)
на тех же original vtables. Все случаи имеют найденную цель и явно заданное
существующее дерево Node;normal startup и загрузка сцены не заявлены.

## Поиск и владение

Смещения PC,шестнадцатеричные;own PS2 поля больше на4.
Все имена подтверждены отдельными original string windows обеих платформ.

| Поле/узел | Поведение |
|---|---|
| own3E0,Knut_shield | При ненулевом cache поиск пропускается. При null выполняется рекурсивный точный поиск. Найденный Node получает refcount word8+1 и сохраняется в3E0. Отсутствие разрешено;ненулевой щит отключается Enable(0,1) |
| own3EC,glow | Всегда выполняется рекурсивный поиск по подстроке;результат сохраняется и отключается |
| own3F0,ptc02 | Аналогичный обязательный для проверенного пути поиск,сохранение и отключение |
| own3F8,charge | Существующий cache пропускает поиск и дополнительную настройку. При null выполняется рекурсивный точный поиск;отсутствие разрешено |
| own3F4,Knut_charge_SFX | Только при впервые найденном charge:после его отключения поиск по подстроке внутри charge и запись результата в3F4 |
| staff_projectile | Только при впервые найденном charge:точный поиск от owner Node;результат этой инструкции здесь не сохраняется в own поле |

Ненулевой charge отключается ещё в конце метода. Поэтому впервые найденный
charge вместе с детьми получает **два** рекурсивных Enable,уже cached —один.
При cached/отсутствующем charge поле3F4 сохраняет прежние bytes.
Refcount glow,ptc02,charge и найденного эффекта в этом методе не увеличивается;
это наблюдение конкретных записей,не утверждение об общем lifetime этих ссылок.
Недоступная на проверенном однопоточном пути ветвь удаления прежнего shield
не считается исполненной.

Матрица:shield lookup/cached/absent × charge lookup/cached/absent ×
заливка5A/A5,18 входов на каждую платформу. glow иptc02 присутствуют во
всех случаях:метод разыменовывает их без null check. Их отсутствие и
поведение ошибки не проверялись. charge имеет child Knut_charge_SFX;
прочие Node,локальная позиция owner и все нетронутые поля входят в guard32KiB.

## Реальный поиск на обеих платформах

Исполнены Node Find421330/1A7160 и Enable421640/1A5B00 с рекурсивными
дочерними вызовами. PC точное сравнение встроено в original Node Find;
внешний CRT strstr использует прежний ограниченный256-byte контракт.
PS2 выполняет исходные strstr40B208 и byte-path strcmp40A8A8.
Return игрового Find или Notify не подставляется.

PS2 strcmp выбирает byte path,потому что исходно объявленные строки
name-pool+9 расположены по невыравненным адресам. Эти адреса присутствовали
уже в первом неуспешном пилоте и **не менялись ради обхода MMI**.
Выполняются original branch40A8B0 и loop40A9B8..40A9E8;alignment
проверен на каждом из140 вызовов. Aligned 64/128-bit ветви,MMI и general
strcmp не квалифицированы. Изменений общего CPU wrapper нет.
