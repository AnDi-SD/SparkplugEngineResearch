# CharacterState: 97 классов PC и PS2

Исследованы `wxCharacterState` и все 96 зарегистрированных прямых потомков
на обеих платформах. По независимым каталогам состав семейства совпадает.
Это первый разбор создания, базовых обработчиков и условий уничтожения;
активные алгоритмы конкретных состояний ещё не восстановлены целиком.

## Проверенный объём

- PC: 97 original factory/RTTI/default clone, 95 успешных полных lifecycle,
  481 вернувшаяся операция класса. Два teardown остановились на непривязанном
  collaborator. Общие clone-map/allocator/clock fixtures описаны в отчётах.
- PS2: 97 независимых factory allocation literals и vtable/getter/registration
  identities; 85 уникальных вызываемых конструкторов, 12 фабрик дополняют общий
  конструктор собственными полями. Полные PS2 constructor execution не заявлены.
- Для всех 97 независимо совпали размер выделения и начальный selector `+10`.
  Его одинаковое значение у разных классов не означает одинаковое поведение.
- Во всех таблицах copy slot унаследован пустым: PC `0040ECE0`, PS2 `00100320`.
  Проверялось клонирование свежего объекта; изменённый source payload отдельно
  не проверялся. Наличие клона не означает сохранение всех runtime полей.
- 20 paired original cases общих обработчиков, reset и простых возвратов:
  2,782 с. Ненулевой handle проверен до входа в consumer, без его подмены.

После root pilot обработка остальных 96 PC классов заняла 32,531 с при трёх
bounded процессах. Повторён только `wxBookMovingState`, которому нужен контекст
сцены. Полный повтор семейства и asset corpus для этого не выполнялись.

## База и группы потомков

Root: hash `44817BC2`; PC factory `00402420`, ctor `00512F20`, vtable
`006F81B0`, getter `00512F10`; PS2 factory `003F51A0`, ctor `002C9150`,
vtable `0049A9E0`, getter `003F9640`. Размер обеих версий `3C` байт.

Конструктор обнуляет слова `10/14/18/24/28`, byte `2C`, устанавливает пять
bytes `1C..20` в 1 и копирует общий vector3 в `30/34/38`.
Источники vector3: PC `007600E0`, PS2 `00476F50`; padding не объявлен нулевым.

Примеры логических групп, все размеры ниже независимо совпадают PC/PS2:

| Группа | Примеры классов | Размеры / selector `+10` |
|---|---|---|
| Передвижение | BasicMoving, Jumping, Crouching, Ladder, Flying | `3C`; соответственно 0, 1, 2, 14, 20 |
| Бой и реакция | Attacking, ChargedAttack, Defending, Hurt, Dying | `40/48/54/40/40`; 5/4/8/10/11 |
| Действия и диалог | Action, Dialogue, PullLever, Glyph, PickFlower | `3C/3C/3C/3C/58`; 25/32/31/37/30 |
| Состояния существ | FrogJumping, SpiderHurt, ShadowBeastAttack | `44/50/58`; 1/10/3 |
| Расширенное движение | ButterflyMoving, BookMoving, GoopMonsterMoving | `70/CC/200`; у всех selector 0 |

В таблице опущены одинаковые префикс `wx` и суффикс `State`. Полный список
из 97 классов, размеры, defaults, слоты и отдельные PC/PS2 доказательства:
[`character-state-construction-contracts-2026-09-10.json`](../../research/character-state-construction-contracts-2026-09-10.json).
Фабрика PickFlower дополнительно конструирует вложенные поля и подписывает
объект на code 48; точная семантика всех этих полей ещё не присвоена.

## Общие обработчики

Нумерация ниже — индекс метода без двух служебных слов PS2 ABI.
`+14` и `+18` обозначают указатели состояния, не угаданные названия классов.

| Slot | PC | PS2 | Подтверждённый контракт |
|---|---|---|---|
| 7 | `00512FA0` | `002C9050` | Обработка pending `+24`, затем self-v12 с исходным аргументом, true |
| 8 | `00512FF0` | `002C8FD0` | Обработка pending, true |
| 9 | `00513040` | `002C8F50` | Обработка pending, void без аргумента |
| 10 | `00513090` | `002C8ED0` | Обработка pending, дополнительное обнуление `+24`, void |
| 11 | `005130F0` | `002C8E40` | Обработка pending, затем self-v12 с исходным аргументом, void |
| 12 | `005B7A00` | `002C8E30` | Пустой void hook |
| 13 | `005A7DB0` | `002C8E00` | true |
| 14 | `005A7DC0` | `002C8DF0` | false |
| 15 | `005B7A00` | `002C8E10` | Пустой void hook |
| 16 | `00513140` | `002C8AC0` | Частичный reset состояния |

Обработка ненулевого `+24`: вызывается predicate объекта `+14` по virtual
offset PC `38` / PS2 `40`. True выбирает consumer PC `004FB2F0` /
PS2 `002A6CD0` объекта `+18` с handle и float bits `3ECCCCCD` (0,4);
false — PC `004FB2D0` / PS2 `002A6CE0` с handle. Затем оригинальный код
обнуляет `+24`. Последний шаг после consumer подтверждён инструкциями;
paired execution ненулевых случаев останавливается на входе consumer.
Исходный PC protected splice `004035A8` исполнился и передал те же float bits.

Нулевые случаи прошли полностью на PC; PS2 исполнил обычные инструкции
после исключённого SQ prologue до заявленного epilogue boundary. Ветви
predicate задавались borrowed vtable с настоящими original constant leaves,
а не выдуманной реализацией игрового consumer. PS2 wrappers далее обращаются
к collaborator `+134` и `00116930` / `00115FA0`; их body здесь не закрыт.

Slots 9 и 10 во всех 97 таблицах прямо указывают на эти общие методы.
Slot 11 общий у 93 классов, reset — у 95. Равенство адресов простых leaves
между потомками нельзя механически сравнивать между PC и PS2: PC чаще
объединяет одинаковые короткие функции компилятором.

Reset независимо исполнился на обеих платформах с заполнением A5 и проверкой
всех байтов объекта: только `1C..1E=1`, `24/28=0`, `2C=0`, `30..38=vector3`.
Он сохраняет `10/14/18`, flags `1F/20` и padding. Это отличается от повторного
конструирования всего состояния.

## Условия и оставшиеся задачи

1. `wxBookMovingState`: первоначальный micro budget остановил protected
   construction. Вложенный `wxPathFinder` по PS2 расположен в `+A4`; повтор
   использовал уже проверенные original Node/search и явную borrowed цепочку
   core→scene→root. Все пять class operations прошли за 0,854 с вместе с
   подготовкой/удалением root. Original engine/scene startup не заявлен.
2. `wxBeforeTrollFightState` и `wxGoopMonsterMovingState`: создание, RTTI и
   clone прошли, delete-clone остановился в PC `0040FB60` при dereference
   непривязанного `+18`. PS2 dtors `0030D750` / `00302E00` независимо делают
   такой же безусловный вызов `00100820`; тот читает `[receiver+4]`.
   Это ограничение factory-only lifetime, не доказанная ошибка игры.
   Нормальная привязка владельца остаётся задачей. Goop teardown далее читает
   десять элементов с `+1D8`, не заполненных показанным конструктором;
   произвольные нули туда не добавлялись.
3. Управление живым персонажем, движения/атаки каждого потомка, actual
   consumers, owner binding, загрузка сцены и корректное полное lifetime
   требуют дальнейшего исследования. Соседние непривязанные функции не
   приписываются классу только по соседству в executable.

Первичная оценка базы PC35/PS230; потомков PC20/PS215, кроме двух остановившихся
PC lifecycle — 15. Это осторожный частичный behavioral учёт, не процент
восстановленных инструкций и не готовность приложения. Полностью закрытых
классов этот блок не добавляет.

Evidence: `local-data/results/native-cycle-20260910-1900/character-state/`.
Сохранены исходный failed Book run, все per-class reports, точные копии probes,
pristine SHA и raw windows. Collector сначала остановился на слишком коротком
окне распространения константы Defending; область расширена до инструкций
после последнего вызова, затем все 97 selectors сверены. Это исправление
проверяющего инструмента до записи sealed contracts, не изменение игры.
