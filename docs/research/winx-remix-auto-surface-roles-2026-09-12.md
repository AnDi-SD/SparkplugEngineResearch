# Универсальные роли поверхностей: прототип, 12 сентября 2026

Первый этап [плана интеграции](winx-remix-integration-plan.md): собственная
прослойка распознаёт совпадающие проходы по геометрии и состоянию D3D9,
передаёт прозрачное наложение отдельным экземпляром Remix API.
В исходниках нет списков игровых мешей, имён уровней или известных texture hashes.
Идентификатор ресурса вычисляется из его данных и не определяет роль.

**Статус:** визуально проверен на уступе Гардинии 2 и в начальной области
Гардинии 1. Доступен отдельным `Run-WinxRemix.ps1 -Mode RTX -AutoSurfaceRoles`.
Пока не заменяет прежний основной профиль: обнаружен сбой штатного USD-захвата
при присутствии API-материалов. Это не завершение всего renderer/camera/light плана.

## Общий алгоритм

В пределах кадра успешный непрозрачный draw регистрируется как возможное
основание. Последующий SRCALPHA/INVSRCALPHA draw с теми же VB/IB, диапазоном
индексов, declaration, world/view/projection, viewport и состоянием отсечения
распознаётся как наложение. Ключ содержит идентичность ресурсов, но не их
заранее известные адреса. Изменение буфера, уничтожение/повторное создание
ресурса, Reset и новый кадр сбрасывают сопоставление.

Поддерживаемая передача: индексированные FFP triangle list/strip, основной
perspective target, Z test/write, один поток, POSITION float3 и вершинный цвет,
одна выбранная UV-пара float2, уравнение texture × diffuse для RGB и alpha.
CURRENT на первом texture stage эквивалентен diffuse. Сохраняются индекс UV,
RGBA, sampler wrap/filter, alpha test, world transform и cull orientation.
Shader draws, skinning, texgen, дополнительные texture stages и иные уравнения
пока остаются обычными draw calls с диагностикой неподдержанной передачи.

Содержимое VB/IB копируется при завершении игровых записей, независимо от
диагностического лимита логов. Это поддерживает WRITEONLY buffers без запрещённого
чтения через Lock(READONLY). Полностью не наблюдавшиеся данные не подменяются нулями:
передача возможна после полного заполнения, затем допускает частичные обновления.
После неполного DISCARD снимок считается недействительным.

Прослойка переводит strip в список треугольников. Если нормалей нет, создаёт
геометрическую нормаль каждого треугольника; это наш backend, а не восстановленная
игровая процедура. DDS — точная копия существующей текстуры через D3DX, без
перекраски. CreateMaterial/CreateMesh кешируются, DrawInstance получает DecalStatic
только для распознанного экземпляра. Соответствующий исходный draw не дублируется.
Самостоятельная прозрачная поверхность с той же текстурой остаётся обычным draw.

Ограничения памяти: зеркало буферов ≤64 МиБ, один буфер ≤8 МиБ, ≤4096 буферов;
SDK-геометрия ≤64 МиБ/512 мешей, неиспользуемые меши удаляются после300 кадров;
≤256 материалов, ≤4096 хешей текстур. Переполнение сохраняет обычную отрисовку
и увеличивает unknown. Текстуры пока только managed A8R8G8B8/X8R8G8B8 с плотным
верхним mip ≤4 мегапикселей. Все эти границы — ограничения прототипа, не правила игры.

## Ограничение штатного API и сбой capture

Первый транспорт через временный SetConfigVariable(decalTextures) оказался
неверным. API возвращал success, но USD показал DecalStatic и у самостоятельной
травы. В исследованном `HashSetLayer::parseFromStrings` значения добавляются;
пустая строка не очищает множество. Поэтому такой транспорт удалён из кода.
Ветка `2026-09-12-auto-roles-gardenia02` сохранена как отрицательный результат.

Явный SDK-транспорт исправил отображение. Однако в
`2026-09-12-auto-api-v4-gardenia02` первая попытка capture в12:14:07 вызвала
`0xC0000005`, чтение адреса`0x20`, в оригинальной `.trex/d3d9.dll`, RVA`0x2BEEFD`.
Дамп и логи сохранены в run. Клиент сообщил об отключении bridge.
Сбой следует за `GameCapturer: New capture`; завершения USD export нет.

В reference source `GameCapturer::newInstance` берёт LegacyMaterialData,
а `captureMaterial` без проверки разыменовывает legacy texture image view
и sampler. API-материал хранится в externalMaterial. Это согласуется с
чтением около null, но точная исходная строка для установленного release
не доказана: reference commit отличается от release, отладочных символов нет.
Повторного намеренного падения не запускали. Успешным USD-захватом новую ветку
считать нельзя; проверка сейчас опирается на снимки окна и API audit.

Дальнейший шаг для production-пути — согласовать typed scene/material transport
с захватом Remix. Если потребуется исправление runtime, делать общий source patch
для API-материалов и capture, сохранив штатный runtime как контрольный, без
бинарных правок по адресам и без возврата к спискам игровых исключений.
Полный build toolchain Remix здесь ещё не подготовлен: Meson/Ninja не найдены
в PATH, VULKAN_SDK не задан, submodule dependencies не инициализированы.
