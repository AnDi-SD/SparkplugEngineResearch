# Keyboard/Mouse: исходные состояния и различия PC/PS2

119 основных original вызовов завершились с первого раза:69 PC и50 PS2.
Отдельно выполнены5 диагностических вызовов PC key-map:3 возврата и2
остановки до чтения за пределами просмотренных записей. COM,OS polling
и реальные устройства не вызываются;проверяются игровые методы обработки
готовых записей и чтения сохранённого состояния.

Классы PC `spDXKeyboard/spDXMouse` и PS2 `spPS2Keyboard/spPS2Mouse`
имеют разные registrations. Они сопоставлены функционально,не объединены
в один class ID или layout. Common spInputDevice и GamePad в этом пакете
только разведаны и нового балла не получают.

## PC-клавиатура: события,состояние и признак изменения

Original helper4CC980 принимает число20-byte records,начинающихся вobj88:
word0 — scan index,word4 — данные. Для каждого record индексируется byte
array obj858:bit80 данных даёт1,его отсутствие0. В obj958[index] всегда
пишется1. Повторный индекс обрабатывается последовательно;последний record
задаёт состояние,признак изменения остаётся1. Нулевое число records не
меняет память. Подтверждён только AL=1,не весь произвольный EAX.

Проверены6 наборов,включая пустой,повторы,разные индексы,bytes7F/80/FF
и данные80000000,у которых bit80 отсутствует. Остальные bytes записей
и ячейки массивов сохраняются. Producer не проверяет флагobj45.
Невалидные scan indices и счётчик за пределами подготовленных records
не подаются;реальный источник и очистка очереди остаются открыты.

Queries4CC9D0/4CCA00 принимают secondary-interface this=obj14.
При ненулевом obj45 получают scan index через настоящий4D6470 и возвращают
true **только при byte==1** вobj858/obj958. Нулевой флаг подавляет также
lookup. Значения2/FF не равны true. Integer query slots3/4 разделяют
original constant-zero body5A7DC0;один вызов проверяет общий адрес,
alias двух slots подтверждён таблицей.

Основные проверки дополнены12 узкими PC calls для codes0,70,99:нужная
ячейка получает0/1,все другие — противоположное значение. Это проверяет
именно маршрутизацию индекса,которую однородная заливка массива не различает.
107 прежних успешных вызовов не повторялись;их точный source сохранён.

## PS2-клавиатура

Проверены реальные interface thunks1F1710/1F1700/1F16F0/1F16E0,
вычитающие14 из A0,и соответствующие bodies1F14D0/1F14C0/1F14B0/1F1490.
Все четыре query возвращают0 без чтения cache или устройств. Это исходные
методы PS2 executable,не заглушки исследовательского стенда. Две заливки,
active0/FF и codes0/FFFFFFFF не меняют результат.

Отдельный исходный1F14F0 пишет только obj44=1 и возвращает1.
Это поведение конкретного метода,не доказательство инициализации реальной
клавиатуры. Factory1F1650 статически задаёт primary4915E0 и secondary491604
вobj14;полный factory/lifecycle здесь не исполнялся.

## Mouse: четыре query slots

Ниже все смещения относительно начала объекта. PC использует secondary
this=obj14,PS2 выполняет оригинальный adjustor −14. Общий interface
slot1/2 проверяет code100..107 и точное равенство сохранённого значения1.
Перед чтением PC проверяет byte45,PS2 —byte44. Соседний байт в fixture
имеет другое значение,чтобы эти поля нельзя было спутать.

| Query | PC | PS2 |
|---|---|---|
| slot1 | 4CC320;bytes50A4..50AB | thunk1F2080→1F18E0;words50..6C |
| slot2 | 4CC350;bytes50B8..50BF | thunk1F2070→1F1890;wordsB0..CC |
| slot3,коды108/109 | 4CC380;words50C0/50C4 | thunk1F2060→1F17E0;float74/78→unsigned integer path |
| slot4,коды108/109/110 | 4CC430;words5098/509C/50A0 | thunk1F2050→1F1770;float74/78/7C→signed integer path |

Остальные проверенные коды и disabled device возвращают0. В PC первая
проверка button range unsigned,вторая signed;на выбранных32-bit boundary
codes результат совпадает. Смысл массива slot2 для мыши пока не выводится
автоматически из клавиатуры:producer мыши в этом пакете не исполнялся.

Матрица покрывает99,100,107,108,109,110,111,FFFFFFFF,active0/1/FF,
stored1/2/FF. PC scalar fixtures:1234/567 и−3/4/−5;PS2 float inputs
10/20/30. PS2 conversion квалифицируется только для этих точных небольших
неотрицательных целых. Дроби,отрицательный unsigned input,ветвь≥2³¹,
FPU exception/status и соответствие физическим координатам не заявлены.

## Нестандартная граница PC key-map

4D6470 использует144 просмотренные пары key/scan по6F3F48..6F43C7:
keys0..142 и176. Код0 отображается вscan1;максимальный scan211.
Helper ищет sentinel key−1,но следующий word6F43C8 равен3A83126F,
после него начинается другая таблица. Для неизвестных codes143/FFFFFFFF
оригинальное исполнение действительно достигает чтения6F43C8.

Диагностический memory hook останавливает гостя **до этого чтения**.
Дальнейшее поведение,его возможный возврат0 или окончательная длина поиска
не установлены;безопасный fallback не подставлен. Домен неизвестных кодов
отложен. Рекомендуемый следующий шаг — установить допустимые коды по
игровым callers и отдельно исследовать исходное поведение за границей,
сохраняя игру эталоном. Разработка tools и замена этого алгоритма не ведутся.

Два ранних inline assertions предполагали наличие sentinel и остановились
до native runs/ledger changes. Exploratory labels `key-map-sentinel` и
`keyboard-ps2-ctor` исправлены отдельным указателем:первое окно содержит
кандидат,который не sentinel;второе — constant query methods,не ctor.
Исходные captures сохранены;правильный factory layout снят отдельно.
