# `spFog` (`0x7AC95AEC`)

Статус: внешний layout и все пять значений подтверждены кодом PC и PS2,
полностью декодируются во всём корпусе; только чтение. Runtime-проверка изменения
параметров ещё не выполнялась.

## Распространённость

| Корпус | Объекты | Уникальные SMO | Физические вхождения | Формы | Payload |
|---|---:|---:|---:|---:|---:|
| `pc-pristine` | 413 | 413 | 413 | 1 | 22 |
| `pc-working` | 413 | 413 | 413 | 1 | 22 |
| `ps2-pristine` | 314 | 314 | 1 470 | 1 | 20 |

В каждом содержащем класс SMO находится ровно один безымянный `spFog`. Единственные
SMO без него одинаковы во всех корпусах: `Menus/gameover.smo`,
`Menus/hud_training.smo` и `Menus/object.smo` (на PS2 с префиксом `data/`).

Непосредственные родители:

| Корпус | `spModel` | `spSkin` | `spParticleSystem` | root |
|---|---:|---:|---:|---:|
| каждый PC | 270 | 103 | 38 | 2 |
| PS2 | 193 | 93 | 28 | 0 |

Собственных дочерних объектов у `spFog` нет. Serializer `spRenderable` отдельно
хранит relation `esfRenderableFog`, поэтому один fog-объект может использоваться
несколькими renderable одного ресурса; его положение в object directory само по
себе не ограничивает область действия одним родителем.

## Байтовая структура

Размер каждого объекта равен 31 байту, сигнатура базы —
`s0:f0:20|s0:end`.

| Смещение | Размер | Значение |
|---:|---:|---|
| `0x00` | 4 | class ID `0x7AC95AEC` |
| `0x04` | 4 | `SBOO` |
| `0x08` | 2 | field 0: header `0xA0`, UInt8 payload size `0x14` |
| `0x0A` | 4 | `UInt32 type` |
| `0x0E` | 4 | `ARGB UInt32 color` |
| `0x12` | 4 | `Single start` |
| `0x16` | 4 | `Single end` |
| `0x1A` | 4 | `Single density` |
| `0x1E` | 1 | terminator собственной serializer-секции `0x00` |

Все числа little-endian. Цвет сохраняется целиком как `uColor`; диагностический
runtime-текст выводит только RGB, поэтому влияние старшего alpha-байта отдельно
не доказано.

## Подтипы и наблюдаемые значения

Первый `UInt32` является настоящим discriminator, а не частью цвета:

| Type | Интерпретация | PC pristine | PC working | PS2 | Всего |
|---:|---|---:|---:|---:|---:|
| 0 | `none`, fog отключён | 385 | 385 | 290 | 1 060 |
| 3 | `linear` в render enum | 28 | 28 | 24 | 80 |

PC runtime по `0x004DF0B9` прямо пропускает объект, если член type `+0x14` равен
нулю, поэтому смысл `none` подтверждён поведением. Значение 3 соответствует
`linear` в передаваемом renderer fog enum. Значения 1 (`exponential`) и 2
(`exponential-squared`) в доступных SMO не встречаются и пока не являются
наблюдаемыми подтипами. Для вариантов базы созданы только `type 0` и `type 3`.

По всем 1 140 объектам:

- 22 различных 20-байтовых payload и 17 цветов;
- `start` лежит в диапазоне `0..5000`;
- `end` лежит в диапазоне `1000..60000`;
- `density` всегда равен `0`;
- все три `Single` конечны, NaN/Infinity не обнаружены.

Постоянный ноль density не означает, что поле не используется: exponential
режимов 1/2 в корпусе нет. Для наблюдаемого linear type 3 существенными
параметрами являются color/start/end.

## Межкорпусное сравнение

Все 413 одноимённых пар `pc-working`/`pc-pristine` имеют совершенно одинаковый
20-байтовый fog payload, хотя содержимое 29 PC SMO в целом различается.

После удаления служебного PS2-префикса `data/` найдено 314 одноимённых
PC/PS2-пар. У всех 314 payload также совпадает побайтно. Тем самым общий layout
подтверждается сразу тремя независимыми признаками: структурой файлов, кодом
обоих executable и фактическими межплатформенными значениями.

Два PC-only payload не означают отдельный PC-layout: PS2 просто не содержит
ресурсов с соответствующими путями. Все 20 вариантов, попавших на PS2, входят в
общий набор из 22.

## Свидетельства executable

Pristine PC `WinxClub.exe`:

- getter class ID `0x7AC95AEC` — `0x0043B820`;
- load — `0x0043B910..0x0043BAE1`;
- serialize — `0x0043BCF0..0x0043C074`;
- строки `spFogSerializer` и диагностик записи — file offsets
  `0x2DEC5C..0x2DEE04`.

Loader читает единственный field 0 и последовательно записывает пять 32-битных
значений в члены объекта `+0x14`, `+0x18`, `+0x1C`, `+0x20`, `+0x24`. Serializer
читает те же члены в порядке type/color/start/end/density и пишет один блок
`esfFog`. Runtime selector `0x004DF0B9..0x004DF0DC` игнорирует type 0, выбирает
активный fog и передаёт его color дальше в состояние сцены.

PS2 `SLES_532.19`:

- load — `0x0018ADE0..0x0018AFF4`;
- serialize — `0x0018B010..0x0018B250`;
- getter class ID — `0x0018B270`;
- строки serializer — file offsets `0x34D170..0x34D390`;
- строка имени класса — file offset `0x39C378`.

MIPS-код использует те же смещения членов и тот же порядок значений. Это не
перенос PC-имен на похожие PS2-байты, а независимое подтверждение реализации.

## Реализация и база

`SmoFogDecoder` принимает только точный 20-байтовый payload, сохраняет raw type и
декодирует цвет и три `Single`. Неизвестный type остаётся видимым как
`unknown-N`, а не подменяется известным enum. Viewer показывает тип одновременно
числом и именем.

Команда

```text
SmoViewer.Inspect research-db analyze-class <db> spFog
```

повторно проверяет три корпуса и оба executable, затем идемпотентно записывает:

- common PC/PS2 definition `fog.parameters`;
- варианты `fog_type_0_none` и `fog_type_3_linear`;
- назначения всех 1 140 объектов;
- декодированные JSON-значения всех PC, PS2 и PS2-tagged PC полей;
- четыре evidence-записи: PC code, PS2 code, полный corpus и точное сравнение
  одноимённых ресурсов.

Статус редактирования остаётся `read_only_research`. Следующий отдельный этап —
создать копию SMO, по одному менять type/color/start/end/density и подтвердить
загрузку и визуальный результат в native runtime.
