# CP133 — один проход создания весов

Дата: 2026-09-08. Продолжение [оптимизации записи CP132](tool-importer-performance-2026-09-08.md).
Текущий Importer 0.6.1 готовит веса двух выбранных настоящих доноров примерно
вдвое быстрее, сохраняя публичный результат подготовки и выходной SMO точно.
Измеритель операций остаётся **16/16**, class ledger не увеличивается.

## Причина и изменение

`GeneratedSkinningPreparer` продолжал выполнять предварительный расчёт без
semantic regions и полный Analyze для подбора числа влияний под старый writer
с ограниченным числом palettes. Текущий clean writer создаёт дополнительные
ветви и разбивает поток при превышении 65 535 вершин. Его подтверждённая
16-слотовая palette принимает треугольник с максимум 3 × 4 = 12 различными
ссылками на кости. Подбор меньшего числа влияний для этого конвейера не нужен.
Поиск также подтвердил отсутствие производителя старого сообщения
`Material group needs more than`, по которому выбирался следующий проход.

Теперь выполняется один проход с постоянным лимитом четыре влияния и одним
разрешением semantic regions. Инвариант проверяется относительно той же
`PaletteCapacity`, которую использует writer. Это сохраняет независимость
весов внешних вершин от включения внутренних semantic regions. Финальный
Analyze, проверки входа и памяти, отмена, контроль геометрии и проверка output
сохранены. Дополнительный Analyze в GUI с выбранным material profile остаётся
отдельным потребителем подготовленного результата.

В выборе palette устранены временные множества `Union` и сортируемые
перечисления на каждый треугольник. Один проход по bins сохраняет прежний
порядок выбора: меньше новых костей, меньше треугольников, меньший ordinal.
Границы материала, renderable и индексов вершин сохраняются.

Прототип кэширования topology сократил выделения примерно на 17 МБ, но не
показал полезного ускорения на выбранном крупном доноре. Он удалён; в текущем
коде нет этого кэша. Контракты [проверенных Skin/палитр PC](tool-importer-clean-targets-2026-09-08.md)
и правила сериализации не менялись.

## Сопоставимое измерение

[Benchmark](../../research/ImporterPreparationBench/Program.cs) вызывает
`PrepareCancellable` с реальной геометрией и явно записанными pose/alignment.
Release, tiered JIT выключен, один разогрев и пять измерений; отдельные процессы
используют **один benchmark DLL**, заменяется только Core CP132/CP133.
Результаты сравнивает [отдельный скрипт](../../research/validate_importer_preparation.py).

| Медиана подготовки | Дафна, 1 701 вершина | Bloom reboot, 12 469 вершин |
|---|---:|---:|
| Wall time, мс | 274,1131 → 141,8026 | 1 405,9016 → 700,0383 |
| Снижение wall time | 48,27% | 50,21% |
| Process CPU time, мс | 281,25 → 140,625 | 1 390,625 → 687,5 |
| Суммарно выделенные bytes | 118 338 448 → 56 150 024 | 511 107 872 → 233 592 992 |
| Снижение выделений | 52,55% | 54,30% |
| Peak working set, bytes | 227 172 352 → 207 802 368 | 324 218 880 → 362 352 640 |

Для Дафны используется фиксированный automatic fit; для reboot — coarse
alignment и исходная поза игрового skeleton. Автоматическая подгонка рук reboot
сохраняет прежний отказ; он не обходился изменением production guards.
В обоих основных случаях автоматическое отделение Back отключено, как в GUI.
Дополнительный контроль Дафны с Back включённым: один разогрев/три измерения,
265,0947 → 134,4044 мс; суммарные выделения −52,70%.

Публичные fingerprints подготовки, analysis и конечные SMO совпадают во всех
трёх сравнениях. В сложной grouped pose из прежнего аудита Дафны отдельный
[control](../../tools/SmoImporter/SmoImporter.FormatTests/GroupedPreparationControl.cs)
также даёт точное совпадение публичного результата, с двумя проходами до и одним
после. Художественное качество весов этим сравнением не измеряется.

Измеряется только подготовка: время отдельного GUI Analyze, drawing и записи
сюда не входит. Windows CPU counter дискретен; фоновые процессы влияют на время.
Сокращение суммарных выделений не гарантирует меньший peak RAM: на крупном
доноре итоговый peak был выше, около 346 МиБ. Все прогоны выполнялись по одному.

## Проверки

- 44 проверки выбранных palette cases на прежнем и новом Core. Полные traces
  совпали: capacity, несколько материалов, фильтрация opaque body, порядок при
  равных вариантах и разбиение 65 538 уникальных вершин по 16-битному индексу.
- Bounded semantic hand: 180 вершин/304 треугольника, topology lobes, wrists,
  finger lanes и mirrored articulation. Один Prepare/один semantic resolve.
- Bounded Head/separation-plane проверки: плечевые anchors, целые компоненты,
  соседние островки, дальнее крыло, редактирование Head и отказ неверных edits.
- Полный прежний Daphne mode3 regression прошёл: разные fitting selections,
  повёрнутый donor, сохранность входов, preview, UV, opacity, две независимые
  текстуры и удаление старой визуальной части. Output совпал с Back benchmark.
- Guard 200 001 вершины и отмена до начала, на первом progress и перед финальным
  Analyze прошли; исходные файлы не менялись.
- 65 clean-target проверок на пяти целях; все пять SHA совпадают с CP131/132.
  Original-PC loaders, 19 palettes/304 matrices и 30 SAN poses этих точных файлов
  переиспользованы без повторного запуска.
- GUI Release 0.6.1: 0 warnings/errors, 15,62 с.

Отдельный старый `DaphneSemanticCoverageAudit` не включён в passed evidence:
он ограничивает selected components четырьмя при фактических 23 и ожидает
прежний Head volume. Диагностическое расширение test budget до32 дошло до
отказа volume и отменено. Исходный лимит4 оставлен. Grouped control на Core
CP132/CP133 подтвердил одинаковые selection/analysis и отсутствие этого volume;
отказ не возник из-за сокращения проходов. Текущие bounded Head/hand проверки
и полный mode3 regression перечислены отдельно. Старый аудит требует обновления
своего oracle и не объявляется успешно пройденным.

[Validation manifest](../../research/tool-importer-preparation-validation-2026-09-08.json)
содержит SHA кода, reports, inputs/outputs и ограничения;
[assessment CP133](../../research/tool-readiness-assessment-2026-09-08-cp133.json)
не меняет знаменатель. Публичная публикация не выполнена.
