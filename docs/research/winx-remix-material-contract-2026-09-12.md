# Входные данные материалов и фонового освещения

12 сентября 2026. Продолжение общего адаптера Winx → stock Remix.
Это собственная диагностика платформенной границы, не новый восстановленный
класс и не исправление итоговой яркости. EXE, игровые shaders и NVIDIA DLL
не изменены. Гардиния 2 не запускалась.

## Установленная связь

[CP43](native-pc-renderer-lights.md) уже подтверждал выбор одного ambient из
кэша объекта и установку D3DRS_AMBIENT. Восстановленный
`spDXShader::BuildConstantsForAnalysis` обрабатывает `AmbientCol` как произведение
цвета выбранного ambient и ambient-цвета материала. Нельзя переносить эту
игровую формулу второй самостоятельной реализацией в shim.

Новый аудит читает уже готовые значения настоящего D3D9 draw. Для Алфеи:

- ambient материала: `[0.717647076, 0.694117665, 0.619607866]`;
- выбранный device ambient: `[183, 177, 158] / 255`;
- фактический shader `AmbientCol`: `[0.515017331, 0.481799334, 0.383913904]`.

Максимальная разница с произведением — `1.77e-8`. После перехода на Домино
материал изменился на `[0.600000024, 0.721568644, 0.847058892]`, а shader input —
на `[0.360000014, 0.520661294, 0.717508793]`; разница с произведением `8.45e-8`.
Это измеренная связь двух сцен, а не доказательство всех способов освещения.

`AmbientCol` уже зависит от материала. Его нельзя объявлять исходным цветом
глобальной лампы и затем повторно умножать на материал. Перенос нескольких
ambient объектов сцены в сумму глобальных источников также потерял бы выбор
получателя. Данные shader constants и материал должны оставаться связанными
в общем механизме передачи.

У большинства проверенных FFP draws окружения освещение выключено, RGB
ambient/emissive материала равны нулю; цвет приходит другим путём. Это
**не доказывает**, что весь vertex color является запечённым освещением.
В reference Remix `vertexColorIsBakedLighting` нормализует RGB вершины по
максимальному каналу. Такое общее переключение не восстанавливает раздельные
albedo/ambient/emissive исходной игры.

Диагностический albedo-view показывает текстуры/цвет окружения, normal-view —
различимые нормали поверхностей. Тёмный финальный кадр не означает потери всех
этих входов. Камера между диагностическими снимками менялась: это не попарное
пиксельное сравнение и не доказательство правильности всех нормалей. Причина
всей темноты пока не локализована; улучшение освещения здесь не заявляется.

## Реализация

`-MaterialAudit` снимает состояние до Scoped* преобразований нашей прослойки,
в том числе после StateBlock Apply. Обычный режим не делает дополнительных
запросов. При включении читаются:

- D3DMATERIAL9 diffuse/ambient/emissive/specular RGBA, включая alpha, и Power;
- LIGHTING, COLORVERTEX, четыре material-source selector, AMBIENT, TEXTUREFACTOR,
  specular enable и depth/alpha enable;
- восемь texture stages: RGB/alpha операции и аргументы, индекс UV, flags;
- primary render target, тип проекции и наличие color/normal/POSITIONT;
- текущий VS/PS; для VS — байткод и CTAB выбранных именованных цветовых входов,
  затем настоящие значения соответствующих float4 registers. Итоговая версия
  сохраняет точные байткоды рядом с логом для независимой сверки через D3DX.

CTAB parser ограничивает offsets/counts/string lengths/registers и проверяет
тип float4. Неизвестные shader paths не заменяются успешной заглушкой.
Идентичность таблицы определяется всеми байтами, hash используется лишь в логе.
Наборы входов дедуплицируются по наблюдённому состоянию; их ID не является
идентичностью игрового материала. Геометрия, выбор света и GPU shader output
здесь не реконструируются.

Выборка — каждый 300-й кадр и существующая начальная/Reset/F8 область. Все
четыре обычных Draw-вызова покрыты общим Observe; наши служебные UI draws
в неё не включаются. Лимит 16 МиБ плюс последняя ограниченная запись,
1024 input records, 256 shader tables/1 МиБ байткода. Failures/rejected
записываются отдельно. Нет доказательства серверных значений констант,
полной shader semantics, arbitrary UV transforms или всего игрового времени.

## Проверки

MSVC x86 `/W4`: итоговая DLL без предупреждений, SHA256
`E8A2919D74D138D3444FC3CB3D565035BD18BC36F6877EB3D1790D0DC5AF7DFC`.
`Test-MaterialAudit.ps1`: 12 граничных проверок и независимое сопоставление
регистров 15 сохранённых игровых байткодов с установленной Microsoft D3DX.
Восемь программ имеют CTAB; семь — выбранные цветовые входы. У shader-0015
после оптимизации остались только transforms. Первоначальное ожидание восьми
цветовых программ в тесте было неверным; все сопоставления регистров уже тогда
совпали, исправлено именно ожидание теста по D3DX disassembly.

- `2026-09-12-material-contract-alfea`: первоначальное исследование через
  прежнюю DLL, albedo/normal/baked-lighting comparison; подробные draws сохранены.
- `2026-09-12-material-audit-alfea`: первый аудит, до добавления primary/depth
  и всех восьми stages. Его проходы анализатор честно помечает unclassified.
- `2026-09-12-material-contract-v2`: предшествующая DLL, NoDrawTrace, без SceneAudit,
  Алфея → Домино через подтверждённый F1 selector. После перехода закрыты
  debug menu/tutorial, active state 4. Аудит продолжает читать материалы,
  световой мост продолжает работать без отмеченных ошибок API.
  Сохранённая сводка: 30 562 sampled draws / 90 кадров, 42 набора входов,
  2 VS, failures/rejected 0.
- `2026-09-12-material-contract-final-domino`: итоговая DLL с Power и сохранением
  байткодов. 3200 sampled draws / 9 кадров, 23 набора входов, 2 VS,
  failures/rejected 0. Таблицы обоих новых сохранённых VS независимо сопоставлены
  с D3DX; это проверяет соответствие имён регистрам, но не серверные значения.

Для автоматизации исправлен `winx_remix_window.py`: когда SetForegroundWindow
отказывает, оконная игра активируется кликом по проверенному заголовку.
Перед кликом проверяется владелец точки; прежний topmost flag восстанавливается
в finally. Fullscreen не использует этот путь. Input queues не соединяются;
причина выбора описана в [документации Microsoft](https://devblogs.microsoft.com/oldnewthing/20080801-00/?p=21393).
Обычные клавиши и снимки по-прежнему требуют фактического foreground нужного окна.

## Следующий общий шаг

Использовать этот контракт для раздельной передачи базового цвета,
эмиссии и исходного освещения с сохранением alpha и shader деформаций.
Начать с подтверждённых режимов материала; shader lighting нельзя определять
по одному D3DRS_LIGHTING. Не вводить глобальный ambient из суммы scene lights
и не объявлять нормализацию vertex RGB точным удалением освещения.
Согласовать представление с API-материалами и ранее обнаруженным USD capture
сбоем. Универсальный рендерный перенос ambient/material behavior ещё не реализован.
