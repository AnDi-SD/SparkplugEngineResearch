# PC: целые SAN и Node SMO в отдельном execution profile

CP101, 7 сентября 2026. Шесть новых сравнений прошли целый оригинальный loader
`00422B50`, включая ранее ограниченные размером micro-пробы файлы. Это снимает
ограничение метода для данной выборки, не закрывает все критерии SMO/SAN.

## Причина и метод

Исторические probes ограничивались 100 000 инструкций / 2 секундами на вызов.
`gameover.smo` останавливался при третьей Node factory; отдельно два объекта
укладывались примерно в 90 000 инструкций. После поручения пользователя ускорять
исследование введён явный профиль `file`: 1 000 000 инструкций / 8 секунд,
выбираемый до создания свежего guest. Внешний child остаётся ограничен 30 секундами.
В этих опытах выбрана уже поддержанная heap arena 128 КиБ.

Старый `micro` остаётся по умолчанию. Остановленные guests не возобновлялись,
старые отключённые probes и manifests не переписаны в успешные. Запущены новые
[SAN](../../research/probe_pc_san_file_profile.py) и
[Node](../../research/probe_pc_node_file_profile.py) probes с отдельными результатами.
Pristine hash, unmapped-memory, privileged/OS и calling-convention проверки
сохранены. Новых подмен engine-поведения нет. Имеющиеся startup/container,
byte-stream, allocation/CRT seams остаются явно заданными: это не полный запуск
игры и не доказательство настоящего D3D device.

## Результаты

| Вход | Инструкции whole load | Время whole load | Сравнение | Native assertions | Освобождённые allocations |
| --- | ---: | ---: | --- | ---: | ---: |
| `bflower.san`, оригинал | 112 341 | 0,835 с | 773 значения | 39 | 82 |
| `barrel.san`, оригинал | 134 049 | 0,969 с | 902 значения | 42 | 97 |
| `bw.san`, оригинал | 123 209 | 0,917 с | 902 значения | 42 | 78 |
| `barrel.san`, запись C++ | 122 111 | 0,900 с | 902 значения | 42 | 78 |
| `object.smo`, оригинал | 109 653 | 0,885 с | 2 Node records | 24 | 25 |
| `gameover.smo`, оригинал | 234 449 | 1,550 с | 6 Node records | 32 | 61 |

Итого: 6 случаев, 221 явная native assertion, 3479 SAN-значений и 8 полных Node
records; каждый случай завершился с освобождением всех записанных native
allocations. SAN float-сравнение использует прежние `rel_tol=abs_tol=4e-5`;
целочисленные поля, имена и структура сравниваются точно. У Node сравниваются
точные биты local/world translation, scale, rotation, flags, имена и рёбра дерева.
Максимально занято в bump arena 44 384 байта из 131 072.

Первый `bflower` загрузился успешно, но проверка споткнулась о порядок аргументов:
JSON записал float `1.0` как int `1`; native дал `0.9999999403953552`. В новом probe
native результат передан первым, как требует существующий comparator. Допуск
не увеличивался. После исправления выполнен свежий процесс и проверен teardown;
первый локальный отчёт сохранён отдельно.

Native `gameover` действительно посетил factory/reader шесть раз и AttachChild
пять раз; full loader сам прочитал оба индекса и очистил FAT. Это теперь
whole-loader evidence, тогда как прежнее свидетельство `object.smo` относилось
только к отдельно вызванному outer `422940`.

Записанный C++ `barrel` содержит canonical field64: native capacity меняется
20 → 21, а track/PRS поведение сохраняется. Остальные три SAN из
[CP99](native-pc-san-file-roundtrip.md) воспроизводятся побайтно; поэтому повторять
native reread тех же байтов под другим именем не требуется. В совокупности CP99
и CP101 подтверждают оригинальный whole reread всех четырёх выходов C++ SAN.

## Границы и воспроизводимость

Проверки: полная Python-регрессия 86/86, включая 11 harness guard tests и 4 arena
tests; file-профиль
сохраняет запрет доступа к unmapped memory и OS instructions и останавливается
по собственному instruction limit. Все прежние микропробы используют прежний
default. Данные запусков лежат локально в `local-data/results/cycle-20260908-0700/`;
сводка и fingerprints — [CP101](../../research/native-cycle-checkpoint-2026-09-08-cp101.json).

Остаются: оригинальные полные manager/FAT/RTTI startup paths, не найденная внешняя
Save orchestration, mesh/material/skin-containing whole SMO, failure/rollback и
общая рекурсивная ownership. Увеличение временного бюджета само по себе не
восстанавливает новый метод класса, поэтому class score здесь не повышается.
