# Первый native-источник геометрии для Remix

13 сентября 2026, первый блок выполнения
[плана прямой сцены](winx-remix-direct-scene-plan-2026-09-12.md).
Это частичная реализация этапов 1–2, не завершённый scene exporter.

## Работающий результат

Обычные поддерживаемые меши получают вершины и индексы из CPU-данных движка,
сохранённых **до** исходной загрузки в D3D. Существующий конвертер и Remix
CreateMesh/DrawInstance используются повторно. Позиция экземпляра читается
из native renderer и сверяется с его D3D-входом. Успешная API-подача, как и
в прежнем MaterialChannels пути, подавляет соответствующий исходный draw.

В оконных RTX-запусках проверены Алфея 27 и Домино 4, движение и переключение
источника без перезапуска. Ни правила уровней, ни texture/mesh allowlists не
добавлялись. В Алфее на неподвижной проверенной сцене выполняется **871 native
подача за кадр**, в Домино — **446**. Это операции подачи, включая повторное
использование мешей; не число уникальных объектов и не процент всей игры.

| Проверка | Алфея | Домино |
|---|---:|---:|
| Запуск | `play-rtx-20260912-235428-858` | `play-rtx-20260913-000239-802` |
| Проверенные поколения пар буферов | 339 | 224 |
| Несовпадения захваченных байтов с загрузкой игры | 0 | 0 |
| Native instances в записанных frame records | 70 551 | 942 844 |
| Полные записанные кадры с native-подачей | 81 | 2 114 |
| Ошибки/лимиты данных в записанных кадрах | 0 / 0 | 0 / 0 |
| Максимум сохранённых CPU-байтов | 3 725 162 | 693 658 |
| Достигнут предел диагностического файла | Да | Нет |

В первом опыте подробный F8 trace достиг лимита 16 MiB. Поэтому числа Алфеи
описывают записанную часть, а не весь запуск; переключения источника записаны
отдельно. В итоговой DLL per-instance trace ограничен одним кадром запроса и
периодическими кадрами. В Домино файл занял 1 425 251 байт.

Камера Алфеи до/после включения: view и projection совпали побитово в JSON
снимках. Высота персонажа при idle изменилась на ~0,0000153 игровой единицы;
покадровое совпадение анимации не заявляется. В Домино projection совпала,
view после движения ещё изменялась: сравнение не объявляется побитовым.
Окружение и HUD присутствуют в просмотренных A/B и motion screenshots.
Избыточное свечение осталось прежним: материальная политика не менялась.

## Граница и происхождение

Собственная обвязка:
[winx_native_mesh_source.h](../../research/rtx-remix/winx_native_mesh_source.h).
Поля читаются через общий `Sparkplug/Analysis/PC/SparkplugAbi.h`; переносимые
классы не подменяются cast-ом объектов живого x86 процесса.

1. `PC4BC670(this=renderer+18, mesh)`, interface slot 9, даёт точный scoped
   mesh-контекст на время оригинальной подачи. Метод и его callbacks выполняются.
2. `PC4AA000(this=mesh+14, indexObject, vertexObject, keepCPU)` даёт входные
   `spIndexBuffer`/`spVertexBuffer`. Для выбранной группы нет весов/packed поля;
   подтверждённый общий `spDXMesh::BuildVertexBytesForAnalysis` копирует эти
   вершины без изменения. uint16 индексы тоже копируются без изменения.
3. После исходной инициализации связываются native VB/IB, COM resources,
   `vertexBegin × stride` и `indexBegin × 2`. Сохраняются только известные
   интервалы объединённого буфера. Пробелы нельзя использовать при подаче.
4. Дополнительно подключён `PC4C29C0(this, indexSize, vertexSize, indexData,
   vertexData)` для raw shared-data пути. **В двух проверенных уровнях он не
   вызывался**; live-готовность именно этого producer не заявляется.

Оба entry hooks переносят только целые position-independent инструкции.
Первый разведочный Original-запуск `play-original-20260912-234722-619` показал
работу mesh submit hook и отсутствие shared-data вызовов. Этот результат
определил подключение второго producer; нулевой захват не назван успехом.

Native cohort: triangle-list/strip, unweighted mesh, native single-pass
DXMaterial, точное совпадение текущих буферов/декларации/диапазона/world,
полное покрытие используемых интервалов и поддержка прежнего FFP конвертера.
Неподдержанный случай остаётся на прежнем источнике. Контрольное сравнение
проверяет byte ranges с D3D upload snapshot; после него используются native
байты. Проверка не делает GPU readback.

Поколение описывает версию пары захваченных буферов. Writable COM Lock,
Release и повторное создание ресурса инвалидируют соответствующий источник;
смешанная пара поколений не допускается. Read-only Lock сохраняет данные.
Это ещё **не** scene generation и **не** долговечная instance identity.
Владение scene/renderable и независимая от видимых draw подача остаются этапом 3.

| Поле текущей API-подачи | Источник |
|---|---|
| Вершины/индексы | Native CPU mesh inputs до D3D-копирования |
| Диапазон/stride | Native mesh, проверенный против D3D draw |
| World | Native renderer, проверенный против D3D transform |
| Layout/выбранный UV канал | D3D declaration и texture state |
| Материал/alpha/texture assets | Прежний D3D MaterialChannels путь |
| Камера | Прежний D3D путь; direct bridge готовится отдельно |
| Свет | Прежний native scene-light bridge |

## Проверки и установленная сборка

- [qualify_native_mesh.py](../../research/rtx-remix/qualify_native_mesh.py):
  все **7/7** полных выбранных code/data regions pristine/debug совпали.
  Используются прежние native mesh payload/renderer-submit доказательства;
  новый виртуальный вариант игровой математики не писался.
- Реальный system D3D9 + recording Remix API: **381/381**, в том числе
  **150** проверок нового источника/fixtures. Проверены native bytes против
  намеренно изменённого D3D audit snapshot, range/owner/world/generation
  mismatch, single-pass/weight guard, read-only/writable VB и IB, partial
  coverage, merge, пробелы и ненулевые базы. Synthetic ABI fixture проверяет
  наш адаптер и не выдаётся за оригинальное выполнение игры.
- Lifetime suite: **57/57**, включая отказы удаления и повторные попытки.
- x86 и x64 adapter builds прошли. x64 native reader отключён; имеются
  предупреждения C4505 о неиспользуемых helper-функциях.

Промежуточный test snapshot сначала не содержал общего `SparkBaseAbi.h`;
скрипты исправлены так, чтобы сохранять обе ABI-зависимости и структуру путей.
Создание GPU device в sandbox не удалось; тот же собранный прежний набор
231 проверки прошёл вне sandbox. Итоговые 381 проверки выполнены вне sandbox
в новом evidence каталоге. Эти подготовительные неудачи сохранены отдельно.

Итоговый x86 adapter: `4F18F5F36634A6E850E9D80A3E94AB8E414179497FF99151055B9965B0D7A6B1`,
`local-data/rtx-remix/build-native-source-v5/d3d9.dll`. Он установлен также в
canonical build и папку игры. Прежняя DLL `5BA41AD4…` сохранена в
`local-data/rtx-remix/native-source-tests/2026-09-12-v1/adapter-before.dll`.
EXE и NVIDIA runtime частей этот блок не менял. Тестовые процессы закрыты;
user.conf, winx.ini, сохранения и bridge.conf совпали с резервными копиями.

Включение: к существующему RTX-профилю с DebugMenu/MaterialChannels добавить
`-NativeMeshSubmit`. Только наблюдение — `-NativeMeshSource`.
В `live.conf`: `winx.nativeMeshSubmit = True/False`.
Без этих флагов новые native hooks не устанавливаются.

Закрытые результаты пересчитывает
[analyze_native_mesh_source.py](../../research/rtx-remix/analyze_native_mesh_source.py):
он проверяет завершение записанного PID, целостность/неизменность файла и
отмечает достигнутый предел лога. Evidence manifest:
[research JSON](../../research/winx-remix-native-mesh-source-2026-09-13.json).

## Следующая работа

Проверить самостоятельный camera transport через фактически собранную пару
client/server, затем поставить native main camera до первого world draw.
Заменять D3D layout/material входы на подтверждённые native данные и переносить
scene ownership/lifecycle по общему плану. Пока сохраняются старое расширение
видимости, D3D material state и обязательный D3D draw-контекст.

Функциональная оценка прежних девяти категорий остаётся **46,25%**: этот блок
меняет происхождение геометрии, не завершает физические материалы, камеры,
персонажей и эффекты. Прогресс прямого пути учитывается отдельно приведёнными
операциями и границами; вся цель остаётся активной.
