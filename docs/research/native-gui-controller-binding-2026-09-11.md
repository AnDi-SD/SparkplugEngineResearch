# GUIObject: поиск GUICollision и история состояния контроллеров

11 сентября 2026. Блок 25 цикла до 07:30 МСК. Исследуется исходный GUI движка;
интерфейсы наших инструментов не изменяются. Новых восстановленных C++-классов
в этом блоке нет. [Предыдущий контракт GUI](native-gui-object-family-2026-09-10.md)
содержит независимые class identities/vtables и исходные оценки.

## Enable: обе ветви записывают 4

`spGUIObject` slot10: PC `004290B0`, PS2 `00165240`. Метод записывает младший
байт аргумента в `this+28`, затем вызывает настоящий Node Find по имени
`GUICollision`, с двумя аргументами `1,1`. Это поиск подстроки, чувствительный
к регистру: `preGUICollisionExtra` подходит, `guicollision` и `GUI` — нет.

У найденного узла все элементы controller vector получают слово `4` по
смещению `+18`. Это происходит **и при включении, и при выключении**:
две ветви исходного метода одинаково обходят список и записывают это значение.
Иные значения слова не сохраняются методом Enable. Неизвестное назначение
отдельных битов слова не подменяется предполагаемым enum.

14 входов на платформу проверяют 0/1/255/12345680/256, пустой список,
один/три элемента, повтор одного указателя, прежнее значение4, подстроку,
несовпадение регистра, отсутствие имени и пустую строку. Сохраняются порядок
и число исходных записей, guard20 КиБ включает неиспользуемый controller.

PC: 14 полных возвратов, original Node Find `00421330` и явно ограниченная
платформенная реализация внешнего CRT `strstr` по IAT `006D932C`.
PS2: 13 полных возвратов из исходного входа, original Find `001A7160`,
original ELF `strstr` `0040B208`, vector-at `0014DD40`. Пустая ненулевая строка
останавливается на `0040B218` перед JR с неподдержанным MOVZ в delay slot;
результат поиска и последующий возврат этой пробы не заявляются.
Пилот2 исполнения:0,272s, пакет26:2,040s.

Входной Node/name-pool/controller-vector явно заимствован. Поле имени `Node+10`
указывает на запись, текст которой начинается с `+9`; это подтверждено
обеими версиями Find. Node vtables PC `006DC4F4`, PS2 `004902F0` и настоящий
lookup slot проверены отдельно. Обе версии выполняют исходные stack frames;
игровые результаты поиска не подставляются.

## Привязка: накопление массива и восстановление с начала

Общий GUI slot9 — **привязка Node**, PC `004294B0`, PS2 `00165330`.
Первое разведочное окно ошибочно названо `Widget_notify`; это только метка
capture, не атрибуция Notify. Настоящий Notify находится в slot1.

Метод при наличии прежнего узла сначала удаляет подписку на него и его
непосредственных детей, затем восстанавливает controller words `+18`
из сохранённого в GUIObject массива. Число восстановлений ограничено
меньшим из двух размеров: controller vector старого узла и saved vector.
При смене указателя уменьшает старый 16-битный reference count, вызывает
его deleting destructor при нуле, увеличивает новый count и меняет `this+18`.
При неизменном указателе reference count не меняется, остальные стадии остаются.

Для нового ненулевого узла выполняется подписка на детей и сам узел;
текущие controller words добавляются в конец saved vector, затем заменяются4.
**Массив не очищается при смене или отвязке узла.** Последующая отвязка
снова читает его с начала. Проверенная последовательность PC:

| Вызов | Контроллеры A | Контроллеры B | Saved vector |
| --- | --- | --- | --- |
| До вызовов | 1,2,3 | 16,32 | пусто |
| bind A | 4,4,4 | 16,32 | 1,2,3 |
| bind B | 1,2,3 | 4,4 | 1,2,3,16,32 |
| bind null | 1,2,3 | **1,2** | 1,2,3,16,32 |

Это фактическое поведение оригинала, а не ошибка нашего ожидаемого результата.
Исправление игрового алгоритма не выполнялось. PS2 статически также добавляет
элементы в конец, а его полные detach-вызовы независимо подтвердили чтение
с начала и сохранение самого массива. Полный PS2 bind→rebind→detach здесь
не выполнялся и не выдаётся за динамически проверенную последовательность.

PC: 9 контекстов,19 полных вызовов, настоящие Node factories, оригинальные
subscribe/unsubscribe, retained reference counts1/2 и preallocated saved
vector. Проверены повторная привязка того же узла, разные размеры списков,
пустые списки, signed-looking32-bit values, короткий/длинный saved prefix,
отвязка без saved words и null→null. Guard16 КиБ плюс оба настоящих Node;
у Node разрешены только reference count и штатный указатель подписок.
Содержимое всех heap-узлов подписок этим guard не покрывается.

PS2: 10 независимых контекстов — 6 полных detach/null возвратов, 3 границы
новой подписки `00100860` и 1 граница настоящего deleting destructor
`001A8CF0`. Использованы явно пустые observer lists, пустые child lists,
literal Node records, исходный unsubscribe `00100820` и list/vector helpers.
Проверены аргументы границ, весь буфер и изменения reference count.
Успешный return новой подписки или destructor не подставлялся.

Main binding pilot4 контекста:0,403s; пакет15:2,550s. Дополнительный первоначальный
PC scout отдельно выполнил три вызова из таблицы за0,478s. Итого два основных
пакета дают57 original method executions:52 полных возврата и5 границ;
дополнительный scout — ещё3 полных PC вызова.

## Исправленные проверки и открытая подготовка

Первый main binding pilot остановился **до вызова исследуемого метода**:
в ожидаемый bytearray был передан абсолютный адрес saved storage вместо
относительного смещения. Старый source/run сохранён, вычисление смещения
исправлено; fresh pilot и пакет прошли. Это ошибка нашего стенда, не игры.

Три первоначальные попытки подготовки имени настоящим `004130F0` не дошли
до Enable: по очереди остановились на внешних `vsprintf`, `OutputDebugStringA`
и `fopen`. Два первых import-контракта заданы явно; diagnostic output
`INI REQUEST: [u32] StringMan.HashSize (default: 256)` принят в память без
вызова Windows. Полный startup/config input StringManager остаётся открытым
на `fopen`; чтение неизвестного файла успешной заглушкой не заменялось.
Главные Enable пробы используют объявленную готовую name-pool запись,
а не заявляют прохождение этого setter или инициализации StringManager.

Для следующего полного PS2 bind также остаются реальная подписка/heap и
исходный vector insert `00165A80`: его пролог содержит SQ в условном delay
slot `00165AB4`, вне [квалифицированной области CPU](native-ps2-stack-spills-2026-09-11.md).
Эта статическая граница не считается новым выполненным отказом. Рекомендация —
добавлять startup/CPU-контекст отдельными ограниченными проверками по мере
следующей нужной зависимости, сохраняя подтверждённое поведение массива.

контекстах. GUI rendering,полное окружение и неизвестные методы остаются открыты.
