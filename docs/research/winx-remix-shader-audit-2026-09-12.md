# Winx / RTX Remix: проверка передачи шейдеров

В проверенных сценах потери программ между игрой и штатным renderer Remix
не обнаружено: **15/15 уникальных байткодов совпали**, для всех15 renderer
создал SPIR-V. Обычный системный Direct3D получил тот же набор15 программ,
тоже с точным совпадением SHA256. Это проверка передачи и перевода программ,
не заявление о полной совместимости RTX или покрытии всех уровней.

Проверялась пользовательская установка `local-data/Winx Club`, существующий
`WinxClubDebug.exe`, меню, загрузка сохранения Алфеи, переход F1→LOAD LEVEL
в Gardenia01 и дневник. Все файлы игры, исходные shaders, настройки,
сохранения и официальные DLL остались прежними:20 контрольных файлов совпали.
Изменён только наш диагностический адаптер и его launcher. Реконструированные
классы игры/движка не изменялись.

## Что находится в Shaders

| Файлы | Содержимое | Результат проверки |
|---|---|---|
| BallisticPFX.vsh, BasicShader.vsh, Blur.vsh, ShadowVolumePoint.vsh | 4 текстовых ассемблерных VS1.1 | Все4 созданы при старте, получены и переведены Remix |
| Blur.psh, BlurLuminance.psh, Luminance.psh | 3 текстовых ассемблерных PS1.1 | Все3 созданы при старте, получены и переведены Remix |
| Fixed.rfx | XML-шаблон: HLSL VS1.1 и PS1.1 | Обнаружены8 дополнительных VS, соответствующих пути генерации Fixed; отдельный PS этого шаблона в проверке не наблюдался |
| Bumpmap.rfx | XML-шаблон: HLSL VS и ассемблерный PS | Использование в проверенных сценах не установлено |

Таким образом, здесь9 файлов, а не9 готовых бинарных шейдеров. Все7 отдельных
ассемблерных файлов были дополнительно собраны установленной Microsoft
`d3dx9_43.dll` вне игры. Их исполняемые инструкции совпали с дизассемблированными
программами из CreateShader. Комментарии компилятора при этом сопоставлении
исключались; при сравнении клиент↔сервер сравнивались **все байты**, включая
метаданные. Извлечённые/скомпилированные payloads остаются в `local-data/`.

Движок содержит не только ссылки: он сканирует файлы, загружает Fixed.rfx,
собирает текст под ключ материала/скелета/освещения/UV и вызывает компилятор.
Это ранее проверенные пути [генерации](native-pc-shader-generation.md) и
[компиляции](native-pc-shader-compile.md), включая нулевой BlendWeightCount
без генерируемого VS. Полный перебор всех ключей здесь не выполнялся.

Для восьми дополнительных программ зафиксированы реальные CTAB-параметры
`BlendMatrices`, `VPTransform`, `MatDiffuse`, а для соответствующих вариантов
также световые параметры и `UVTransform`. Отнесение к Fixed опирается на этот
набор и установленный путь manager; точные строки специализации не перехватывались.
Четыре первых варианта появились в Алфее, ещё четыре — в Гардинии.

## Измерение

Собственный `winx_shader_audit.h` подключается только по
`WINX_REMIX_SHADER_AUDIT`. Хуки обычного IDirect3DDevice9 сохраняют аргументы
и HRESULT Create/SetVertexShader, Create/SetPixelShader и шести видов
SetShaderConstant. GetFunction после успешного Create сравнивается с входом
и сохраняется; новая Create обновляет идентичность при повторном адресе COM.

Перед каждым игровым DrawPrimitive, DrawIndexedPrimitive, DrawPrimitiveUP,
DrawIndexedPrimitiveUP читаются текущие VS/PS. Это учитывает state-block Apply
и изменения состояния вне SetShader. Вставляемые адаптером UI-маркеры исключены.
Сводки накопительных счётчиков записываются раз в2 секунды, F8 запрашивает
дополнительную сводку. Последние неполные2 секунды перед закрытием не гарантированы.

Remix1.5.2 сам сохраняет `.dxso` и `.spv` через `DXVK_SHADER_DUMP_PATH`.
В reference commit `b81a7b566b1eeb9edb4dc2b3c9d3972e0f253ad4` это
`src/d3d9/d3d9_shader.cpp:30–93`. Передача через клиент и сервер прослеживается
в `bridge/src/client/d3d9_device.cpp:2538` и `bridge/src/server/main.cpp:1423`.
Одного успешного HRESULT клиента недостаточно: bridge может отвечать асинхронно.
Поэтому результат подтверждён независимыми серверными дампами.

Последняя сводка Remix, frame131259:

| Проверка | Результат |
|---|---:|
| Create VS / PS | 14 / 3 вызова |
| Уникальные VS / PS | 12 / 3 |
| Побайтно получены / переведены | 15 / 15 |
| Использованы в игровых draws | 8 VS, 0 PS |
| Игровые draws через сводку | 13 908 113 |
| SetVertexShader / SetPixelShader | 240 184 / 2 |
| SetVertexShaderConstantF | 6 730 221 |
| Ошибки наблюдённых Create, Set, GetFunction, GetShader, Draw, дампа | 0 |
| Отличия входного байткода от GetFunction | 0 |

Числа вызовов — объём этой сессии, не оценка производительности. Семь отдельных
шейдеров были созданы, но не участвовали в draws проверенных сцен. PS не нужен
для каждой поверхности: игра активно использует fixed-function texture stages.
Один кадр Алфеи:120 draws без VS/PS и14 с генерируемым VS. В зафиксированной
сводке Гардинии с открытым debug overlay:652 без VS/PS и44 с VS. В дневнике
последняя сводка содержит120 без VS/PS.

Контроль через системный Direct3D подтвердил тот же набор15 байткодов и
использование тех же8 VS. Порядок создания некоторых вариантов различается.
**Ограничение native-контроля:** Set/Constant-счётчики остались1/1 и0 при
наблюдаемом использовании VS. Полнота этих хуков в системной реализации
не установлена; причина не исследована. Их нули не являются доказательством
отсутствия вызовов. Для native-сравнения использованы только реальные байткоды
созданных объектов и состояние при draw. На Remix счётчики менялись во время игры.

## Что это означает для дефектов картинки

Возможность исполнить VS/PS в raster-пути не означает автоматическое понимание
его материала трассировщиком. Shader-based Vertex Capture извлекает результаты
вершинного этапа; NVIDIA описывает этот механизм и его условия в
[Game Setup](https://docs.omniverse.nvidia.com/kit/docs/rtx_remix/latest/docs/runtimeinterface/remix-runtimeinterface-gamesetup.html).
Различие между pixel shader и доступным трассировщику цветом поверхности
объяснено в [официальном FAQ](https://docs.omniverse.nvidia.com/kit/docs/rtx_remix/latest/docs/remix-faq.html).

В текущем запуске runtime сообщил о texture-transform counts>2, projected
texture transforms и привязке текстуры к mesh без UV. Первые два ограничения
видны также в `src/d3d9/d3d9_rtx_utils.cpp:111,120`. Связь конкретного предупреждения
с синей областью земли пока не доказана. На новых снимках исходная Гардиния
рисует дорогу полностью, RTX сохраняет дефект при одинаковом наборе шейдеров.
Следующая обоснованная проверка — состояния и UV конкретных проблемных draws,
их классификация и материалы, а не массовое переписывание шейдеров.

Покрытие других уровней, эффектов частиц, blur/luminance и всех специализаций
Fixed/Bumpmap остаётся открытым. Передачу значений констант на сервер побайтно
здесь не сравнивали. Ex-only CreateDeviceEx/PresentEx не покрыты. Ограничения
объёма audit описаны в [README](../../research/rtx-remix/README.md).
