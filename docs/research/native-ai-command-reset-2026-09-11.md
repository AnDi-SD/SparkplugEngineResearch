# AIAction: настоящий virtual reset объекта команд

Закрыта ранее оставленная зависимость v11 у GolemAttack, StormyAttack,
YetiAttack и IcyAttack; дополнительно проверен вход Idle. В48 успешных
исполнениях PC/PS2 реальные callbacks завершились без подстановки результата.
Полная подготовка персонажа и все методы этих классов остаются открытыми.

## Объект команд

У записи команд найдены original tables PC `703090` и PS2 `494710`.
Их reset slots: PC+4→`5992E0`, PS2+C→`3730E0`.
Это отдельный объект с доказанным размером74 на проверенных allocation paths;
его регистрационное имя не установлено. Нового выдуманного имени класса
или новой строки в каталоге исследование не добавляет.

PS2 Character setup `2A9700` при собственном word154==1 выделяет74,
вызывает `3731D0` и сохраняет возврат в character13C. Конструктор записывает
таблицу494710 и вызывает её настоящий reset. PC конструктор `599430`
записывает703090 и вызывает `5992E0`; прямой caller `4E2B57` сохраняет
указатель в своём поле18. Общность reset и layout подтверждена отдельно.
Эти два пути создания не объявляются одной и той же ветвью startup:
PC конструктор выставляет byte18=0, выбранный PS2 конструктор —1.
Это не доказательство платформенной ошибки или различия всех конструкторов.

На обеих платформах reset обнуляет:

- words04,08,0C,10,14,6C;
- bytes19..31 включительно,5C..60 включительно,64,70.

Остальные байты74-byte записи сохраняются, в том числе vtable,byte18,
координатные и промежуточные поля. Reset не является memset всей структуры.

Отдельно выполнены полные конструкторы на заполнениях00/5A/A5/FF.
Помимо reset они переносят прежние bytes4C..52 в44..4A, очищают4C..52,
устанавливают4B по обнаруженным изменениям, word54=7F7FFFFF,
words34/38/3C/40/58/68=0, bytes61/62/63=0. В проверенной подготовке
byte4B равен0 при нулевом заполнении, иначе1. Это результат настоящего
helper `599380/372F90`, не имитация его возврата.
PC использует нулевое loader BSS по7600E0; PS2 читает нулевой вектор
из file-backed476F50. Не предполагается эквивалентность всех вариантов
состояния этих глобальных данных после startup.

## Вызовы AIAction

Граф заимствован явно: PC action20→owner144→character130→command,
PS2 action24→owner154→character13C→command. Vtables записи command
проверены отдельными конструкторными исполнениями. Каждый action получает
свою ранее доказанную таблицу. Полный16KiB guard проверяет весь входной граф.

| Метод | Действия после настоящего command reset |
|---|---|
| GolemAttack, StormyAttack, YetiAttack v11 | own word3A8/3AC=0 |
| IcyAttack v11 | profile byte510=1, затем own word3A8/3AC=0 |
| Idle v10 | вызывает собственный v12 независимо от наличия command |

PC общие exits `5B79D0`, Icy `5BE2C0`; PS2 `24DC70`, `266540`,
`270CA0`, `259160`. Icy использует существующий global profile
765AD4/49FC7C; ленивое создание профиля не включено.

Idle `5D66A0/25AF10` сначала проверяет command на null, при ненулевом
вызывает reset, затем всегда делает virtual v12. В этом пакете v12
исполнен целиком при owner permission0 иFF: в последнем случае настоящий
поиск perception возвращает0 из-за явно нулевого perception owner.
Null/non-null command, два заполнения и входные аргументы0/FFFFFFFF
проверены. Положительный выбор цели и граница selector уже исследованы
в [пакете восприятия](native-ai-perception-control-2026-09-11.md), здесь
не повторялись. Null command не допускается этим контрактом для четырёх exits.

## Проверки, остановки и уточнения

Основные результаты:8 constructor calls,24 exit calls,16 Idle entry calls;
48 полных возвратов,40 реальных reset entries и8 perception entries.
PS2 выполнил104 явно записанных SQ/LQ; исходные слова не менялись,
SP/RA/S0..S4 и upper64 восстановлены. Используются прежние ограниченные
CPU profiles; универсальный EE CPU и весь игровой runtime не заявляются.

Первый пилот сделал2 попытки за0,115s: PC прошёл, PS2 дошёл до
`3730D0`, но NOP в delay slot возврата оказался за концом разрешённого
окна helper. После чтения исходного JR/NOP окно расширено на10 bytes;
первоначальный source,selection и отказ сохранены. Новый пилот7 вызовов
за0,417s прошёл, включая только PS2-версию уже успешного PC constructor.
Общий пакет40 вызовов за2,636s тоже прошёл. Итого49 попыток/48 успешных
в основном пакете; ни один успешный случай без причины не повторён.

Отдельный PC scout пытался связать command через Character с original
factories Character/Node и literal полями. Вызов кандидата4F3ED0 остановился
на598E3E при чтении0 после перехода в контейнерный helper. Нормальный
контекст и полный контракт этого защищённого пути не доказаны; нельзя
считать причиной установленную ошибку игры или завершённый command startup.
Отказ/source сохранены, этот путь отложен. Рекомендуемый следующий шаг —
проследить фактический Notify caller/аргументы и владельца контейнера,
после чего отдельно повторить штатное связывание. Для текущих независимых
reset проверок никакой успешный startup не подставлялся.

Поиск кандидатов также оставил неприменённые scouts: линейный PC участок
4F42F0 с предварительной меткой binding не доказывает этот метод; найдено
только два открытых immediate xref таблицы703090, пустой дополнительный
capture отвергнут; PC BSS не читается как file-backed range; первоначально
ошибочно выбранный адрес466F50 исправлен на476F50 до исполнения constructor.
Эти поисковые материалы не являются дополнительными успешными методами.

10 platform updates по5: четыре exits и Idle entry, PC и PS2 независимо.
Новых C++ классов, закрытых классов и отдельного балла объекту команд нет.
Ранее изученные v12/perception повторно не засчитываются.
