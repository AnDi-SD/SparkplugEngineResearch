# CharacterStateMachine: создание и раскладка 36 классов

Независимые PC/PS2 каталоги дают одинаковое семейство: базовая машина, 28
прямых потомков и 7 дальнейших потомков. После root pilot batch35 занял
17,111 с при трёх bounded workers. Original PC factory/RTTI/default clone
вернулись для 35 классов, оба teardown — для 34; всего 173 class operations.
PS2: 36 независимых factory sizes, constructor windows, vtables/getters.
Полная PS2 execution и активная логика переходов здесь не заявлены.

Полный набор классов, обе таблицы первых 21 унаследованных методов, отдельные
размеры, constructor stores/calls и ссылки на исходные probes находятся в
[`character-machine-construction-contracts-2026-09-10.json`](../../research/character-machine-construction-contracts-2026-09-10.json).
Эти 21 метода — минимальная общая часть; дополнительные методы потомков
не объявляются отсутствующими.

## База и различия раскладок

`wxCharacterStateMachine`: PC factory `004016A0`, vtable `006F6680`, getter
`004FAB90`; PS2 factory `003F75A0`, ctor `002B48D0`, vtable `0049B490`,
getter `003F9880`. PC constructor stores в `013DD6FB` и далее действительно
посещены original factory; это точный участок payload, не угаданный entry.

| Поле | PC | PS2 | Начальное значение |
|---|---|---|---|
| Указатель после wxEntity | `124` | `130` | 0 |
| Код вида машины, название enum ещё не установлено | `128` | `134` | 68 в базе |
| Следующее слово | `12C` | `138` | 0 |
| Индекс текущего состояния | `130` | `13C` | 0 |
| Предыдущий индекс | `134` | `140` | 0 |
| Флаг/слово перехода | `138` | `144` | 1 |
| Три управляющих слова | `13C/140/144` | `148/14C/150` | 0 |
| Массив 42 указателей состояний | `148..1EF` | `154..1FB` | 0 |
| Счётчик стека | `218` | `224` | 0 |
| Слово дополнительного режима | `21C` | `228` | 0 |
| Последний byte flag | `220` | `22C` | 1 |

Между массивом состояний и счётчиком лежат два массива по пять слов. Их
push/pop потребители захвачены отдельно для следующего этапа; данный блок
не приписывает конструктору обнуление этих массивов или защиту переполнения.
Код вида машины совпал на 35 сравнимых PC/PS2 объектах. Например, база и
GeneralCharacters — 68, Bird — 3, GoopMonster — 20. Это отдельное поле;
его нельзя использовать как индекс массива из 42 состояний.

| Примеры | Размер PC | Размер PS2 |
|---|---:|---:|
| База, Baco, Droid, GoopMonster, большинство простых существ | `224` | `230` |
| Book | `244` | `250` |
| Fish | `260` | `270` |
| Bird | `27C` | `290` |
| GeneralCharacters, Faragonda, Griffin, Specialists, Winx, Mikael | `284` | `2A0` |
| Students, WandringNPC | `288` | `2B0` |

Разница размеров не постоянна: в сравнимых объектах она составляет
12/16/20/24/28/40 байт. Нельзя переносить на всё семейство один offset delta.
В отличие от CharacterState, copy здесь не повсеместно пустой: база и многие
потомки используют PC `004D9700` / PS2 `00286AB0`, GeneralCharacters и ряд
потомков — PC `0052EA30` / PS2 `002B7560`; есть отдельные copy у Bird, Book,
Butterfly, Fish, GhostlySpirit, IceBat, SimpleDating. Полное копирование
изменённого runtime source ещё не проверялось.

## Остановившиеся пути

- `wxGoopMonsterStateMachine`: factory/RTTI/clone прошли. Original PC teardown
  в `013BF163` читает **machine+24**, затем вызывает `0040FB60`; при отсутствии
  этой привязки получает read4. PS2 deleting body `003041A0` независимо читает
  **machine+24** и вызывает `00100820` в `00304220`. Это другая привязка,
  чем state+18 у двух CharacterState. Дополнительно видны снятие подписок
  codes5/8 и вызов внешнего manager. Нормальная привязка остаётся открытой.
- `wxBloomStateMachine`: PC factory не вернулся при 100k, 1M и 6M instruction
  caps. Последний занял 14,393 с; arena25584 байта, память не исчерпана.
  Отдельный диагностический 1M run сохранил firstWord выделений и последние
  обычные text addresses по порядку первого посещения. Путь входит в
  protected `00524430`: видимый vtable store `006F64F8` и getter `004F5F10`
  к registration `0074E6C8` независимо определяют **wxCharacterMoveCtrl**.
  Никакой успешный результат этого конструктора не подставлен. PS2 Bloom
  factory выделяет `2F0`, ctor `002E0B20` вызывает `002E02A0`, где независимо
  видны 33 выделения состояний. У PC до возврата фабрики оценка не начислена.

Соседние bytes в protected payload могут декодироваться с неверной границы.
Для Goop и base ctor сохранены дополнительные окна с точных исполняемых
entries; произвольная линейная декодировка не заменяет эту проверку.

Первичный учёт: PC34×20 и Goop15; PS236×15. Это scouted construction,
без закрытых классов. Активные переходы, input handling, нормальная привязка
персонажа и причины protected Bloom path исследуются следующими блоками.
Глобальные выделения, оставшиеся после удаления машины, не объявляются
утечками без отдельного установления их владельцев.

Evidence: `local-data/results/native-cycle-20260910-1900/character-state-machine/`.
Сохранены pristine SHA, точные версии lifecycle runner, все остановившиеся
попытки и отдельные PS2 windows. Исправление UTF-8 чтения вспомогательного
скрипта потребовалось до извлечения identities; игровые bytes не менялись.
