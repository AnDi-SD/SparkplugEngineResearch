# Политика исследовательского корпуса

Файлы игры нужны для локальной проверки, но не должны попадать в Git. Корневая папка `local-data/` игнорируется целиком.

## Рекомендуемая структура

```text
local-data/
  pc-pristine/       # нетронутая PC-сборка
  pc-working/        # текущая папка после экспериментов
  ps2-pristine/      # извлечённый локальный PS2-корпус
  focused-samples/   # локальная выборка для быстрых scan
  results/           # JSON, логи и промежуточные сравнения
  manifests/         # локальные полные списки и SHA-256
```

Не копируйте данные внутрь submodule `Samples/`: это делает их рабочее дерево грязным и повышает риск случайной публикации.

## Что не коммитить

- оригинальные или изменённые `.smo`, `.san`, `.anm`, `.stx`, `.spt`, `.spl`;
- executable, DLL и полный каталог установки;
- PS2 image или извлечённые игровые ресурсы;
- memory dumps, captures и декомпилированные большие фрагменты;
- screenshots/текстуры, если право на публикацию не установлено.

Публиковать можно собственный код, структурные описания, агрегированную статистику, hashes и минимальные синтетические fixtures, не воспроизводящие защищённые данные.

## Manifest до эксперимента

Перед изменением корпуса сохраните SHA-256 локально:

```powershell
Get-ChildItem local-data/pc-pristine -File -Recurse |
  Get-FileHash -Algorithm SHA256 |
  Export-Csv local-data/manifests/pc-pristine-sha256.csv -NoTypeInformation
```

Для воспроизводимой публичной записи достаточно указать:

- понятный локальный ID корпуса;
- платформу и происхождение (без ссылки на нелегальное распространение);
- hash целого образа/официального установщика, если допустимо;
- число просмотренных файлов и объектов;
- commit parser;
- команду запуска;
- агрегированный результат.

Полный список локальных путей публиковать необязательно.

## Классы корпуса

| Класс | Допустимые выводы |
|---|---|
| `pristine` | свойства оригинального ресурса для конкретной сборки |
| `working/modified` | regression и исследование последствий изменения |
| `recovered` | только гипотезы восстановления, пока не сверено с pristine |
| `synthetic` | точное поведение parser для сконструированного случая |

Результат изменённого корпуса нельзя переносить на формат в целом без независимого pristine-примера.

## Работа с тестами

`SmoViewer.FormatTests` способен выполнить synthetic checks без корпуса и corpus checks с явным путём. `SMOTextureTool.FormatTests` содержит ожидания для конкретной исторической выборки, поэтому его следует запускать только на совместимом наборе.

Долгосрочная цель — вынести нейтральные synthetic fixtures в сами проекты, а локальные game-data тесты сделать manifest-driven и отчётливо помеченными как необязательные.
