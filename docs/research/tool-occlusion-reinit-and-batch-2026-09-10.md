# Occlusion: повторный Init, отдельные объекты и стоимость пакета

Original `470FE0` проверен после успешного первого вызова: затем на том же
объекте задана другая геометрия. Это новый штатный вызов после return, не
продолжение остановленного guest. Второй Init вернул AL=0; при последующем
destructor строгий heap fixture обнаружил повторный free `3100D170` из
`46F900`. Первый free этого же edge уже произошёл внутри clear повторного Init.
Три прежних CPU buffers освобождены, но старые faces/edge entries остались
в логических массивах. Получены stale position/face references и смешанное
состояние. Реальную сцену игры этот прямой вызов не воспроизводит; допустимость
re-init по контракту вызывающей стороны не установлена.

Первая diagnostic проба потеряла финальный JSON из-за исключения в cleanup;
её script/log сохранены. Отдельная fresh run2 исправила только наблюдение:
запись результата до teardown и запись free request до проверки heap fixture.
Original инструкции и строгий запрет повторного free не менялись. После
исключения больше guest calls не было. Повторный Init в общем runtime остаётся
неподдерживаемым; исправление игровой функции не предлагается как обычный fix.

Контрольный пакет использовал **три разных actual factory objects** в одном
guest. После каждого нормального return следующий объект получал actual CPU
buffers и вызывал original Init. Все три AL=1, весь tracked heap освобождён:

| Случай | Инструкции Init | Время Init |
| --- | ---: | ---: |
| Первый `race_02` quad | 3 971 161 | 10,034564 с |
| Тот же quad на новом объекте | 15 304 | 0,049026 с |
| Положительный synthetic triangle, UInt32 indices | 11 638 | 0,045817 с |

Для одинакового quad совпали plane bits, порядок indices/faces/edges/outgoing,
bounds/sphere и известные flags. Из сравнения исключены только разные адреса
выделений и неинициализированный camera-side word. Разница времени около205x
относится к **этой паре вызовов**; это не ускорение всего исследования.
Гостевой процесс естественно сохранил результат защищённой подготовки и
instruction cache. Код не подставлялся, VM не пропускалась внешним patch.
Heap bump usage всего пакета57 808/65 536 байт, процесс30s, каждый вызов
по существующему character4M/16s. Host RSS отдельно не измерялась.

У последнего fresh объекта индексы `10000/10001/10002` превратились в UInt16
`0/1/2`: original Init действительно отбрасывает старшие16 бит. Bounds
`(0,0,0)..(4,6,3)` включают начало координат, хотя все три вершины положительны;
sphere `(2.5,4,3,2.5)`. Это исправляет возможное предположение о min/max только
по вершинам и отделяет допустимый fresh input от проблемного re-init.

У этого single-triangle случая обнаружена дополнительная граница: после
добавления reverse face первые три edge.own не входят в текущий faces vector
(в capture `own_face=null`, что означает не найденный адрес, а не доказанный
NULL pointer). Original driver резервирует faces по triangleCount=1; reverse
append меняет storage, прежние own pointers не перепривязываются.
Общий host shape entry поэтому отдельно отказывается от одного треугольника,
а standalone producer остаётся допустимым. Нельзя скрывать этот случай
увеличенным reserve и приписывать безопасный новый граф original игре.

Рекомендация для будущего runtime: новый объект для нового Init; re-init и
single-triangle full shape оставить отдельными неподдерживаемыми операциями
до определения пользовательского контракта. Полные Init/serializer пока не
перенесены; остаётся также общий geometry optimizer и CRT duplicate-tie порядок.
