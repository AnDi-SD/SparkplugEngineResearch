# wxEntityManager: добавление и удаление указателей

Продолжение [таблиц и classifier](native-entity-manager-tables-2026-09-10.md).
Проверены **18 пар insertion prefixes за2,603 с** и **13 пар полных array
removal helper за2,344 с**. PC и PS2 сохраняют свои ёмкости и раскладки.
Это original-code execution; игровой алгоритм не заменён стандартным контейнером.

## Добавление после classifier

Метод PC **005748D0**, PS2 **002892C0**. Предыдущее досье ошибочно указало
PS2 entry002892B0: этот адрес является JR RA предыдущего array-removal helper.
Настоящий entry002892C0 подтверждается собственным прологом; текущие probes
используют точные entry выбранных ниже участков и не зависят от старой подписи.

Входы — явно подготовленные manager/указатель entity, результат ранее
проверенного classifier и первый свободный type slot. PC начинает в00574933,
PS2 —002893CC. Button cases начинают после диагностического вывода:
00574982 /0028952C; этому выводу не подставляется успешный return.
Prefixes останавливаются перед настоящим list append либо перед epilogue.
Это не полный callback/diagnostic/list lifecycle метода.

| Полученная группа | PC | PS2 |
|---|---:|---:|
| Обычная0..39 | 130 указателей на группу | 80 |
| 41 / wxHUDPart | 100 | 100 |
| 42 / wxButton | 130 | 105 |
| Дополнительный список wxCharacterMoveCtrl | 130 | 80 |

Для обычной найденной группы:

- Если count уже достиг лимита, запись пропускается.
- Поиск дубликата проверяет **всю ёмкость**, включая позиции после count.
  Поэтому stale указатель в последней ячейке препятствует повторному добавлению
  даже при count=0. Это подтверждённый локальный контракт, не оценка допустимых
  игровых состояний.
- Если дубликата нет, указатель записывается по текущему count, затем count++.

Для нового типа classifier возвращаетFFFFFFFF. При наличии свободного
индекса1..39 метод пишет первый указатель группы, её class hash и count=1.
При отсутствии свободного индекса записи нет. Slot0 сохраняет особый статус.
HUD/Button дописываются в свои массивы до отдельных лимитов.

После успешной основной записи class hash680838E4 (`wxCharacterMoveCtrl`)
добавляется также в свой дополнительный список, если там есть место. Заполнение
этого списка не отменяет уже сделанную основную запись. Затем выполнение
переходит к append manager list+14; сам append здесь не подменяется и не
исполняется через неизвестную fixture.

Проверены пустая группа, последняя свободная ячейка, достигнутый/превышенный
лимит, дубликаты в0/4/последней позиции, stale duplicate при нулевом count,
новые slots1/39, отсутствие slots, HUD и Button capacity boundaries, полный
дополнительный MoveCtrl список. Guard всего manager разрешает только точные
записи указателей/ключей/счётчиков. Результаты решения о переходе к list append
совпали в18 парах; абсолютные индексы near-capacity различаются по платформам.

Оригинальные общие epilogues возвращают true, включая ветви без записи
из-за лимита или дубликата. Нельзя трактовать этот return как отдельное
подтверждение фактического добавления.

## Общий helper удаления из массива

PC **00573CE0**, PS2 **00289180..002892B4** получают искомый указатель,
адрес count, ёмкость и начало массива. Обе полные функции исполнены до
оригинального return; нет SQ/LQ frames, аппаратных вызовов или fake callbacks.

Цикл ищет совпадения, пока индекс меньше текущего count. При совпадении:

1. Сдвигает слова от следующего элемента **до конца ёмкости**, а не только
   живую часть до count.
2. Обнуляет последнюю ячейку всей ёмкости и уменьшает count.
3. Переходит к следующему индексу, не проверяя заново сдвинувшийся элемент.

Поэтому из `[A,A,B]` с count3 удаление A оставляет `[A,B]` с count2;
из `[A,B,A,C]` удаляет оба A и оставляет `[B,C]`. Три соседних A оставляют
один A. Возвращается признак того, что встретилось хотя бы одно удаление.

13 случаев включают пустой массив, отсутствие совпадения, первый/средний/
последний элемент, соседние и разделённые дубликаты, ёмкости1/9/10/80/105/130.
Особенно проверены границы PS2 unrolled loop: сдвиг8 и9 слов. В неактивной
части массива лежат разные ненулевые маркеры, поэтому подтверждён сдвиг
именно до конца ёмкости. Guards перед/после массива и count сохранены.
Вызывающий код с count>capacity не исследован и не нормализуется стендом.

## Границы результата

Полное удаление entity из менеджера PC00574630 /PS200288C70 дополнительно
сбрасывает flags записи, вызывает notification, чистит другие массивы и
списки. Его mutable callbacks и итоговый bool не закрываются этим helper.
Данные entity+24, normal startup/binding и аппаратная часть PS2 всё ещё открыты.

Исходники, exact versions и reports `insertion-run1.json`,
`removal-helper-run1.json` находятся в
`local-data/results/native-cycle-20260910-1900/entity-manager/`.
Score wxEntityManager повышен **PC30→45 /PS225→40**. Полное закрытие класса
не заявлено; приложения и восстановленная игровая реализация не изменялись.
