# Видимость Алфеи и сохранение исходного unlit-цвета в RTX

12 сентября 2026, `unlit-preservation-v2`. Собственная адаптация PC D3D9 →
штатный Remix, без изменений EXE, NVIDIA runtime и восстановленной логики игры.

Алфея стала видимой: стены, пол и персонажи получают свет. Основная причина
улучшения — передача видимого цвета исходных **FFP LIGHTING=0** поверхностей
в emissive-канал. Это промежуточный гибридный перенос, а не завершённая
реконструкция физического освещения от игровых ламп.

## Причина и границы решения

В [предыдущем блоке](winx-remix-material-channels-2026-09-12.md) все 892 успешно
переданных draw выбранного кадра Алфеи имели LIGHTING=0. Оригинальный FFP
показывает `texture × interpolated COLOR0` независимо от источников света.
Прослойка использовала этот сигнал только как отражающий цвет. При слабом
доступном физическом свете он практически исчезал из итогового кадра.

Новый общий режим сохраняет этот сигнал в обоих каналах:

- albedo: прежний `texture × COLOR0`, чтобы поверхность реагировала на RTX;
- emission: тот же исходный видимый сигнал с единичной intensity;
- alpha: исходная независимая формула и порог alpha-test;
- lit FFP: прежнее ограниченное разложение diffuse / ambient / emissive.

Неиспользуемые D3DMATERIAL9 и D3DRS_AMBIENT не добавляются к unlit-цвету.
Наличие unlit-цвета не доказывает запечённое освещение: он может содержать
художественный цвет, готовое освещение либо их смесь. Их разделение не выполнено.
Сохранение видимого сигнала через emission — выбор нового renderer; в оригинале
эти поверхности не становились физическими источниками света для соседних мешей.
В Remix они участвуют в косвенном свете, поэтому возможно усиление цветовых
рефлексов и яркости. Единичная emission не гарантирует равенство финальных кадров.

Оригинальный системный D3D9 кадр тоже содержит красные стены и жёлтый коридор.
Новый RTX кадр заметно светлее оригинала. Точная яркость, пересвет окон и
цветовые рефлексы остаются задачей общего переноса материалов и освещения.
Выбор не использует названия уровней, мешей, текстур или списки известных хешей.

Поддерживаемые declaration, texture stages и состояния остаются ограниченными
контрактом предыдущего блока. Неподдерживаемые draw продолжают исходный путь;
Fixed.rfx 4/5, полноценное разделение vertex lighting и skinning не закрыты.
Новых ошибок реконструкции игровых классов в этом блоке не установлено:
меняются платформенная прослойка и исследовательская диагностика.

## Что установлено об источниках

Контрольная сфера штатного Remix у камеры осветила комнату при неизменных
native view/projection/viewport. Диагностический источник затем убран.
Это проверка реакции поверхностей, не включённый в итоговый профиль фонарь.

В исходных данных ближайшей точки `[-912.975891, 232.283508, 195.430054]`
D3DLIGHT9.Position совпадает с world position узла. Range = 446.924805,
Falloff = 1, attenuation = `[1,0,0]`. Во всех 19 снятых point payload
attenuation равна `[1,0,0]`; физический inverse-square перенос и видимость
через стены не эквивалентны исходному освещению без таких теней.
Игра также использует per-object ambient и unlit-поверхности.

Добавлен ограниченный снимок наблюдавшейся FFP-геометрии: 1110 draw,
294123 треугольника выбранного кадра. CPU BVH-запросы находят две точки,
окружённые одним мешем во всех шести осевых направлениях на расстоянии
примерно 3–18 единиц. Несколько настенных точек имеют ближайшую геометрию
в направлении +Z примерно через 30 единиц.

Это **кандидаты на перекрытие света**, а не доказанная RTX-непрозрачность:
CPU запрос двусторонний, не вычисляет alpha и не включает все shader-пути.
Автоматическое перемещение ламп по этим данным не внедрено. Источник около
начала уровня не доказан как находящийся внутри закрытого объёма.
Отключение игровых источников после включения unlit-preservation мало меняет
выбранный кадр: главную видимость пока обеспечивает сохранённый сигнал материалов.

## Реализация и проверки

`material_channels::Read` получает явную политику сохранения unlit-цвета.
Общий множитель COLOR0 остаётся в вершинах; текстура и вся mip-цепь передаются
раздельно в albedo и emission. Сохраняются ограничения ресурсов и fallback.

При смене политики старые меши освобождаются перед материалами. При отказе API
владение сохраняется, ресурс остаётся кандидатом на повторное удаление.
Первый игровой A/B без этого изменения заполнил кэш до 512 мешей: его кадры
сохраняются как диагностические, но не используются для чистого количественного
сравнения режимов. Финальная версия повторяет проверку с освобождением кэша.

| Проверка | Результат и граница доказательства |

| System D3D9 и штатный RTX Remix | По 18 случаев, 67 проверок PASS. Новый emissive соответствует исходному unlit-сигналу, сохраняет alpha rejection/acceptance. |

Средние RGB фиксированной области `(150,100)-(950,575)` в окончательном A/B:
чистый before `[0.408,0.334,0.198]`, after `[209.931,159.581,124.566]`,
after-return `[210.885,160.362,125.040]`. Это описание видимости, не измерение
физической освещённости. В before-return после 12 секунд ещё остаётся свет
`[114.347,54.537,27.934]`, хотя старые ресурсы прослойки освобождены и fallback
не увеличился. Причина оставшейся истории внутри runtime не локализована.
Количественное сравнение off/on использует исходный холодный before;
мгновенное визуальное выключение накопленного света не заявляется.

В семи закрытых запусках проверено сохранение user.conf, winx.ini, сохранений

`play-rtx-20260912-222005-874`, PID 22092; её временный bridge config будет
возвращён уже запущенным помощником после закрытия игры.

В раннем `source-light-records.json` поле `rangeAttenuation` ошибочно названо:
оно начинается с D3DLIGHT9+80 и содержит Falloff/Att0/Att1/Att2, без Range.
Поле `worldPrefix` тоже не является корректно размеченной world orientation.
Исходный файл сохраняется; значения выше получены из `rawHex`, Range по +76.
Origin 0 раннего CPU-снимка скопирован из идентичного стартового ракурса другого
запуска; он не выдаётся за отдельное live-измерение камеры того кадра.

Установленная DLL SHA256:
`171F18A83DB839F80D0954E01CBE23C22B04FC014EFEAF852DE7273EDC800D76`.
Предыдущая D615… сохранена как
`local-data/rtx-remix/before-light-visibility-2026-09-12.dll`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File research/rtx-remix/Run-WinxRemix.ps1 -Mode RTX -DebugMenu -SceneLights -SceneGeometry -MaterialChannels -LiveConfig -StartLevel 27 -Windowed
```

Сохранение unlit-цвета включено по умолчанию внутри `-MaterialChannels`.
`winx.preserveUnlitColor = False` в run/live.conf возвращает отражающий вариант,
`True` возвращает сохранение сигнала. Этот переключатель не меняет игровой EXE.
Для диагностического снимка добавить `-MaterialGeometryProbe`, затем использовать
`Analyze-LightGeometry.ps1 -Geometry …/material-geometry.bin -Origins …/origins.txt -Name fresh-name`.
Origins — строки `id x y z`, до 64; снимок — один кадр до 64 МиБ/4096 draw.
Неполный файл не используется как доказательство полного кадра.
