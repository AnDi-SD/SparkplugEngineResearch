# Yeti: полное начало атаки и рекурсивное отключение Node

24 исполнения PC/PS2 прошли с первого раза:16 прямых Node Enable и8
полных Yeti v10. Предыдущая остановка до поля3E0/3E4 снята для явно
заданного существующего базового Node. Загрузка ресурса и обычный игровой
startup этим опытом не подменяются и остаются открыты.

## Связь поля с Node

Исходный Yeti v9 передаёт поле3E0 в PC Node AttachChild421A60 на5B2768,
затем вызывает его virtual+34 на5B2777. PS2 counterpart передаёт поле3E4
в1A8A60 на270F8C и вызывает virtual+3C на270FA4. Эти callers и ранее
подтверждённый Node contract обосновывают проверку с существующим базовым
Node. Оригинальные таблицы6DC4F4/4902F0 ведут в Enable421640/1A5B00.
Присваивание результата загрузчика и resource lifecycle динамически
в этом пакете не исполнялись;тип конкретного производного ресурса не заявлен.

## Полный Yeti v10

Entries5AFEA0/270CE0. Сначала исполняются прежние command/target/zero writes
и настоящий cached registry lookup из
[предыдущего пакета](native-ai-registry-entry-2026-09-11.md).
При найденной цели оригинальный код вызывает Node Enable(0,1) на поле
3E0/3E4. Проверены пустое дерево и дерево изчетырёх Node с двумя детьми
иодним внуком. Mask200 снимается на всех достижимых узлах,прочие биты
и остальная память сохраняются. Все рекурсивные методы исполняются.

После возврата Enable появляются дополнительные PC own writes:
word3E4=0,byte3B8=1,byte3D4=0,word3C4=0,byte478=1;
PS2 смещения больше на4. Затем три настоящих base wxEntity Notify:

| Порядок | Code | Строка payloadA | Bool low byte payloadB |
|---|---|---|---|
| 1 | 2725 | target_face,PC708F48/PS245EF18 | 0 |
| 2 | 2725 | teeth_left,PC7093C0/PS245EEF8 | 1 |
| 3 | 2725 | teeth_right,PC7093B4/PS245EF08 | 1 |

Остальные envelope words:code,0,0,0,sender-action,0,payloadA,payloadB.
Как и прежде,исходный код задаёт только младший bool byte;upper24 сохраняют
явный pre-entry stack fill5A/A5. Выполнен реальный пустой Notify базового
wxEntity5B7A00/100810. Реакция производного игрового владельца не заявляется.
Восемь Yeti вызовов завершились оригинальным возвратом;null target пути
предыдущего пакета не повторялись.

## Node Enable: точные границы аргументов

Прямые исполнения проверили состояния0,1,255,256 и рекурсивный параметр
0,1,255,256. Канонические0/1 дают одинаковую семантику mask200 и обхода.
PC проверяет младшие8 бит обоих аргументов,PS2 — ненулевой входной регистр.
Поэтому raw ABI input256 отключает Node на PC,включает на PS2;для второго
аргумента256 PC пропускает детей,PS2 обходит. Это наблюдение неканонических
машинных входов,не утверждение о допустимом C++ bool или расхождении
нормального игрового caller. Проверки требуют явно сохранять исходный ABI.

Обход тестового дерева:root,first child,grandchild,second child. Потомки
получают тот же enabled argument и canonical recursive1. Граф имеет
оригинальные base Node tables и явные child lists:PC pointer sentinel,
PS2 inline sentinel18 с forward link4 и реальным accessor1163F0.
Конструктор и normal scene registration не симулируются успешными заглушками.

## Проверка и учёт

Пилот4 /0,313290s,пакет20 /1,403020s;24 whole returns,63 actual Node Enable,
24 Notify,8 registry calls,214 PS2 SQ/LQ. Guard24KiB и неизменность original
PS2 code проверены. На полных PS2 возвратах восстановлены SP,RA,S0..S4
и все upper64 GPR. Новых CPU изменений и повторной общей регрессии нет.

Первый временный sealer сохранил путь контракта предыдущего пакета.
Защита fresh output остановила его до перезаписи контракта или изменения
учёта;0 guest executions. Ошибка и исходник сохранены,путь исправлен
в отдельном sealer,готовые результаты и snapshot hashes использованы повторно.

Два Yeti assessments повышаются на5:PC35→40,PS230→35. Старый Node контракт
не получает повторного балла. Нормальная загрузка ресурса,derived receiver
behavior и полный AI lifecycle остаются открыты. Новых C++ и полностью
закрытых классов нет;Knut continuation в этом пакете только разведан.
