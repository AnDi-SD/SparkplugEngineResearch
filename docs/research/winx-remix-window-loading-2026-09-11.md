# Winx Remix: загрузочные экраны и смена разрешения

Продолжение первого прототипа по двум замечаниям пользователя. Собственный
платформенный адаптер; EXE, восстановленные классы и upstream Remix не меняются.
Runtime 1.5.2, reference `b81a7b566b1eeb9edb4dc2b3c9d3972e0f253ad4`.

## Установленные причины

1. При загрузке Алфеи игра вызывает Reset с 1280×960, Windowed=TRUE,
   hDeviceWindow=NULL. Исходное окно имеет client 1024×807. Последний NULL
   обозначает окно фокуса устройства, а не отсутствие окна.
2. В renderer `d3d9_swapchain.cpp:327` creation width/height сохраняются как
   `m_originalWidth/Height`. `NormalizePresentParameters`, строки1110–1111,
   вычисляет масштаб относительно этих первоначальных размеров и после Reset.
   `d3d9_device.cpp:1786` умножает переданный viewport на этот масштаб.
   При 1024×768 →1280×960 получается лишний коэффициент1,25, то есть
   viewport1600×1200. Это объясняет обрезку даже при client1280×960.
3. Старый ScopedUi отключал Z-write у каждой настоящей UI-геометрии.
   Экран загрузки содержит ортографические textured quads и отдельный фон.
   Сохранение исходной записи глубины вернуло изображение учебного класса.

## Проверочные запуски

Все папки ниже находятся в `local-data/rtx-remix/runs/`.

* `2026-09-11-window-loading-trace`, DLL1D2E892C…: исходная обрезка и подробная
  трасса. Вызов Reset на frame17951; первые загрузочные quads — frame17955.
  Последний пользовательский запуск отдельно сохранён в `window-loading-before`.
* `2026-09-11-window-ui-boundary`: проверено меню; случайный выбор Quit
  завершил запуск до загрузки. Не считается проверкой Алфеи.
* `2026-09-11-window-ui-boundary-alfea`, DLLF7431773…: изображение загрузки
  восстановлено (`loading-010.png`). Реальный client после Reset1280×960,
  но `diary.png` всё ещё обрезан. Изменение размера окна не решает масштаб.
* `2026-09-11-reset-viewport-alfea`, DLL77431658…: bridge после Reset
  действительно возвращал старый cached viewport1024×768, MinZ=0, MaxZ=0,02.
  Принудительный SetViewport1280×960,0..1 не исправил обрезку.
  Эта экспериментальная правка удалена, причина увеличения описана выше.
* `2026-09-11-viewport-scale-alfea`, DLL90EB092E…: проверка компенсации
  масштаба выполняется; результат пока не объявлен подтверждённым.

Эталон загрузки и полного дневника — изображения `load-alfea.png`, `world.png`
из `2026-09-11-system-baseline` с системным D3D9.

## Изменения адаптера

* Вместо отключения Z-write настоящих UI-draws перед первым ортографическим
  проходом основного target посылается треугольник нулевой площади. Он обозначает
  UI boundary для Remix. Z-write, declaration и stream0 восстанавливаются до
  настоящего draw. Все реальные элементы сохраняют собственную глубину.
* `WINX_REMIX_FIT_WINDOW`: client согласуется с backbuffer с сохранением
  пропорций и ограничением рабочей областью текущего монитора. В Present
  явно передаются полная область источника и client destination.
* `WINX_REMIX_VIEWPORT_SCALE`: перед draw viewport делится на известный
  коэффициент Remix; сразу после draw client-visible состояние восстанавливается.
  Размеры учитываются относительно CreateDevice и последнего успешного Reset.
  Применяется и к offscreen targets, поскольку upstream увеличивает их тоже.
* Диагностика пишет presentation parameters и первые120 кадров после Reset/F8.
  Обычный запуск остаётся без draw trace. Window helper умеет снимать короткую
  последовательность загрузочных кадров только выбранного игрового окна.

Контракт viewport/target дополнительно сверялся с
[документацией Microsoft SetRenderTarget](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-setrendertarget).
Первоначальная проблема cached viewport отделена от найденного масштабирования;
исследовательская гипотеза не объявляется исправлением реконструкции.
