# Триггеры: направление взаимодействия и ограничение PS2 SQRT

11 сентября 2026. Изучены GenericTrigger v23/v24 и вызываемый ими helper.
PC выполняет оба метода и helper целиком; PS2 подтверждает аргументы caller
и начальную обработку координат. Полное PS2 вычисление направления отложено
из-за обнаруженной несовместимости исследовательского CPU-стенда.

## Подтверждённое поведение PC

`597220(firstNode,secondNode,threshold,ignoreY,negate)` получает позиции
PC74/78/7C и ось второго Node из A4/A8/AC. При ненулевом младшем байте ignoreY
обнуляет Y обеих локальных позиций. Вычисляет `firstPosition-secondPosition`,
нормализует этот вектор настоящим `41D2D0`, затем сравнивает его dot с осью
второго Node: результат true только если dot строго больше threshold.
Ненулевой negate предварительно меняет знак dot. Ось второго Node дополнительно
не нормализуется; входные Node не изменяются.

Оригинальная нормализация обнуляет локальный вектор при длине не больше
binary32 `3A83126F` (приблизительно0,001). При большей длине делит его на длину.
Проверены совпавшие точки, вертикальные/горизонтальные направления, противоположные
оси, малые длины ниже/на/выше границы, threshold0,25 и соседние float по обе стороны
точного равенства dot. Неединичная ось в граничных пробах — диагностический вход,
не утверждение о нормальном состоянии transform игры.

| GenericTrigger метод | Первый Node | Второй Node, чья ось используется |
|---|---|---|
| v23 `5906A0 / 3AC6B0` | player из profile2B4→record24 | trigger изthis18 |
| v24 `5906E0 / 3AC650` | trigger изthis18 | player из profile2B4→record24 |

Оба caller передают threshold0,25, ignoreY1, negate0. Иными словами, методы
проверяют две стороны направленного взаимодействия. Оригинальные имена оси
и этих методов пока не установлены.

## PS2 и ошибка исследовательского CPU

PS2 helper `292190` получает позиции70/74/78 и ось второго Node A8/AC/B0.
Начальный участок до2921D8 подтвердил выбор оси, перестановку узлов, игнорирование
вертикали и разность координат. В нём нет подстановки normal/dot результата.
Caller-компоненты начинаются после SQ-пролога и останавливаются на настоящем
входе292190 с проверенными A0/A1/A2/A3/F12.

В новом helper обнаружено исходное слово `46010044` у2921E4. Для EE SQRT
операндом служит FT; используемая generic MIPS модель Unicorn берёт FS.
Отдельная диагностическая проба FS=9,FT=25 дала результат3 вместо sqrt(25)=5
и в r4000,и в integer-squares. Она сохранена и не засчитана как игровое evidence.
Выбор FT сверён по [официальному интерпретатору PCSX2](https://github.com/PCSX2/pcsx2/blob/master/pcsx2/FPU.cpp).
Особенности округления/исключительных чисел EE описаны в
[Sony EE Core User's Manual, §8.5–8.8](https://docs.alexrp.com/mips/ee.pdf).

Исправлена наша обвязка:SQRT.S теперь явно отвергается до изменения FPR,
включая integer-squares. Старый wrapper сохранён. Реализация корня и dot
для PS2 не придумана, игровая инструкция не патчится. Прямое использование
обычного MIPS SQRT больше не может незаметно дать здесь неверный результат.
Остальные R5900 accumulator/delay ограничения сохранены.

Проверка исправления:2 новых tests (три профиля/сохранение FPR и допустимая
остановка перед SQRT),9 прежних scalar и10 integer-square tests прошли.
Это21 test method; повтор для оформления лога не выполнялся.

Адресный статический аудит двух циклов просмотрел882 result-файла,1805 записей
исполнения/515 разных entry-stop-profile. В прямом CFG до записанных остановок
и ранее запрещённых ISA границ не найдено SQRT-кандидатов. У75 границ остаются
54 разных косвенных перехода/вызова; их цели этим анализом не разрешены.
Поэтому результат не объявляется полной проверкой истории. Подтверждённого
старого ошибочного class result пока нет, но остаток аудита явно открыт.
Это была целевая проверка после ошибки CPU, не полный scan ассетов.

## Пакет и учёт

86 разных исполнений прошли с первого раза:PC33 полных helper и10 полных
caller;PS2 33 префикса helper и10 остановок caller. Пилот6 за0,478s,
общий пакет80 за6,085s внутри процессов. В каждом случае проверены все28KiB
заимствованных receiver/profile/player/Node records, они не меняются.
Нормальная конструкция профиля/сцены, cache misses и произвольная точность float
не заявляются. GenericTrigger PC50→55,PS245→50; helper не получает отдельного
class score. Полностью закрытых классов и новых C++ нет.

Дальнейший PS2 путь:сначала отдельно подтвердить корректную модель SQRT и
accumulator dot с разными source registers,затем соединять original helper.
До этого использовать только подтверждённые границы; PC работу продолжать.
