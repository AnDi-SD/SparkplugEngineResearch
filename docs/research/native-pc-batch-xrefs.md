# PC: пакетный поиск кандидатов ссылок на CPU и RTX 3070

CP100, 7 сентября 2026. Ускорение исследовательского инструмента, без изменения
оценок классов и без доказательства работы игрового renderer.

[pc_batch_xrefs.py](../../research/pc_batch_xrefs.py) ищет unaligned abs32 и
байтовые последовательности `E8 rel32` в секциях pristine PC EXE. Эти совпадения
требуют проверки границ инструкций и контекста; сами по себе они не являются
call graph. На GPU исполняется собственный поисковый kernel, оригинальный x86-код
не исполняется. Windows OpenCL доступен через установленный системный runtime;
дополнительные пакеты и драйверы не устанавливались. ABI сверен с
[официальным заголовком Khronos](https://github.com/KhronosGroup/OpenCL-Headers/blob/main/CL/cl.h).

## Измерение

Выборка: 434 прямых native entry points из вызовов существующих `probe_pc_*.py`.
Вход — 23 110 717 байт секций проверенного PC EXE. Два независимых CPU алгоритма
и GPU дали одинаковые **12 546 кандидатов**; максимум на одну цель — 4099.

| Вариант | Время |
| --- | ---: |
| CPU, отдельный `bytes.find` на каждую цель | 8,510 с |
| CPU, четыре прохода по 32-битным окнам без копирования | 3,058 с |
| GPU, создание контекста, компиляция и загрузка входа | 1,843 с |
| Первый поиск GPU | 0,0358 с |
| Повторный поиск при сохранённом контексте | 0,0157 с |

Для этой выборки GPU вместе с подготовкой быстрее лучшего CPU варианта примерно
в 1,63 раза. 16 мс — время запроса к уже подготовленному GPU, а не время всего
исследования. Пик working set процесса — 207 638 528 байт (198 МиБ), private bytes
267 505 664; собственные GPU buffers — около 26 МиБ. Показатели процесса не
являются измерением всех внутренних ресурсов драйвера. Подробный замер сохранён
локально: `local-data/results/cycle-20260908-0700/gpu-benchmark.json`.

## Использование и границы

```text
python research/pc_batch_xrefs.py --backend compare 466490 4664f0 6dc5fc 6e8004
python research/pc_batch_xrefs.py --backend compare --targets-file TARGETS.json --output RESULT.json
python -u research/pc_batch_xrefs.py --serve
```

По умолчанию используется CPU. Для небольших наборов он избегает стоимости
подготовки GPU. `--serve` принимает строки JSON вида `{"targets":[4613264]}`;
`{"quit":true}` завершает процесс. Рабочий процесс хранит неизменный образ секций
на GPU, завершает работу после 15 минут без запросов и освобождает ресурсы.
Отчёты пишутся в игнорируемый `local-data/research-cache/xrefs/`, с ключом из
хэшей pristine EXE, файла алгоритма на старте процесса и списка целей. Сохранение
отчёта пока не означает автоматического повторного использования результата.

Пределы: образ 64 МиБ, 8192 цели, 32 768 кандидатов на цель, 500 000 суммарно;
выходной GPU buffer ограничен 4 000 000 байт. Обычный CLI имеет внешний timeout
30 секунд. Резидентный процесс имеет idle timeout, но отдельного внешнего
watchdog на каждый OpenCL вызов пока нет; зависший драйвер потребует завершения
принадлежащего исследованию helper. При недостатке RAM контекст закрывается.

Проверки: 5 CPU unit tests и 6 фактических GPU fixtures, включая отрицательный
rel32, перекрывающиеся слова, короткий хвост и оба предела количества результатов.
Переполнение явно останавливает запрос, а не обрезает результат. Исходные данные,
выборка адресов и полный список найденных ссылок остаются локальными по
[corpus policy](corpus-policy.md).
