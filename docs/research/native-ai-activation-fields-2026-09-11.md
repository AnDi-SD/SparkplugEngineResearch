# Активация IceWormHoles и начальные связи Kiko

Блок 43. 34 оригинальных опыта PC17/PS217, все с первого раза:
пилот6 /0,485622s, пакет28 /2,107546s. 22 завершённых метода IceWormHoles,
4 остановки KikoHole перед подпиской, 8 остановок KikoMoving перед
построением ориентации. В каждом опыте сверены все 24 KiB связанных
объектов. Продолжение за указанными остановками не исполнялось.

## IceWormHoles: весь слот9

PC `5226C0`, PS2 `254B40`. Action получает Node через
owner→entity→Node, сохраняет его по `+3C0` / PS2 `+3C4`, затем в
его parent `Node+2C` рекурсивно ищет точные имена `in` и `out`.
Настоящий NodeFind возвращает найденные узлы или null; они сохраняются
по action `+3BC/+3B8`, PS2 `+3C0/+3BC` соответственно.

Проверены все четыре сочетания наличия узлов, два заполнения памяти,
похожие имена `inlet`/`outside` и owner type 0, 1, 2, FFFFFFFF.
Byte action `+3B4` / PS2 `+3B8` становится 1 только при owner type==1
(owner `+1B0` / PS2 `+1C0`). Word action `+3A8` / PS2 `+3AC`
получает 5; метод возвращает true даже при отсутствии искомых узлов.

Игра исполняет свои NodeFind и strcmp. PS2 Node-имена с начала опыта
имеют явное невыровненное размещение; наблюдатель подтверждает byte-loop
strcmp. Выровненная MMI-ветвь не считается исследованной. Искусственных
результатов поиска или возвратов игровых callbacks нет.

## KikoHole: связи перед подпиской

PC `5221C0`, PS2 `2E9EF0`: собственный Node сохраняется по `+3A8`,
Node из `profile+2B4→entity+24` — по `+3AC`; PS2 смещения больше на 4.
Следующий вызов `410050` / `100860` получает subject персонажа
(`character+124` / PS2 `+130`) и action как слушателя.

Проверка останавливается на входе этого настоящего helper. Статически
видно создание/пополнение списка, но выделение узла и продолжение
подписки в блоке не проверены. Следующие записи состояния 1/0 после
подписки не включены в выполненную часть и остаются кандидатами.

## KikoMoving: позиция перед ориентацией

PC `5AD280`, PS2 `25B930` сохраняет собственный Node, Node игрока,
текущую структуру команд и копию мировой позиции игрока. Собственному
Node задаёт local `(-1954,225,1241)`, dirty bit1 и ту же позицию в
movement `+138` / PS2 `+144`.

При ненулевой ссылке movement `+1E4` / PS2 `+1F0` мировая позиция
связанного Node прибавляется и сохраняется в movement `+150` / PS2 `+15C`.
При null эти дополнительные поля остаются прежними. Проверены оба пути
с двумя заполнениями. PC исполняет настоящий `4E41C0`, PS2 — исходные
встроенные операции и `109AF0`.

Остановка перед `420470` / `1090E0` подтверждает аргументы направлений
`(-1,0,0)` и `(0,1,0)`. Ориентация и последующие записи конечной цели
не объявляются выполненными. Для продолжения нужно отдельно квалифицировать
этот helper и его PS2 арифметику; общая проблема EE SQRT остаётся открытой.

## Учёт и ограничения

По +5 для трёх классов на каждой платформе. Семь остальных v9 из
разведочного capture не получили балла: их resource/scene/animation
зависимости ещё не проверены. C++ не добавлялся, полные классы не закрыты.
Существующие Node, profile и связи заданы явно; нормальная сцена и полный
жизненный цикл AI этим не доказываются. На завершённых PS2 путях проверены
SP/RA, S0/S1 и верхние 64 бита GPR; на остановках frame ещё активен.
