# Общий перенос цветовых операций и UV в Remix

12 сентября 2026. Продолжение [контракта материалов](winx-remix-material-contract-2026-09-12.md).
Собственный платформенный адаптер; оригинальная игровая логика, shaders, EXE
и штатные NVIDIA DLL не изменены. Гардиния 2 не запускалась.

## Что реализовано

Выделен общий `surface_material::Contract`, который передаёт RGB и alpha
независимо. Распознанные наложения AutoSurfaceRoles используют его вместо
жёстко заданного `texture × vertex RGBA`:

- `SELECTARG1`, `SELECTARG2`, `MODULATE` отдельно для RGB и alpha;
- аргументы texture, diffuse/current первого stage, texture factor;
- настоящий ARGB texture factor, включая alpha, без второго умножения;
- выбранная UV-пара FLOAT2 с индексом 0–7;
- выключенное преобразование либо аффинное `D3DTTFF_COUNT2`, включая
  поворот, масштабирование и смещение. UV преобразуются до передачи меша;
  изменение UV меняет ключ геометрии, прежний лимит кеша сохраняется.

На системном D3D9 подтверждено: для FLOAT2/COUNT2 вход дополняется до
`(u,v,1,0)`. Смещение задаётся третьей строкой текстурной матрицы. Это отличается
от привычной четвёртой строки world matrix; тест специально задаёт разные
значения обеих строк. Проективные UV требуют иного интерполирования и здесь
не заменяются делением в вершинах.

Перенос выполняется только для уже распознанного индексированного FFP-наложения
с выключенным освещением. Shader deformation, дополнительный texture stage,
texgen, specular после текстурирования, запись результата в TEMP, модификаторы
аргументов, separate alpha blending и stencil остаются обычными draws.
Отказ от API-передачи не удаляет исходный игровой draw.
Неиспользуемый аргумент SELECT не ограничивает поддержку.

В reference Remix RGB-операции MODULATE2X/4X намеренно не умножают яркость,
а ADD не ограничивает RGB единицей. Простое совпадение названий перечислений
не доказывает эквивалентность; эти операции не объявлены перенесёнными.
Новые списки имён уровней, материалов и хешей не добавлялись.

## Почему эмиссия остаётся следующим шагом

Уже передаваемые unlit vertex colors не объявляются запечённым светом либо
эмиссией. D3D9 отдельно выбирает источник эмиссии: материал или один из
цветов вершины; отсутствие нужного цвета возвращает источник к материалу.
Это описано в [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/direct3d9/emissive-lighting).

В использованном Remix API `InstanceInfoBlendEXT` задаёт одну RGB-операцию,
которую `opaque_surface_material_interaction.slangh` применяет и к albedo,
и к emissive color. Для общего случая, где материал отражения и эмиссия
используют разные источники цвета, одной этой операции недостаточно.
Нужны раздельное представление входов и проверка результата. Добавлять
глобальную ambient-лампу или считать весь vertex RGB эмиссией оснований нет.
Текущий блок готовит общий перенос формул и координат, но не завершает
разделение albedo/ambient/emissive и не исправляет темноту Алфеи.

## Проверка

`Test-SurfaceMaterial.ps1`: **144 пары изображений, максимальная разница
по каждому RGBA-каналу — 0**, 1310 проверок с учётом проверок внутри цикла.
Первое изображение каждого случая строит штатный system D3D9 FFP. Второе —
отдельный pixel shader, интерпретирующий подготовленный Remix blend descriptor,
с UV из адаптера. Проверяются разные операции RGB/alpha, порядок аргументов,
texture factor, два набора UV и преобразования. Отдельно проверены отказы
на неизвестных и неэквивалентных состояниях.

Это независимая проверка платформенного преобразования по системному D3D9,
не сравнение с GPU-результатом самого Remix. Тест использует скрытое окно
и небольшой render target; ему нужен доступ к графическому устройству.
Первый запуск в sandbox вернул D3DERR_NOTAVAILABLE. При запуске с доступом
к устройству исправлена ошибка swizzle в тестовом shader; итоговые сравнения
выполнены полностью. Проверочная программа не меняет файлы игры.

MSVC x86 `/W4`: обе DLL собраны без предупреждений.

- `2026-09-12-surface-material-alfea`, промежуточная v1:
  Алфея → Гардиния 1 → Домино в одном процессе, 437 секунд до штатного выхода.
  При первой навигации Enter оказался слишком длинным и загрузил первый пункт
  списка (Гардинию 1); это не проверка выбора Домино. Последующий переход на
  Домино выполнен существующим `Sweep.select(4)`, индекс 3 подтверждён отдельно.
  Игровое состояние Домино 4, меню и подсказка закрыты, проверено короткое движение.
  732 sampled API submissions; RGB/alpha `texture × vertex`, UV 0 и 1.
  В проверенных кадрах Гардинии 1 — 31–32 наложения, Домино — 2, unknown 0.
  Ошибок light API не зарегистрировано; материальный аудит:
  30 282 sampled draws, 111 кадров, 68 наборов, 5 VS, failures/rejected 0.
  Сохранённые VS дополнительно сверены с D3DX.
- `2026-09-12-surface-material-final`: проверка итоговой v2 на Гардинии 1
  после добавления отказов для post-texture specular и TEMP. 203 секунды,
  штатный выход; кадр 8700 — 286 оснований, 32 наложения, unknown 0.
  Аудит: 17 013 sampled draws, 29 кадров, 30 наборов, 4 VS; failures/rejected 0,
  ошибок light API нет. Новые байткоды также сверены с D3DX.

В обоих запусках bridge.conf восстановлен; установленные INI, user.conf,
сохранения и четыре исходных EXE/runtime файла совпали с контрольными хешами.
Игровые процессы завершены. Точные SHA256 артефактов приведены в manifest.

В живой выборке пока встретилась прежняя комбинация MODULATE. Новые SELECT,
texture factor и COUNT2 проверены графическим стендом, но не объявлены
визуально исправленными случаями в самой игре. USD capture не запускался;
его известный сбой с API-материалами остаётся открытым.

Итоговая DLL v2:
`420F9DB77D0A1E1CFA322071CD59F8D1DDB63DF228AE5B5ABC62E91E93D3E49C`.
Предыдущая установленная DLL сохранена в локальной резервной копии.
Прогресс материалов: **15% → 20%** за реализованный и проверенный перенос
базовых формул/UV. Общая готовность после взвешивания **39,5%, округлённо ≈40%**.
Остальные категории не повышаются за эту проверку.
