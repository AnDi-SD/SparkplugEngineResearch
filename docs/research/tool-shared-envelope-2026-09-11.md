# Общая запись FFPS/FAT для ядер tools

Реализован ранее [предложенный host encoder](tool-container-writer-boundary-2026-09-10.md).
Основание — разрешение пользователя 11 сентября самостоятельно применять
ускоряющие технические замены ради готовности ядер за 3–4 дня.
Оригинальное тело whole-file Save не установлено; новый код обозначен как host.

## Что изменилось

Одна реализация в `Sparkplug/Analysis/Host/ResourceEnvelope.h` записывает
семь header words, FAT с точными raw name bytes и нулевую external file table.
Ею пользуются Editing, Importer, LVLcreator и замена leaf-объектов для
TextureTool. Исходный host producer `spSerializerManager::BuildResourceFileForAnalysis`
также подключён к ней через FAT helper; его строгие условия индексации,
C-string имён и поддержанных payload writers сохранены.

Удалены три отдельных encoder и ручное исправление FAT/header у leaf replacement.
Relocation, выбор объектов, поля и вложенные ID/size prefixes остаются в
соответствующих операциях. Это не заявление об устранении всей редакторской
логики или готовности всех ядер. Неизвестные payload, raw names, ID и порядок
каталога сохраняются. External file tables и преобразование платформ не добавлены.

Managed-код передаёт каталог через тонкую обвязку. Запись уровня в Stream
сохраняет последовательную передачу data section; временно готовится только
prefix и metadata, без дополнительной полной native копии файла.
При создании документа в памяти prefix сразу записывается в итоговый buffer.

## Проверка

- **23 операции** на четырёх pristine файлах (`object`, `logo_screen`, `barrel`,
  `Alfea02`) дали побайтно те же outputs, что сохранённые предыдущие реализации:
  добавление поля, вставка/удаление ветви, preview, stream save и leaf replacement.
  Alfea02 содержит 4 266 объектов и занимает 7 106 313 байт. Это выбранные
  примеры операций, не полный корпус и не полная игровая валидность всех мутаций.
- **17 адресных проверок**: пустой каталог, точный header, null/empty/embedded-NUL
  и non-UTF8 имена, самостоятельное владение name bytes, 65 535/65 536 байт имени,
  переполнение размера, границы output и не поддерживающий seek Stream.
- **Три свежих original PC 422B50** прочитали изменённые Node-файлы: добавление
  поля, удаление inline ветви и изменение leaf. Два/один/два Node records точно
  совпали с C++; 25/15/25 allocations освобождены. Сохранены прежние явные
  file/allocator/name fixtures и пределы 1M instructions/8 s, 128 KiB arena,
  30 s процесса. Это совместимость с оригинальным чтением, не original Save.
- Native FullLoader и SaveReference прошли после подключения общего producer;
  NodeSerialization прошёл для fresh source comparison. Managed builds успешны.
  TextureTool: **2 PNG, 6 замен, 2 052 assertions**, один Bloom_body; final report
  содержит измеренную память. Это также проверка настоящего потребителя leaf API.

Каждая финальная capture сохраняет hashes фактически загруженных assemblies и
native DLL. Старые outputs/бинарные snapshots сохранены отдельно. Финальный пакет
повторён после завершения изменения общей зависимости; первоначальные результаты
не переписаны. Исходники и результаты: [manifest](../../research/tools-core-shared-envelope-2026-09-11.json).

## Время и ограничения

В прогретых сериях по семь выполнений каждой из пяти операций Alfea02 исходно
заняло 634,73 ms; первая новая серия — 569,44 ms, финальная — 633,45 ms.
**Устойчивое ускорение исполнения не подтверждено.** Для трёх маленьких файлов
финальная сумма 14,75 ms против исходных 14,46 ms. Основной выигрыш этого шага —
одна реализация вместо нескольких и устранение общего препятствия миграции.
Дополнительные managed allocations на Alfea02 в первой серии составили примерно
0,23–0,27 MB на операцию; полного дополнительного буфера 7,1 MB нет.
Замеры относятся к операциям внутри процесса, без запуска и сбора доказательств.

При подготовке исправлена nullable ParentIndex в новом test harness. Две команды
native build были отклонены до сборки из-за передачи массива PowerShell и
execution policy; затем использован обычный Build-Native через разрешённый
process-local Bypass. В раннем synthetic fixture class/SBOO были переставлены:
исправлены и добавлена проверка настоящих signatures; окончательные 17 checks
прошли. Native rebuild показал прежнее предупреждение C4756 в spVertexBounds.h;
код расчёта сферы этим пакетом не изменялся, проверочные suites прошли.
