# Viewer 0.7.0: прямое подключение восстановленных классов Sparkplug

CP138, 8 сентября 2026. Задача после завершённого цикла CP137: заменить
самостоятельные расчёты ядра просмотра вызовами существующих C++-классов
Sparkplug, сохранив C#-приложение. Интерфейс рассматривается отдельно.

## Что подключено

Viewer 0.7.0 использует обязательную `SparkplugViewerNative.dll` через небольшой
C ABI и P/Invoke. CMake компилирует существующий `SparkplugEngine`; мост управляет
владением, индексами и буферами. Второй SAN sampler внутри моста не написан.
Это восстановленные по EXE переносимые классы из `Sparkplug/`, а не исходный SDK
разработчиков. Приложение не загружает игровой EXE.

| Ответственность | Классы, непосредственно выполняющие работу |
|---|---|
| Чтение целого SAN, создание анимации | `spSerializerManager`, `spAnimationSerializer`, `spAnimation`, `spAnimTrack` |
| Вычисление каналов и применение позы | `spTransformTrackEval`, `spNodeController` |
| Локальные преобразования и иерархия | `spNode::UpdateWorldForAnalysis` |
| Матрицы костей для skin | `spSkin::ComposePaletteMatrixForAnalysis` |

В `MainWindow` удалены прежние вызовы C# sampler, рекурсивный FK и самостоятельное
умножение palette-матриц. Обработчик воспроизведения вызывает `SparkplugSceneRuntime`.
Перемотка начинает расчёт с исходных PRS узлов; scene удерживает собственное
владение анимацией даже после освобождения managed-обёртки. Повторные обращения
к одному PRS-треку в кадре объединены, словари узлов и массивы palette переиспользуются.

## Граница переноса

Полный переносимый SMO loader пока не закрывает все зависимости, в частности
collision-объекты. Поэтому существующие C# декодеры передают в C++ исходные PRS,
логические связи дочерних узлов и inverse-bind. Разбор остальных объектов SMO,
подготовка мешей/материалов, первоначальная статическая сцена и OpenGL/WPF остаются
адаптерами Viewer. Деформация вершин для отображения и picking ещё выполняется
существующим кодом. Полный native renderer, события, actor scheduling/blending,
камерные billboards и запуск игры этим результатом не подтверждаются.

Имена связываются точно, с учётом регистра; при конфликте одного канала выбирается
первый трек и выдаётся предупреждение. Это политика Viewer. Связи не объявлены
полной реконструкцией `spActor`. Managed sampler сохраняется для Importer/Exporter;
перевод этих инструментов не входит в данную задачу.

Bloom `blwalk.san` не объявляет размеры пулов ключей. Для такого входа мост явно
выбирает `AllowMissingWithOwnedKeys` у существующего serializer: ограниченные
владеющие векторы вместо требования декларации. Любая присутствующая декларация,
включая нулевую, проверяется по-прежнему. Остальные вызовы serializer сохраняют
строгую политику по умолчанию. Поведение оригинального allocator без деклараций
не приписывается этой адаптации.

## Исправление по оригинальному PC-коду

Первое независимое сравнение выявило расхождение Icy при 1 секунде: до 0,113613
в координатах вершины. Допуск не увеличивали. Ограниченный probe оригинального
`43DB90`/`479290` прочитал SAN и снял PRS всех 64 треков. Дополнительно записаны
256 образцов для четырёх моментов времени.

Причина находилась в quaternion interpolation `4648C0`: важны порядок суммы
Z/Y/X/W, сохранение dot во float по `464901` и дальнейшие конкретные x87 spills,
включая разные промежуточные округления компонент. Простая замена всех операций
на double не воспроизводит их. Исправлен общий `spAnimationMath.h`.

После исправления 64 трека при 1 секунде совпадают с оригинальным probe точно
(максимальная абсолютная ошибка 0). Предыдущий C# reference отличается на шести
треках, максимум 0,0009660335. Для проверки Viewer только записанные PRS Icy
заменены оригинальными; независимый NumPy FK, исходная геометрия и допуски
сохранены. Битовая точность всех файлов/времён не заявляется.

## Проверки и производительность

- Пять существующих C++ suites: animation keys/runtime, node world, transform inputs,
  SAN reader — все прошли, 4,75 с.
- Interop: 2267 проверок, включая 195 сохранённых оригинальных PRS, размеры ABI,
  время жизни объектов, повторную привязку, перемотку, циклы и неверные буферы.
  Выборка: Bloom, Icy, Knut, Flora, Tecna и `igmenu_opt_pc`; около 49 МБ peak
  процесса, 0,756 с. Это число assertions, а не проверенных файлов.
- Реальные обработчики Viewer: 8359 проверок, 43 позы; независимое сравнение
  419 mesh/time строк прошло с прежними допусками. Это проверка вычисленной
  геометрии, а не сравнение итоговых пикселей GPU.
- Контракт упаковки: 11 проверок EXE/DLL, повторного использования и отказов при
  отсутствующем/лишнем файле, повреждённом кэше и неверных именах.
- Локальный пакет: состав, версии, SHA-256 ZIP и передача SMO/SAN между Viewer,
  Exporter и Importer проверены; кириллица/пробелы в путях сохранены. Peak job
  commit трёх приложений 770756608 байт, лимит 939524096 байт.

Тот же короткий CPU benchmark CP129 (60 прогревочных и 240 измеряемых кадров)
дал для расчёта иерархии Icy 0,0673–0,0801 мс вместо 0,1479, Knut 0,0629–0,0646
вместо 0,1773. Это ускорение примерно в 1,85–2,82 раза; managed allocations этого
режима уменьшились с 16176 до 296 байт/кадр. Нативные allocations этим счётчиком
не измеряются. Полный обработчик Icy колебался в пределах 0,8130–1,0157 мс
при прежних 0,8251: стабильное ускорение всего отображения не заявляется.
Это CPU handler benchmark, не FPS и не GPU timing.

## Сборка и дальнейшая работа

[Инструкция моста](../../tools/SparkplugViewer.Native/README.md) описывает сборку
x64 DLL с static CRT. Используются два compiler workers и инкрементальный Ninja.
Исправлена обнаруженная ошибка кодировки локализованного MSVC include-prefix:
до исправления Ninja терял зависимости заголовков, теперь они отслеживаются.
Полные corpus scans не запускались.

Пакет `SmoViewer-0.7.0-suite-win-x64.zip` находится в локальном каталоге
`artifacts/release/viewer-sparkplug-070/`; DLL лежит рядом с Viewer в `app/`.
Нужен .NET 8 Desktop Runtime. Отдельный clone Viewer собирается с готовой DLL
через `SparkplugNativePath`/`SkipSparkplugNativeBuild=true` либо в полном workspace.

[Validation manifest](../../research/tool-viewer-sparkplug-core-validation-2026-09-08.json)
фиксирует исходники, локальные отчёты и пакет. Игровые файлы/EXE не включены.
CP138 обновляет доказательства `viewer.scene` и `viewer.san` в прежнем scope v1;
новая архитектура не добавляет искусственный процент готовности.

Следующий перенос относится к данным геометрии/материалов и SMO загрузке:
использовать существующие классы по мере закрытия конкретных зависимостей.
Работа над интерфейсом остаётся отдельной задачей пользователя.
