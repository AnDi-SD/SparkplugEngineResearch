# CP136 — очередь следует готовности операций

После CP135 старая очередь всё ещё предлагала шесть широких PC-задач,
начиная с «интегрировать запись текстур», и общий PS2 serializer review.
Нужный срез этих операций уже прошёл проверки, но `partial` отражал оставшуюся
часть оригинальных классов. Это создавало повод повторять закрытую работу.

В [work items](../../research/native-work-items.json) сохранены все 19 PC и
3 PS2 задачи. У семи изменено только планирование: фиксированные ID операций
указаны в `resumeForOperations`, covered-срезы отложены, а исходные статусы,
классы, unknowns, evidence и test profiles сохранены. PS2 не получает credit
из готовности PC; эта связь только указывает возможную пользу сравнительного
исследования при новом конкретном пробеле.

## Поведение очереди

`native_workbench.py queue` читает последнюю assessment и проверяет текущие
hashes её evidence через существующий измеритель. При готовых16/16 очередь
не предлагает повторно исследовать эти срезы. Полный список доступен с
`--include-deferred`; явный запуск сохранённых test profiles не запрещён.

Если связанная операция не готова, отсутствует в отчёте или требует review,
соответствующая задача возвращается в `operation-review`. Например, потеря
`import.skin` возвращает три PC-задачи и один возможный PS2-срез, а не всю
очередь. Статус вычисляется при чтении и не записывается в класс/базу данных.
Восстановленная готовность снова убирает повторную работу из активного списка.

Явно активная задача по новому дефекту показывается и при16/16. Привязки
проверяются по зафиксированному SHA scope: неизвестные/повторные ID и другая
версия scope отклоняются. Недостающая информация не скрывает работу молча.

## Проверка и стоимость

22 unit tests прошли за1,768с: существующие ограничения runner/платформ,
порядок зависимостей, возврат только связанных задач, восстановление состояния,
приоритет явно активного дефекта, отсутствие assessment и смена scope.
Runner-процессы в unit tests подменены; новые native-запуски здесь не делались.

Сравнение JSON до/после подтвердило точное сохранение всех непланировочных
полей22 задач и test profiles. Ранее активные6 PC/1 PS2 теперь отложены;
широкое знание классов и metric16/16 не изменены.

Один warmup и пять измерений: валидация config, чтение77 уникальных evidence
files, read-only открытие SQLite и обе очереди — медиана1,662с внутри Python.
Это цена проверки актуальности, а не заявленное ускорение CLI. Корпус и EXE
не сканируются. Польза изменения — отсутствие повторной интеграции/реверса
уже подтверждённых операций в следующем цикле.
