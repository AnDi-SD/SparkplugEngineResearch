# События анимации: завершение,текущее состояние и звук

112 подтверждённых platform cases,56 на каждой платформе. PC40 полных
возвратов и16 callee boundaries;PS2 56 компонентов после SQ или до SQ child.
Всего было115 попыток:три ошибки нового тестового кода исправлены и только
затронутые случаи повторены. Игровые методы не заменялись и не исправлялись.
Новых C++ классов нет. Адреса и offsets ниже шестнадцатеричные,остальные
числа десятичные.

## Отметки окончания

Настоящий wxAnimationController v1 PC4FB780 иPS2 2A6DA0 обрабатывает code3,
9,11 и28. Перечень проверенных игнорируемых значений:0/2/8/10/12/27/29/FFFFFFFF.
Code28 начинает bind actor/поиск персонажа;эта ветвь здесь не квалифицирована.

Для code3 и9 handle берётся из message1C. Вначале сравнивается old,
затем recent. При совпадении очищается только первая совпавшая запись и
счётчик уменьшается на1 modulo32bit. Даже если old==recent==handle,два
декремента не происходят. Совпадение с0 также учитывается;явный counter0
может статьFFFFFFFF. При отсутствии совпадения счётчик сохраняется.

| Поле | PC | PS2 |
|---|---|---|
| old / recent | 178 /17C | 184 /188 |
| счётчик | 180 | 18C |
| mark события3 | 174 | 180 |
| mark события9 | 170 | 17C |

Mark записывается независимо от совпадения с историей. Code3 затем передаёт
исходное сообщение через настоящий spBaseObject forward40F960/100610.
Code9 заканчивается после собственного mark. Для code3 PC использует реальные
4FB5A0+40F960,для9 —4FB5E0;PS2 имеет ту же логику inline.

PC code3 с parent4=0 исполняется полностью. PS2 post-SQ вход2A6DB4 имеет
A0=parent,A1=message,V1=11,как после настоящего prologue,и останавливается
на100610. Code9/ignored доходят до2A6F84 перед LQ. Это не полный PS2 v1.

Отметки согласованы с уже проверенным consuming query4FB330/2A6C30:
их [потребители](native-character-state-permissions-2026-09-11.md) получают
разные сигналы завершения и fade. Здесь производитель и потребитель проверены
отдельно;полная последовательность доставки→переход игрового состояния не
объявляется выполненной.

## Тег сначала поступает состоянию,затем звуку

Code11 получает character из parent124/130. Если character==0,вызовов нет.
Иначе machine находится в character124/130,current index в machine130/13C,
state pointer в machine148/154+index*4. Вызывается настоящий state v15
(PC vtable3C,PS2 vtable44) с исходным message. Проверены индексы0 и41.

Затем заново читается character и его поле144/150. Это **wxAudioEmitter**,
class ID CCABEFEA,а не AIAction/AIBehavior. Идентичность найдена через
PS2 initialization2A9798..A8: lookup2933A0(CCABEFEA)→character150.
Это часть реального character v10 2A96B0. На PC protected code13E0F8A
передаёт тот же ID в599120,а return13E0FAA записывает EAX в[this+144].
Исходные getter/factory таблицы независимо связывают vtable701B94/495530
с wxAudioEmitter. Его нужный v14 —586C60/3C7DE0.

Если audio!=0,он получает `(message,variant)`. Variant —byte movement20D/219,
когда movement character12C/138 существует;при null movement передаётся0.
Проверены0/1/255 и отсутствие movement/audio. Вызов состояния предшествует
audio,точные receivers/arguments зафиксированы на настоящих входах методов.
PC останавливается до586C60,PS2 до3C7DE0,без подмены звукового поведения.

Для base state исполняются настоящие no-op v15:PC5B7A00/PS2 2C8E10 из
оригинальных vtables6F81B0/49A9E0. PC маршрут также прошёл через реальный
BirdFlyingState517C40:точное `event_takeoff` очищает только character byte26C
до передачи звуку;суффикс не совпадает. PS2 Bird маршрут останавливается на
2E5480 до SQ;его отдельно проверенное тело из предыдущего блока не подставляется.

## Пересылка наблюдателям

Отдельные PC40F960/PS2 post-SQ100624→1006C8 проверяют borrowed intrusive list
по parent4 и реальные spBaseObject v1 callbacks5B7A00/100810 из vtables
6DAEB8/48C5E0. Эти методы выполняются,а не возвращают синтетический success.
Проверены null container,пустой список,один/три элемента,разный порядок и
явная дублирующая запись. Callbacks следуют порядку списка,повторная запись
вызывает тот же объект снова. Callback message pointer сохраняется.

PC container4→head;head0/next0/element8. PS2 end=container4,first вend4,
next4/element8. Лишь используемые поля заданы явно,создание контейнера,
ownership,нормальная допустимость duplicate и mutation/reentry не утверждаются.
На всех случаях целиком сравниваются4000h bytes borrowed storage.

## Предварительный фильтр звукового события

Отдельно проверен wxAudioEmitter v14 до настоящего lookup582690/3CB8E0.
Game global755294/49FD4C задан ненулевым,его startup factory не исполняется.
Поле game1B0 сравнивается как signed32. Ветка lookup разрешена при
`state<=37 || (41<=state && state<=49) || state==70`.
Проверены0/37/38/40/41/49/50/69/70/71/7FFFFFFF/80000000/FFFFFFFF.
Отрицательные diagnostic values удовлетворяют первому сравнению;это не
утверждение об их достижимости в настоящем game flow.

Разрешённая ветвь строит key из tag10 name pointer,неизменённого variant и
константы1000000. PC lookup receiver=audio128,PS2=audio134. Здесь lookup ещё
не исполняется:тип сравнения key,выбор audio entry,загрузка/проигрывание,
random/no-repeat и доставка на устройство остаются открытыми. Отклонённая
PC ветка возвращается полностью;PS2 достигает3C7FEC перед LQ. PS2 start3C7DF8
получает S2=audio,A1=message,A2=variant,как после собственного prologue.

## Проверки и ограничения стенда

Пилот8 попыток0,679s:одна PC запись о callee не попала в UC_HOOK_CODE observer,
поскольку PcBlocks остановился раньше на block entry. Теперь аргументы этого
stop читаются из реальных регистров/стека после остановки. Повторён1 случай,
0,147s. Старый runner сохранён как probe-before-boundary-observation-fix.py.

Два общих пакета104 попытки заняли6,598/2,304s внутри двух параллельных
процессов. Две ошибки ожидания:новый тест очищал word26C вместо byte26C.
Прежний контракт и настоящая инструкция517C63 подтверждают byte store.
Исправлено только ожидание нового теста;повторены2 случая за0,314s.
Версия до исправления сохранена как probe-before-bird-byte-fix.py.
109 первоначально успешных случаев повторно не исполнялись.

Первый scout искал секцию с именем.text,но у этого ELF исполняемая секция
без имени. Его пустой результат не принят за отсутствие writes. Повторный
word scout по executable flag нашёл167 кандидатов;это включая stack/data,
кандидаты проверялись по инструкциям и class ID. Первое окно PC literal
было не выровнено по инструкции;отдельное окно13E0F8A иreturn13E0FAA фиксируют
настоящий call/store. Scout-ошибки не являются ошибками игры или native tests.

Учёт: wxAnimationController PC35→45,PS2 30→40;wxAudioEmitter PC20→25,
PS2 15→20. Четыре updates,новых полностью закрытых классов нет. Forward и
уже изученный Bird callback служат зависимостями,повторного credit не получают.
