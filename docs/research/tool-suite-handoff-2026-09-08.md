# CP135 — передача SMO/SAN между приложениями комплекта

Проверен фактический пакет Viewer 0.6.1 из
[CP134](tool-release-packages-2026-09-08.md): открытие персонажа с SAN,
кнопки запуска Exporter/Importer и запись FBX через GUI Exporter 0.7.0.
Производственный код и шесть подготовленных архивов не менялись.

Один исходный `bloom_jeans.smo` и `blwalk.san` скопированы в локальный каталог
с кириллицей и пробелами. В Viewer запущен корневой launcher, переданы оба
пути. UI Automation обращалась только к окнам проверенных процессов в
приватном desktop; пути дочерних EXE совпали с `suite/tools/...`.

## Результат

- Viewer показал 6/6 мешей с текстурами, нулевые texture issues, unsupported
  и ошибки. SAN дал 78 tracks, 52 совпадения со skeleton, 31 ключ и 1 секунду;
  интерфейс сообщил о запуске воспроизведения.
- Кнопка «Экспорт…» передала тот же SMO и ровно один SAN. Exporter показал
  `blwalk`, отключил повторный автопоиск и удалил прочитанный временный manifest.
- Кнопка «Импорт…» открыла тот же SMO: 6 mesh slots, 5 280 вершин,
  1 880 треугольников. Донор не назначался, запись SMO не выполнялась.
- Через GUI выбран FBX, отмечен `blwalk` и нажата кнопка экспорта. Применён
  bridge из `suite/native/` с прежним SHA CP128; переменная выбора внешнего
  bridge удалена только из окружения стенда. Создан FBX 1 069 632 байта,
  6 meshes/placements/skins, 97 nodes, одна исходная анимация.
- Предупреждение Exporter о приближении интерполяции между запечёнными
  ключами сохранено. Ошибок экспорта нет.
- Все окна закрылись штатно, собственных процессов не осталось, обе исходные
  и обе скопированные входные последовательности байт сохранились точно.

UI-сценарий `v2` занял 44,66 секунды, максимальный aggregate job commit
779 456 512 байт (около 743 МиБ). Лимит Job Object — 896 МиБ и четыре процесса;
Exporter и Importer закрывались по очереди. Это память всей цепочки приложений
и UI helper, не отдельного алгоритма и не рабочий набор всей машины.

## Независимый приём FBX

Blender 4.5.3 импортировал созданный GUI файл: 6 мешей, 5 280 вершин,
1 880 треугольников, у каждого меша один armature modifier. Получены armature
из 73 bones и две доступные текстуры 64×64/256×256. Один SAN представлен
Blender как 22 action для соответствующих объектов; это не 22 исходных клипа.

На кадрах 0,15,29 проверены 15 840 конечных vertex positions и изменение позы;
максимальные перемещения от начальной позы — 41,0072 и 3,78968 единицы.
Проверка после запуска Blender заняла 1,84 секунды. Его предупреждение об
отсутствии отдельного Python binary для multiprocessing не затронуло сценарий;
multiprocessing не использовался.

Эта проверка подтверждает работоспособность поставленного GUI и передачу
ресурсов. Она не заменяет численные сравнения SAN/FK из
[CP128](tool-shared-san-2026-09-08.md), оценку качества автоматических весов,
визуальный просмотр игры или проверку всех возможных моделей. Новая операция
и дополнительный процент готовности не начисляются: scope остаётся 16/16.

## Воспроизведение

Исходники стенда: `research/PackageUiProbe.cs`, `research/probe_suite_handoff.py`
и `research/inspect_package_fbx_blender.py`. UI helper собирается штатным
.NET Framework x64 `csc.exe` с `System`, `System.Core`, `System.Web.Extensions`,
`UIAutomationClient`, `UIAutomationTypes`, `WindowsBase`; source path передаётся
абсолютно. Probe принимает пакет, SMO, SAN, helper, новый локальный output
и необязательный `--export-fbx`. Пример сценария записан в validation manifest.

Локальные отчёты и точные hashes:
[validation manifest](../../research/tool-suite-handoff-validation-2026-09-08.json).
`v1` проверял только передачу; основной результат `v2` включает SAN acceptance,
удаление временного manifest и экспорт. Пакеты/архивы остаются локальными;
ранее запрошенное подтверждение GitHub destinations не получено.
