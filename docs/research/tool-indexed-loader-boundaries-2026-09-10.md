# Выбор следующего loader-среза по индексу

Повышать лимиты загрузчика сейчас не требуется: среди записей существующего
индекса самый большой SMO занимает 10 894 825 байт, максимальный каталог —
7513 объектов. Это запрос сохранённых метаданных БД, без повторного сканирования
игровых файлов. Лимиты 64 МиБ / 8192 созданных ресурсов не менялись.

Два независимых fresh-process вызова текущего `spv_graph_load`:

| PC input | Результат | Native load | Пик working set через load |
| --- | --- | ---: | ---: |
| Domino04, 10 894 825 B | 3693 объекта, 614 узлов, root1 | 0,0733 с | 44 621 824 B |
| race_02, 3 329 842 B | отказ на class43D24430, object8 | 0,00068 с | 22 044 672 B |

Отказ race_02 относится к незавершённому `spOcclusionVolume`, а не к памяти.
Каталожные 7513 объектов не означают столько успешных allocations: reader
останавливается раньше. Поэтому этот результат не подтверждает верхнюю границу
8192. Следующий полезный контракт — полный Occlusion Init и его reader.

Alfea01 также не является большим файлом: 5 945 520 B, 4411 ресурсов;
его существующий успешный spatial full-load не повторялся. Cached texture1848
остаётся отдельной границей authoring coverage.

Проверены только загрузка и уничтожение двух выбранных графов, без GUI,
рендеринга, редактирования и полного корпуса. Один worker, 30 с на процесс;
вход читается в один owned bytearray. Исходники игры и DLL не менялись.
