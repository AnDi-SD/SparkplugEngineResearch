# SAN → VMD: подтверждённые редкие ключи

CP127, 8 сентября 2026. Рабочая версия конвертера **0.3.0-test** добавляет
недостающие packed cubic position/rotation и scalar rotation, включая смешанные
линейные/кубические оси. Исследование опирается на уже восстановленные части
`spAnimation` / `spAnimTrack`; новые оригинальные классы не придумывались.
[Исходный контракт PC](native-pc-animation-keys.md) остаётся историческим досье.

## Реализация и границы

| Wire representation | Данные и выборка |
|---|---|
| 1 | Packed XYZ linear либо quaternion SLERP |
| 2 | Пять XYZ-блоков cubic либо quaternion + пересчитанный Squad control |
| 3 | Три независимые scalar linear оси |
| 4 | Три независимые scalar cubic оси; допускается смешение осей 3 и 4 |

Все времена идут перед массивом значений. Кубические коэффициенты и quaternion
controls готовятся один раз при чтении. Полином использует нормированную долю
интервала; не умножает тангенсы на длительность. Scalar rotation — радианы,
порядок `qZ*qY*qX`. Конвертер сохраняет самостоятельные времена/числа ключей осей.

Попутно исправлены две прежние математические подмены: small-angle SLERP
оригинала копирует первый quaternion при `sin(theta)<0.001`, а interval helper
для ровно двух ключей на/после последнего времени даёт index 0, fraction 0.
При трёх и более ключах возвращается последний интервал с fraction 1.
Время позы округляется до float32 один раз перед обходом костей, как аргумент
PC sampler. Это может изменить последний кадр по сравнению с Python double.

Это контракт sampler, а не всех actor time/wrap правил игры. У конвертера
нет игрового scheduler. VMD записывается с шагом 30 fps и не обещает точного
повторения кубической кривой между выходными кадрами.

Явные ограничения/отличия безопасного host-кода: нормализация входных quaternion,
roundoff clamp для Log, ограниченный сосед для одного ключа, проверка конечных
значений/границ/строго возрастающих времён, отказ от пустых cubic/scalar ветвей.
Перезаписываемые файловые коэффициенты/control могут содержать мусор; они не
используются как результат. Эти защиты не выдаются за поведение оригинального
reader при повреждённом файле и не являются побитовой эмуляцией x87.

VMD не имеет scale-канала. Неединичные использованные масштабы и cubic tangents,
которые меняли бы масштаб между ключами, по-прежнему отклоняются. Настоящий
`bbush.san / Plane01` подтверждает этот отказ: его cubic scale нельзя объявлять
перенесённым только потому, что decoder уже умеет читать его структуру.

## Проверки результата

**28 синтетических регрессий**, 0,096 с: реальные размеры/порядок данных,
коэффициенты, независимые оси, радианы и порядок вращений, Squad, единичный
scale/тангенсы, endpoint/float32, отсутствующие и повреждённые каналы, прежние
PMD/атомарная запись/пропуск ненужных ветвей. Новые тесты расширяют прежние 18.

**Оригинальный PC reader → sampler:** 29 выбранных случаев, 195 временных
точек, PRS и validity flags. Максимальное абсолютное расхождение компонента
`1.7661e-7`, допуск absolute/relative `4e-5`; фактическая ошибка сохранена.
Включены все representations, два/три/один ключ, смешанные scalar оси,
малые вращения и движение времени назад. Восемь реальных SAN: `barrel`,
`bbush`, `bflower`, `bw` и четыре Icy; в каждом сравниваются только нужные
треки. Полный корпус не перечитывался.

Original entries: payload reader `0x43DB90`, PRS sampler `0x479290`, interval
`0x478F90`, original preparation/SLERP/Log/Exp/Squad через их фактические вызовы.
Seams ограничены байтовым stream, выдачей 16-байтового descriptor и двумя ABI
CRT `acos`. Сам engine sampler/reader не заменён Python-кодом. Использованы
прежние ограничения гостя: 64 КиБ arena, 100 000 instructions/2 с на вызов,
30 с на отдельный процесс; оригинальный игровой процесс не запускался.

Дополнительно оригинал подготовил **244 PRS-позы** для четырёх синтетических
SAN с корректной FFPS-оболочкой, pool counts и двумя нужными костями Icy.
Это явно созданные контрольные клипы, не найденные игровые анимации.

**Готовый VMD:** копия единственного production-скрипта запускается из другого
рабочего каталога с обычными `input`/`output`. Три PMD: Miku Ver2, Luka и MEIKO.
На каждую — четыре реальные анимации Icy (walk/run/idle/hit) и четыре редкие
контрольные. Всего **24 VMD, 55 024 ключа**, около 11 с. Существующий независимый
MMD Tools reader читает все секции; проверяются имена, кадры, конечные unit
quaternion, hemisphere continuity, нейтральные кости и отключение IK.

Для редких клипов проверены **все 732 выходные позы**: исходная matrix FK
строится из сохранённых original-PC PRS и rest SMO, без вызова нашего sampler.
Целевая FK строится из реально прочитанных VMD. Максимальная ошибка направления
руки/ноги `8.4667e-7`. Для обычных клипов — три позы каждого; их reference
использует converter и считается регрессией, а не независимой native-проверкой.
Нового визуального запуска оригинального MMD, мешей и физики не заявляется.

Версия 0.3 не побайтно совместима с 0.2: исправленные малые вращения и выбор
конечного ключа меняют часть старых VMD. Изменения измерены по 12 обычным
результатам, детальные максимумы по каждому клипу сохранены в validation.
Историческая матрица 240 VMD версии 0.2 не прогонялась повторно.
