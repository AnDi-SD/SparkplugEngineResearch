# Материал, свет и геометрия на границе игрового draw

12 сентября 2026, `native-draw-v3`. Исследована связанная цепочка нужных для
RTX классов; добавлены общая ABI-разметка и включаемый считыватель живых данных.
Полное восстановление каждого класса и физически правильное освещение этим
блоком не объявляются завершёнными. Изображение сохраняет прежний временный
unlit → albedo + emission перенос.

Главный результат: данные для следующего переноса доступны в оригинальной
игре. Теперь материал, выбранный renderer свет, формат вершин и D3D-состояния
сопоставляются **на одном draw**. Поиск классов перестал быть предположением,
основанным только на конечном цвете экрана.

блоке нет. Прежние доказательства не переписывались; PC/PS2 различия сохранены.

## Детали, влияющие на следующую реализацию

1. **Unlit действительно выбирает игра.** В выбранных scene draws mode 2
   соответствует FFP без освещения: 3 166 draw обычной Алфеи, 2 386 RTX Алфеи,
   17 822 RTX Домино. У 19 934 из этих draw в renderer были ordinary lights
   либо ambient, но этот путь не использует их для освещения поверхности.
   Поэтому «перечислить ещё больше ламп» не воспроизводит исходную яркость.
   Цвет вершин может смешивать авторский цвет и готовое освещение; EXE не
   содержит достаточных сведений, чтобы автоматически разделить их по смыслу.

2. **Материал имеет несколько последовательных состояний.** CP33 и байты
   `4BE180` показывают: указатель установки пишется в E47C, 17 слов цвета
   копируются material+78 → E4A4, затем вызывается обновление контроллера.
   После этого lighting mode может изменить копию. Selected C18C, installed
   E47C и актуальные source colors — разные понятия. У шейдера часть констант
   читается из текущего материала. В новом живом срезе контроллеров цвета
   scene-материалов не было; анимированное различие опирается на прежнюю
   завершённую native-проверку, не на предположение о новой выборке.

3. **Mode 4 требует учитывать FFP/VS.** В `Fixed.rfx` RGB добавляет vertex
   color к рассчитанному освещению, alpha берётся из MatDiffuse. В FFP mode 4
   renderer выбирает другие material-source состояния: правило шейдера нельзя
   применять ко всем draw с числом 4. Новый журнал хранит и исходный режим,
   и реальный D3D-путь. Материальные alpha и stages записываются до адаптации.

4. **UV и отсутствие нормалей — реальные входы.** В новой выборке найдены
   stride 24 без NORMAL, stride 32 без COLOR0, stride 44 с TEXCOORD0/1,
   преобразованные UV и TCI=0x20000 / transformFlags=0x103. Последняя
   комбинация — camera-space position с projected divide, а не обычные UV0.
   В `Fixed.rfx` включённые выходные UV берутся из In.TexCoord0 и получают
   собственную матрицу; FFP может выбирать UV1. Визуальные дефекты этих путей
   нельзя автоматически приписывать ошибке view/projection.

5. **Остаточные неизвестные видимы.** Реестр API-света в Алфее содержит 20
   поддержанных источников, в Домино — 1. Ambient отдельно не является
   физической лампой. `unsupportedDynamic=1` в Домино относится к расширению
   offscreen-геометрии; это не ошибка чтения нового аудита и не доказательство,
   что объект вообще отсутствует в оригинальном draw. Перемещать лампы или
   добавлять исключение для уровня оснований нет.

## Что добавлено в код

[SparkplugAbi.h](../../Sparkplug/Analysis/PC/SparkplugAbi.h) получил две
именованные области наблюдения: renderer C178..CA0B и E47C..E4EF. Размеры
и ключевые смещения проверяются `static_assert`; полные прежние layouts
сохраняются. Это именование уже доказанных полей, **не изменение игровой
логики**. Ошибка реконструкции, требующая изменения алгоритма, не обнаружена.

[winx_native_draw_audit.h](../../research/rtx-remix/winx_native_draw_audit.h)
использует эти общие структуры. Он читает borrowed state на render thread,
проверяет renderer/device и известные material/pass/light/buffer families,
сверяет renderer material с `GetMaterial` и native VB с `GetStreamSource`.
Не вызывает методы нативных объектов, не получает владение ими и не ставит
собственный перехват. Адрес light cache не превращается в адрес RenderNode
вычитанием F0: владельцы static/partition/skin могут различаться.

Включение: `-NativeDrawAudit` у `Run-WinxRemix.ps1` или `Start-Probe.ps1`;
требуется hash-verified debug EXE, MaterialAudit включается автоматически.
Опция по умолчанию выключена. Журнал ограничен 32 MiB, 4 096 contexts,
16 MiB текста contexts; чтения и массивы ограничены. `-ShaderSemantics`
добавляет прежнюю проверку shader key/bytecode. Никаких правил по уровню,
имени материала или хешу текстуры не введено.

[analyze_native_draw.py](../../research/rtx-remix/analyze_native_draw.py)
связывает журналы по `(frame, draw)`, считает FFP/VS, исходный/эффективный
режим, форматы, alpha/UV/stages, selected lights и несколько passes.
Он не дублирует вычисление света или материалов. На Windows требует
завершения записанного PID, отвергает неполный хвост и изменение файлов
во время анализа. Последние отчёты называются `native-analysis-closed-v3.json`.

побайтово совпали. Оригинальный SHA256 `3F022480…`, debug `C27EA9DB…`.
Компиляции x86 и x64 прошли; x64 не включает native reader. Финальная
установленная x86 DLL: `5BA41AD46263BDF49CDFF580E932B6670122C1A0B4BE19A99F02222BE741B937`.

На всех 24 203 выбранных scene draws: известный DXMaterial, selected равен
installed, 68 байт renderer material равны D3D material, native VB совпал
с привязанным буфером. Невалидных selected lights/passes, ошибок чтения,
лимитов и пропусков join — **0**. Microsoft D3DX подтвердил CTAB двух
наблюдавшихся программ во всех трёх запусках; это шесть проверок двух
одинаковых программ, а не шесть новых шейдеров.

Алфея прошла диалог 70 → 27 и движение в Original/RTX; Домино — tutorial
71 → 4 и движение с ограниченной покадровой записью. Кадры просмотрены:
прежняя чрезмерная яркость/эмиссия остаётся. В исходных статичных снимках
Алфеи projection совпал точно, максимальная разница view около 2,63e-9;
это не побитовое равенство всех camera/frustum полей и не новая проверка
матриц внутри Remix. Конечные позиции после движения не сравнивались
как одинаковый маршрут или одинаковое время симуляции.

Первый RTX-запуск `play-rtx-20260912-224914-418` оставлен как непригодный
для native draw join: проверка оригинального scene entry выполнялась после
установки существующего scene hook. v3 перенёс проверку перед ним; файл
аудита появился в обоих финальных RTX-запусках. Этот запуск не включён в
таблицу. Ошибка затрагивала включение диагностики, не игровую математику.

У закрытых RTX-запусков resourceFailures=0; все тестовые процессы закрыты.
Сохранения, user.conf и winx.ini совпали с резервными копиями; bridge.conf
восстановлен и совпал по хешу. EXE и NVIDIA DLL не менялись. Предыдущая DLL
сохранена в `local-data/rtx-remix/native-draw-tests/2026-09-12-v1/adapter-before.dll`.
Опись: [research JSON](../../research/winx-remix-native-draw-context-2026-09-12.json).

## Следующий связанный блок

Сделать единый материальный вход для FFP и подтверждённых Fixed.rfx-путей:
отражающий цвет, исходный добавочный цвет, ambient/emission и отдельная alpha.
Для персонажей включить в тот же контракт палитру/нормали, для окружения —
действительный UV-источник и принадлежность прохода. Использовать общие
восстановленные функции, а RT-представление держать в собственном адаптере.
Это позволит отдельно решить временное свечение unlit-поверхностей и перенос
игрового освещения, сохраняя исходные слагаемые для сравнения.

Не закрыты физическая интерпретация ламп, независимые цветовые слагаемые
в RT, геометрия без нормалей, общий multi-pass/проецируемый UV, точный класс
одного unsupported dynamic support и полнота специальных камер/эффектов.
**Готовность интеграции остаётся 46,25% по весам, округлённо около 45%.**
Диагностика не начисляет проценты работающему изображению.
