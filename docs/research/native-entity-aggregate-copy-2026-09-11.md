# Entity: строки, векторы и блок параметров при Copy

69 случаев прошли с первого раза:30 полных PC Copy,29 PS2 собственных
компонентов и10 PS2 остановок у настоящей библиотечной функции.
Пилот8 случаев за1,527s, общий пакет61 за7,429s внутри процессов.
Новых C++ реализаций, полностью закрытых классов и изменённых игровых
алгоритмов нет. Продолжен [разбор копирования Entity](native-entity-modified-copy-2026-09-11.md).

## Строки

PC содержит собственные byte loops: переносится очередной byte, включая
первый NUL, затем цикл заканчивается. PS2 вызывает original strcpy `0040A9F0`.
Оставшиеся bytes в destination не обнуляются. Проверены пустые строки,
`Test123`, строки с NUL перед следующим полем и `FF 80 41 00` с непереносимым
хвостом после NUL. Источник целиком сохраняется; destination проверен целиком.

| Класс | PC Copy / PS2 Copy | Начала строк PC → PS2 | Дополнительные поля PC |
|---|---|---|---|
| wxBreakableBarrel | 00541CB0 / 00399B90 | 140→14C,15E→16A | words180/184 |
| wxBreakableVase | 00541450 / 0039A840 | 13C→148,15A→166 | word17C |
| wxBush | 005441A0 / 0039B270 | 14C→158,16A→176 | нет |

Порядок дополнительных полей и исходные инструкции сохранены в
[контракте](../../research/entity-aggregate-copy-contracts-2026-09-11.json).
Их PS2 offsets независимо прочитаны из инструкций и отличаются на12.
Название или смысл строки не определяется лишь по Copy. Расстояние до
следующего поля используется как ограничение входа теста, а не как отдельное
доказательство объявленной C++ ёмкости массива. Максимальные тестовые длины
без NUL:29 для Barrel/Vase/Bush,63 для Cutscene/HudMeters,31 для TargetRegion.
В исходных byte loops PC нет ограничения этими числами. Выход за object extent
не исполнялся и не объявляется нормальным игровым входом.

PS2 объекты расположены на16-byte boundaries. У Barrel/Vase/Bush/HudMeters
реально исполняются byte и/или64-bit ветки strcpy и оба возврата в caller.
Число и аргументы вызовов проверены; остаточные bytes не затронуты.
Ветвь byte `0040AAE0`,64-bit `0040AAA0`; в последнем слове поиск NUL
переходит к byte loop, который не переносит хвост после NUL.

У Cutscene и TargetRegion первая строка смещена на130, поэтому оба указателя
16-byte aligned. Original strcpy выбирает MMI `0040AA40` и LQ `0040AA44`,
не поддержанные скалярным стендом. Их PS2 success cases останавливаются
у **0040A9F0**, проверяют оба аргумента и отсутствие собственных writes до
вызова; не продолжаются с подставным успешным strcpy. Другой alignment
объектов для обхода этой ветви не применялся. Остальные части этих PS2
методов видны статически, но не считаются исполненными.

## Векторы платформы и маятника

wxMovingPlatform Copy `0057E4D0 / 00391080` переносит17 полей, wxPendulum
`005805D0 / 00392260` —16. PC выполняет полный метод, PS2 — всю собственную
часть после parent success до restore. В обоих случаях при различных
конечных положительных и отрицательных входах проверены все object bytes.

Дополнительно к собственным полям после124/130 оба метода переносят base
words4C/84 и три компонента68/6C/70 по одинаковым offsets PC/PS2.
MovingPlatform также переносит base byte48. Это не универсальный+12 для
всего объекта. PC переносит6C/70 через x87 FLD/FSTP,68 через integer MOV;
PS2 все три через LWC1/SWC1. Исполнялась исходная последовательность,
при конечных четвертях значения совпали побитно. NaN, infinity, denormal,
x87 exception/rounding behavior не квалифицированы.

## ChallengeParams

PC Copy `0057FDE0` после parent success прибавляет124 к обоим указателям,
ставит ECX=13 hex и выполняет `REP MOVSD` в `0057FE08`: **19 words /76 bytes**.
Это вся область124..16F при размере класса170. Два разных raw byte patterns
перенесены полностью, весь остальной объект и источник проверены.
Вход использует штатное для вызова направление DF=0; DF=1 не исследован.

PS2 Copy `00386050` передаёт `destination+130, source+130, 4C` в настоящий
memcpy `004074F0`. Размер класса180; аргумент4C не включает padding17C..17F.
PS2 success остановлен у memcpy, потому что выровненная ветка доходит до
LQ `00407514`. Перенос76 bytes внутри PS2 memcpy не исполнялся, padding
после его возврата не проверялся. До boundary объект полностью неизменен.

## Общий контекст и учёт

Для каждой PC проверки два настоящих factory, пустые имена, настоящий
wxEntity parent `004D9700` и CloneManager. Проверяются и подтверждённые
общие bytes28/38/39,word3C. Для PS2 источники и получатели — bounded borrowed
records; S1/S0 и начало после parent взяты из оригинального prologue.
V0=1/0 задан явно, сам parent не исполняется. Девять отдельных PS2 случаев
V0=0 подтверждают отсутствие собственных writes/библиотечных вызовов и
возврат0 перед restore для всех выбранных классов.

Свежий guest для каждого случая. PC micro100k/2s,arena64KiB,allocation32KiB;
PS2 data24KiB плюс stack/global pages,10000 instructions/500ms;process30s.
Pointer-like данные изменены только как Copy input, teardown не исполнялся.
Full PS2 parent/SQ/LQ, нормальный gameplay/ownership, непустые shared names,
self-copy и неподдержанные библиотечные ветки остаются открытыми.

18 platform assessment updates. Девять PC и шесть PS2 получают+5 за
исполненный изменённый payload; PS2 Cutscene/TargetRegion/ChallengeParams
сохраняют score15, получая новые boundary evidence без прибавки за
неисполненный перенос. Это15 повышений score, не18. Полные классы не закрыты.
Локальные артефакты в `local-data/results/native-cycle-20260911-0730/entity-aggregate-copy/`
не входят в Git; карта полей/строк и точные source hashes опубликованы в JSON.
