# Привязка Node: Barrel и назначение Copy у MoveCtrl

10 сентября 2026. Продолжение
[entity-протокола](native-entity-reference-flags-2026-09-10.md) и
[проверки триггеров](native-generic-trigger-family-2026-09-10.md).
Используется прежняя проверенная связка original Node factory `421E20` и
spEntity setter `419D00`; новые игровые реализации не добавлены.

## BreakableBarrel

Предыдущий PC default clone проходил, удаление останавливалось на чтении
`[entity+18]+2C`. При заданном пустом scene источник получил отдельный настоящий
Node до клонирования, клон — отдельный Node после возврата clone. Оба через
оригинальный setter, со счётчиками ссылок 0→1. Factory, getter, clone и оба
удаления прошли за 0,801 с; узлы освобождены оригинальным кодом сущностей.

Результат: `entity-direct/pc-wxBreakableBarrel-run5.json`, контекст
`empty-scene-bound-node`. Это полный проверяемый цикл с указанной привязкой,
не полный startup игры. PS2 destructor `00399FA0` отдельно подтверждает чтение
того же `+18 → +2C`; полный PS2 lifecycle здесь не исполнялся.
Оценка PC15→20, PS2 остаётся15.

## CharacterMoveCtrl: Copy требует Node назначения

Привязка только источника не устранила остановку Clone:
`entity-direct/pc-wxCharacterMoveCtrl-run5.json` по-прежнему завершился внутри
Copy на `004E6638`. Причина уточнена по оригинальным телам, а не по одному
адресу исключения.

PC Copy `004F6300` сохраняет аргумент назначения в ESI, источник в EDI;
перед `004F666D → 004E6630` переносит именно ESI в ECX. Helper получает
`destination+18` и вызывает у этого Node поиск трёх имён:

| Имя | PC destination offset | PS2 destination offset |
|---|---:|---:|
| camera_lookat_head | 2B4 | 2C0 |
| model_root_master | 2B8 | 2C4 |
| hand_right | 2BC | 2C8 |

Offsets шестнадцатеричные. На PS2 Copy `002B1E20` делает эти поиски inline:
загружает `destination+18` в `002B208C`, `002B20A8`, `002B20CC`, затем вызывает
Node virtual method через `vtable+30`. Source и destination не перепутаны:
S1 хранит источник, S0 — назначение.

[PC проба](../../research/probe_pc_move_controller_bound_copy.py) создала два
настоящих MoveCtrl и два Node, заранее привязала оба объекта, затем вызвала
оригинальный Copy между ними. За 0,840 с Copy вернул true; наблюдение helper
показало receiver назначения и его Node. Все три поиска вернули null у
реальных пустых Node. Собственные привязки source/destination сохранились;
оба MoveCtrl и оба Node затем удалены оригинальными методами. Всего12 стадий
с подготовкой окружения. Это проверка Copy между существующими объектами,
не прохождение или изменение Clone.

[PS2 проба](../../research/probe_ps2_move_copy_node_dependency.py) за0,117 с
проверила три scalar-префикса после явно заданного inherited copy success:
оба узла заданы; узел только у назначения; узел только у источника.
При наличии destination Node достигается настоящий consumer `001A7160`
с именем `camera_lookat_head`, аргументами `(1,0)` и receiver назначения.
При его отсутствии остановка сделана перед разыменованием null в `002B2090`.
Source не изменяется, destination+18 сохраняется. Никакой результат поиска
не подставляется; полное исполнение PS2 Copy не заявляется.

Теперь установлено, что обычная схема `factory → Copy → назначить Node`
не удовлетворяет этому Copy. Как оригинальная игра подготавливает назначение
в нормальном процессе клонирования, ещё не восстановлено. Переставлять шаги
в восстановленном Clone, копировать туда source Node или подставлять пустые
результаты поиска нельзя. Эта ветвь остаётся открытой.

Оценка MoveCtrl: PC15→25 за полный Copy с проверенной зависимостью и оба
удаления; PS215→20 за независимо установленное и проверенное требование
к назначению. Это оценки частичного поведения; ни один класс не закрыт целиком.

## Свидетельства

Локальный каталог `local-data/results/native-cycle-20260910-1900/entity-bound-node/`
содержит PC copy/caller windows, независимый PS2 copy и начало Barrel destructor,
сырые байты трёх имён на обеих платформах, две новые пробы и точные snapshots
использованного harness. Результаты прежних неудачных циклов не перезаписаны.
Все новые свидетельства привязаны к отдельному platform manifest; старые
досье с уже импортированными SHA не изменялись.
