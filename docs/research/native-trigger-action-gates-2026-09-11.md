# DispelTrigger и ChestTrigger: условия действия

11 сентября 2026. Проверены четыре runtime-метода DispelTrigger и короткий
предикат ChestTrigger. Исполняются оригинальные инструкции; новых C++ классов
и замены игровой логики нет. Связь методов с классами закреплена отдельными
окнами настоящих vtable в [контракте](../../research/trigger-action-gate-contracts-2026-09-11.json).

## DispelTrigger

| Поле / операция | PC | PS2 |
|---|---|---|
| Активный byte, рабочее описание | 1B0 | 1C8 |
| Счётчик | 1B4 | 1CC |
| Byte раннего завершения | 1B8 | 1D0 |
| Проверяемый selector | 1BC | 1D4 |
| v16 Tick | 549CE0 | 3A81C0 |
| v20 действие | 549D50 | 3A8030 |
| v21 включить / v22 выключить byte | 549AF0 / 549B00 | 3A8290 / 3A8280 |

Имена полей в таблице описывают наблюдаемое использование, исходные C++ имена
не установлены. v21 записывает ровно один byte со значением1, v22 —0;
соседние байты сохраняются.

Tick при ненулевом byte раннего завершения сразу возвращает1. Иначе вызывает
v20, если одновременно ненулевые активный byte, command+1E персонажа и
profile+2CB6. Затем передаёт управление оригинальному GenericTrigger Tick.
PC-пробы задают у родителя single125=1/fired127=1, поэтому он исполняет свой
короткий путь и настоящий v17. Это явно заданное состояние родителя, не
подставленный результат. Другие родительские ветви здесь не проверяются.

v20 отправляет событие только при выполнении всех условий:

- command+1E ненулевой;
- состояние машины персонажа PC130/PS213C равно0;
- profile+2CB4 ненулевой либо собственный selector равен6;
- среди10 записей GameFlow начиная с1B8, шагC, нет первого слова70;
- первое слово самой первой записи равно0;
- signed32 GameFlow+1B0 меньше37.

Порядок проверок подтверждён оригинальным кодом. После этого отправляется
событие2807, key22, payloadA=this, payloadB=старый счётчик. Только после
возврата отправки увеличивается текущее слово счётчика с переполнением32 бит.
При ненулевом command/flags учитывается весь byte; значение255 также проходит.
GameFlow80000000/FFFFFFFF проходит signed сравнение,37 и7FFFFFFF не проходит.
Это граничные диагностические входы, не утверждение о достижимости всех
таких состояний при нормальной игре.

GameFlow helper595050/339260 ищет ключ70 по первому слову каждой из10 записей.
Дальнейшая проверка первой записи различается по ABI: PC4F4870 возвращает bool,
PS23392B0 возвращает адресflow+1B8, а caller читает первое слово сам.
Четыре дополнительные PC-пробы защищённого getter подтвердили чтения1B8/1BC/1C0
и результат только от полного первого слова. Наблюдался реальный участок402CE1;
его точные байты сняты отдельно с правильной границы инструкции. Значение100hex
даётtrue при нулевом младшем byte. Остальные два прочитанных слова не меняют bool.

## Отправка и границы PS2

На PC настоящий4165B0 создаёт пустой менеджер подписок. В17 допустимых вызовах
настоящие40EC00 и415A20 сформировали и обработали сообщение
`[2807,0,0,22,this,0,this,oldCounter]`. Число подписок остаётся0; временные
выделения освобождены, записи менеджера сохранены. Настоящий destructor в конце
освободил все его allocations. Непустая игровая рассылка и изменение счётчика
получателем события этим опытом не проверяются. Внешняя граница стенда —
прежние bounded allocation/free и nonthrowing SEH; игровых callback-заглушек нет.

PS2 участки исполняются как независимые свежие пробы:

- Tick: head3A81CC до lookup/parent/собственного выхода; после lookup —
  отдельный вход3A81F8 с объявленным указателем персонажа до action/parent.
- v20: head3A803C до lookup;3A8050 после первого lookup до второго/выхода;
  3A8074 после второго lookup до1007A0/выхода. В последнем участке оригинальные
 339260 и3392B0 исполняются полностью. В8 допустимых случаях проверены
  A0/A1/A2/A3/T0 у настоящего входа отправки.
- Счётчик: отдельный компонент3A8130→3A813C после объявленной границы отправки;
  значения0,1,FFFFFFFF. Он не является возобновлением остановленного guest
  и не выдаётся за выполненную PS2 отправку сообщения.

Кэшированные manager/character/command/state-machine/profile/GameFlow records
заимствованы явно. Реальная конструкция этих зависимостей, cache misses,
SQ/LQ кадры и полная PS2 action-транзакция остаются открытыми.

## ChestTrigger и пакет

Chest v18 `537B80 / 39D540` возвращает `word398/3B0 == 0`. Проверены0,1,100hex,
80000000,FFFFFFFF. Вызов прямой по оригинальному адресу; неизвестное смысловое
имя поля не придумано. Общая заимствованная запись сохраняет неиспользуемое поле
vtable Dispel как decoy. Это проверка тела Chest-метода, не virtual invocation
на сконструированном Chest; его слот18 подтверждён отдельно по настоящей таблице.

108 разных основных исполнений прошли с первого раза:55 полных PC методов,
11 полных PS2 leaf-методов и42 независимых PS2 компонента. Пилот10 за0,876s,
пакет98 за10,073s внутри процессов. Ещё4 PC getter-пробы заняли0,550s и служат
поддерживающим свидетельством. Полные36KiB заимствованных записей проверены
в каждой основной пробе; допускаются только описанные byte/counter изменения.

Учёт: Dispel PC20→30/PS215→25; Chest PC20→25/PS215→20. Это четыре обновления
оценки двух классов, без полностью закрытых классов и без новых C++ реализаций.
Оценка не является долей готового исходного кода.
