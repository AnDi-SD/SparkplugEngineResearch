# Renderer skinning strides — подготовленный патч, 13 сентября 2026

Патч [skin-strides-v1.patch](skin-strides-v1.patch) исправляет два шага чтения массивов Remix API в `rtx_remix_api.cpp` из commit `b81a7b566b1eeb9edb4dc2b3c9d3972e0f253ad4`:

- Веса: `sizeof(float) * bonesPerVertex`, поскольку API хранит полный tuple на каждую вершину.
- Индексы костей: `sizeof(uint32_t) * ceil(bonesPerVertex / 4)`, поскольку один packed word содержит четыре индекса. При B≤4 это сохраняет прежний шаг; B5+ требуют нескольких words.

Это собственное исправление upstream renderer, подготовленное отдельно от исходников игры. Исходное дерево не изменено. Патч проверен `git apply --check` и применён к отдельной копии; её SHA256 совпал с ожидаемым. **Полный renderer не собран, изменённый DLL не проверен на GPU и не установлен в игру.** Связь с изображением stock runtime описана в [парном checkpoint](../../../docs/research/winx-remix-skin-api-paired-checkpoint-2026-09-13.md); идентичность исходников stock-бинарнику этим не устанавливается.

CPU-регрессия [test_skin_strides.cpp](test_skin_strides.cpp) прошла **104 проверки**. Компилируются неизменные upstream `skinning.h`, `SkinningArgs`, CPU compatibility, `Matrix4` и vector/math headers. Выражения обоих strides и цикл упаковки индексов извлекаются из точного исходного и исправленного C++, без второй вручную написанной таблицы. Передача strides из `RasterGeometry` в `SkinningArgs` дополнительно проверяется по исходным присваиваниям `dispatchSkinning`; сам Vulkan backend и полный `DrawCallState` тест не создаёт.

На B1/2/3/4/5/8 все **18 вершин** после исправления совпали с независимой формулой для заданных переносов костей. Исходные strides дали **10 неверных вершин**; исправление только weights сохранило **4 ошибки** индексов B5/B8. Проверены нормали и упаковка восьми индексов, включая 255. Порог сравнения координат CPU — `1e−5`; пороги прежнего GPU fixture и его массивы не менялись.

Тест имеет две явно ограниченные платформенные подстановки: POD `VkTransformMatrixKHR` нужен только для разбора неиспользуемого конструктора матрицы при отсутствующем Vulkan-Headers; `Logger::err` заменён тестовым обработчиком, который завершает проверку ошибкой при любой диагностике математики. Арифметика skinning и типов не заменяется. Запуск ограничен внешними 10 секундами. Нет COM, Vulkan, игры или исполнения оригинальных адресов.

Неизменённые ограничения renderer подтверждены кодом и отдельными CPU-случаями:

- `skinning.h` читает B−1 весов и вычисляет последний как `1−sum`; сохранённый B-й вес игнорируется. При B1 эффективный вес всегда 1. Поэтому произвольные authored/nonunit weights этим патчем не поддержаны.
- Вклады `weight<=0` пропускаются; позиция после этого не нормализуется. Например остаток −0,25 даёт Z=6,25 вместо 5. Нормаль нормализуется отдельно.
- Public API требует counts `vertices * B`, но текущий `CreateMesh` не проверяет соответствие массивов. `blendIndices_count` не ограничивает чтение.
- Индексы костей упакованы в bytes; `uint32` значение 256 загрязняет соседний lane. До API нужны проверка размеров/указателей, B>0 и индексов `< actualPaletteCount <= 256`. Shader не выполняет последнюю проверку. Геометрические indices являются отдельным массивом uint32 triangle-list.

Два первоначальных отказа сохранены: `strides-v1` — CRLF-зависимый поиск границы исходного фрагмента до компиляции (ошибка в tool output, отдельного stderr нет); `strides-v2` — linker `Logger::err`, с исходниками и build.log. Итоговый `strides-v3` прошёл; остаётся предупреждение повторного определения `WIN32_LEAN_AND_MEAN`. Все подробности и **351 hash-запись** — в [manifest](manifest.json) и связанном локальном evidence.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File research/rtx-remix/renderer-skinning-fix/Test-CPU.ps1 -Name strides-fresh
```

До успешного результата weighted API остаётся незавершённым.
