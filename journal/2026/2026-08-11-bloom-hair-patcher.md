# 2026-08-11 — Bloom Hair Patcher 0.1.0

## Исходная задача

Whole-model replacement сохранял стандартные длинные волосы Bloom. Первая
гипотеза состояла в переносе шести `hair_top_*`/`hair_bottom_*` точек далеко за
камеру. Эксперимент в игре опроверг её: волосы остались прикреплены к голове и
наклонились примерно на 90 градусов. Изменения SMO были удалены из Importer.

## Уточнённый вывод

Корень `Hair_Master` прикрепляется непосредственно к `Head`. Шесть body-точек
управляют ориентацией/динамикой прядей, а не положением корня всей hair-модели.
Дополнительно исправлена ранняя ошибка интерпретации ID 1: Bloom X получает
внешнюю `bloom_hair.smo`, хотя пропускает обычную attachment/runtime-логику.
Полное штатное отключение относится к Winter, ID 5.

Fashion-список начинается с ID 0 (`bloom_jeans.smo`), после него следует ID 1
(`bloomx.smo`). Это учтено в интерфейсе патчера.

## Реализация

Создан `tools/WinxHairPatcher` из Core, WPF GUI и консольных проверок. Патчер
заменяет три подтверждённых блока x86 на проверки битовых масок одинаковой
длины. Для полного отключения hair setup используется пользовательская маска;
для body attachment lookup и runtime update — та же маска плюс штатные ID 1 и
5. Это позволяет отключить волосы у Bloom X, не утверждая, что они были
отключены в оригинале.

Перед записью проверяются MD5 оригинала и сигнатуры кода. Совместимый уже
пропатченный EXE можно перенастроить. Неизвестные версии отклоняются. Запись
атомарно заменяет выбранный EXE и создаёт резервную копию с временной меткой.

## Проверка

Release-сборка завершилась без предупреждений. На локальном совместимом
`WinxClub.exe` выполнено 9 assertions: распознавание поддерживаемого состояния, Jeans ID 0,
семантика Bloom X, применение и чтение маски, сохранение размера, повторный
патч и отклонение повреждённой сигнатуры. Игровая проверка результата остаётся
следующим обязательным этапом.

При финальной упаковке выяснилось, что локальные копии EXE уже имеют MD5,
отличные от зафиксированного pristine-хеша; тестовые данные являются живыми и
могли быть изменены ручной проверкой патчера. Поэтому regression test принимает
как точный оригинал, так и собственный совместимый патч, но по-прежнему
отклоняет неизвестные сигнатуры. Эталонный оригинальный MD5 остаётся требованием
для первого применения к неподписанному патчем файлу.
