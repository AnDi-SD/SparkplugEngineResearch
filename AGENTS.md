# Обязательные правила работы в репозитории

Перед изменением софта или восстановленных исходников прочитать
[основы разработки](docs/engine/software-development-rules.md) и применять их
вместе с [манифестом исследования](docs/research/research-manifesto.md).
Правила закреплены пользователем 8 сентября 2026 и действуют для всех инструментов.

1. **Игра всегда права.** Цепочка зависимостей: наши программы → восстановленные
   исходники → игра. При расхождении сначала установить причину по оригинальной
   игре. Исправлять восстановленную логику можно только при доказанной ошибке
   реконструкции; в остальных случаях исправлять приложение или его обвязку.
   Подгонять классы под ожидаемый нашим софтом результат запрещено.
2. **Одна общая реализация игровой логики и логики движка.** Использовать
   восстановленные классы `Sparkplug/` и `Winx/` напрямую или через тонкий
   межъязыковой мост. Не создавать их C#-копии, параллельные sampler/serializer
   и обходные реализации для отдельных инструментов. Недостающую логику
   исследовать по игре и дополнять в общем восстановленном коде.
3. **Платформенный слой пишем сами.** Работа с ОС, устройствами и графическим API
   принадлежит нашему современному backend. Целевые графические API — OpenGL
   и Vulkan. DirectX 9 и привязки Windows 98/XP не переносятся в приложения.
   Новая реализация backend сохраняет подтверждённые игровые правила и результат.

При изменении восстановленной логики записывать оригинальное поведение,
доказанную ошибку реконструкции и относящуюся к исправлению проверку.
Адаптеры, UI и платформенный код не выдавать за восстановленные классы игры.

Промежуточная проверочная сборка не означает завершения всей переработки.
Граница завершения определяется задачей пользователя. Контрольная компиляция
и локальный commit не являются выпуском. Не превращать очередной этап
разработки в упаковку релиза без задачи на выпуск.
